除了兼容 OpenAI 的 API，SGLang Runtime 还提供原生服务端 API。我们介绍以下 API：

- `/generate`（文本生成模型）
- `/get_model_info`
- `/server_info`
- `/health`
- `/health_generate`
- `/flush_cache`
- `/update_weights`
- `/encode`（嵌入模型）
- `/v1/rerank`（交叉编码器重排序模型）
- `/v1/score`（仅解码器打分）
- `/classify`（奖励模型）
- `/start_expert_distribution_record`
- `/stop_expert_distribution_record`
- `/dump_expert_distribution_record`
- `/tokenize`
- `/detokenize`
- 完整的 API 列表见 [http_server.py](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/entrypoints/http_server.py)

在下面的示例中，我们主要用 `requests` 测试这些 API。你也可以使用 `curl`。

## 启动服务端

```python Example
from sglang.test.doc_patch import launch_server_cmd
from sglang.utils import wait_for_server, print_highlight, terminate_process

server_process, port = launch_server_cmd(
    "python3 -m sglang.launch_server --model-path qwen/qwen2.5-0.5b-instruct --host 0.0.0.0 --log-level warning"
)

wait_for_server(f"http://localhost:{port}", process=server_process)
```

## 生成（文本生成模型）
生成补全内容。这与 OpenAI API 中的 `/v1/completions` 类似。详细参数见[采样参数](./sampling_params)。

<Note>
💡 AI Infra 学习笔记：一次文本生成可以分成两个阶段——prefill（预填充）并行处理整个输入提示词、逐位置写入 KV 缓存，决定首个输出 token；decode（解码）逐 token 自回归生成，每一步都依赖上一步结果，串行且访存密集。绝大多数推理优化（分块预填充、投机解码、PD 分离等）都是围绕这两个阶段的特性展开的。
</Note>

```python Example
import requests

url = f"http://localhost:{port}/generate"
data = {"text": "What is the capital of France?"}

response = requests.post(url, json=data)
print_highlight(response.json())
```

## 获取模型信息

获取模型的信息。

- `model_path`：模型的路径/名称。
- `is_generation`：该模型是用作生成模型还是嵌入模型。
- `tokenizer_path`：分词器的路径/名称。
- `preferred_sampling_params`：通过 `--preferred-sampling-params` 指定的默认采样参数。本例中我们未在服务端参数里显式配置，因此返回 `None`。
- `weight_version`：该字段包含模型权重的版本，常用于追踪模型训练参数的变化或更新。
- `has_image_understanding`：模型是否具备图像理解能力。
- `has_audio_understanding`：模型是否具备音频理解能力。
- `model_type`：来自 HuggingFace 配置的模型类型（例如 "qwen2"、"llama"）。
- `architectures`：来自 HuggingFace 配置的模型架构（例如 ["Qwen2ForCausalLM"]）。
- `embedding`：解析后的嵌入服务方案。它包含池化、归一化、执行与注意力风格、Matryoshka 维度、缓存策略，以及生效的 BCG 预填充设置。当模型配置暴露了嵌入能力契约时，该字段可用。

```python Example
url = f"http://localhost:{port}/get_model_info"

response = requests.get(url)
response_json = response.json()
print_highlight(response_json)
assert response_json["model_path"] == "qwen/qwen2.5-0.5b-instruct"
assert response_json["is_generation"] is True
assert response_json["tokenizer_path"] == "qwen/qwen2.5-0.5b-instruct"
assert response_json["preferred_sampling_params"] is None
assert response_json.keys() == {
    "model_path",
    "is_generation",
    "tokenizer_path",
    "preferred_sampling_params",
    "weight_version",
    "has_image_understanding",
    "has_audio_understanding",
    "model_type",
    "architectures",
    "embedding",
}
```

## 清空缓存

清空 Radix 缓存。当 `/update_weights` API 更新模型权重时，会自动触发清空。

参数：
- `timeout`（query，float，默认 `0`，单位：秒）：清空前的空闲等待时间。`0` 表示若未空闲则立即失败。当 HiCache 异步操作正在进行时，非零 timeout 允许服务端等待至空闲后再清空，避免不必要的 400 错误。

<Note>
💡 AI Infra 学习笔记：Radix 缓存把 prompt 的 token 序列组织成共享前缀树，命中的前缀直接复用已有 KV 缓存，省去重新 prefill。`flush_cache` 用于在权重更新等场景下清空这些缓存，避免旧 KV 与新权重不匹配；离线批量推理/评测时通常希望干净状态，所以先 flush 再跑更可靠。
</Note>

```bash Command
# With timeout (wait up to 30s for idle state)
curl -s -X POST "http://127.0.0.1:30000/flush_cache?timeout=30"
```

```python Example
url = f"http://localhost:{port}/flush_cache"

response = requests.post(url)
print_highlight(response.text)
```

## 从磁盘更新权重

无需重启服务端即可从磁盘更新模型权重。仅适用于架构和参数量相同的模型。

SGLang 支持 `update_weights_from_disk` API，用于训练过程中的持续评估（把检查点保存到磁盘，再从磁盘更新权重）。

```python Example
# successful update with same architecture and size

url = f"http://localhost:{port}/update_weights_from_disk"
data = {"model_path": "qwen/qwen2.5-0.5b-instruct"}

response = requests.post(url, json=data)
print_highlight(response.text)
assert response.json()["success"] is True
assert response.json()["message"] == "Succeeded to update model weights."
```

```python Example
# failed update with different parameter size or wrong name

url = f"http://localhost:{port}/update_weights_from_disk"
data = {"model_path": "qwen/qwen2.5-0.5b-instruct-wrong"}

response = requests.post(url, json=data)
response_json = response.json()
print_highlight(response_json)
assert response_json["success"] is False
assert response_json["message"] == (
    "Failed to get weights iterator: "
    "qwen/qwen2.5-0.5b-instruct-wrong"
    " (repository not found)."
)
```

```python Example
terminate_process(server_process)
```

## v1/rerank（交叉编码器重排序模型）
给定一个查询，用交叉编码器模型对一组文档重排序。注意，该 API 仅适用于像 [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) 这样的交叉编码器模型，且 `attention-backend` 需为 `triton` 或 `torch_native`。

```python Example
reranker_process, port = launch_server_cmd("""
python3 -m sglang.launch_server --model-path BAAI/bge-reranker-v2-m3 \
    --host 0.0.0.0 --disable-radix-cache --chunked-prefill-size -1 --attention-backend triton --is-embedding --log-level warning
""")

wait_for_server(f"http://localhost:{port}", process=reranker_process)
```

```python Example
# compute rerank scores for query and documents

url = f"http://localhost:{port}/v1/rerank"
data = {
    "model": "BAAI/bge-reranker-v2-m3",
    "query": "what is panda?",
    "documents": [
        "hi",
        "The giant panda (Ailuropoda melanoleuca), sometimes called a panda bear or simply panda, is a bear species endemic to China.",
    ],
}

response = requests.post(url, json=data)
response_json = response.json()
for item in response_json:
    print_highlight(f"Score: {item['score']:.2f} - Document: '{item['document']}'")
```

```python Example
terminate_process(reranker_process)
```

## v1/score（仅解码器打分）

给定一个查询和若干候选项，计算指定 token 的概率。这对分类任务、响应打分或计算对数概率很有用。

参数：
- `query`：查询文本
- `items`：要打分的候选项文本
- `label_token_ids`：要计算概率的 token ID
- `apply_softmax`：是否应用 softmax 得到归一化概率（默认：False）
- `item_first`：拼接顺序中候选项是否在前（默认：False）
- `model`：模型名

响应中包含 `scores` —— 一个概率列表的列表，每个候选项对应一份，每份按 `label_token_ids` 的顺序排列。

```python Example
score_process, port = launch_server_cmd("""
python3 -m sglang.launch_server --model-path qwen/qwen2.5-0.5b-instruct \
    --host 0.0.0.0 --log-level warning
""")

wait_for_server(f"http://localhost:{port}", process=score_process)
```

```python Example
# Score the probability of different completions given a query
query = "The capital of France is"
items = ["Paris", "London", "Berlin"]

url = f"http://localhost:{port}/v1/score"
data = {
    "model": "qwen/qwen2.5-0.5b-instruct",
    "query": query,
    "items": items,
    "label_token_ids": [9454, 2753],  # e.g. "Yes" and "No" token ids
    "apply_softmax": True,  # Normalize probabilities to sum to 1
}

response = requests.post(url, json=data)
response_json = response.json()

# Display scores for each item
for item, scores in zip(items, response_json["scores"]):
    print_highlight(f"Item '{item}': probabilities = {[f'{s:.4f}' for s in scores]}")
```

```python Example
terminate_process(score_process)
```

## 分类（奖励模型）

SGLang Runtime 也支持奖励模型。这里我们用奖励模型对成对生成的质量进行分类。

```python Example
# Note that SGLang now treats embedding models and reward models as the same type of models.
# This will be updated in the future.

reward_process, port = launch_server_cmd("""

""")

```

```python Example
from transformers import AutoTokenizer

PROMPT = (
    "What is the range of the numeric output of a sigmoid node in a neural network?"
)

RESPONSE1 = "The output of a sigmoid node is bounded between -1 and 1."
RESPONSE2 = "The output of a sigmoid node is bounded between 0 and 1."

CONVS = [
    [{"role": "user", "content": PROMPT}, {"role": "assistant", "content": RESPONSE1}],
    [{"role": "user", "content": PROMPT}, {"role": "assistant", "content": RESPONSE2}],

tokenizer = AutoTokenizer.from_pretrained("Skywork/Skywork-Reward-Llama-3.1-8B-v0.2")
prompts = tokenizer.apply_chat_template(CONVS, tokenize=False, return_dict=False)

url = f"http://localhost:{port}/classify"
data = {"model": "Skywork/Skywork-Reward-Llama-3.1-8B-v0.2", "text": prompts}

responses = requests.post(url, json=data).json()
for response in responses:
    print_highlight(f"reward: {response['embedding'][0]}")
```

## 捕获 MoE 模型中的专家选择分布

SGLang Runtime 支持记录 MoE 模型运行过程中每个专家被选中的次数。这在分析模型吞吐量、规划优化时很有用。

*注意：为了便于阅读，下面我们只打印 csv 的前 10 行。如果你需要更深入地分析结果，请按需调整。*

<Note>
💡 AI Infra 学习笔记：MoE（混合专家）模型每个 token 只激活少量专家（top-k），不同专家被选中的频率差异很大，会出现「热门专家」与「冷门专家」。统计专家选择分布能帮助判断负载是否均衡，进而指导专家并行（EP）切分、专家复制等优化——这是 MoE 推理性能调优的重要分析手段。
</Note>

```python Example
expert_record_server_process, port = launch_server_cmd(
    "python3 -m sglang.launch_server --model-path Qwen/Qwen1.5-MoE-A2.7B --host 0.0.0.0 --expert-distribution-recorder-mode stat --log-level warning"
)

wait_for_server(f"http://localhost:{port}", process=expert_record_server_process)
```

```python Example
response = requests.post(f"http://localhost:{port}/start_expert_distribution_record")
print_highlight(response)

url = f"http://localhost:{port}/generate"
```

## Tokenize/Detokenize 示例（往返）

这个示例演示了如何一起使用 /tokenize 和 /detokenize 端点。我们先把一个字符串分词，再把得到的 ID 反分词以重建原始文本。当需要在外部处理分词、但仍想借助服务端进行反分词时，这个工作流很有用。

```python Example
tokenizer_free_server_process, port = launch_server_cmd("""
python3 -m sglang.launch_server --model-path qwen/qwen2.5-0.5b-instruct
""")

wait_for_server(f"http://localhost:{port}", process=tokenizer_free_server_process)
```

```python Example
import requests
from sglang.utils import print_highlight

base_url = f"http://localhost:{port}"
tokenize_url = f"{base_url}/tokenize"
detokenize_url = f"{base_url}/detokenize"

model_name = "qwen/qwen2.5-0.5b-instruct"
input_text = "SGLang provides efficient tokenization endpoints."
print_highlight(f"Original Input Text:\n'{input_text}'")

# --- tokenize the input text ---
tokenize_payload = {
    "model": model_name,
    "prompt": input_text,
    "add_special_tokens": False,
}
try:
    tokenize_response = requests.post(tokenize_url, json=tokenize_payload)
    tokenize_response.raise_for_status()
    tokenization_result = tokenize_response.json()
    token_ids = tokenization_result.get("tokens")

    if not token_ids:
        raise ValueError("Tokenization returned empty tokens.")

    print_highlight(f"\nTokenized Output (IDs):\n{token_ids}")
    print_highlight(f"Token Count: {tokenization_result.get('count')}")
    print_highlight(f"Max Model Length: {tokenization_result.get('max_model_len')}")

    # --- detokenize the obtained token IDs ---
    detokenize_payload = {
        "model": model_name,
        "tokens": token_ids,
        "skip_special_tokens": True,
    }

    detokenize_response = requests.post(detokenize_url, json=detokenize_payload)
    detokenize_response.raise_for_status()
    detokenization_result = detokenize_response.json()
    reconstructed_text = detokenization_result.get("text")

    print_highlight(f"\nDetokenized Output (Text):\n'{reconstructed_text}'")

    if input_text == reconstructed_text:
        print_highlight(
            "\nRound Trip Successful: Original and reconstructed text match."
        )
    else:
        print_highlight(
            "\nRound Trip Mismatch: Original and reconstructed text differ."
        )

except requests.exceptions.RequestException as e:
    print_highlight(f"\nHTTP Request Error: {e}")
except Exception as e:
    print_highlight(f"\nAn error occurred: {e}")
```

```python Example
terminate_process(tokenizer_free_server_process)
```
