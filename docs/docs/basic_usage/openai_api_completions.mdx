SGLang 提供兼容 OpenAI 的 API，帮助你从 OpenAI 服务平滑过渡到本地自托管模型。
完整的 API 参考见 [OpenAI API Reference](https://platform.openai.com/docs/api-reference)。

本教程介绍以下热门 API：

- `chat/completions`
- `completions`

视觉语言模型的[视觉 API](./openai_api_vision) 和嵌入模型的[嵌入 API](./openai_api_embeddings) 请参阅其他教程。

## 启动服务端

在终端启动服务端并等待其初始化完成。

```python Example
from sglang.test.doc_patch import launch_server_cmd
from sglang.utils import wait_for_server, print_highlight, terminate_process

server_process, port = launch_server_cmd(
    "python3 -m sglang.launch_server --model-path qwen/qwen2.5-0.5b-instruct --host 0.0.0.0 --log-level warning"
)

wait_for_server(f"http://localhost:{port}")
print(f"Server started on http://localhost:{port}")
```

## 聊天补全（Chat Completions）

### 用法

服务端完整实现了 OpenAI API。
如果有对话模板，它会自动应用 Hugging Face 分词器中指定的对话模板。
你也可以在启动服务端时用 `--chat-template` 指定自定义对话模板。

```python Example
import openai

client = openai.Client(base_url=f"http://127.0.0.1:{port}/v1", api_key="None")

response = client.chat.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    messages=[
        {"role": "user", "content": "List 3 countries and their capitals."},
    ],
    temperature=0,
    max_tokens=64,
)

print_highlight(f"Response: {response}")
```

### 模型的思维/推理支持

部分模型支持内部推理或思考过程，并可在 API 响应中暴露出来。SGLang 通过 `chat_template_kwargs` 参数和兼容的推理解析器，为各种推理模型提供统一支持。

<Note>
💡 AI Infra 学习笔记：推理模型会先在内部生成一段「思考」内容（如 DeepSeek-R1 的思维链），再输出最终答案。`chat_template_kwargs` 负责在对话模板层开关思考模式，`--reasoning-parser` 负责把模型输出的特殊标记解析成独立的 `reasoning_content` 字段——两者配合才能把推理过程与答案干净地分离开，供上层应用展示或处理。
</Note>

#### 基本用法

要启用推理输出，你需要：
1. 用合适的推理解析器启动服务端
2. 在 `chat_template_kwargs` 中设置模型专属参数
3. 可选地使用 `separate_reasoning: False` 不单独返回推理内容（默认 `True`）

<Note>
**Qwen3-Thinking 模型注意：** 这些模型始终生成思考内容，不支持 `enable_thinking` 参数。请用 `--reasoning-parser qwen3-thinking` 或 `--reasoning-parser qwen3` 解析思考内容。
</Note>

#### 示例：Qwen3 模型

```python Example
# Launch server:
# python3 -m sglang.launch_server --model Qwen/Qwen3-4B --reasoning-parser qwen3

from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",
    base_url=f"http://127.0.0.1:30000/v1",
)

model = "Qwen/Qwen3-4B"
messages = [{"role": "user", "content": "How many r's are in 'strawberry'?"}]

response = client.chat.completions.create(
    model=model,
    messages=messages,
    extra_body={
        "chat_template_kwargs": {"enable_thinking": True},
        "separate_reasoning": True
    }
)

print("Reasoning:", response.choices[0].message.reasoning_content)
print("-"*100)
print("Answer:", response.choices[0].message.content)
```

**示例输出：**
```text Output
Reasoning: Okay, so the user is asking how many 'r's are in the word 'strawberry'. Let me think. First, I need to make sure I have the word spelled correctly. Strawberry... S-T-R-A-W-B-E-R-R-Y. Wait, is that right? Let me break it down.

Starting with 'strawberry', let's write out the letters one by one. S, T, R, A, W, B, E, R, R, Y. Hmm, wait, that's 10 letters. Let me check again. S (1), T (2), R (3), A (4), W (5), B (6), E (7), R (8), R (9), Y (10). So the letters are S-T-R-A-W-B-E-R-R-Y.
...
Therefore, the answer should be three R's in 'strawberry'. But I need to make sure I'm not counting any other letters as R. Let me check again. S, T, R, A, W, B, E, R, R, Y. No other R's. So three in total. Yeah, that seems right.

----------------------------------------------------------------------------------------------------
Answer: The word "strawberry" contains **three** letters 'r'. Here's the breakdown:

1. **S-T-R-A-W-B-E-R-R-Y**
   - The **third letter** is 'R'.
   - The **eighth and ninth letters** are also 'R's.

Thus, the total count is **3**.

**Answer:** 3.
```
<Note>
设置 `"enable_thinking": False`（或省略该参数）会让 `reasoning_content` 为 `None`。Qwen3-Thinking 模型始终生成推理内容，不支持 `enable_thinking` 参数。
</Note>

#### 对数偏置（Logit Bias）支持

SGLang 在聊天补全和补全 API 中都支持 `logit_bias` 参数。该参数通过给某些 token 的 logits 加上偏置值，来修改这些 token 被生成的概率。偏置值范围是 -100 到 100，其中：

- **正值**（0 到 100）提高该 token 被选中的概率
- **负值**（-100 到 0）降低该 token 被选中的概率
- **-100** 实际上会阻止该 token 被生成

<Note>
💡 AI Infra 学习笔记：LLM 每一步都在「词汇表上的 logits 分布」上采样，`logit_bias` 就是在 softmax 之前直接对某些 token 的 logit 值做加减。加偏置相当于人为抬高/压低该 token 的概率；设为 -100 时其概率被压到接近 0，等同「禁用」。这是实现敏感词过滤、强制偏好等需求的最直接手段。
</Note>

`logit_bias` 参数接受一个字典，键为 token ID（字符串形式），值为偏置量（浮点数形式）。

#### 获取 token ID

要有效使用 `logit_bias`，你需要知道想偏置的词的 token ID。获取方法如下：

```python Example
# Get tokenizer to find token IDs
import tiktoken

# For OpenAI models, use the appropriate encoding
tokenizer = tiktoken.encoding_for_model("gpt-3.5-turbo")  # or your model

# Get token IDs for specific words
word = "sunny"
token_ids = tokenizer.encode(word)
print(f"Token IDs for '{word}': {token_ids}")

# For SGLang models, you can access the tokenizer through the client
# and get token IDs for bias
```
<Tip>
**重要：** `logit_bias` 参数使用字符串形式的 token ID 作为键，而不是实际的词。
</Tip>

### 参数

聊天补全 API 接受 OpenAI Chat Completions API 的参数。更多细节参见 [OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat/create)。

SGLang 通过 `extra_body` 参数扩展了标准 API，支持额外定制。`extra_body` 中的一个关键选项是 `chat_template_kwargs`，可用来向对话模板处理器传参。

```python Example
response = client.chat.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    messages=[
        {
            "role": "system",
            "content": "You are a knowledgeable historian who provides concise responses.",
        },
        {"role": "user", "content": "Tell me about ancient Rome"},
        {
            "role": "assistant",
            "content": "Ancient Rome was a civilization centered in Italy.",
        },
        {"role": "user", "content": "What were their major achievements?"},
    ],
    temperature=0.3,  # Lower temperature for more focused responses
    max_tokens=128,  # Reasonable length for a concise response
    top_p=0.95,  # Slightly higher for better fluency
    presence_penalty=0.2,  # Mild penalty to avoid repetition
    frequency_penalty=0.2,  # Mild penalty for more natural language
    n=1,  # Single response is usually more stable
    seed=42,  # Keep for reproducibility
)

print_highlight(response.choices[0].message.content)
```

同时也支持流式模式。

#### 对数偏置支持

补全 API 同样支持 `logit_bias` 参数，功能与上面聊天补全部分所述一致。

```python Example
stream = client.chat.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    messages=[{"role": "user", "content": "Say this is a test"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices[0].delta.content is not None:
        print(chunk.choices[0].delta.content, end="")
```

#### 返回路由专家（MoE 模型）

对于 MoE 模型，在 `extra_body` 中设置 `return_routed_experts: true` 即可返回专家路由数据。这需要 `--enable-return-routed-experts` 服务端参数。`routed_experts` 字段会在每个 choice 的 `sgl_ext` 对象中返回，包含 base64 编码的 int32 专家 ID，作为逻辑形状为 `[num_tokens, num_layers, top_k]` 的扁平数组。默认返回 `[0, seqlen - 1)`，即全部可用序列，因为 RL 工作流需要整段序列的路由专家。在 `extra_body` 中设置 `routed_experts_start_len` 为某个绝对前缀长度，可以只返回 `[routed_experts_start_len, seqlen - 1)`。例如，在多轮 RL rollout 中，前几轮 token 的路由专家已经收集过了，设置该值可避免不必要的传输——它往往是瓶颈所在。

<Note>
💡 AI Infra 学习笔记：MoE 的每个 token 都要经路由器选出 top-k 个专家，这条「路由信息」本身对训练对齐（如 GRPO）很有价值，但对纯推理却是多余的输出开销。`return_routed_experts` 把每层每 token 的专家 ID 传回客户端；多轮 rollout 里还可以用 `routed_experts_start_len` 只取本轮新增部分，避免重复传输——这是 RL 数据流水线的传输优化细节。
</Note>

```python Example
# Example with logit_bias parameter for completions API
# Note: You need to get the actual token IDs from your tokenizer
# For demonstration, we'll use some example token IDs
response = client.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    prompt="The best programming language for AI is",
    temperature=0.7,
    max_tokens=20,
    logit_bias={
        "12345": 75,  # Strongly favor token ID 12345
        "67890": -100,  # Completely avoid token ID 67890
        "11111": -25,  # Slightly discourage token ID 11111
    },
)

print_highlight(f"Response with logit bias: {response.choices[0].text}")
```

## 补全（Completions）

### 用法
补全 API 与聊天补全 API 类似，但没有 `messages` 参数，也不走对话模板。

```python Example
response = client.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    prompt="List 3 countries and their capitals.",
    temperature=0,
    max_tokens=64,
    n=1,
    stop=None,
)

print_highlight(f"Response: {response}")
```

### 参数

补全 API 接受 OpenAI Completions API 的参数。更多细节参见 [OpenAI Completions API](https://platform.openai.com/docs/api-reference/completions/create)。

下面是一个详细的补全请求示例：

```python Example
response = client.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    prompt="Write a short story about a space explorer.",
    temperature=0.7,  # Moderate temperature for creative writing
    max_tokens=150,  # Longer response for a story
    top_p=0.9,  # Balanced diversity in word choice
    stop=["\n\n", "THE END"],  # Multiple stop sequences
    presence_penalty=0.3,  # Encourage novel elements
    frequency_penalty=0.3,  # Reduce repetitive phrases
    n=1,  # Generate one completion
    seed=123,  # For reproducible results
)

print_highlight(f"Response: {response}")
```

对于 MoE 模型，在 `extra_body` 中设置 `return_routed_experts: true` 即可返回专家路由数据。这需要 `--enable-return-routed-experts` 服务端参数。`routed_experts` 字段会在每个 choice 的 `sgl_ext` 对象中返回，包含 base64 编码的 int32 专家 ID，作为逻辑形状为 `[num_tokens, num_layers, top_k]` 的扁平数组。默认返回 `[0, seqlen - 1)`，即全部可用序列，因为 RL 工作流需要整段序列的路由专家。在 `extra_body` 中设置 `routed_experts_start_len` 为某个绝对前缀长度，可以只返回 `[routed_experts_start_len, seqlen - 1)`。例如，在多轮 RL rollout 中，前几轮 token 的路由专家已经收集过了，设置该值可避免不必要的传输——它往往是瓶颈所在。

## 使用 LoRA 适配器

SGLang 支持与 OpenAI 兼容 API 配合使用的 LoRA（低秩适配）适配器。你可以用 `base-model:adapter-name` 语法直接在 `model` 参数中指定要使用的适配器。

**服务端设置：**
```bash Command
python -m sglang.launch_server \
    --model-path qwen/qwen2.5-0.5b-instruct \
    --enable-lora \
    --lora-paths adapter_a=/path/to/adapter_a adapter_b=/path/to/adapter_b
```

LoRA 服务化配置的更多细节见 [LoRA 文档](../advanced_features/lora)。

**API 调用：**

（推荐）使用 `model:adapter` 语法指定要使用的适配器：
```python Example
response = client.chat.completions.create(
    model="qwen/qwen2.5-0.5b-instruct:adapter_a",  # ← base-model:adapter-name
    messages=[{"role": "user", "content": "Convert to SQL: show all users"}],
    max_tokens=50,
)
```

**向后兼容：使用 `extra_body`**

旧版的 `extra_body` 方法仍受支持，用于向后兼容：
```python Example
# Backward compatible method
response = client.chat.completions.create(
    model="qwen/qwen2.5-0.5b-instruct",
    messages=[{"role": "user", "content": "Convert to SQL: show all users"}],
    extra_body={"lora_path": "adapter_a"},  # ← old method
    max_tokens=50,
)
```
**注意：** 当同时指定 `model:adapter` 和 `extra_body["lora_path"]` 时，`model:adapter` 语法优先。
