使用针对 SGLang 的 [AWS Deep Learning Container（DLC）](https://aws.github.io/deep-learning-containers/sglang/) 把 SGLang 部署到 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/) 端点上。
SageMaker 镜像变体通过环境变量接收模型配置，并在 8080 端口对外服务。

本指南使用预构建的 DLC 镜像。如果你想自行构建并部署自己的容器，请参见安装指南中的[方法七：在 AWS SageMaker 上运行](/docs/get-started/install#more-3)。

## 容器镜像

AWS 发布了预构建且已打安全补丁的 SGLang DLC。SageMaker GPU 镜像可在每个受支持区域的 Amazon ECR 仓库（账号 `763104351884`）中获取。例如，在 `us-west-2` 区域：

```text
763104351884.dkr.ecr.us-west-2.amazonaws.com/sglang:server-sagemaker-cuda-v1.0
```

完整的镜像标签列表请参见 [可用 DLC 镜像](https://aws.github.io/deep-learning-containers/reference/available_images/) 参考文档；区域专属的账号 ID 与受支持区域请参见[区域可用性](https://aws.github.io/deep-learning-containers/reference/region_availability/)。

## 指定模型

SageMaker 镜像按以下顺序解析模型：

1. **`SM_SGLANG_MODEL_PATH` 环境变量** —— 显式指定的 Hugging Face ID 或路径。
2. **`/opt/ml/model`** —— 当 SageMaker 通过 `ModelDataUrl` 或 `ModelDataSource` 挂载模型产物时，入口脚本默认使用该路径。

对于受门禁（gated）控制的模型，还需要传入 `HF_TOKEN`。

所有 `SM_SGLANG_*` 环境变量都会被转换为 `--<name>` 形式的 SGLang 服务端参数（例如，`SM_SGLANG_CONTEXT_LENGTH=4096` 会变成 `--context-length 4096`）。

<Note>
💡 AI Infra 学习笔记：用环境变量统一配置入口（`SM_SGLANG_*` → `--<name>`）是云平台容器化部署的常见模式——它把推理引擎的启动参数与托管平台的配置接口解耦，方便平台侧以标准方式注入模型路径、上下文长度等运行时设置。理解这类「配置适配层」有助于排查云端部署中参数没生效的问题。
</Note>

## 使用 SageMaker Python SDK 部署

```python
from sagemaker.model import Model
from sagemaker.predictor import Predictor
from sagemaker.serializers import JSONSerializer

model = Model(
    image_uri="763104351884.dkr.ecr.us-west-2.amazonaws.com/sglang:server-sagemaker-cuda-v1.0",
    role="arn:aws:iam::<account_id>:role/<role_name>",
    predictor_cls=Predictor,
    env={"SM_SGLANG_MODEL_PATH": "openai/gpt-oss-20b"},
)

predictor = model.deploy(
    instance_type="ml.g5.2xlarge",
    initial_instance_count=1,
    inference_ami_version="al2023-ami-sagemaker-inference-gpu-4-1",
    serializer=JSONSerializer(),
)

response = predictor.predict({
    "model": "openai/gpt-oss-20b",
    "messages": [{"role": "user", "content": "What is deep learning?"}],
    "max_tokens": 256,
})
print(response)

# Cleanup
predictor.delete_model()
predictor.delete_endpoint(delete_endpoint_config=True)
```

## 使用 Boto3 部署

```python
import json
import boto3

sm = boto3.client("sagemaker")
smrt = boto3.client("sagemaker-runtime")

sm.create_model(
    ModelName="sglang-model",
    PrimaryContainer={
        "Image": "763104351884.dkr.ecr.us-west-2.amazonaws.com/sglang:server-sagemaker-cuda-v1.0",
        "Environment": {"SM_SGLANG_MODEL_PATH": "openai/gpt-oss-20b"},
    },
    ExecutionRoleArn="arn:aws:iam::<account_id>:role/<role_name>",
)

sm.create_endpoint_config(
    EndpointConfigName="sglang-config",
    ProductionVariants=[{
        "VariantName": "default",
        "ModelName": "sglang-model",
        "InstanceType": "ml.g5.2xlarge",
        "InitialInstanceCount": 1,
        "InferenceAmiVersion": "al2023-ami-sagemaker-inference-gpu-4-1",
    }],
)

sm.create_endpoint(EndpointName="sglang-endpoint", EndpointConfigName="sglang-config")
sm.get_waiter("endpoint_in_service").wait(EndpointName="sglang-endpoint")

resp = smrt.invoke_endpoint(
    EndpointName="sglang-endpoint",
    ContentType="application/json",
    Body=json.dumps({
        "model": "openai/gpt-oss-20b",
        "messages": [{"role": "user", "content": "What is deep learning?"}],
        "max_tokens": 256,
    }),
)
print(json.loads(resp["Body"].read()))

# Cleanup
sm.delete_endpoint(EndpointName="sglang-endpoint")
sm.delete_endpoint_config(EndpointConfigName="sglang-config")
sm.delete_model(ModelName="sglang-model")
```

## 模型产物

当 `ModelDataUrl`（或 `ModelDataSource`）指向一个 tarball 或 S3 前缀时，SageMaker 会把它挂载到 `/opt/ml/model`。入口脚本默认把 `--model-path` 指向该位置，因此可以省略 `SM_SGLANG_MODEL_PATH`：

```text
model.tar.gz
├── config.json              # standard model files (Hugging Face layout)
├── tokenizer.json
└── *.safetensors
```

## 注意事项

- GPU 部署需要 `inference_ami_version` —— SageMaker 默认宿主 AMI 的 NVIDIA 驱动与 CUDA 13 镜像不兼容。合法取值请参见 [ProductionVariant API 参考](https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_ProductionVariant.html)。
- 该端点暴露的是兼容 OpenAI 的 API，因此请求体与 SGLang 服务端的 `/v1/chat/completions` 模式一致。
