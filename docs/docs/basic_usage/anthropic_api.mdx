SGLang 内置了一个兼容 Anthropic 的 `/v1/messages` 端点，因此任何为 Anthropic Messages API 构建的客户端——包括 Anthropic SDK 和 Claude Code 等智能体 CLI——都可以不加改动地连接到自托管的 SGLang 服务端。完整的 API 参考见
[Anthropic API Reference](https://docs.anthropic.com/en/api/messages)。

该端点会在每个 SGLang 服务端上自动注册，无需额外参数开启。
它复用与兼容 OpenAI 的端点相同的模型、对话模板和推理/工具调用解析器，并同时支持非流式与流式响应、工具使用，以及一个 `count_tokens` 路由。

本教程涵盖：

- `POST /v1/messages`（非流式与流式）
- `POST /v1/messages/count_tokens`
- 把 **Claude Code** 指向该服务端，包括实现良好前缀缓存复用所必需的 `CLAUDE_CODE_ATTRIBUTION_HEADER` 设置。

<Note>
💡 AI Infra 学习笔记：推理引擎提供「兼容 Anthropic/OpenAI」端点，本质是做一个协议翻译层——把 Anthropic Messages API 的请求格式（system、tools、tool_use 块等）映射成引擎内部统一的请求表示。对自托管部署来说，这意味着 Claude Code 等成熟生态工具可以直接换后端，是低迁移成本落地企业级应用的关键设计。
</Note>

## 启动服务端

在终端启动服务端并等待其初始化完成。Anthropic `/v1/messages` 端点会自动注册——除常规启动参数外无需额外参数。下面的示例是一个单节点 GLM-5.2-FP8 配置；跨硬件与量化方案的已验证命令请参见
[GLM-5.2 cookbook](/cookbook/autoregressive/GLM/GLM-5.2)。

```bash Command
sglang serve \
    --model-path zai-org/GLM-5.2-FP8 \
    --tp 8 \
    --speculative-algorithm EAGLE \
    --speculative-num-steps 5 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 6 \
    --reasoning-parser glm45 \
    --tool-call-parser glm47 \
    --host 0.0.0.0 \
    --port 30000
```

<Note>
- **该端点与模型无关。** `/v1/messages` 路由对任何模型默认开启；这里用 GLM-5.2 是因为其推理 + 工具使用输出最能体现 Claude Code 集成的价值，但任何模型都可以。
- **模型名与 `[1m]`。** SGLang 不校验请求中的 `model` 字段，因此 Claude Code 可以发送任意名称。`[1m]` 后缀是一个**客户端侧提示**：只有当模型名以 `[1m]` 结尾时，Claude Code 才会启用其 1M 上下文 beta 功能——没有它，上下文会被截断。在下面的 `ANTHROPIC_DEFAULT_*_MODEL` 环境变量中设置相同的 `glm-5.2[1m]`。
- **`--reasoning-parser` / `--tool-call-parser` 是可选的。** 当模型会输出推理内容（GLM-5.2、Qwen3、DeepSeek-R1 等），或你想把工具调用解析为结构化的 `tool_use` 块时，加上它们即可。没有工具调用解析器时，工具 schema 仍会被接受，但模型的工具调用会以原始文本形式返回，Claude Code 将无法执行它们。
- **上下文长度**默认为模型自身的长度（GLM-5.2 为 1M）；只有在需要截断时才传 `--context-length`。
</Note>

## 发送消息

### 非流式

使用指向该服务端的 Anthropic Python SDK。与 OpenAI SDK 不同，Anthropic SDK 会自行追加 `/v1/messages`，因此 `base_url` 应为服务端根地址，**不带** `/v1` 后缀。

```python Example
from anthropic import Anthropic

client = Anthropic(
    base_url="http://127.0.0.1:30000",
    api_key="EMPTY",  # SGLang does not require a real key by default
)

message = client.messages.create(
    model="zai-org/GLM-5.2-FP8",
    max_tokens=512,
    messages=[{"role": "user", "content": "List 3 countries and their capitals."}],
)
# A reasoning model may emit a `thinking` block before the `text` block —
# pick the text block rather than assuming content[0].
print(next(b.text for b in message.content if b.type == "text"))
```

**示例输出：**
```text Output
Here are 3 countries and their capitals:

1. **France** - Paris
2. **Japan** - Tokyo
3. **Brazil** - Brasília
```

### 流式

设置 `stream=True` 即可在生成时实时接收 Server-Sent Events。

```python Example
with client.messages.stream(
    model="zai-org/GLM-5.2-FP8",
    max_tokens=512,
    messages=[{"role": "user", "content": "Say this is a test"}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
```

**示例输出：**
```text Output
This is a test.
```

### 系统提示词

顶层 `system` 字段可接受字符串或文本块列表，与 Anthropic API 的形状一致：

```python Example
message = client.messages.create(
    model="zai-org/GLM-5.2-FP8",
    max_tokens=512,
    system="You are a helpful assistant that answers concisely.",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
)
print(next(b.text for b in message.content if b.type == "text"))
```

**示例输出：**
```text Output
The capital of France is Paris.
```

### 工具使用

工具定义遵循 Anthropic 的 `tools` schema。当服务端以 `--tool-call-parser` 启动时，模型的工具调用会以 `tool_use` 内容块的形式返回：

```python Example
message = client.messages.create(
    model="zai-org/GLM-5.2-FP8",
    max_tokens=512,
    tools=[
        {
            "name": "get_weather",
            "description": "Get the weather for a city",
            "input_schema": {
                "type": "object",
                "properties": {"city": {"type": "string"}},
                "required": ["city"],
            },
        }
    ],
    messages=[{"role": "user", "content": "What is the weather in Paris?"}],
)
print(message.stop_reason)
print([b for b in message.content if b.type == "tool_use"])
```

**示例输出：**
```text Output
tool_use
[ToolUseBlock(type='tool_use', id='toolu_01XXXX', name='get_weather', input={'city': 'Paris'})]
```

### 统计 token 数

`POST /v1/messages/count_tokens` 返回一个请求的分词后长度，而不会生成响应。它复用与 `/v1/messages` 相同的请求转换逻辑，因此系统提示词、工具和多轮历史都会被计入。

```python Example
resp = client.messages.count_tokens(
    model="zai-org/GLM-5.2-FP8",
    messages=[{"role": "user", "content": "Hello, world"}],
)
print(resp.input_tokens)
```

**示例输出：**
```text Output
15
```

## 使用 Claude Code

可以通过在启动它的 shell 里设置几个环境变量，把 Claude Code 指向 SGLang 服务端。在服务端已运行于 `:30000` 的前提下，导出全部变量并启动 `claude`：

```bash Command
export ANTHROPIC_BASE_URL="http://127.0.0.1:30000"
export ANTHROPIC_AUTH_TOKEN="dummy"                 # required by Claude Code; any non-empty string works
export API_TIMEOUT_MS="3000000"                     # long timeout — reasoning + 1M-context turns are slow
export CLAUDE_CODE_AUTO_COMPACT_WINDOW="1000000"     # let auto-compact use the full 1M window
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1   # drop autoupdater/telemetry/error-reporting noise
export CLAUDE_CODE_ATTRIBUTION_HEADER=0             # required for prefix-cache reuse — see below
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm-5.2[1m]"    # [1m] suffix enables Claude Code's 1M-context beta
export ANTHROPIC_DEFAULT_SONNET_MODEL="glm-5.2[1m]"  # [1m] suffix enables Claude Code's 1M-context beta
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm-5.2[1m]"     # [1m] suffix enables Claude Code's 1M-context beta
claude
```

每个变量的作用：

- **`ANTHROPIC_BASE_URL`** —— 把 Claude Code 指向你的 SGLang 服务端，而不是 Anthropic API。
- **`ANTHROPIC_AUTH_TOKEN`** —— Claude Code 要求非空的认证 token；当 SGLang 未以 `--api-key` 启动时，接受任意值。
- **`API_TIMEOUT_MS`** —— 调大它；推理模型的长输出和 1M 上下文的轮次经常超过默认超时时间。
- **`ANTHROPIC_DEFAULT_{HAIKU,SONNET,OPUS}_MODEL`** —— Claude Code 为各档位发送的模型名。SGLang 不校验该字段，因此任意名称都可以。使用 `glm-5.2[1m]`：`[1m]` 后缀是启用 Claude Code 1M 上下文 beta 的客户端侧提示（没有它，上下文会被截断）。
- **`CLAUDE_CODE_AUTO_COMPACT_WINDOW`** —— 设为 `1000000`，让自动压缩使用完整的 1M 窗口而非默认值，从而保持长会话存活。

<Tip>
与其在每个 shell 里导出这些变量，不如把它们持久化到 `~/.claude/settings.json` 的 `env` 键下——这样对所有 Claude Code 会话都生效：

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:30000",
    "ANTHROPIC_AUTH_TOKEN": "dummy",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
    "CLAUDE_CODE_ATTRIBUTION_HEADER": "0",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.2[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.2[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.2[1m]"
  }
}
```
</Tip>

### 必做：为前缀缓存复用设置 `CLAUDE_CODE_ATTRIBUTION_HEADER=0`

<Note>
**只要 Claude Code 经由 SGLang（或任何非 Anthropic 网关）路由，就一定要设置它。** 否则多轮对话每一轮都会把整段历史重新预填充。
</Note>

Claude Code 会在系统提示词开头附加一个按请求生成的归属块，形式为
`x-anthropic-billing-header: cc_version=<ver>.<per-request-hash>; cc_entrypoint=...; cch=<hash>;`。这个按请求生成的哈希是**各轮之间第一个不同的 token**，因此 Radix 前缀缓存只能复用这个哈希之前的短前缀，每一轮都要重新预填充系统提示词和整段对话历史。

<Note>
💡 AI Infra 学习笔记：前缀缓存（SGLang 的 Radix 缓存）按 token 序列复用相同前缀的 KV 缓存——多轮对话里只有新增部分需要重新 prefill，能大幅降低延迟与算力开销。但任何「每个请求都变化的 token」（如 Claude Code 的按请求哈希）都会让前缀在第二个 token 处就断开，缓存命中率断崖式下降。这正是这类缓存对「请求间可复用的稳定前缀」极度敏感的原因。
</Note>

设置 `CLAUDE_CODE_ATTRIBUTION_HEADER=0` 会把整行归属信息从系统提示词中移除。这是 Claude Code 文档化的环境变量，其明确目的就是「在经由 [LLM 网关](https://code.claude.com/docs/en/llm-gateway) 路由时提高提示词缓存命中率」（见 [Claude Code 环境变量参考](https://code.claude.com/docs/en/env-vars)）。

<Note>
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` **不会**移除归属块——它只涵盖自动更新器/遥测/错误上报。归属头是独立的代码路径；请使用 `CLAUDE_CODE_ATTRIBUTION_HEADER=0` 处理它。
</Note>

## 故障排查

**连接被拒绝 / `fetch failed`** —— 确保服务端已启动，且 `ANTHROPIC_BASE_URL` 中的端口与 `--port`（默认 30000）一致。如果你把 `ANTHROPIC_BASE_URL` 设为远程主机，请确认其可达，且没有被会拦截连接的代理挡在后面。

**`Model not found` / 服务端返回 404** —— SGLang 不校验请求中的 `model` 字段，服务的是启动时加载的模型，因此 404 通常意味着请求根本没到达 `/v1/messages` 路由。请确认 `ANTHROPIC_BASE_URL` 指向服务端（且没有漏掉端口），并确认服务端已完成加载。

**工具调用不生效 / 以原始文本返回** —— 用与你的模型匹配的 `--tool-call-parser` 启动服务端（例如 `glm47`、`qwen3`）。没有它，`tools` 字段仍会被接受，但模型的工具调用会以文本而不是 `tool_use` 块返回，Claude Code 将无法执行它们。

**慢 / 每一轮都重新预填充整段历史** —— 你缺少 `CLAUDE_CODE_ATTRIBUTION_HEADER=0`。Claude Code 在系统提示词里的按请求归属哈希会破坏 Radix 前缀缓存的复用；见上文。

**上下文被截断到 1M 以下** —— 要让 Claude Code 启用 1M 上下文 beta，模型名必须以 `[1m]` 结尾。请确认 `ANTHROPIC_DEFAULT_*_MODEL` 使用了 `[1m]` 后缀，且加载的模型原生上下文为 1M（GLM-5.2 是 1048576；`--context-length` 只用于截断，不能扩展）。

## 参数

`/v1/messages` 端点接受标准 Anthropic Messages API 参数。完整列表请参考
[Anthropic Messages API 参考](https://docs.anthropic.com/en/api/messages)。

推理模型通过与兼容 OpenAI 的端点相同的 `--reasoning-parser` 机制支持；通过请求传入模型的推理 kwarg（例如 DeepSeek-V3 风格模型用 `thinking`，Qwen3 风格模型用 `enable_thinking`）。推理解析器/对话模板的映射见 [OpenAI API - 补全](./openai_api_completions)。

<Note>
💡 AI Infra 学习笔记：`--reasoning-parser` / `--tool-call-parser` 是「输出后处理」组件——推理模型会输出 `<thinking>` 之类的特殊格式，解析器把推理内容与答案分开返回；工具调用同理，需按模型的特定格式解析成结构化的 `tool_use` 块。选错解析器，模型输出对客户端就不可用。
</Note>
