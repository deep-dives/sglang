## 系统配置

使用 AMD GPU（如 MI300X）时，某些系统级优化有助于保证稳定的性能。这里以 MI300X 为例。AMD 提供了 MI300X 优化与系统调优的官方文档：

- [AMD MI300X 调优指南](https://rocm.docs.amd.com/en/latest/how-to/tuning-guides/mi300x/index.html)
- [AMD Instinct MI300X 上的 LLM 推理性能验证](https://rocm.docs.amd.com/en/latest/how-to/rocm-for-ai/inference/vllm-benchmark.html)
- [AMD Instinct MI300X 系统优化](https://rocm.docs.amd.com/en/latest/how-to/system-optimization/mi300x.html)
- [AMD Instinct MI300X 工作负载优化](https://rocm.docs.amd.com/en/latest/how-to/rocm-for-ai/inference-optimization/workload.html)
- [在 AMD Instinct MI300X 上加速 DeepSeek-R1 推理](https://rocm.blogs.amd.com/artificial-intelligence/DeepSeekR1-Part2/README.html)

**注意：** 我们强烈建议完整阅读这些文档和指南，以充分发挥你的系统性能。

下面是需要为 SGLang 确认或启用的几个关键设置：

### 更新 GRUB 设置

在 `/etc/default/grub` 中，把以下内容追加到 `GRUB_CMDLINE_LINUX`：

```text GRUB Configuration
pci=realloc=off iommu=pt
```

然后运行 `sudo update-grub`（或你的发行版对应的命令），并重启。

### 禁用 NUMA 自动平衡

```bash Disable NUMA
sudo sh -c 'echo 0 > /proc/sys/kernel/numa_balancing'
```

你可以用[这个辅助脚本](https://github.com/ROCm/triton/blob/rocm_env/scripts/amd/env_check.sh)自动化或验证该修改。

请再次通读全部文档，确认你的系统采用了推荐配置。

## 安装 SGLang

你可以通过以下任一方式安装 SGLang。

### 从源码安装

```bash Command
# Use the last release branch
git clone -b v0.5.16 https://github.com/sgl-project/sglang.git
cd sglang

# Compile sgl-kernel
pip install --upgrade pip
cd python/sglang/kernels/aot
python setup_rocm.py install

# Install sglang python package along with diffusion support
cd ../../../..
rm -rf python/pyproject.toml && mv python/pyproject_other.toml python/pyproject.toml
pip install -e "python[all_hip]"
```

### 使用 Docker 安装（推荐）

Docker 镜像发布在 Docker Hub 的 [lmsysorg/sglang](https://hub.docker.com/r/lmsysorg/sglang/tags)，由 [rocm.Dockerfile](https://github.com/sgl-project/sglang/tree/main/docker) 构建。

下面的步骤演示如何构建并使用一个镜像。

1. 构建 docker 镜像。
   如果使用预构建镜像，可以跳过这一步，并在下面的步骤中把 `sglang_image` 替换成预构建镜像的名称。

   ```bash Command
   docker build -t sglang_image -f rocm.Dockerfile .
   ```

2. 创建一个方便的别名。

   ```bash Command
   alias drun='docker run -it --rm --network=host --privileged --device=/dev/kfd --device=/dev/dri \
       --ipc=host --shm-size 16G --group-add video --cap-add=SYS_PTRACE \
       --security-opt seccomp=unconfined \
       -v $HOME/dockerx:/dockerx \
       -v /data:/data'
   ```

   如果使用 RDMA，请注意：
     - `--network host` 和 `--privileged` 是 RDMA 所必需的。如果不需要 RDMA，可以去掉它们。
     - 如果使用 RoCE，可能需要设置 `NCCL_IB_GID_INDEX`，例如：`export NCCL_IB_GID_INDEX=3`。

3. 启动服务端。

   **注意：** 把下面的 `<secret>` 替换成你的 [huggingface hub token](https://huggingface.co/docs/hub/en/security-tokens)。

   ```bash Command
   drun -p 30000:30000 \
       -v ~/.cache/huggingface:/root/.cache/huggingface \
       --env "HF_TOKEN=<secret>" \
       sglang_image \
       python3 -m sglang.launch_server \
       --model-path NousResearch/Meta-Llama-3.1-8B \
       --host 0.0.0.0 \
       --port 30000
   ```

4. 要验证工具是否可用，可以在另一个终端运行基准测试，或者参考[其他文档](../basic_usage/openai_api_completions)向引擎发送请求。

   ```bash Command
   drun sglang_image \
       python3 -m sglang.bench_serving \
       --backend sglang \
       --dataset-name random \
       --num-prompts 4000 \
       --random-input 128 \
       --random-output 128
   ```

把 AMD 系统配置好并安装 SGLang 之后，你就可以充分利用 AMD 硬件来驱动 SGLang 的机器学习能力了。

## AMD GPU 上的量化

[量化文档](../advanced_features/quantization#platform-compatibility)给出了完整的兼容性矩阵。简而言之：FP8、AWQ、MXFP4、W8A8、GPTQ、compressed-tensors、Quark 和 **petit_nvfp4**（通过 [Petit](https://github.com/causalflow-ai/petit-kernel) 在 ROCm 上运行的 NVFP4）在 AMD 上都可以使用。依赖 Marlin 或 NVIDIA 专属 kernel 的方法（`awq_marlin`、`gptq_marlin`、`gguf`、`modelopt_fp8`、`modelopt_fp4`）则不可用。

需要记住的几点：

- FP8 通过 Aiter 或 Triton 工作。DeepSeek-V3/R1 这类预量化 FP8 模型开箱即用。
- 在 AMD 上，AWQ 使用 Triton 反量化 kernel。更快的 Marlin 路径不可用。
- MXFP4 需要 CDNA3/CDNA4 和 `SGLANG_USE_AITER=1`。
- `petit_nvfp4` 可通过 [Petit](https://github.com/causalflow-ai/petit-kernel) 在 MI250/MI300X 上运行 NVFP4 模型（例如 [Llama 3.3 70B FP4](https://huggingface.co/nvidia/Llama-3.3-70B-Instruct-FP4)）。用 `pip install petit-kernel` 安装；加载预量化 NVFP4 模型时不需要 `--quantization` 参数。
- `quark_int4fp8_moe` 是 AMD 独有的在线量化方法，用于 CDNA3/CDNA4 上的 MoE 模型。

其中几个后端由 [Aiter](https://github.com/ROCm/aiter) 加速。用以下方式启用：

```bash Command
export SGLANG_USE_AITER=1
```

示例——服务一个 AWQ 模型：

```bash Command
python3 -m sglang.launch_server \
    --model-path hugging-quants/Mixtral-8x7B-Instruct-v0.1-AWQ-INT4 \
    --trust-remote-code \
    --port 30000 --host 0.0.0.0
```

示例——FP8 在线量化：

```bash Command
python3 -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
    --quantization fp8 \
    --port 30000 --host 0.0.0.0
```

<Note>
💡 AI Infra 学习笔记：量化方法在不同硬件上的可用性差异，本质是 kernel 绑定的结果——Marlin 是专为 NVIDIA GPU 的稀疏/张量核心设计的反量化 kernel，AMD 只能退而求其次用 Triton 或 Aiter 实现。给 LLM 推理做量化选型时，先确认目标硬件的 kernel 生态，否则容易出现"文档说支持、实际跑不起来"的情况。
</Note>

## 示例

### 运行 DeepSeek-V3 {#running-deepseek-v3}

运行 DeepSeek-V3 的唯一区别在于启动服务端的方式。下面是一个示例命令：

```bash Command
drun -p 30000:30000 \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    --ipc=host \
    --env "HF_TOKEN=<secret>" \
    sglang_image \
    python3 -m sglang.launch_server \
    --model-path deepseek-ai/DeepSeek-V3 \ # <- here
    --tp 8 \
    --trust-remote-code \
    --host 0.0.0.0 \
    --port 30000
```

[在单台 NDv5 MI300X 虚拟机上运行 DeepSeek-R1](https://techcommunity.microsoft.com/blog/azurehighperformancecomputingblog/running-deepseek-r1-on-a-single-ndv5-mi300x-vm/4372726) 也是一个很好的参考。

### 运行 Llama3.1

运行 Llama3.1 与运行 DeepSeek-V3 几乎完全一样。唯一的区别是启动服务端时指定的模型，如下面的示例命令所示：

```bash Command
drun -p 30000:30000 \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    --ipc=host \
    --env "HF_TOKEN=<secret>" \
    sglang_image \
    python3 -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \ # <- here
    --tp 8 \
    --trust-remote-code \
    --host 0.0.0.0 \
    --port 30000
```

### 预热步骤

当服务端显示 `The server is fired up and ready to roll!` 时，表示启动成功。
