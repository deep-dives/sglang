## 安装

### 从源码安装

目前 SGLang XPU 只支持从源码安装。请参考 [PyTorch 官方文档"在 Intel GPU 上入门"](https://docs.pytorch.org/docs/stable/notes/get_start_xpu.html)安装 XPU 依赖。

```bash Command
# Create and activate a conda environment
conda create -n sgl-xpu python=3.12 -y
conda activate sgl-xpu

# Set PyTorch XPU as primary pip install channel to avoid installing the larger CUDA-enabled version and prevent potential runtime issues.
pip3 install torch==2.12.0+xpu torchao==0.17.0+xpu torchvision==0.27.0+xpu torchaudio==2.11.0+xpu --index-url https://download.pytorch.org/whl/xpu
pip3 install xgrammar --no-deps # xgrammar will introduce CUDA-enabled triton which might conflict with XPU
pip3 install apache-tvm-ffi # xgrammar requires apache-tvm-ffi

# Clone the SGLang code
git clone https://github.com/sgl-project/sglang.git
cd sglang
git checkout <YOUR-DESIRED-VERSION>

# Use dedicated toml file
cd python
cp pyproject_xpu.toml pyproject.toml
# Install SGLang dependent libs, and build SGLang main package
pip install --upgrade pip setuptools
pip install -v . --extra-index-url https://download.pytorch.org/whl/xpu
```

### 使用 Docker 安装

我们提供了 [SGLang XPU Dockerfile](https://github.com/sgl-project/sglang/blob/main/docker/xpu.Dockerfile) 方便安装。
把下面的 `<secret>` 替换成你的 [HuggingFace access token](https://huggingface.co/docs/hub/en/security-tokens)。

```bash Command
# Clone the SGLang repository
git clone https://github.com/sgl-project/sglang.git
cd sglang/docker

# Build the docker image
docker build -t sglang-xpu:latest -f xpu.Dockerfile .

# Initiate a docker container
docker run \
    -it \
    --privileged \
    --ipc=host \
    --network=host \
    --user root \
    --group-add $(getent group video | cut -d: -f3) \
    --device /dev/dri \
    -v /dev/dri/by-path:/dev/dri/by-path \
    -v /dev/shm:/dev/shm \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    -p 30000:30000 \
    -e "HF_TOKEN=<secret>" \
    sglang-xpu:latest /bin/bash
```

## 启动推理服务

启动 SGLang 服务的示例命令：

```bash
sglang serve                         \
    --model-path <MODEL_ID_OR_PATH>  \
    --trust-remote-code              \
    --disable-overlap-schedule       \
    --device xpu                     \
    --host 0.0.0.0                   \
    --tp 2                           \   # using multi GPUs
    --attention-backend intel_xpu    \   # using intel optimized XPU attention backend
    --page-size                      \   # intel_xpu attention backend supports [32, 64, 128]
```

## 用请求做基准测试

你可以通过 `bench_serving` 脚本对性能做基准测试。
在另一个终端运行该命令。

```bash
python -m sglang.bench_serving   \
    --dataset-name random        \
    --random-input-len 1024      \
    --random-output-len 1024     \
    --num-prompts 1              \
    --request-rate inf           \
    --random-range-ratio 1.0
```

通过以下命令可以查看参数的详细说明：

```bash
python -m sglang.bench_serving -h
```

[OpenAI Completions API](../basic_usage/openai_api_completions)
来格式化，并通过命令行（例如用 `curl`）或你自己的脚本发送。

## XPU 图 [实验性]

SGLang 支持 XPU 图捕获，以降低每一步的 kernel 启动开销。

<Note>
💡 AI Infra 学习笔记：CUDA 图 / XPU 图是一类"图捕获"优化——把一串 kernel 启动预录制下来再整体重放，省去逐 kernel 的启动开销（launch overhead）。对 decode 这类"同一个很小的计算要反复跑几千次"的场景收益尤其明显。Intel GPU 上对应的机制是 `torch.xpu.XPUGraph`，SGLang 把解码、预填充两个阶段的图捕获做成了可独立开关的后端。
</Note>

| 阶段 | 后端 | 机制 | 默认 |
|---|---|---|---|
| 解码 | `full` | 每个批大小一个 `torch.xpu.XPUGraph`，启动时捕获 | **关闭**（需手动开启） |
| 预填充 | `tc_piecewise` | `torch.compile` + XPU 图，每个 token 长度桶一个图段 | **关闭**（需手动开启） |
| 预填充 | `breakable` | 分段式 `torch.xpu.XPUGraph` 捕获/重放（不用 `torch.compile`）；在 attention / MoE 边界处做 eager 断点 | **关闭**（需手动开启） |

### 启用解码图

XPU 上的解码图捕获是**可选**的。需要显式启用：

```bash
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-decode full
```

### 启用预填充图

XPU 上的预填充图捕获是**可选**的，必须显式启用。
有两个后端可用：`tc_piecewise` 和 `breakable`。

#### tc_piecewise

使用 `torch.compile` 加 XPU 图，每个 token 长度桶对应一个图段：

```bash
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-prefill tc_piecewise
```

默认情况下，预填充子图用 `eager` 模式编译。切换到 `inductor` 可以生成更高质量的代码，但会拉长启动时间：

```bash
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-prefill tc_piecewise \
    --cuda-graph-tc-compiler inductor
```

#### breakable

把 transformer 堆栈捕获为分段的 `XPUGraph`，在 attention / MoE 边界处做 eager 断点，不使用 `torch.compile`：

```bash
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-prefill breakable
```

你也可以用一个 `--cuda-graph-config` JSON 参数同时配置两个阶段：

```bash
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-config '{"decode":{"backend":"full"},"prefill":{"backend":"tc_piecewise","tc_compiler":"eager"}}'
```

### 为解码启用 torch.compile

`--enable-torch-compile` 会在解码 XPU 图之上再加一层 `torch.compile` 处理：先编译模型前向，再把编译后的前向捕获为 `XPUGraph`。这可以进一步降低逐 kernel 开销，但会拉长启动时间。

```bash
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --enable-torch-compile
```

> **注意：** `--enable-torch-compile` 与预填充 `tc_piecewise` 图互斥（兼容性规则会自动禁用其中之一）。需要两者时请分开使用，或通过 `--cuda-graph-config` 显式锁定预填充后端。

### 禁用 XPU 图

两个阶段默认都是关闭的。如果想显式禁用它们：

```bash
# Disable decode graph (already off by default; explicit form)
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-decode=disabled

# Disable prefill graph (already off by default; explicit form)
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-prefill=disabled

# Disable both phases
python -m sglang.launch_server --model-path <MODEL> --device xpu \
    --cuda-graph-backend-decode=disabled \
    --cuda-graph-backend-prefill=disabled
```

### 自定义捕获分桶

默认情况下，预填充捕获规模由 `--chunked-prefill-size` 推导而来。
要指定显式的 token 长度桶：

```bash
python -m sglang.launch_server \
    --model-path <MODEL> --device xpu \
    --cuda-graph-backend-prefill tc_piecewise \
    --cuda-graph-bs-prefill 64 128 256 512
```

要指定显式的解码图批大小：

```bash
python -m sglang.launch_server \
    --model-path <MODEL> --device xpu \
    --cuda-graph-bs-decode 1 2 4 8
```

### 服务端参数

| 参数 | XPU 允许值 | 默认值 | 描述 |
|---|---|---|---|
| `--cuda-graph-backend-decode` | `full`, `disabled` | `disabled` | 解码阶段的后端。XPU 上只支持 `full`。设为 `full` 即可启用。 |
| `--cuda-graph-backend-prefill` | `tc_piecewise`, `breakable`, `disabled` | `disabled`* | 预填充阶段的后端。显式设为 `tc_piecewise` 或 `breakable` 即可启用。 |
| `--cuda-graph-tc-compiler` | `eager`, `inductor` | `eager` | `tc_piecewise` 预填充子图的编译器。`inductor` 生成的代码更优，但启动更慢。 |
| `--cuda-graph-bs-prefill` | 整数列表 | 自动 | 预填充要捕获的显式 token 长度桶。 |
| `--cuda-graph-bs-decode` | 整数列表 | 自动 | 解码要捕获的显式批大小。 |
| `--cuda-graph-config` | JSON 字符串 | — | 同时配置两个阶段的一次性 JSON 配置，例如 `'{"decode":{"backend":"full"},"prefill":{"backend":"tc_piecewise","tc_compiler":"eager"}}'`。会覆盖所有分阶段参数。 |
| `--disable-decode-cuda-graph` | — | `False` | `--cuda-graph-backend-decode=disabled` 的简写。 |
| `--disable-prefill-cuda-graph` | — | `False` | `--cuda-graph-backend-prefill=disabled` 的简写。 |
| `--enable-torch-compile` | — | `False` | 在解码 XPU 图之上应用 `torch.compile`，做进一步的 kernel 优化。 |
| `--torch-compile-max-bs` | 整数 | `32` | 设置 `--enable-torch-compile` 后，`torch.compile` 编译的最大批大小。 |

\* 除非通过 `--cuda-graph-backend-prefill` 或 `--cuda-graph-config` 显式锁定后端，
否则 XPU 上的预填充图会被自动禁用。

### 限制

| 特性 | 状态 |
|---|---|
| 内存节省器（`--enable-memory-saver`） | 暂不支持 |
| 两批重叠（`--enable-two-batch-overlap`） | 暂不支持 |
| 投机解码 | 尚未实现 |

## Intel XPU 上的预填充-解码（P/D）分离部署 [实验性]

SGLang 支持在 Intel XPU 上使用 [NIXL](https://github.com/ai-dynamo/nixl) KV 传输后端进行预填充-解码分离部署。

**已测试的模型：**

| 模型 | 备注 |
|:---:|:---:|
| [Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) | 用于集成测试；已在 Intel XPU 上通过同构 P/D 验证（XPU 预填充 + XPU 解码） |
| [Qwen/Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) | 已在 Intel XPU 上通过同构 P/D 验证（XPU 预填充 + XPU 解码） |

**前置条件：** `pip install nixl sglang-router`

**启动预填充服务端（GPU 0）：**

```bash
ZE_AFFINITY_MASK=0 UCX_POSIX_USE_PROC_LINK=n python -m sglang.launch_server \
    --model-path Qwen/Qwen3-0.6B --trust-remote-code --device xpu \
    --disaggregation-mode prefill --disaggregation-transfer-backend nixl \
    --disaggregation-bootstrap-port 12335 --host 0.0.0.0 --port 30000
```

**启动解码服务端（GPU 1）：**

```bash
ZE_AFFINITY_MASK=1 UCX_POSIX_USE_PROC_LINK=n python -m sglang.launch_server \
    --model-path Qwen/Qwen3-0.6B --trust-remote-code --device xpu \
    --disaggregation-mode decode --disaggregation-transfer-backend nixl \
    --disaggregation-bootstrap-port 12335 --host 0.0.0.0 --port 30001
```

**启动路由器：**

```bash
python -m sglang_router.launch_router \
    --pd-disaggregation \
    --prefill http://127.0.0.1:30000 \
    --decode  http://127.0.0.1:30001 \
    --host 0.0.0.0 --port 8000
```

**发送请求：**

```bash
curl http://127.0.0.1:8000/v1/completions \
    -H "Content-Type: application/json" \
    -d '{"model": "Qwen/Qwen3-0.6B", "prompt": "The capital of France is", "max_tokens": 32}'
```

> **注意：** 在 Intel XPU 上必须设置 `UCX_POSIX_USE_PROC_LINK=n`，以避免 UCX 共享内存传输问题。
