本文介绍如何借助 [Metal (MLX)](https://opensource.apple.com/projects/mlx/) 在 Apple Silicon 上运行 SGLang。如果遇到问题或有疑问，请[提 issue](https://github.com/sgl-project/sglang/issues)。

<Note>
💡 AI Infra 学习笔记：Apple Silicon 走的是完全不同的软件栈——Metal 是苹果的 GPU 框架，MLX 是苹果的机器学习框架，两者都基于统一内存（CPU/GPU 共享内存）。CUDA 生态的 kernel 和 CUDA 图在这里全部不适用，所以 SGLang 需要独立的 MLX 后端，启动时也要加 `--disable-cuda-graph`。
</Note>

## 前置条件

在 `sgl-kernel` 中编译原生 Metal kernel 需要苹果工具链（`clang++`、Metal 框架头文件和 `xcrun`）。它们随 **Xcode Command Line Tools** 一起提供，无法通过 `pip` 安装：

```bash
xcode-select --install
```

如果安装了完整的 Xcode 应用，Command Line Tools 就已经可用了。可以用 `xcode-select -p && xcrun --find metal` 验证。

## 安装 SGLang

你可以通过以下任一方式安装 SGLang。

### 从源码安装

```bash
# Use the default branch
git clone https://github.com/sgl-project/sglang.git
cd sglang

# Create and activate a virtual environment
uv venv -p 3.12 sglang-metal
source sglang-metal/bin/activate

# (Optional) Compile sgl-kernel
uv pip install --upgrade pip
uv run python/sglang/kernels/aot/setup_metal.py install

# Install sglang python package along with diffusion support
rm -f python/pyproject.toml && mv python/pyproject_other.toml python/pyproject.toml
uv pip install -e "python[all_mps]"
```

## 启动推理服务

用以下命令启动服务端：

```bash
SGLANG_USE_MLX=1 python -m sglang.launch_server \
  --model <MODEL_ID_OR_PATH> \
  --disable-cuda-graph \
  --host 0.0.0.0
```

**关键参数说明：**

1. `SGLANG_USE_MLX=1` - 启用 MLX 作为 SGLang 运行时后端（如果不设置，SGLang 会回退到支持较少的 `torch.mps`）
2. `--disable-cuda-graph` - 禁用 CUDA 图，它不适用于 Apple Metal。
3. `--disable-overlap-schedule` - 禁用 overlap 调度（默认开启，通过 MLX 的 `async_eval()` 实现）
4. `SGLANG_MLX_USE_CUSTOM_ROPE=1` - 启用可选的定制 Metal RoPE kernel。默认关闭，因此除非你为了 A/B 测试而主动开启，否则 MLX 后端使用标准 RoPE 路径。
5. `SGLANG_MLX_FUSE_SWIGLU=1` - 启用融合的 Swish-Gated Linear Unit kernel（默认关闭）
6. `SGLANG_MLX_CLEAR_CACHE_STEPS=256` - 设置清除 MLX 缓存前的解码步数（默认 256）

## 量化

MLX 后端在 Apple Silicon 上支持两条量化路径：

1. **预量化 HF 仓库。** 任何 `mlx-community/<model>-4bit`（或 `-8bit`）仓库都可以直接通过 `mlx_lm.load(...)` 加载——无需额外参数。
   ```bash
   SGLANG_USE_MLX=1 python -m sglang.launch_server \
     --model-path mlx-community/Qwen3-0.6B-4bit \
     --disable-cuda-graph
   ```
2. **在线量化。** 对于任何 fp16 模型，传入 `--quantization mlx_q4` 或 `--quantization mlx_q8`，让 sglang 在加载时通过 `mlx_lm.utils.quantize_model` 量化权重（group size 64，即 mlx-community 的默认值）。量化后的权重只保留在进程内存中，磁盘上的模型不受影响。
   ```bash
   SGLANG_USE_MLX=1 python -m sglang.launch_server \
     --model-path Qwen/Qwen3-0.6B \
     --quantization mlx_q4 \
     --disable-cuda-graph
   ```
   预期日志：
   ```
   Quantizing MLX model on-the-fly: bits=4 group_size=64 (preset=mlx_q4)
   Quantization complete in 0.13s — active mem: 1.11 GB -> 0.31 GB (71.9% reduction)
   ```
   当模型已在 HF 配置中量化（路径 1）时，MLX 后端会静默忽略 `--quantization mlx_q4`，所以这个参数无论哪种情况都可以安全传入。

## 用请求做基准测试

`sglang.benchmark_one_batch` 直接调用同步的 prefill/decode 方法，不经过调度器和 overlap 代码路径。

`sglang.benchmark_offline_throughput` 可以通过 `--disable-overlap-schedule` 参数切换是否启用 overlap 调度，因为它走的是调度器和 overlap 代码路径。

### 吞吐量测试

基本的同步单批吞吐量：
```bash
SGLANG_USE_MLX=1 python -m sglang.bench_one_batch \
  --model-path <MODEL_ID_OR_PATH> \
  --disable-cuda-graph \
  --tp-size 1 \
  --batch-size 1 \
  --input-len 60 \
  --output-len 10
```

同步离线吞吐量：
```bash
SGLANG_USE_MLX=1 python -m sglang.bench_offline_throughput \
  --model-path <MODEL_ID_OR_PATH> \
  --disable-cuda-graph \
  --num-prompts 1 \
  --disable-overlap-schedule
```

异步离线吞吐量：
```bash
SGLANG_USE_MLX=1 python -m sglang.bench_offline_throughput \
  --model-path <MODEL_ID_OR_PATH> \
  --disable-cuda-graph \
  --num-prompts 1
```
