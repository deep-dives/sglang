SGLang 通过 SGLang-JAX 后端提供高性能 TPU 推理，该后端针对 Google Cloud TPU 做了专门优化。基于 JAX 的实现可在 TPU 硬件上为大型语言模型（LLM）服务负载提供出色的吞吐量和低延迟。

如需报告 TPU 相关问题或功能请求，请访问 [sglang-jax GitHub issues 页面](https://github.com/sgl-project/sglang-jax/issues)。

**注意：** SGLang 的 TPU 支持是通过 SGLang-JAX 后端实现的，这是一个独立的、专门基于 JAX 的推理引擎，作为独立仓库维护在 [https://github.com/sgl-project/sglang-jax](https://github.com/sgl-project/sglang-jax)。

<Note>
💡 AI Infra 学习笔记：TPU 与 GPU 的架构差异很大——GPU 面向通用并行计算，kernel 通常用 CUDA 手写；TPU 是 Google 的专用矩阵乘法加速器（脉动阵列），主要依靠 XLA/JAX 这类编译器把计算图编译成高效的底层指令，极少手写 kernel。因此 SGLang 的 TPU 支持不是把 CUDA 代码移植过来，而是另起一套独立的 SGLang-JAX 引擎。理解了这一点，就能明白为什么推理引擎在不同硬件上往往是"不同实现"，而不是"同一套代码换编译目标"。
</Note>

## 安装

### 方法一：使用 PyPI（推荐）

```bash Command
pip install sglang-jax
```

### 方法二：从源码安装

```bash Command
git clone https://github.com/sgl-project/sglang-jax
cd sglang-jax
uv venv --python 3.12 && source .venv/bin/activate
uv pip install -e "python[all]"
```

### 方法三：使用 Docker

**注意：** TPU 的 Docker 支持目前仍在开发中。请使用 PyPI 或源码安装方式。

### 方法四：用 SkyPilot 使用云 TPU

[SkyPilot](https://github.com/skypilot-org/skypilot) 可以在 Google Cloud TPU 上提供简化的部署：

1. 安装 SkyPilot 并配置 GCP 访问权限（参见 [SkyPilot 文档](https://skypilot.readthedocs.io/)）

2. 创建一个 SkyPilot 配置文件：

<Accordion title={<>SkyPilot YAML：<code>sglang-jax.sky.yaml</code></>}>

```yaml Config
# sglang-jax.sky.yaml
resources:
   accelerators: tpu-v6e-4
   accelerator_args:
      tpu_vm: True
      runtime_version: v2-alpha-tpuv6e

run: |
  git clone https://github.com/sgl-project/sglang-jax.git
  cd sglang-jax
  uv venv --python 3.12
  source .venv/bin/activate
  uv pip install -e "python[all]"
```

</Accordion>

3. 启动你的 TPU 集群：

```bash Command
# Standard deployment
sky launch -c sglang-jax sglang-jax.sky.yaml --infra=gcp

# With spot instances for cost savings
sky launch -c sglang-jax sglang-jax.sky.yaml --infra=gcp --use-spot
```

## 启动推理服务

### 基础示例：Qwen-7B

```bash Command
JAX_COMPILATION_CACHE_DIR=/tmp/jit_cache python3 -u -m sgl_jax.launch_server \
    --model-path Qwen/Qwen-7B-Chat \
    --trust-remote-code \
    --dist-init-addr=0.0.0.0:10011 \
    --nnodes=1 \
    --tp-size=4 \
    --device=tpu \
    --random-seed=3 \
    --node-rank=0 \
    --mem-fraction-static=0.8 \
    --max-prefill-tokens=8192 \
    --download-dir=/tmp \
    --dtype=bfloat16 \
    --skip-server-warmup \
    --host 0.0.0.0 \
    --port 30000
```

**关键参数说明：**

1. `JAX_COMPILATION_CACHE_DIR=/tmp/jit_cache` - 启用 JIT 编译缓存，加速后续的服务端启动
2. `--tp-size=4` - 张量并行规模；与你的 TPU 核心数匹配（通常为 1、4 或 8）
3. `--device=tpu` - 指定 TPU 设备（这是 sglang-jax 的默认值）
4. `--dtype=bfloat16` - 使用 bfloat16 精度，TPU 为此做了优化
5. `--mem-fraction-static=0.8` - 为静态内存分配 80% 的 TPU HBM（可在 0.2 到 0.9 之间调整）
6. `--max-prefill-tokens=8192` - 预填充阶段处理的最大 token 数

### 高性能配置：Qwen3-8B

面向追求最优吞吐量的生产负载：

```bash Command
python3 -u -m sgl_jax.launch_server \
    --model-path Qwen/Qwen3-8B \
    --trust-remote-code \
    --tp-size=4 \
    --device=tpu \
    --mem-fraction-static=0.8 \
    --chunked-prefill-size=2048 \
    --dtype=bfloat16 \
    --max-running-requests=256 \
    --page-size=128 \
    --attention-backend=fa
```

### 进阶：投机解码（EAGLE3）

对于兼容模型，投机解码可以把吞吐量提升 20-40%：

```bash Command
python3 -u -m sgl_jax.launch_server \
    --model-path Qwen/Qwen3-32B \
    --trust-remote-code \
    --device=tpu \
    --tp-size=4 \
    --mem-fraction-static=0.8 \
    --max-prefill-tokens=4096 \
    --attention-backend=fa \
    --dtype=bfloat16 \
    --port=30000 \
    --host=0.0.0.0 \
    --disable-overlap-schedule \
    --speculative-algorithm=EAGLE3 \
    --speculative-draft-model-path=AngelSlim/Qwen3-32B_eagle3 \
    --page-size=64 \
    --speculative-eagle-topk=1 \
    --speculative-num-steps=3 \
    --speculative-num-draft-tokens=4
```

**注意：** 投机解码目前支持 Qwen3 和 LLaMA 模型家族。详细的配置指南请参阅[投机解码文档](https://github.com/sgl-project/sglang-jax/blob/main/docs/features/speculative_decoding.md)。

### 多节点分布式部署

对于需要多台 TPU VM 的大模型：

```bash Command
# Node 0 (coordinator)
python3 -m sgl_jax.launch_server \
    --model-path MODEL_PATH \
    --dist-init-addr=NODE0_IP:10011 \
    --nnodes=2 \
    --node-rank=0 \
    --tp-size=8 \
    [other parameters...]

# Node 1 (worker)
python3 -m sgl_jax.launch_server \
    --model-path MODEL_PATH \
    --dist-init-addr=NODE0_IP:10011 \
    --nnodes=2 \
    --node-rank=1 \
    --tp-size=8 \
    [other parameters...]
```

```bash Command
max_concurrencies=(8 16 32 64 128 256)

for input_seq_len in "${input_seq_lens[@]}"; do
    for output_seq_len in "${output_seq_lens[@]}"; do
        echo "======================================="
        echo "Testing ISL/OSL: $input_seq_len/$output_seq_len"
        echo "======================================="
        for max_concurrency in "${max_concurrencies[@]}"; do
            num_prompts=$((num_prompts_per_concurrency * max_concurrency))
            python3 -m sgl_jax.bench_serving \
                --backend ${backend} \
                --dataset-name random \
                --num-prompts ${num_prompts} \
                --random-input ${input_seq_len} \
                --random-output ${output_seq_len} \
                --max-concurrency ${max_concurrency} \
                --random-range-ratio 1 \
                --disable-ignore-eos \
                --warmup-requests 0
        done
    done
done
```

## 性能优化

### 内存优化

**降低内存占用：**
- 降低 `--mem-fraction-static`（从 0.8 → 0.5 → 0.3）
- 减小 `--max-prefill-tokens`（从 16384 → 8192 → 4096）
- 减小 `--max-running-requests`

**处理 OOM 错误：**
- 从保守的内存设置开始（`--mem-fraction-static=0.5`）
- 逐步调大，直到找到最优平衡点
- 增大 `--page-size` 以获得更好的内存局部性（1 → 16 → 64 → 128）

### 吞吐量优化

为了最大化每秒 token 数：

- 使用 FlashAttention 后端：`--attention-backend=fa`
- 为 Qwen3 模型启用投机解码（EAGLE3）（提升 20-40%）
- 把 `--max-running-requests` 提高到 256+
- 把 `--mem-fraction-static` 设为 0.8 以上（如果内存允许）
- 使用更大的页大小（64-128）
- 启用分块预填充：`--chunked-prefill-size=2048`

### 延迟优化

为了最小化首 token 时间（TTFT）和 token 间延迟：

- 把 `--page-size` 减小到 1-4
- 降低 `--max-running-requests`（16-32）以使用更小的批
- 减小 `--chunked-prefill-size`
- 使用保守的内存设置以避免 GC 停顿

<Note>
💡 AI Infra 学习笔记：TPU 的 HBM 容量比同代 GPU 小很多（TPU v6e 每芯片 32 GB），所以推理引擎在 TPU 上格外强调内存管理——`--mem-fraction-static` 控制静态 KV 缓存与 JIT 运行时内存的分配比例，`--page-size` 则影响分页注意力（Paged Attention）的块粒度。这些参数通常是吞吐量与延迟之间的权衡：大页提升内存局部性和吞吐，小页降低碎片与首 token 延迟。
</Note>

### TPU 特有优化

1. **JIT 编译缓存：**
   ```bash Command
   export JAX_COMPILATION_CACHE_DIR=/tmp/jit_cache
   ```
   始终设置这个环境变量，以缓存已编译的 kernel 并加快服务端启动。

2. **数据类型优化：**
   使用 `--dtype=bfloat16` 以获得 TPU 原生优化。TPU 就是专门为 bfloat16 计算设计的。

3. **张量并行：**
   让 `--tp-size` 与你的 TPU 核心配置（1、4 或 8）匹配，以获得最佳的模型分布。

4. **Attention 后端：**
   生产环境负载始终使用 `--attention-backend=fa`（FlashAttention）。

## 故障排查

### OOM（内存不足）错误

如果遇到内存不足错误：

1. 把 `--mem-fraction-static` 从 0.8 降到 0.5 或更低
2. 把 `--max-prefill-tokens` 从 8192 降到 4096 或 2048
3. 降低 `--max-running-requests` 以减小并发批大小
4. 增大 `--page-size` 以获得更好的内存布局效率

### 编译耗时过长

如果服务端启动耗时过长：

1. 确保正确设置了 `JAX_COMPILATION_CACHE_DIR`
2. 要知道首次运行需要 JIT 编译（这很正常）
3. 有编译缓存后，后续运行会明显更快
4. 可以考虑使用 `--skip-server-warmup` 把编译推迟到第一个请求到来时

### 吞吐量偏低

如果没有达到预期的吞吐量：

1. 确认 `--tp-size` 与你的 TPU 核心配置匹配
2. 检查是否启用了 `--attention-backend=fa`
3. 提高 `--max-running-requests` 以形成更大的批
4. 考虑为兼容模型启用投机解码
5. 确保内存设置允许足够的批大小

### 连接问题

如果客户端无法连接服务端：

1. 确保使用 `--host=0.0.0.0` 以便外部访问（而不只是 `127.0.0.1`）
2. 确认防火墙规则允许指定端口（默认：30000）上的流量
3. 检查服务进程是否在运行：`curl http://localhost:30000/health`

## 高级特性

### 投机解码

SGLang-JAX 支持针对 Qwen3 和 LLaMA 模型家族的 EAGLE 与 EAGLE3 投机解码算法。投机解码可以在不影响输出质量的情况下把吞吐量提升 20-40%。

详细的配置和受支持的模型组合请参阅[投机解码文档](https://github.com/sgl-project/sglang-jax/blob/main/docs/features/speculative_decoding.md)。

### 分块预填充

启用预填充与解码混合批处理，以更好地利用 TPU：

```bash Command
--chunked-prefill-size=2048 --enable-mixed-chunk
```

这让调度器可以在同一批中混合预填充和解码操作，从而提升整体吞吐量。

### 自定义 Attention 后端

SGLang-JAX 支持基于插件的 Attention 后端系统。你可以为特定用例实现自定义的注意力 kernel。

实现细节请参阅[Attention 后端文档](https://github.com/sgl-project/sglang-jax/blob/main/docs/features/attention_backend.md)。

### 环境验证

在部署前验证你的 TPU 环境：

```bash Command
python -c "from sgl_jax import check_env; check_env.check_env()"
```

该命令会检查：
- 已安装的软件包版本
- TPU 设备的可用性与规格
- 系统资源与配置
- 设置项的兼容性
