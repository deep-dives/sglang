你可以通过以下任一方式安装 SGLang。
本页主要适用于常见的 NVIDIA GPU 平台。
其他或更新的平台请参考专门页面：[AMD GPU](../hardware-platforms/amd_gpu)、[Apple Metal](../hardware-platforms/apple_metal)、[Intel Xeon CPU](../hardware-platforms/cpu_server)、[Google TPU](../hardware-platforms/tpu)、[NVIDIA DGX Spark](https://lmsys.org/blog/2025-11-03-gpt-oss-on-nvidia-dgx-spark/)、[NVIDIA Jetson](../hardware-platforms/nvidia_jetson)、[Ascend NPU](../hardware-platforms/ascend-npus/getting-started/installation) 和 [Intel XPU](../hardware-platforms/xpu)。

<Note>
前置条件：Python 3.10 及以上版本。
</Note>

## 方法一：使用 pip 或 uv

推荐使用 uv 安装，速度更快：

```bash Command
pip install --upgrade pip
pip install uv
uv pip install --prerelease=allow sglang
```

默认安装的 CUDA 主版本为 13。要在 CUDA 12 下用 pip 或 uv 安装 SGLang，请尝试以下命令：
```bash Command
pip install --upgrade pip
pip install uv
uv pip install --prerelease=allow sglang
uv pip install --force-reinstall torch==2.13.0 torchaudio==2.11.0 torchvision --index-url https://download.pytorch.org/whl/cu129
uv pip install --force-reinstall sglang-kernel --index-url https://docs.sglang.ai/whl/cu129/
uv pip install --force-reinstall sgl-deep-gemm --index-url https://docs.sglang.ai/whl/cu129/ --no-deps
```

### 每日构建版（Nightly）

想在下一个稳定版发布前用到最新特性和修复，可以安装每日构建版。Nightly wheel 包由最新的 `main` 分支构建，并发布到 SGLang 的 wheel 索引。通过 `--extra-index-url` 添加该索引，并把 `--prerelease=allow` 与 `--index-strategy unsafe-best-match` 组合使用，这样 uv 就会把 nightly（预发布）版本与 PyPI 上的版本放在一起考虑：

```bash Command
pip install --upgrade pip
pip install uv
uv pip install --prerelease=allow --index-strategy unsafe-best-match --extra-index-url https://docs.sglang.ai/whl/cu130/ sglang
```

要在 CUDA 12 下安装 nightly 版本，把索引换成 `cu129`：
```bash Command
pip install --upgrade pip
pip install uv
uv pip install --prerelease=allow --index-strategy unsafe-best-match --extra-index-url https://docs.sglang.ai/whl/cu129/ sglang
```

### 常见问题的快速修复
- 如果遇到 `OSError: CUDA_HOME environment variable is not set`，请用以下任一方式把它设置到你的 CUDA 安装根目录：
  1. 使用 `export CUDA_HOME=/usr/local/cuda-<your-cuda-version>` 设置 `CUDA_HOME` 环境变量。
  2. 先按 [FlashInfer 安装文档](https://docs.flashinfer.ai/installation.html) 安装 FlashInfer，再按上述方式安装 SGLang。

## 方法二：从源码安装

```bash Command
# 使用最新的发布分支
git clone -b v0.5.16 https://github.com/sgl-project/sglang.git
cd sglang

# 安装 python 包
pip install --upgrade pip
pip install -e "python"
```

**常见问题的快速修复**

- 如果你想开发 SGLang，可以试试开发用 docker 镜像。请参考 [搭建 docker 容器](../developer_guide/development_guide_using_docker#setup-docker-container)。镜像名为 `lmsysorg/sglang:dev`。

## 方法三：使用 docker

Docker 镜像发布在 Docker Hub 的 [lmsysorg/sglang](https://hub.docker.com/r/lmsysorg/sglang/tags)，由 [Dockerfile](https://github.com/sgl-project/sglang/tree/main/docker) 构建。
把下面的 `<secret>` 替换成你的 huggingface hub [token](https://huggingface.co/docs/hub/en/security-tokens)。

<Note>
`latest` 和 `dev` 是**可变**标签：`latest` 始终指向最新的稳定版，`dev` 则每天从最新的 `main` 重新构建，并包含构建/开发工具。由于它们会随时间被覆盖，可复现的部署请固定一个不可变的版本标签——例如 `lmsysorg/sglang:v0.5.16`。在 [Docker Hub](https://hub.docker.com/r/lmsysorg/sglang/tags) 上可以浏览所有已发布版本。
</Note>

```bash Command
docker run --gpus all \
    --shm-size 32g \
    -p 30000:30000 \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    --env "HF_TOKEN=<secret>" \
    --ipc=host \
    lmsysorg/sglang:latest \
    python3 -m sglang.launch_server --model-path meta-llama/Llama-3.1-8B-Instruct --host 0.0.0.0 --port 30000
```

生产部署建议使用 `runtime` 变体，它去掉了构建工具和开发依赖，体积显著更小（约减小 40%）：

```bash Command
docker run --gpus all \
    --shm-size 32g \
    -p 30000:30000 \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    --env "HF_TOKEN=<secret>" \
    --ipc=host \
    lmsysorg/sglang:latest-runtime \
    python3 -m sglang.launch_server --model-path meta-llama/Llama-3.1-8B-Instruct --host 0.0.0.0 --port 30000
```

你还可以在[这里](https://hub.docker.com/r/lmsysorg/sglang/tags?name=nightly)找到 nightly docker 镜像。

注意事项：
- SGLang 默认随 CUDA 13 环境一起发布。要在 CUDA 12 环境下运行 SGLang，请使用带 `-cu12` 或 `-cu129` 后缀的镜像，例如 `lmsysorg/sglang:latest-cu129` 或 `lmsysorg/sglang:dev-cu12`。

## 方法四：使用 Kubernetes

请查看 [OME](https://github.com/sgl-project/ome)——一个用于企业级大语言模型（LLM）管理与推理服务的 Kubernetes Operator。

<Accordion title="更多">

1. 方案一：单节点推理服务（通常适用于模型大小能装进单个节点 GPU 的情况）

   执行 `kubectl apply -f docker/k8s-sglang-service.yaml` 创建 k8s deployment 和 service，以 llama-31-8b 为例。

2. 方案二：多节点推理服务（通常适用于大模型需要多个 GPU 节点的情况，例如 `DeepSeek-R1`）

   按需修改 LLM 模型路径和参数，然后执行 `kubectl apply -f docker/k8s-sglang-distributed-sts.yaml`，创建两节点的 k8s statefulset 和推理服务。

</Accordion>

## 方法六：用 SkyPilot 在 Kubernetes 或云上运行

<Accordion title="更多">

要在 Kubernetes 或 12+ 个云平台上部署，可以使用 [SkyPilot](https://github.com/skypilot-org/skypilot)。

1. 安装 SkyPilot 并配置 Kubernetes 集群或云平台访问：参见 [SkyPilot 文档](https://skypilot.readthedocs.io/en/latest/getting-started/installation.html)。
2. 用一条命令部署到你自己的基础设施上，并获取 HTTP API 端点：

<Accordion title={<>SkyPilot YAML：<code>sglang.yaml</code></>}>

```yaml Config
# sglang.yaml
envs:
  HF_TOKEN: null

resources:
  image_id: docker:lmsysorg/sglang:latest
  accelerators: A100
  ports: 30000

run: |
  conda deactivate
  python3 -m sglang.launch_server \
    --model-path meta-llama/Llama-3.1-8B-Instruct \
    --host 0.0.0.0 \
    --port 30000
```

</Accordion>

```bash Command
# 部署到任意云平台或 Kubernetes 集群。用 --cloud <cloud> 选择特定的云厂商。
HF_TOKEN=<secret> sky launch -c sglang --env HF_TOKEN sglang.yaml

# 获取 HTTP API 端点
sky status --endpoint 30000 sglang
```

3. 想进一步通过自动扩缩容和故障恢复来扩展部署，请查看 [SkyServe + SGLang 指南](https://github.com/skypilot-org/skypilot/tree/master/llm/sglang#serving-llama-2-with-sglang-for-more-traffic-using-skyserve)。

</Accordion>

## 方法七：在 AWS SageMaker 上运行

<Accordion title="更多">

要在 AWS SageMaker 上部署 SGLang，请查看 [AWS SageMaker 推理](https://aws.amazon.com/sagemaker/ai/deploy)

Amazon Web Services 为 SGLang 容器提供支持，并会做常规安全补丁。可用的 SGLang 容器请查看 [AWS SGLang DLCs](https://aws.github.io/deep-learning-containers/reference/available_images/#sglang)。

要直接部署预构建的 SGLang 深度学习容器（无需自己构建镜像），参见 [Amazon SageMaker AI](/docs/basic_usage/aws_sagemaker)。

要用自己的容器托管模型，请按以下步骤操作：

1. 用 [sagemaker.Dockerfile](https://github.com/sgl-project/sglang/blob/main/docker/sagemaker.Dockerfile) 和 [serve](https://github.com/sgl-project/sglang/blob/main/docker/serve) 脚本构建 docker 容器。
2. 把你的容器推送到 AWS ECR。

<Accordion title={<>Dockerfile 构建脚本：<code>build-and-push.sh</code></>}>

```bash Command
#!/bin/bash
AWS_ACCOUNT="<YOUR_AWS_ACCOUNT>"
AWS_REGION="<YOUR_AWS_REGION>"
REPOSITORY_NAME="<YOUR_REPOSITORY_NAME>"
IMAGE_TAG="<YOUR_IMAGE_TAG>"

ECR_REGISTRY="${AWS_ACCOUNT}.dkr.ecr.${AWS_REGION}.amazonaws.com"
IMAGE_URI="${ECR_REGISTRY}/${REPOSITORY_NAME}:${IMAGE_TAG}"

echo "Starting build and push process..."

# Login to ECR
echo "Logging into ECR..."
aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_REGISTRY}

# Build the image
echo "Building Docker image..."
docker build -t ${IMAGE_URI} -f sagemaker.Dockerfile .

echo "Pushing ${IMAGE_URI}"
docker push ${IMAGE_URI}

echo "Build and push completed successfully!"
```

</Accordion>

3. 在 AWS Sagemaker 上部署模型进行推理，参见 [deploy_and_serve_endpoint.py](https://github.com/sgl-project/sglang/blob/main/examples/sagemaker/deploy_and_serve_endpoint.py)。更多信息请查看 [sagemaker-python-sdk](https://github.com/aws/sagemaker-python-sdk)。
   1. 默认情况下，SageMaker 上的模型服务会运行以下命令：`python3 -m sglang.launch_server --model-path opt/ml/model --host 0.0.0.0 --port 8080`。这对在 SageMaker 上托管你自己的模型是最优的。
   2. 要修改模型的推理服务参数，[serve](https://github.com/sgl-project/sglang/blob/main/docker/serve) 脚本支持 `python3 -m sglang.launch_server --help` 中列出的所有选项，只需设置带 `SM_SGLANG_` 前缀的环境变量。
   3. serve 脚本会自动把所有带 `SM_SGLANG_` 前缀的环境变量从 `SM_SGLANG_INPUT_ARGUMENT` 转换为 `--input-argument`，供 `python3 -m sglang.launch_server` CLI 解析。
   4. 例如，要用带推理解析器的方式运行 [Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B)，只需额外设置环境变量 `SM_SGLANG_MODEL_PATH=Qwen/Qwen3-0.6B` 和 `SM_SGLANG_REASONING_PARSER=qwen3`。

</Accordion>

## 常见注意事项

- [FlashInfer](https://github.com/flashinfer-ai/flashinfer) 是默认的注意力 kernel 后端。它只支持 sm75 及以上的设备。如果你在 sm75+ 设备（例如 T4、A10、A100、L4、L40S、H100）上遇到 FlashInfer 相关问题，请通过添加 `--attention-backend triton --sampling-backend pytorch` 切换到其他 kernel，并在 GitHub 上提 issue。
- 要在本地重装 flashinfer，使用命令：`pip3 install --upgrade flashinfer-python --force-reinstall --no-deps`，然后删除缓存 `rm -rf ~/.cache/flashinfer`。
