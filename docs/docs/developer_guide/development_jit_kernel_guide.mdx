<Note>
💡 AI Infra 学习笔记：JIT（just-in-time）kernel 在推理引擎中的作用，是把「C++/CUDA 代码」在运行时即时编译成针对当前 GPU 的机器码，从而绕开「每种模型/形状都预编译一份」的 AOT 方案。SGLang 对 attention 等热点算子同时维护 AOT（sgl-kernel）与 JIT（`python/sglang/kernels/jit`）两套 kernel：JIT 适合快速迭代、按需特化（如把常量作为模板参数），但首次调用要付一次编译开销；AOT 则把编译成本前置到发版时。理解这套「以编译换灵活性、以缓存换编译开销」的取舍，是推理引擎 kernel 开发的基础。
</Note>

## 环境搭建

我们强烈推荐使用 `clangd` 作为 JIT kernel 开发的语言服务器。
对于 Ubuntu/Debian，你可以从 [apt.llvm.org](https://apt.llvm.org/) 下载 clangd。
如果你使用 VS Code，我们建议安装 `clangd` 扩展以获得更好的 IDE 集成。

所有 JIT 相关文件位于 `python/sglang/kernels/jit`。
与提前（AOT）编译 CUDA/C++ 二进制的 `sgl-kernel` 不同，just-in-time（JIT）kernel 在运行时编译。
因此，无法生成静态的 `compile_commands.json`。
要启用 clangd 的代码补全，运行 `python -m sglang.kernels.jit` 在当前目录生成 `.clangd` 配置文件。
生成后重启 clangd 语言服务器，它就能识别所有 JIT kernel 文件了。

## 代码结构

### C++ 实现

C++ 源码位于 `python/sglang/kernels/jit/csrc`。
可复用的函数应放在 `python/sglang/kernels/jit/include`。

我们使用 [tvm-ffi](https://github.com/apache/tvm-ffi) 实现高效的跨语言绑定。
高级用法（如导出 C++ 对象）请参考[文档](https://tvm.apache.org/ffi/)。
通常 `tvm::ffi::TensorView` 就足以从 Python 传递 PyTorch Tensor。

### Python 接口

Python 接口定义在 `python/sglang/kernels/jit`。
`python/sglang/kernels/jit/utils/compile.py` 中的 `load_jit` 工具函数负责加载并返回编译好的模块。
要导出一个 C++ 函数（例如 `cpp_func`），向 `load_jit` 传 `cuda_wrappers=[("func", "cpp_func")]`。
之后就可以在 Python 中以 `module.func` 的方式调用该函数。

对于编译后模块的缓存，优先使用 `sglang.kernels.jit.utils.cache_once` 而不是 `functools.lru_cache`。
`functools.lru_cache` 与 `torch.compile` 不兼容。

### C++ 工具

下面这些 C++ 工具可用：

#### 整数区间

与 PyTorch 类似，我们提供了表示整数区间的 `irange` 函数。

```C++ Example
#include <sgl_kernel/utils.h>

void test() {
  for (auto i : host::irange(100)) { // [0, 100)
    // do something
  }
  for (auto i : host::irange(0, 100)) { // [0, 100)
    // do something
  }
}

```

#### 运行时检查

`CHECK_HOST` 是推荐的运行时检查方式：流式风格，检查通过时零开销——消息表达式只在失败时才求值。
`RuntimeCheck` 是函数式风格的替代；注意它的消息参数无论检查是否通过都会求值。
`RuntimeDeviceCheck` 校验上一次 kernel 启动的状态，`CHECK_CUDA` 是它的流式风格等价物，用于带额外上下文检查 `cudaError_t`。

```C++ Example
#include <sgl_kernel/utils.h>
#include <sgl_kernel/utils.cuh>

void test() {
  CHECK_HOST(1 + 1 == 2) << 1 + 1 << " != " << 2;  // preferred
  host::RuntimeCheck(1 + 1 == 2, 1 + 1, " != ", 2);
  host::RuntimeDeviceCheck();
  // check the provided `cudaError_t`
  host::RuntimeDeviceCheck(cudaGetLastError());
  CHECK_CUDA(cudaGetLastError()) << "after my_kernel launch";
}

```

#### 张量检查

`TensorMatcher` 提供了一种可读的方式来校验并提取张量形状信息。

```cpp Example
#include <sgl_kernel/tensor.h>

void test(const tvm::ffi::TensorView k_cache, const tvm::ffi::TensorView v_cache) {
  using namespace host;

  auto D = SymbolicSize{"D"};  // cache dimension
  auto N = SymbolicSize{"N"};  // kvcache stride
  auto dtype = SymbolicDType{};
  auto device = SymbolicDevice{};

  TensorMatcher({-1, D})  //
      .with_strides({N, 1})
      .with_dtype<int32_t, int64_t>(dtype)
      .with_device<kDLCUDA, kDLCPU>(device)
      .verify(k_cache)
      .verify(v_cache);
}
```

在验证前，先用期望的 stride、dtype 和设备属性配置 `TensorMatcher`。
- 如果省略 `with_strides`，张量应被视为连续（contiguous）。
- `with_dtype` 的模板参数限制了允许的数据类型。
- `with_device` 的模板参数限制了允许的设备。
- 传给 `with_xxx` 方法的值会强制相等检查。
- 对 size 或 stride 传 `-1` 表示匹配任意值。

一个 `Symbolic` 变量必须在所有验证中解析为相同的值。
验证后使用 `.unwrap()` 取回匹配到的值。

> Note: `TensorMatcher` 是一个临时表达式，不应该存储到变量中。

> Tip: 在 `TensorMatcher` 链末尾加 `//` 以保证正确的缩进。

#### Kernel 启动

`LaunchKernel::resolve_device` 从 PyTorch 获取当前的 `cudaStream`。
也可以直接用 `LaunchKernel` 启动 kernel。

```cpp Example
#include <sgl_kernel/utils.cuh>

#include <dlpack/dlpack.h>

__global__ void kernel() {}

void test() {
  const auto num_blocks = 1;
  const auto num_threads = 32;
  const auto dynamic_smem = 0;

  DLDevice dev;  // suppose this is initialized properly
  host::LaunchKernel(num_blocks, num_threads, dev)(kernel);

  cudaStream_t stream = host::LaunchKernel::resolve_device(dev);
  host::LaunchKernel(num_blocks, num_threads, stream, dynamic_smem)(kernel);
}

```

## 添加新 kernel

本节用一个完整的端到端示例，介绍如何向系统添加一个新的 JIT kernel。
我们用简单的 add_constant kernel 作为贯穿示例，它给输入张量的每个元素加上一个常量整数值。

概念上，Python 接口看起来是这样的：

```python Example
def add_constant(src: torch.Tensor, c: int):
    return src + c
```

### 第一步：编写 C++ kernel

在 [kernels/jit/csrc/add_constant.cuh](https://github.com/sgl-project/sglang/blob/main/python/sglang/kernels/jit/csrc/add_constant.cuh) 中编写你的 CUDA kernel。为了演示，我们把常量值作为模板参数传入。

```cpp Example
#include <sgl_kernel/tensor.h>   // For TensorMatcher, SymbolicSize, SymbolicDevice
#include <sgl_kernel/utils.cuh>  // For LaunchKernel
#include <sgl_kernel/utils.h>    // For div_ceil, CHECK_HOST

#include <dlpack/dlpack.h>
#include <tvm/ffi/container/tensor.h>

#include <cstddef>
#include <cstdint>

namespace {

template <int32_t kConstant>
__global__ void add_constant_kernel(int32_t* dst, const int32_t* src, size_t length) {
  size_t idx = blockIdx.x * blockDim.x + threadIdx.x;
  if (idx < length) {
    dst[idx] = src[idx] + kConstant;
  }
}

constexpr size_t kBlockSize = 256;

// You can also use struct with static method as an alternative
template <int32_t kConstant>
void add_constant(tvm::ffi::TensorView dst, tvm::ffi::TensorView src) {
  using namespace host;

  // 1. Validate input tensors
  SymbolicSize N = {"num_elements"};
  SymbolicDevice device_;
  TensorMatcher({N})                  // 1D tensor, must be contiguous
      .with_dtype<int32_t>()          // must be int32
      .with_device<kDLCUDA>(device_)  // must be on CUDA device
      .verify(dst)                    // check tensor dst
      .verify(src);                   // check tensor src

  // 2. Extract required parameters, prepare for kernel launch
  const size_t num_elements = N.unwrap();
  const size_t grid_size = div_ceil(num_elements, kBlockSize);
  const DLDevice device = device_.unwrap();
  // some extra runtime checks using CHECK_HOST
  CHECK_HOST(num_elements > 0) << "We only support non-empty tensors, got num_elements = " << num_elements;

  // 3. Launch the kernel. Error code will be automatically checked.
  LaunchKernel(grid_size, kBlockSize, device /*, dynamic_smem*/)(
      // kernel function
      add_constant_kernel<kConstant>,
      // kernel arguments
      static_cast<int32_t*>(dst.data_ptr()),
      static_cast<int32_t*>(src.data_ptr()),
      num_elements);
}

}  // namespace

```

### 第二步：创建 Python 接口

接下来，通过一个 Python 包装器暴露该 kernel。
在 [kernels/ops/attention/add_constant.py](https://github.com/sgl-project/sglang/blob/main/python/sglang/kernels/ops/attention/add_constant.py) 创建新文件，并暴露所需的接口。

```python Example
from __future__ import annotations
from typing import TYPE_CHECKING

import torch

from sglang.kernels.jit.utils import cache_once, load_jit, make_cpp_args

if TYPE_CHECKING:
    from tvm_ffi.module import Module


@cache_once
def _jit_add_constant_module(constant: int) -> Module:
    args = make_cpp_args(constant)  # pass all the template argument
    return load_jit(
        "add_constant",
        *args,
        cuda_files=["add_constant.cuh"],
        cuda_wrappers=[("add_constant", f"add_constant<{args}>")],
    )


def add_constant(src: torch.Tensor, constant: int) -> torch.Tensor:
    if not src.is_cuda:
        raise RuntimeError("src must be a CUDA tensor")
    if src.dtype != torch.int32:
        raise RuntimeError(f"Unsupported dtype {src.dtype}. Supported: int32")
    dst = torch.empty_like(src)
    module = _jit_add_constant_module(constant)
    module.add_constant(dst, src)
    return dst

```

Python 包装器要保持轻薄，但在分发前仍要校验基本的不可变约束（如设备与 dtype）。在当前 JIT/FFI 路径下，非法张量并不总是在启动前被安全拒绝。

### 第三步：使用你的 kernel

最后，像普通 Python 函数一样导入并使用该 kernel：

```python Example
from sglang.kernels.jit.add_constant import add_constant
```

完整的可运行示例，请参考 [test_add_constant.py](https://github.com/sgl-project/sglang/blob/main/test/registered/jit/test_add_constant.py)。
