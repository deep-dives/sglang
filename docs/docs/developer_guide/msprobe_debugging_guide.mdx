MSProbe 是一个面向 AI 模型的调试工具，用于诊断模型训练与推理过程中的精度异常和数值错误。它捕获并监控中间数据（特征图、权重、激活值、层输出）与上下文元数据（提示词、张量 dtype、硬件配置），并支持可视化分析，从而系统地追踪精度下降或数值错误（例如 NaN/Inf、输出漂移、预测不一致）的根因。

<Note>
💡 AI Infra 学习笔记：性能剖析（profiling）回答「慢在哪」，而数值调试工具（如 MSProbe）回答「为什么算错了」——两者是 AI Infra 排查的两类主要手段。推理引擎里精度异常往往由量化误差、kernel 实现差异、dtype 混用或算子替换引发，这类问题用「问题侧 vs 基准侧」双份 dump 对比就能快速定位到具体模块或算子。理解这类工具的「捕获中间张量 → 可视化对比 → 定位根因」工作流，是排查精度类线上事故的基本功。
</Note>

## 基本说明

### 背景概念：MSProbe 的 Dump 层级

MSProbe 支持三个用于数据 dump 的精度层级，分别应对不同的调试需求：

- **L0**：在**模块（module）级** dump 张量/统计信息，并生成 `construct.json`（用于可视化时的网络结构重建）。需要传入模型/子模块句柄。
- **L1**：在**torch API 级** dump 张量/统计信息，适合细粒度的 API 级数值检查。
- **mix**：结合 L0 + L1，适合既需要**图结构重建**又需要**数值对比**的场景。

### 前置条件：安装 MSProbe

用 pip 安装 MSProbe：

```shell
pip install mindstudio-probe --pre
```

### 关键配置参数

MSProbe 使用 JSON 配置文件来自定义数据 dump。下表列出了所有核心参数，并提供默认 JSON 配置供参考。

#### 配置参数表

|    字段     | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 是否必需 |
|:------------:|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:--------:|
|    `task`    | Dump 任务的类型。常见的 PyTorch 取值包括 `"statistics"` 与 `"tensor"`。statistics 任务收集张量统计信息（mean、variance、max、min 等），tensor 任务捕获任意张量。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |   是   |
| `dump_path`  | 存放 dump 结果的目录。省略时 `MSProbe` 使用其默认路径。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |    否    |
|    `rank`    | 要采样的 rank。空列表表示收集所有 rank。单卡任务必须把该字段设为 `[]`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |    否    |
|    `step`    | 要采样的 token 迭代。空列表表示每个迭代都采样。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |    否    |
|   `level`    | Dump 层级字符串（`"L0"`、`"L1"` 或 `"mix"`）。`L0` 针对 `nn.Module`，`L1` 针对 `torch.api`，`mix` 同时收集两者。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |   是   |
| `async_dump` | 是否启用异步 dump（PyTorch 的 `statistics`/`tensor` 任务支持）。默认是 `false`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |    否    |
|   `scope`    | 自定义 dump 的范围。提供两个遵循工具命名约定的模块名或 API 名来锁定区间，只 dump 这两个名字之间的数据。空列表表示 dump 每个模块或 torch API。<br/><br/>示例：<br/>`"scope": ["Module.conv1.Conv2d.forward.0", "Module.fc2.Linear.forward.0"]`<br/>`"scope": ["Tensor.add.0.forward", "Functional.square.2.forward"]`<br/><br/>`level` 设置决定可以传什么——`level=L0` 时传模块，`level=L1` 时传 API，`level=mix` 时模块或 API 均可。                                                                                                                                                                                                                                                                |    否    |
|    `list`    | 自定义 dump 列表，只 dump 列表中的元素。空列表表示 dump 每个模块或 torch API。选项包括：<br/><br/>&#8226;在 PyTorch eager 模式下提供特定 API 的完整名称，只 dump 这些 API。示例：`"list": ["Tensor.permute.1.forward", "Tensor.transpose.2.forward", "Torch.relu.3.backward"]`。<br/>&#8226;当 `level=mix` 时，可以传模块名，使 dump 扩展到该模块运行期间产生的一切。示例：`"list": ["Module.module.language_model.encoder.layers.0.mlp.ParallelMlp.forward.0"]`。<br/>&#8226;传一个子串，例如 `"list": ["relu"]`，会 dump 名称包含该子串的每个 API。当 `level=mix` 时，名称包含该子串的模块也会被展开。 |    否    |

#### 默认配置

```json
{
  "task": "statistics",
  "dump_path": "./dump_path",
  "rank": [],
  "step": [],
  "level": "L1",
  "async_dump": false,
  "statistics": {
    "scope": [],
    "list": [],
    "data_mode": [
      "all"
    ],
    "summary_mode": "statistics"
  },
  "tensor": {
    "scope": [],
    "list": [],
    "data_mode": [
      "all"
    ],
    "file_format": "npy"
  },
  "acc_check": {
    "white_list": [],
    "black_list": [],
    "error_data_path": "./"
  }
}
```

#### 输出

Dump 文件写入你定义的 `dump_path`。它们通常包含：

- `dump.json`，记录 dtype、shape、min、max、mean、L2 范数、`requires_grad` 等元数据。
- `construct.json`，层级结构描述，当 `level` 为 `L0` 或 `mix` 时生成（可视化必需），其内容不为空。
- `stack.json`，记录 API/Module 的调用栈信息。
- `dump_tensor_data`，当 `task` 为 `tensor` 时生成，保存收集到的张量数据。

细节参见 [Dump 目录说明](#dump-directory-description)。

> **注意**：启用 MSProbe 时，cuda graph 会被禁用（disable_cuda_graph=True），因为 MSProbe 只支持 eager 模式下的 dump；预热也会被禁用（skip_server_warmup=True），因为这个阶段无需 dump 数据。

<Note>
💡 AI Infra 学习笔记：`L0`（模块级）/`L1`（API 级）/`mix` 三种 dump 层级对应不同粒度的排查：模块级适合快速判断「哪一层出问题」，API 级适合精确锁定「哪个算子数值不对」，mix 则兼顾结构重建与数值对比。调试时先粗后细——先用 L0 定位发散层，再用 L1 深挖具体算子，能显著减少 dump 数据量。
</Note>

## 端到端示例

MSProbe 的完整调试工作流遵循 **启用 → 收集数据 → 可视化 → 分析根因**。下面是基于 SGLang 的模型推理调试的常见 E2E 示例。

### 示例：带自定义配置的高级调试

适合针对性调试（例如只收集特定 rank/step 的统计信息数据、启用 mix 层级做图重建 + 数值对比）以及通过**问题侧与基准侧对比**做根因分析。

#### 第一步：启用
##### 准备自定义配置 JSON

创建 `msprobe-config.json`（dump rank0/1、step0/1 的统计信息数据，mix 层级）：

```json
{
  "task": "statistics",
  "dump_path": "./problem_dump",
  "rank": [
    0,
    1
  ],
  "step": [
    0,
    1
  ],
  "level": "mix",
  "async_dump": false,
  "statistics": {
    "scope": [],
    "list": [],
    "data_mode": [
      "all"
    ],
    "summary_mode": "statistics"
  }
}
```

##### 在 SGLang 中用自定义配置启用 MSProbe

启动 SGLang 服务端，并用 `--msprobe-dump-config` 指定配置文件路径：

```bash
python3 -m sglang.launch_server \
 --model-path Qwen/Qwen2.5-0.5B-Instruct \
 --host 127.0.0.1 \
 --port 1027 \
 --msprobe-dump-config /home/msprobe-config.json
```
#### 第二步：收集数据
##### 为问题侧与基准侧收集 Dump 数据

发送正常的推理请求来触发模型运行（MSProbe 会在请求处理过程中自动收集数据）：

```bash
curl -H "Content-type: application/json" \
 -X POST \
 -d '{
     "model": "Qwen/Qwen2.5-0.5B-Instruct",
     "messages": [
         {
             "role": "user",
             "content": "Hello, my name is"
         }
     ],
     "max_tokens": 10
 }' \
 http://127.0.0.1:1027/v1/chat/completions
```

- **问题侧**：运行上面的 SGLang 服务端（带有精度/数值问题）并发送推理请求；dump 数据保存在 `./problem_dump`。
- **基准侧**：用**相同的自定义配置**启动一个正常的 SGLang 服务端（无此问题，例如稳定的框架版本/算子），发送**相同的推理请求**；把 dump 目录改名为 `./bench_dump`。

> **关键要求**：问题侧与基准侧的 dump 必须使用相同的输入和采样点（rank/step），对比才有效。

##### 检查生成的 Dump 文件

Dump 文件保存到你定义的 `./problem_dump` 与 `./bench_dump`，包含后续分析所需的核心文件：

- `dump.json`：记录 API 与模块的张量元数据（dtype、shape、min/max/mean、L2 范数、`requires_grad` 等）。
- `stack.json`：记录 API 与模块的调用栈信息。
- `construct.json`：层级结构描述，可视化必需，其内容不为空。

#### 第三步：可视化
##### 可视化问题侧与基准侧对比（多 rank）

生成一个多 rank 对比可视化文件（mix 层级会生成 `construct.json` 用于图重建）：

```shell
msprobe graph_visualize -tp ./problem_dump/step0 -gp ./bench_dump/step0 -o ./graph_output
```

- `-tp`：问题侧 dump 数据的路径
- `-gp`：基准侧 dump 数据的路径
- `-o`：可视化文件的输出目录

如果你想做溢出检查（用于 NaN/Inf 检测），请指定 `-oc` 参数

```shell
msprobe graph_visualize -tp ./problem_dump/step0 -gp ./bench_dump/step0 -o ./graph_output -oc
```

对比或构建任务结束后，`graph_output` 下会生成一个 `compare_{timestamp}.vis.db` 文件。

dump 出来的数据可以用 Matplotlib、Excel 等可视化工具生成的表格或图表来可视化并分析差异。

##### 启动 TensorBoard

启动 TensorBoard：
```bash
tensorboard --logdir ./graph_output --bind_all --port 6006
```
#### 第四步：分析根因
##### 定位根因

在 TensorBoard 中做根因分析：
- 发散节点（存在精度/数值差异）会以**红色**高亮（红色越深表示差异越大）。
- 点击发散节点可查看详细的张量数据（输入/输出、参数）以及 API/模块调用栈。
- 用**搜索/过滤**功能快速定位关键层/API（例如 "relu"、"conv"）。
- 通过 UI 在不同 rank/step 之间切换，检查跨 rank/跨 step 的发散情况。
- 查看**溢出检查**页签，检查特定节点中的 NaN/Inf 值（数值不稳定的直接原因）。

##### 验证根因

定位到发散节点（例如某个张量值异常的 Conv 层或 torch API）后，通过以下方式验证：

- 把 dump 范围收窄到这个节点（通过配置文件里的 `scope`/`list`），做细粒度的数据收集。
- 修改有问题的层/API（例如替换算子、调整 dtype），重新运行调试工作流，确认问题是否解决。

## 故障排查

### 没有生成 Dump 文件

1. 用 `pip show mindstudio_probe` 确认 MSProbe 是否已安装。如果已安装，会打印出 MSProbe 的版本信息。如果确认没安装，请用 `pip install mindstudio-probe --pre` 安装；
2. 确认 `--msprobe-dump-config` 参数指向**正确的 JSON 文件路径**。

### Dump 文件过大（数据过多）

1. 先用 `task: "statistics"` 而不是 `"tensor"`，只收集张量统计信息（避免原始张量 dump）；
2. 用 `scope` 字段收窄 dump 范围（指定起始/结束模块或 API）；
3. 用 `list` 字段过滤 dump 目标（只 dump 特定模块/API 或子串）；
4. 采样特定的 `rank` 与 `step`（避免 dump 所有 rank/迭代）。

### TensorBoard 可视化失败

1. 确认 `construct.json` 不为空（需要 `level: L0` 或 `mix`——L1 不会生成图文件）；
2. 检查 `-tp`（问题侧 dump）与 `-gp`（基准侧 dump）路径指向**有效的 rank/step 子目录**（例如 `step0/rank0`）；
3. 确保 MSProbe 版本是最新的（用 `pip install mindstudio-probe --pre --upgrade` 重装）；
4. 确认 TensorBoard 已安装，且 `--logdir` 指向包含 `.vis.db` 文件的目录（不是文件本身）。

### 数值对比无发散但模型精度仍然很低

1. 扩大 dump 的 `step` 范围（检查更多 token 迭代，看后期发散）；
2. 切换到 `task: "tensor"`（统计信息可能掩盖原始张量数据中的细微数值差异）；
3. 确保问题侧与基准侧 dump 使用**相同的输入数据/硬件配置**（输入不同会导致对比无效）；
4. 使用 TensorBoard 中的 `manual mapping` 功能（自动映射对自定义模型可能漏掉一些节点）。

## 附录

### Dump 目录说明 {#dump-directory-description}

```text
├── problem_dump or bench_dump
│   ├── step0
│   │   ├── rank0
│   │   │   ├── dump_tensor_data
│   │   │   │    ├── Tensor.permute.1.forward.pt
│   │   │   │    ├── Functional.linear.5.backward.output.pt    # Format: {api_type}.{api_name}.{call_count}.{forward/backward}.{input/output}.{arg_index}.
│   │   │   │    │                                              # arg_index is the nth input or output of the API. If an input is a list, keep numbering with decimals (e.g., 1.1 is the first element of the first argument).
│   │   │   │    ├── Module.conv1.Conv2d.forward.0.input.0.pt          # Format: {Module}.{module_name}.{class_name}.{forward/backward}.{call_count}.{input/output}.{arg_index}.
│   │   │   │    ├── Module.conv1.Conv2d.forward.0.parameters.bias.pt  # Module parameter data: {Module}.{module_name}.{class_name}.forward.{call_count}.parameters.{parameter_name}.
│   │   │   │    └── Module.conv1.Conv2d.parameters_grad.weight.pt     # Module parameter gradients: {Module}.{module_name}.{class_name}.parameters_grad.{parameter_name}. Gradients do not include call_count because the same gradient updates all invocations.
│   │   │   │                                                          # When the `model` argument passed to dump is a List[torch.nn.Module] or Tuple[torch.nn.Module], module-level data names also include the index inside the list ({Module}.{index}.*), e.g., Module.0.conv1.Conv2d.forward.0.input.0.pt.
│   │   │   ├── dump.json
│   │   │   ├── stack.json
│   │   │   ├── dump_error_info.log
│   │   │   └── construct.json
│   │   ├── rank1
│   │   │   ├── dump_tensor_data
│   │   │   │   └── ...
│   │   │   ├── dump.json
│   │   │   ├── stack.json
│   │   │   ├── dump_error_info.log
│   │   │   └── construct.json
│   │   ├── ...
│   │   │
│   │   └── rank7
│   ├── step1
│   │   ├── ...
│   ├── step2
```

- `rank`：设备 ID。每张卡把数据写到对应的 `rank{ID}` 目录。非分布式场景下目录直接命名为 `rank`。
- `dump_tensor_data`：保存收集到的张量数据。
- `dump.json`：每个 API 或模块前向数据的统计信息，包括名称、dtype、shape、max、min、mean、L2 范数（L2 方差的平方根），以及 `summary_mode="md5"` 时的 CRC-32。
  细节参见 [dump.json 文件说明](#dump-json-file-description)。
- `dump_error_info.log`：仅当 dump 工具遇到错误时出现，记录失败日志。
- `stack.json`：API/模块的调用栈。
- `construct.json`：层级结构描述。`level=L1` 时为空。

### dump.json 文件说明 {#dump-json-file-description}

#### L0 层级

一个 L0 的 `dump.json` 包含模块的前向/反向 I/O，以及参数与参数梯度。以 PyTorch 的 `Conv2d` 为例，网络代码如下：

`output = self.conv2(input)  # self.conv2 = torch.nn.Conv2d(64, 128, 5, padding=2, bias=True)`

`dump.json` 包含以下条目：

- `Module.conv2.Conv2d.forward.0`：模块的前向数据。`input_args` 表示位置参数输入，`input_kwargs` 表示关键字参数输入，`output` 保存前向输出，`parameters` 保存权重/偏置。
- `Module.conv2.Conv2d.parameters_grad`：参数梯度（weight 和 bias）。
- `Module.conv2.Conv2d.backward.0`：模块的反向数据。`input` 表示流入模块的梯度（前向输出的梯度），`output` 表示流出的梯度（模块输入的梯度）。

**注意**：当传给 dump API 的 `model` 参数是 `List[torch.nn.Module]` 或 `Tuple[torch.nn.Module]` 时，模块级名称会包含列表内的索引（`{Module}.{index}.*`）。示例：`Module.0.conv1.Conv2d.forward.0`。

#### L1 层级

一个 L1 的 `dump.json` 记录 API 的前向/反向 I/O。以 PyTorch 的 `relu` 函数为例（`output = torch.nn.functional.relu(input)`），文件包含：

- `Functional.relu.0.forward`：API 的前向数据。`input_args` 是位置参数输入，`input_kwargs` 是关键字参数输入，`output` 保存前向输出。
