R-Fork（Tensor Remote Fork）是一种新颖的权重加载方法，它利用高效的节点间 GPU 到 GPU 数据传输通路，从一台正在运行的 SGLang 实例把张量零拷贝加载到新实例。它能显著优化 SGLang 实例的启动时间，把模型权重加载从几分钟压缩到短短几秒。

要了解更多 R-Fork 的细节，请看 **<a href="https://lmsys.org/blog/2025-12-10-rfork/"> R-Fork 博客 </a>**。

<Note>
💡 AI Infra 学习笔记：模型权重加载是大模型服务冷启动的主要耗时——动辄几十 GB 的权重从磁盘读入就要几分钟。R-Fork 的思路是直接从另一台已持有相同权重的运行中实例上，通过 GPU 间高速链路（如 NCCL）零拷贝复制权重，把启动时间从分钟级压到秒级，适合频繁扩缩容、需要快速拉起新副本的场景。
</Note>

<Note>
💡 AI Infra 学习笔记：R-Fork 需要区分"seed 实例"（提供权重的一方）和"client 实例"（加载权重的一方）。NCCL 后端需要手动指定 seed 的 IP 与端口，而 ModelExpress 作为集中式协调服务，让实例自动注册与发现，省去了直连配置——这相当于把点对点复制演进成"注册中心"式的管理。
</Note>

### 以 NCCL 作为后端

seed 实例：
```shell Command
python -m sglang.launch_server [args]
```

client 实例：
```shell Command
python -m sglang.launch_server [args] \
  --load-format remote_instance \
  --remote-instance-weight-loader-seed-instance-ip [seed_instance_ip] \
  --remote-instance-weight-loader-seed-instance-service-port [seed_instance_service_port] \
  --remote-instance-weight-loader-send-weights-group-ports [send_weights_nccl_group_ports_list]  \
  --remote-instance-weight-loader-backend nccl
```

### 以 TransferEngine 作为后端

seed 实例：
```shell Command
python -m sglang.launch_server [args] \
  --remote-instance-weight-loader-start-seed-via-transfer-engine
```

```shell Command
python -m sglang.launch_server [args] \
  --load-format remote_instance \
  --remote-instance-weight-loader-seed-instance-ip [seed_instance_ip] \
  --remote-instance-weight-loader-seed-instance-service-port [seed_instance_service_port] \
  --remote-instance-weight-loader-backend transfer_engine
```

### 以 ModelExpress 作为后端

[ModelExpress](https://github.com/ai-dynamo/modelexpress) 是一个管理点对点权重传输元数据的协调服务。它通过集中式注册中心（实例向其中发布并从中发现彼此）免去了直接配置 seed IP/端口的需求。ModelExpress Python 包必须安装在 SGLang 镜像中。

需要一个正在运行的 ModelExpress 服务端。搭建方法见 [ModelExpress 文档](https://github.com/ai-dynamo/modelexpress)。

服务端实例：
```bash Command
python -m sglang.launch_server [args] \
  --load-format remote_instance \
  --remote-instance-weight-loader-backend modelexpress \
  --modelexpress-config '{"url": "[modelexpress_grpc_host:port]", "transport": "nixl"}'
```

所有 SGLang 实例使用相同的命令形式。如果不存在已就绪的权重来源，该实例会原生加载权重，并把元数据发布到 ModelExpress；如果存在兼容的权重来源，它就会通过 ModelExpress 的点对点传输加载权重。设置 <code>"transport": "transfer_engine"</code> 可以使用 Mooncake TransferEngine，而不是默认的 NIXL 传输。
