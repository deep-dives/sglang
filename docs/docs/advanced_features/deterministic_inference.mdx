## 为什么确定性推理重要

确定性推理保证 LLM 输出在多次运行之间保持一致，这对以下场景至关重要：
- **强化学习**：保证多次运行之间的 logprob 一致，减少随机噪声，让 RL 训练更稳定、更可复现、更易调试。
- **测试与调试**：支持可复现的验证
- **生产环境**：提升可靠性与用户体验

即使在 `temperature=0` 下，标准 LLM 推理也可能因为动态批处理以及 GPU kernel 中不同的归约顺序而产生不同输出。

<Note>
💡 AI Infra 学习笔记：很多人以为 `temperature=0` 就等于确定性，其实不是——`temperature=0` 只是采样策略变成贪心，但浮点运算的顺序仍然受批大小影响。动态批处理下批大小一直在变，kernel 的归约顺序也随之变化，而浮点加法不满足结合律（`(a + b) + c ≠ a + (b + c)`），微小的舍入差异就会导致不同的 token 被选中。这是推理引擎"看起来应该确定、实际不确定"的经典根源。
</Note>

## 非确定性的根本原因

主要来源是**不断变化的批大小**。不同的批大小会让 GPU kernel 以不同方式拆分归约操作，导致加法顺序不同。由于浮点数不满足结合律（`(a + b) + c ≠ a + (b + c)`），即使输入完全相同，也会产生不同结果。

## SGLang 的解决方案

基于 [Thinking Machines Lab 的批不变算子](https://github.com/thinking-machines-lab/batch_invariant_ops)，SGLang 在保持与分块预填充、CUDA 图、Radix 缓存以及非贪心采样兼容的同时，实现了完全确定性的推理。确定性推理特性的开发路线图见这个 [issue](https://github.com/sgl-project/sglang/issues/10278)。

## 用法

### 基本用法

加上 `--enable-deterministic-inference` 参数即可启用确定性推理：

```bash Command
python3 -m sglang.launch_server \
    --model-path Qwen/Qwen3-8B \
    --attention-backend fa3 \
    --enable-deterministic-inference
```

### 非贪心采样（Temperature > 0）下的确定性推理

通过使用采样种子（sampling seed），SGLang 即使在非贪心采样下也能支持确定性推理。这对 GRPO（Group Relative Policy Optimization）这类强化学习场景特别有用——你需要在同一个提示词上生成多个多样但可复现的响应。

#### 默认行为

默认情况下，SGLang 使用采样种子 `42` 实现可复现的采样：

```python Example
import requests

response = requests.post(
    "http://localhost:30000/generate",
    json={
        "text": "Tell me a joke",
        "sampling_params": {
            "temperature": 0.8,  # Non-greedy sampling
            "max_new_tokens": 128,
        },
    },
)
print(response.json())
# This will always produce the same response across runs
```

#### 生成多个可复现的响应

要针对同一个提示词采样出不同的响应、同时保持可复现性（例如用于 GRPO 训练），请在请求中提供不同的采样种子：

```python Example
import requests

# Prepare a list of sampling seeds for different responses
sampling_seeds = [42, 43, 44, 45, 46]

responses = []
for seed in sampling_seeds:
    response = requests.post(
        "http://localhost:30000/generate",
        json={
            "text": "Tell me a joke",
            "sampling_params": {
                "temperature": 0.8,
                "max_new_tokens": 128,
                "sampling_seed": seed,  # Specify sampling seed
            },
        },
    )
    responses.append(response.json())

# Each seed will produce a different but reproducible response
# Using the same seed will always produce the same response
```

<Note>
💡 AI Infra 学习笔记：确定性采样为什么对 RL 这么重要？GRPO 之类的算法要对同一提示词采样多个响应并计算相对奖励，如果采样不可复现，同一份代码在不同时间跑出来的训练数据就不同，梯度也随之漂移，实验对比和 bug 定位都会非常痛苦。用种子把随机性"钉死"后，多样性（不同种子）与可复现性（同一种子）可以同时满足。
</Note>

这种方式保证了：
- 不同种子产生多样化的响应
- 同一种子在多次运行之间总是产生相同响应
- 结果可复现，便于调试与评估


## 验证

运行确定性测试来验证输出一致性：

```bash Command
# Single test: same prompt, varying batch sizes
python3 -m sglang.test.test_deterministic --test-mode single --n-trials 50

# Prefix test: prompts with different prefix lengths
python3 -m sglang.test.test_deterministic --test-mode prefix --n-trials 50

# Radix Cache Consistency mode: test radix cache determinism (cached vs uncached prefill)
python3 -m sglang.test.test_deterministic --test-mode radix_cache
```

预期结果：所有测试都应显示 `Unique samples: 1`（完全确定性）。
