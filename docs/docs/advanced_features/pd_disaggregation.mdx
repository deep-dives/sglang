## 为什么需要 PD 分离、它是什么？

大语言模型（LLM）推理包含两个截然不同的阶段：**预填充（Prefill）** 和 **解码（Decode）**。预填充阶段计算密集，处理整个输入序列；解码阶段内存密集，负责管理用于 token 生成的键值（KV）缓存。传统上，这两个阶段在同一个引擎内处理，预填充与解码批的混合调度会带来效率损失。为解决这些挑战，我们在 SGLang 中引入了 **PD 分离部署（Prefill and Decoding Disaggregation）**。

### 统一调度的弊端

传统统一引擎同时处理预填充和解码批，会导致两个显著问题：

1. **预填充打断**：新来的预填充批会频繁打断正在进行的解码批，造成 token 生成的明显延迟。
2. **DP 注意力不均衡**：在数据并行（DP）注意力下，一个 DP worker 可能在处理预填充批，而另一个同时在处理解码批，导致解码延迟上升。

PD 分离部署通过分离这两个阶段来解决这些问题，从而可以对每个阶段做针对性优化。

设计细节请参见[此链接](https://docs.google.com/document/d/1rQXJwKd5b9b1aOzLh98mnyMhBMhlxXA5ATZTHoQrwvc/edit?tab=t.0)。

目前，我们支持 Mooncake 和 NIXL 作为传输引擎。

<Note>
💡 AI Infra 学习笔记：PD 分离的核心矛盾是「预填充吃算力、解码吃带宽」。合在一起时，大请求的预填充会周期性抢占解码资源，导致解码阶段的 token 间延迟（ITL）抖动；而且两类请求的计算特征差异大，很难同时把 GPU 用满。分离后，预填充实例专注高吞吐的矩阵计算、解码实例专注低延迟的 KV 访存，两者按各自特性独立扩缩容——这是大型推理服务（如 DeepSeek）标配的架构。关键挑战在于：预填充算完的 KV 缓存必须通过高速网络（RDMA/NVLink）搬给解码实例。
</Note>


## PD 分离模式下的性能剖析

在 PD 分离模式下对预填充或解码 worker 做性能剖析时，请参考《基准测试与性能剖析》指南中的 [PD 分离模式下的剖析](../developer_guide/benchmark_and_profiling#profile-in-pd-disaggregation-mode) 一节。由于 torch profiler 的限制，预填充和解码 worker 必须使用各自的专用命令行选项单独剖析。

## 路由器集成

为了以带负载均衡和故障容错的方式规模化部署 PD 分离，SGLang 提供了一个路由器。路由器可以用多种路由策略在预填充和解码实例之间分发请求。关于 PD 分离下路由配置的详细信息，包括配置选项和部署模式，参见 [SGLang Model Gateway（原 Router）](./sgl_model_gateway#prefill-decode-disaggregation)。


## Mooncake
### 依赖

```bash
uv pip install mooncake-transfer-engine
```

### IB 设备配置

使用 Mooncake 后端时，`--disaggregation-ib-device` 支持以下格式：

1. 所有 GPU 共享的设备列表：`mlx5_0` 或 `mlx5_0,mlx5_1`
2. 按 GPU 的 JSON 映射：`{"0": "mlx5_0,mlx5_1", "1": "mlx5_2,mlx5_3"}`
3. 包含相同按 GPU 映射的 JSON 文件路径

每个 JSON 值使用与共享配置相同的逗号分隔设备列表格式。

```bash
python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.1-8B-Instruct \

  --port 30000 \
  --disaggregation-ib-device mlx5_roce0

  --model-path meta-llama/Llama-3.1-8B-Instruct \

  --port 30001 \
```

### 高级配置

Mooncake 的 PD 分离支持以下环境变量，用于对系统行为做细粒度控制。

#### NVLink 传输配置
要为 mooncake 后端的 KV 缓存传输启用 NVLink（推荐用于 NVL72 部署），设置以下环境变量。注意辅助数据传输暂时仍走 TCP，作为一个临时方案。

```bash Command
export SGLANG_MOONCAKE_CUSTOM_MEM_POOL=NVLINK
export MC_FORCE_MNNVL=True
```

要利用 Mooncake 后端节点内（Intra-Node）NVLink 传输 KV 缓存（推荐用于 A100、H20、H100 等），设置以下环境变量。请注意辅助数据仍需要通过 TCP 传输。

```bash
export SGLANG_MOONCAKE_CUSTOM_MEM_POOL=INTRA_NODE_NVLINK
export MC_INTRANODE_NVLINK=true
```
`SGLANG_MOONCAKE_CUSTOM_MEM_POOL` 环境变量启用自定义内存池。支持的值有 `NVLINK`（或 `True`）、`BAREX` 和 `INTRA_NODE_NVLINK`。

## 异构 TP 与 GPU 暂存缓冲区

当预填充和解码使用不同的张量并行（TP）大小时（例如预填充 TP=4、解码用 TP=1 的 DP 注意力），两侧的 KV 缓存内存布局不同。**GPU 暂存缓冲区**的解决方案是：在预填充侧把 KV 头的分片收集到连续缓冲区，执行批量 RDMA 传输，然后在解码侧散布到正确的 KV 缓存页中。在高并发下，相比默认的逐 token 分片方式，它能带来 **2–5 倍的吞吐提升**，且与同构 TP 基线相比只差约 5%。

<Note>
💡 AI Infra 学习笔记：异构 TP 是 PD 分离的高级形态——预填充和解码用不同规模的并行度（如预填充 TP=4、解码 TP=1 加 DP 注意力），各自贴近最优配置。代价是两侧 KV 缓存的张量分布不一致，跨节点搬运时不能再按「每个 TP rank 一一对应」传输，而要先在预填充侧聚合成连续缓冲、批量 RDMA、再在解码侧重新散布。这条「聚合-搬运-散布」链路是分布式推理里典型的布局转换优化。
</Note>


当预填充和解码使用**不同的 TP 大小**、且传输后端为 **Mooncake** 时，启用暂存缓冲区。当两侧使用相同 TP 大小时，即使启用，暂存也会被自动绕过。

> **注意：** 暂存缓冲区是为非 MLA 模型（如 GQA、MHA）设计的。MLA 模型（如 DeepSeek-V2/V3）不应启用该参数。

### 使用示例

```bash Command
# Set staging buffer environment variables on BOTH prefill and decode
export SGLANG_DISAGG_STAGING_BUFFER=1
export SGLANG_DISAGG_STAGING_POOL_SIZE_MB=4096

# Prefill with TP=4
python -m sglang.launch_server \
  --model-path $MODEL_PATH \
  --disaggregation-mode prefill \
  --port 30000 \
  --tp 4 \
  --trust-remote-code \
  --disaggregation-ib-device mlx5_1,mlx5_2

# Decode with TP=1 (or DP attention with effective attention TP=1)
python -m sglang.launch_server \
  --model-path $MODEL_PATH \
  --disaggregation-mode decode \
  --port 30001 \
  --tp 4 \
  --dp 4 \
  --enable-dp-attention \
  --trust-remote-code \
  --disaggregation-ib-device mlx5_3,mlx5_4

# Router
python -m sglang_router.launch_router \
  --pd-disaggregation \
  --prefill http://127.0.0.1:30000 \
  --decode http://127.0.0.1:30001 \
  --host 0.0.0.0 --port 8000
```

### 高级配置

#### NIXL 后端选择

默认情况下，NIXL 使用 **UCX** 后端进行 KV 缓存传输。你可以通过环境变量 `SGLANG_DISAGGREGATION_NIXL_BACKEND` 根据你的基础设施选择不同的 NIXL 插件后端。

示例：`export SGLANG_DISAGGREGATION_NIXL_BACKEND=LIBFABRIC`

**可用的后端：** UCX（默认）、LIBFABRIC，或任何已安装的 NIXL 插件。

示例用法：
```bash
export SGLANG_DISAGGREGATION_NIXL_BACKEND=LIBFABRIC
python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.1-8B-Instruct \
  --disaggregation-mode prefill \
  --disaggregation-transfer-backend nixl \
  --port 30000
```
