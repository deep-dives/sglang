SGLang 可以直接从对象存储加载模型，无需在本地完整下载。它使用 `runai_streamer` 加载格式从云端存储流式读取模型权重，从而减少启动时间和本地存储占用。

<Note>
💡 AI Infra 学习笔记：模型权重加载"流式化"是解决大模型冷启动慢的另一条路——不再把几十 GB 权重先全部下载到本地再加载，而是边下载边用。这样本地机器（或临时弹出的实例）几乎不需要预留磁盘空间，也从"等下载完"变成了"边下边算"，启动时间大幅缩短。runai_model_streamer 就是这类方案的实现。
</Note>

## 概览

从对象存储加载模型时，SGLang 采用两阶段方案：

1. **元数据下载**（进程启动前，一次性）：配置文件与分词器文件会下载到本地缓存
2. **权重流式读取**（模型加载期间，惰性）：模型权重按需直接从对象存储流式读取

## 支持的存储后端

1. **Amazon S3**：`s3://bucket-name/path/to/model/`
2. **Google Cloud Storage**：`gs://bucket-name/path/to/model/`
3. **Azure Blob**：`az://some-azure-container/path/`
4. **S3 兼容存储**：`s3://bucket-name/path/to/model/`

## 快速上手

### 基本用法

直接把对象存储 URI 作为模型路径即可：

```bash
# S3
python -m sglang.launch_server \
  --model-path s3://my-bucket/models/llama-3-8b/ \
  --load-format runai_streamer

# Google Cloud Storage
python -m sglang.launch_server \
  --model-path gs://my-bucket/models/llama-3-8b/ \
  --load-format runai_streamer
```

**注意**：使用对象存储 URI 时会自动识别出 `--load-format runai_streamer`，所以你可以省略它：

```bash
python -m sglang.launch_server \
  --model-path s3://my-bucket/models/llama-3-8b/
```

### 结合张量并行

```bash
python -m sglang.launch_server \
  --model-path gs://my-bucket/models/llama-70b/ \
  --tp 4 \
  --model-loader-extra-config '{"distributed": true}'
```

## 配置

### 加载格式

`runai_streamer` 加载格式专为对象存储、SSD 与共享文件系统设计。

```bash
python -m sglang.launch_server \
  --model-path s3://bucket/model/ \
  --load-format runai_streamer
```

### 扩展配置参数

用 `--model-loader-extra-config` 以 JSON 字符串传入额外配置：

```bash
python -m sglang.launch_server \
  --model-path s3://bucket/model/ \
  --model-loader-extra-config '{
    "distributed": true,
    "concurrency": 8,
    "memory_limit": 2147483648
  }'
```

## 性能注意事项

### 分布式流式加载

对于多 GPU 环境，启用分布式流式加载可以在各进程间并行加载权重：

```bash
python -m sglang.launch_server \
  --model-path s3://bucket/model/ \
  --tp 8 \
  --model-loader-extra-config '{"distributed": true}'
```

<Note>
💡 AI Infra 学习笔记：多 GPU 并行时，如果每个进程都各自从对象存储下载全部权重，等于白白浪费带宽。分布式流式加载让每个进程只下载自己 TP 分片需要的那部分权重——既省带宽，也顺带验证了"权重加载也要并行化"的思路。`concurrency` 控制同时建立的下载流数量，是带宽充足时压吞吐的关键参数。
</Note>

## 限制

- **支持的格式**：只支持 `.safetensors` 权重格式。
- **支持的设备**：分布式流式加载只在 CUDA 类设备上受支持；其他设备会回退到非分布式流式加载。
