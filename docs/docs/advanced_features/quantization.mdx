SGLang 支持多种量化方法，包括离线量化和在线动态量化。

离线量化是推理时直接加载预量化好的模型权重。GPTQ 和 AWQ 这类量化方法必须采用离线量化——它们需要用校准数据集从原始权重中收集并预先计算各种统计量。

在线量化则是在运行时动态计算缩放参数（例如模型权重的最大值/最小值）。与 NVIDIA FP8 训练中的[延迟缩放](https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/examples/fp8_primer.html#Mixed-precision-training-with-FP8)机制类似，在线量化会即时计算合适的缩放因子，把高精度权重转换成低精度格式。

<Note>
💡 AI Infra 学习笔记：量化是把模型的权重和激活值从高精度（如 FP16/BF16）压缩到低精度（如 FP8、INT4），用来省显存、提升访存带宽和计算吞吐。LLM 推理通常是"访存带宽瓶颈"而非"算力瓶颈"，权重越瘦，解码阶段每个 token 要搬运的字节越少，延迟越低、单位显存能装的模型越大。主流方法中，GPTQ/AWQ 属于离线量化（用校准数据预计算缩放因子，质量更可控、启动快），FP8 动态量化属于在线量化（运行时算缩放因子，省事但启动慢）。INT4 相比 FP8 能进一步减半显存，但精度损失与 kernel 支持复杂度更高。
</Note>

**注意：考虑到性能、易用性和便利性，推荐优先使用离线量化，而不是在线量化。**

如果使用预量化模型，**不要同时添加 `--quantization` 去开启在线量化**。
想找流行的预量化模型，可以访问 Hugging Face 上的 [Unsloth](https://huggingface.co/unsloth)、[NVIDIA ModelOpt](https://huggingface.co/collections/nvidia/inference-optimized-checkpoints-with-model-optimizer) 或 [NeuralMagic](https://huggingface.co/collections/neuralmagic) 集合，里面有一些经过质量验证的热门量化模型。量化后的模型必须通过基准测试验证，以防范异常的量化质量回退。

<Note>

**`auto` 的选择顺序：** 1) DeepGEMM（SM90/SM100，已安装时）；2) FlashInfer TRTLLM（SM100，FlashInfer 可用时）；3) CUTLASS（SM120）；4) AITER（AMD）；5) Triton（兜底）。

**MXFP8 稠密线性层：** `auto` 在 SM100 上使用 `flashinfer_cutlass`（否则用 `triton`）。`flashinfer_cutlass` 在大多数形状下最快；`flashinfer_trtllm` 只在 M 较小时更快。

<Note>
💡 AI Infra 学习笔记：量化模型的 GEMM（矩阵乘）kernel 选择直接决定性能——不同后端针对不同硬件架构（SM90 Hopper / SM100 Blackwell）做了专门优化：DeepGEMM 是 JIT 编译的 GEMM 库，FlashInfer 的 TensorRT-LLM 后端面向低延迟优化，Marlin 是 CUDA-only 的 W4A16 kernel，Aiter 是 AMD ROCm 专属。同一模型在不同 GEMM 后端下的吞吐可能相差数倍，这是推理引擎性能调优的重要抓手，也是面试高频考点。
</Note>

## 离线量化

加载已量化模型很简单，直接加载模型权重和配置即可。**再次强调：如果模型已经离线量化过，启动引擎时就不需要加 `--quantization` 参数。量化方法会从下载的 Hugging Face 或 msModelSlim 配置中自动解析。例如，DeepSeek V3/R1 模型本身就是 FP8，不要再加冗余参数。**

```bash Command
python3 -m sglang.launch_server \
    --model-path hugging-quants/Meta-Llama-3.1-8B-Instruct-AWQ-INT4 \
    --port 30000 --host 0.0.0.0
```

请注意，如果你的模型是**带 per-token 动态量化激活值的 per-channel 量化（INT8 或 FP8）**，可以加上 `--quantization w8a8_int8` 或 `--quantization w8a8_fp8` 来调用 sgl-kernel 中对应的 CUTLASS int8_kernel 或 fp8_kernel。这样做会忽略 Hugging Face 配置中的量化设置。例如，对 `neuralmagic/Meta-Llama-3.1-8B-Instruct-FP8-dynamic`，如果执行时带 `--quantization w8a8_fp8`，系统会使用 SGLang 的 `W8A8Fp8Config` 调用 sgl-kernel，而不是 vLLM kernel 的 `CompressedTensorsConfig`。

```bash Command
python3 -m sglang.launch_server \
    --model-path neuralmagic/Meta-Llama-3.1-8B-Instruct-FP8-dynamic \
    --quantization w8a8_fp8 \
    --port 30000 --host 0.0.0.0
```

### 离线模型量化示例

#### 使用 [Unsloth](https://docs.unsloth.ai/basics/inference-and-deployment/sglang-guide)

我们强烈建议用 Unsloth 来量化并加载模型。请参考 [使用 Unsloth 部署与推理 SGLang 指南](https://docs.unsloth.ai/basics/inference-and-deployment/sglang-guide)。

#### 使用 [auto-round](https://github.com/intel/auto-round)

```bash Command
# Install
pip install auto-round
```

- LLM 量化

```py Example
# for LLM
from auto_round import AutoRound
model_id = "meta-llama/Llama-3.2-1B-Instruct"
quant_path = "Llama-3.2-1B-Instruct-autoround-4bit"
# Scheme examples: "W2A16", "W3A16", "W4A16", "W8A16", "NVFP4", "MXFP4" (no real kernels), "GGUF:Q4_K_M", etc.
scheme = "W4A16"
format = "auto_round"
autoround = AutoRound(model_id, scheme=scheme)
autoround.quantize_and_save(quant_path, format=format) # quantize and save

```

- VLM 量化
```py Example
# for VLMs
from auto_round import AutoRoundMLLM
model_name = "Qwen/Qwen2-VL-2B-Instruct"
quant_path = "Qwen2-VL-2B-Instruct-autoround-4bit"
scheme = "W4A16"
format = "auto_round"
autoround = AutoRoundMLLM(model_name, scheme)
autoround.quantize_and_save(quant_path, format=format) # quantize and save

```

```bash Command
auto-round \
```

- SGLang API 用法（CPU/CUDA）

```python Example
from sglang.srt.configs.load_config import LoadConfig
from sglang.srt.configs.model_config import ModelConfig
from sglang.srt.model_loader.loader import get_model_loader
from sglang.srt.configs.device_config import DeviceConfig

# Configure model with inc quantization and saving
model_config = ModelConfig(
    model_path="meta-llama/Llama-3.2-3B-Instruct",
    quantization="auto-round-int8",
    trust_remote_code=True,
)

load_config = LoadConfig(
    inc_save_path="./quantized_model",
)
device_config = DeviceConfig(device="cpu")

# Load and quantize the model
model_loader = get_model_loader(load_config, model_config)
quantized_model = model_loader.load_model(
    model_config=model_config,
    device_config=device_config,
)
```

- 已知问题

目前 sglang 在加载离线量化模型时存在一些限制，这些问题可能会在 sglang 后续更新中解决。如果遇到问题，可以考虑改用 Hugging Face Transformers。

1. 混合位宽量化的限制

    混合位宽量化支持不完整。由于 vLLM 的层融合（例如 QKV 融合），对同一个融合层内的不同组件应用不同位宽会导致兼容性问题。

2. 量化 MoE 模型支持有限

    由于 kernel 的限制（例如缺少对 mlp.gate 层量化的支持），量化后的 MoE 模型可能会遇到推理问题。请尽量跳过这些层的量化以避免此类错误。

3. 量化 VLM 支持有限

4. SGLang API 用法支持有限

    SGLang API 用法目前只支持 `auto-round-int8` 一种量化方法，更多量化方法正在路上。

#### 使用 [GPTQModel](https://github.com/ModelCloud/GPTQModel)

```bash Command
# install
pip install gptqmodel --no-build-isolation -v
```

```py Example
from datasets import load_dataset
from gptqmodel import GPTQModel, QuantizeConfig

model_id = "meta-llama/Llama-3.2-1B-Instruct"
quant_path = "Llama-3.2-1B-Instruct-gptqmodel-4bit"

calibration_dataset = load_dataset(
    "allenai/c4", data_files="en/c4-train.00001-of-01024.json.gz",
    split="train"
  ).select(range(1024))["text"]

quant_config = QuantizeConfig(bits=4, group_size=128) # quantization config
model = GPTQModel.load(model_id, quant_config) # load model

model.quantize(calibration_dataset, batch_size=2) # quantize
model.save(quant_path) # save model
```

```python Example
from transformers import AutoTokenizer
from llmcompressor.transformers import SparseAutoModelForCausalLM

from llmcompressor.modifiers.quantization import QuantizationModifier

# Step 1: Load the original model.
MODEL_ID = "meta-llama/Meta-Llama-3-8B-Instruct"

model = SparseAutoModelForCausalLM.from_pretrained(
  MODEL_ID, device_map="auto", torch_dtype="auto")
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)

# Step 2: Perform offline quantization.
# Step 2.1: Configure the simple PTQ quantization.
recipe = QuantizationModifier(
  targets="Linear", scheme="FP8_DYNAMIC", ignore=["lm_head"])

# Step 2.2: Apply the quantization algorithm.
oneshot(model=model, recipe=recipe)

# Step 3: Save the model.
SAVE_DIR = MODEL_ID.split("/")[1] + "-FP8-Dynamic"
model.save_pretrained(SAVE_DIR)
tokenizer.save_pretrained(SAVE_DIR)
```

#### 使用 [NVIDIA ModelOpt](https://github.com/NVIDIA/Model-Optimizer)

NVIDIA Model Optimizer（ModelOpt）提供针对 NVIDIA 硬件优化过的先进量化技术。

**离线量化 vs. 在线量化：**

SGLang 支持 ModelOpt 的两种模式。

* **离线量化（预量化）：**
    * **用法：** 从 Hugging Face 下载预量化模型，或运行一次 `hf_ptq.py` 生成新的量化检查点，然后加载这个量化检查点。
    * **优点：** 服务端启动快，量化质量可以在部署前验证，资源利用高效。
    * **缺点：** 需要额外的准备步骤。

* **在线量化（量化即服务）：**
    * **用法：** 加载普通 BF16/FP16 模型并加一个参数。引擎会在*启动时*应用量化。
    * **优点：** 方便（不需要生成新检查点）。
    * **缺点：** **启动时间很长**，初始化期间显存占用上升（有 OOM 风险）。

<Note>
💡 AI Infra 学习笔记：在线量化虽然省事，但代价是在引擎启动时实时完成权重转换——启动时间显著变长、初始化期间显存占用上升（有 OOM 风险）。生产环境通常推荐离线量化：一次性量化、多次复用，启动快、量化质量可以预先用基准测试验证。理解"离线 vs 在线"的取舍，是量化部署方案设计的基本功。
</Note>

下面各节引导你走离线路径：加载预量化模型，或创建自己的检查点。

##### 使用预量化检查点

如果模型已经量化好（例如来自 Hugging Face），可以直接加载。

* **FP8 模型：**
    使用 `--quantization modelopt_fp8`。
    ```bash Command
    python3 -m sglang.launch_server \
        --model-path nvidia/Llama-3.1-8B-Instruct-FP8 \
        --quantization modelopt_fp8 \
        --port 30000
    ```

* **FP4 模型：**
    使用 `--quantization modelopt_fp4`。
    ```bash Command
    python3 -m sglang.launch_server \
        --model-path nvidia/Llama-3.3-70B-Instruct-NVFP4 \
        --quantization modelopt_fp4 \
        --port 30000
    ```

##### 创建自己的量化检查点

如果找不到适合你模型的预量化检查点，可以用 NVIDIA Model Optimizer 的 `hf_ptq.py` 脚本自己生成。

**为什么要量化？**
- 减少显存占用
- 更高的吞吐和更低的延迟
- 部署更灵活（可以在更小的 GPU 上运行）

**哪些部分可以量化？**
- 整个模型
- 仅 MLP 层
- KV 缓存

**`hf_ptq.py` 中的关键选项：**

`--qformat`：量化格式 `fp8`、`nvfp4`、`nvfp4_mlp_only`

`--kv_cache_qformat`：KV 缓存量化格式（默认：`fp8`）

**注意：** 默认的 `kv_cache_qformat` 未必适合所有使用场景。建议显式设置它。

**硬件要求：** 推荐 Hopper 及以上。GPU 内存不足可能导致权重卸载，量化时间会极其漫长。

详细用法和受支持的模型架构，见 [NVIDIA Model Optimizer LLM PTQ](https://github.com/NVIDIA/Model-Optimizer/tree/main/examples/llm_ptq)。

SGLang 内置了一套用 ModelOpt 量化模型并自动导出部署的工作流。

##### Python API 用法

你也可以用代码方式使用 ModelOpt 量化：


## 在线量化

要启用在线量化，只需在命令行指定 `--quantization`。例如，下面的命令可以为模型 `meta-llama/Meta-Llama-3.1-8B-Instruct` 启用 `FP8` 量化：

```bash Command
python3 -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
    --quantization fp8 \
    --port 30000 --host 0.0.0.0
```

我们团队正在努力支持更多在线量化方法。SGLang 很快会支持包括但不限于 `["awq", "gptq", "marlin", "gptq_marlin", "awq_marlin", "bitsandbytes", "gguf"]` 的方法。

### torchao 在线量化方法

SGLang 也支持基于 [torchao](https://github.com/pytorch/ao) 的量化方法。只需在命令行指定 `--torchao-config` 即可启用。例如，想为模型 `meta-llama/Meta-Llama-3.1-8B-Instruct` 启用 `int4wo-128`，可以用下面的命令启动服务端：

```bash Command
python3 -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
    --torchao-config int4wo-128 \
    --port 30000 --host 0.0.0.0
```

SGLang 支持以下基于 torchao 的量化方法：`["int8dq", "int8wo", "fp8wo", "fp8dq-per_tensor", "fp8dq-per_row", "int4wo-32", "int4wo-64", "int4wo-128", "int4wo-256"]`。

注意：根据[这个 issue](https://github.com/sgl-project/sglang/issues/2219#issuecomment-2561890230)，`"int8dq"` 方法在与 CUDA graph 捕获一起使用时目前存在一些 bug。因此使用 `"int8dq"` 时建议禁用 CUDA graph 捕获，也就是用下面的命令：

```bash Command
python3 -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3.1-8B-Instruct \
    --torchao-config int8dq \
    --disable-cuda-graph \
    --port 30000 --host 0.0.0.0
```

### `nvfp4_online` 在线量化方法

用 `--quantization nvfp4_online` 可以在加载时把符合条件的 BF16、FP16 或 FP8 MoE 专家权重转换成 NVFP4，并带 per-token FP32 激活缩放。序列化的 NVFP4 检查点或需要 per-tensor FP32 激活缩放的同类加载时转换，请用 `modelopt_fp4`。

这个设计把权重量化和激活缩放分离开来：

- **权重：** SGLang 在加载每个符合条件的 MoE 专家权重张量时进行量化，使用标准的 2D NVFP4 权重量化。生成的 NVFP4 权重使用静态 E4M3 block 缩放，外加由权重 amax 推导出的静态 per-tensor FP32 缩放。对于门控 MoE 专家，w1/w3 这对权重共享同一个 per-tensor FP32 缩放。
- **激活值：** FlashInfer 在运行时计算并传播每个 token 一个 FP32 缩放。只接受每个 tensor 一个 FP32 激活缩放的端须使用 `modelopt_fp4`。
- **FP8 检查点：** 如果某个符合条件的专家权重以 FP8 存储，SGLang 会先用检查点缩放对该张量反量化，然后在加载过程中重新量化为 NVFP4。
- **其他层：** 稠密线性层保持其源检查点的精度或检查点量化路径。

只支持 `--moe-runner-backend flashinfer_trtllm` 和 `--moe-runner-backend flashinfer_trtllm_routed`。如果省略 `--moe-runner-backend`，SGLang 会选择 `flashinfer_trtllm`。支持张量并行；每个 TP rank 在本地计算激活 per-token 缩放，而在线权重量化仍使用已加载专家张量基于 per-tensor amax 推导的 FP32 缩放。

FlashInfer TRTLLM MoE 后端会禁用共享专家融合，因此在线量化只作用于路由 MoE 专家，共享专家保持检查点精度。两种在线模式都遵循 `SGLANG_FP4_IGNORED_LAYERS`；对于 FP8 源检查点，列出的专家保持 FP8，不会被转换成 NVFP4。

```bash Command
python3 -m sglang.launch_server \
    --model-path Qwen/Qwen3-30B-A3B-Instruct-2507 \
    --tp-size 2 \
    --ep-size 2 \
    --quantization nvfp4_online \
    --port 30000 --host 0.0.0.0
```

### `quark_int4fp8_moe` 在线量化方法

运行在 AMD GPU（CDNA3 或 CDNA4 架构）上的 SGLang 支持 `--quantization quark_int4fp8_moe` 量化方法，它会把原本高精度（bfloat16、float16 或 float32）的 [MoE 层](https://github.com/sgl-project/sglang/blob/v0.4.8/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L271)替换为使用动态量化为 int4 的权重，推理时这些权重会上转换到 float8，以 float8 精度计算，而激活值则即时动态量化为 float8。

其他层（例如注意力层中的投影层）的权重会直接在线量化为 float8。

### `quark_mxfp4` 在线量化方法

运行在带硬件 FP4 支持的 AMD GPU（CDNA4 架构，例如 MI355x）上的 SGLang 支持 `--quantization quark_mxfp4` 量化方法，它会在加载时把 BF16 模型权重量化为 MXFP4，对激活值使用动态 MXFP4 量化，并用 MXFP4 GEMM 替代 BF16 GEMM。

示例（BF16 到 MXFP4 的重新量化）：

```bash
sglang serve --model-path Qwen/Qwen3-30B-A3B \
    --tensor-parallel-size 1 \
    --quantization quark_mxfp4
```

`--quantization quark_mxfp4` 选项也支持把 FP8 稠密模型和 MoE 模型转换为 MXFP4，转换逻辑如下：

1. 加载 FP8 权重张量，
2. 反量化为 BF16，
3. 重新量化为 MXFP4

在权重加载过程中逐步完成。

示例（FP8 到 MXFP4 的重新量化）：

```bash
sglang serve --model-path Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 \
    --tensor-parallel-size 1 \
    --quantization quark_mxfp4
```

### Intel® Neural Compressor 在线量化方法

SGLang 支持基于先进算法 [auto-round](https://github.com/intel/auto-round) 的量化方法，它位于 [Intel® Neural Compressor](https://github.com/intel/neural-compressor) 中。只需指定 `--quantization auto-round-int8` 即可使用该功能。它会即时把模型量化到目标格式。更多在线量化方法正在路上。

##### 可用的量化方法

| 量化方法 | 方案 | 验证过的硬件环境 |
|:--------------------|:--------|:-------------------------------|
| auto-round-int8     |INT8 逐通道量化权重 <br /> INT8 逐 token 动态量化激活 | Intel Xeon 可扩展处理器 <br /> Nvidia A100 GPU |

## Ascend NPU 上的扩散模型量化

SGLang-Diffusion 在 Ascend A5 NPU 上支持扩散模型（如 Wan2.2）的 MXFP8 量化，有在线和离线（ModelSlim）两种模式。这与 LLM 推理路径是分开的，使用 `sglang serve` / `sglang generate` CLI。

```bash
sglang serve \
```
