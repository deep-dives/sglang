SGLang 提供多种投机解码方案，包括 EAGLE-2/EAGLE-3、MTP、DFLASH、经典草稿模型解码，以及基于 NGRAM 的变体。我们的实现以速度和效率最大化为目标，被认为是开源 LLM 引擎中速度最快的之一。

<Note>
💡 AI Infra 学习笔记：投机解码（speculative decoding）的核心思路是「用小而快的草稿模型（draft model）先猜一串 token，再用大模型一次并行验证，接受与目标分布一致的 token」。自回归解码每步只能生成 1 个 token，而投机解码把多步生成合并成一次并行前向，从而在不改变输出分布的前提下大幅提升吞吐——代价是额外显存，以及草稿与验证两条路径的实现复杂度。
</Note>

### 快速指引

- **速度/质量最佳（推荐）**：使用 **EAGLE-3**，配合 `--speculative-algorithm EAGLE3`。
- **稳健默认 / 广泛兼容**：使用 **EAGLE-2**，配合 `--speculative-algorithm EAGLE`。
- **工作负载的接受率随时间变化**：在 **EAGLE** 之上使用 [**自适应投机解码**](./adaptive_speculative_decoding)，配合 `--speculative-eagle-topk 1`。
- **降低 EAGLE-2 的 `lm_head` 开销**：用 `--speculative-token-map` 启用 **FR-Spec**。
- **模型支持 MTP**：使用**基于投机解码的 MTP**（通常配合较小的 `speculative_num_steps/topk/num_draft_tokens`，参见示例部分）。
- **你有 DFlash 草稿检查点**：使用 **DFLASH**，配合 `--speculative-algorithm DFLASH` 和 `--speculative-draft-model-path ...`。
- **你有更小的草稿 LLM**：使用 **STANDALONE**（`--speculative-algorithm STANDALONE`）。
- **没有额外的模型可用**：使用 **NGRAM**（`--speculative-algorithm NGRAM`，仅 CUDA）。

这些参数对 EAGLE-2 和 EAGLE-3 大体相同。`--speculative-token-map` 对 EAGLE-3 模型会被忽略。
对于 `--speculative-num-steps`、`--speculative-eagle-topk` 和 `--speculative-num-draft-tokens`：要么三者都不设置以使用自动调优，要么在调参时三者都显式设置。
如果你使用 EAGLE 且 `--speculative-eagle-topk 1`，但各请求的接受率差异较大，参见 [自适应投机解码](./adaptive_speculative_decoding)。

<Note>
💡 AI Infra 学习笔记：EAGLE 与经典「小模型草稿」的关键区别在于草稿空间：经典方法在 token 空间逐 token 猜测，而 EAGLE 直接预测 LLM 的隐藏层特征（feature），再经语言头采样出 token。特征空间更平滑、可预测性更高，因此 EAGLE 的接受率通常显著高于 token 级草稿——这正是它在开源引擎中速度领先的原因。EAGLE-3 进一步去掉特征预测目标、融合低中层特征，草稿更准。
</Note>


你可以用 [bench_speculative.py](https://github.com/sgl-project/sglang/blob/main/scripts/playground/bench_speculative.py) 找到这些参数的最佳组合。


### EAGLE-2 解码

你可以通过设置 `--speculative-algorithm EAGLE` 并选择合适的模型来启用 EAGLE-2 解码。

**启动服务端：**

```bash Command
python3 -m sglang.launch_server \
    --model meta-llama/Llama-2-7b-chat-hf \
    --speculative-algorithm EAGLE \
    --speculative-draft-model-path lmsys/sglang-EAGLE-llama2-chat-7B \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 4 \
    --speculative-num-draft-tokens 16 \
    --mem-fraction-static 0.7 \
    --cuda-graph-max-bs-decode 8 \
    --log-level warning
```

**发送请求：**

```python Example
import openai

client = openai.Client(base_url="http://127.0.0.1:30000/v1", api_key="None")

response = client.chat.completions.create(
    model="meta-llama/Llama-2-7b-chat-hf",
    messages=[
        {"role": "user", "content": "List 3 countries and their capitals."},
    ],
    temperature=0,
    max_tokens=64,
)

print(response.choices[0].message.content)
```

### 基于频率排序投机采样的 EAGLE-2 解码

## 投机解码 V2（重叠调度器）

投机解码默认以启用重叠调度器的方式运行 V2 投机工作进程（例如 `StandaloneWorkerV2`、`EAGLEWorkerV2`）。传入 `--disable-overlap-schedule` 可回退到同步（非重叠）路径。

注意事项：
- 重叠调度器目前只支持 `--speculative-eagle-topk 1`；**请显式设置 `--speculative-eagle-topk 1`**。
- 如果你显式设置 `--speculative-eagle-topk > 1`，服务端会报错。
- 如果你省略 `--speculative-eagle-topk`，自动调优可能为某些模型（如 Llama）选择 `topk > 1`。这与重叠调度器不兼容，且不一定立刻触发配置错误，所以请显式设置 `--speculative-eagle-topk 1`。

<Note>
💡 AI Infra 学习笔记：重叠调度器（overlap scheduler）把「草稿生成」与「目标验证」做成异步流水：GPU 在跑当前 batch 解码的同时，CPU 提前准备下一个 batch 并预取草稿，从而隐藏草稿与验证阶段之间的大部分空闲等待。它目前只在 `--speculative-eagle-topk 1` 下工作，因为多分支树形验证的调度复杂度更高，难以做干净的流水重叠。
</Note>


```bash Command

    --speculative-draft-model-path Qwen/Qwen2.5-1.5B-Instruct \
    --speculative-num-steps 4 \
    --speculative-eagle-topk 1 \
```

## OOM 故障排查

> [!WARNING]
> **遇到显存不足（OOM）？** 投机解码可能增加 GPU 显存占用，因为草稿树、CUDA 图以及与验证相关的缓冲区会消耗额外显存。如果遇到 OOM 错误，请尝试以下调整。

### 第 1 步：降低静态内存比例（最有效）

```bash Command
--mem-fraction-static 0.5   # when omitted, this value is auto-computed
```

- `--mem-fraction-static` 控制模型权重 + KV 缓存池的内存预算。
- 降低它会直接增加激活值和 CUDA 图缓冲区的动态余量。
- 如果省略，SGLang 会根据其他设置自动估算该值，而这些自动设置对某些工作负载可能仍然过于激进。

### 第 2 步：减小 CUDA 图批大小

```bash Command
# Fewer CUDA graph captures = less memory reserved
--cuda-graph-max-bs-decode 4   # or even 2 for tight memory situations
```

- 如果省略，`--cuda-graph-max-bs-decode` 会根据 GPU 显存和 TP 大小自动选择，在高显存 GPU 上可能大得多。

### 第 3 步：减小草稿树大小

这三个参数直接控制草稿树消耗多少内存：

```bash Command
# Before (aggressive, high memory)
--speculative-num-steps 5 --speculative-eagle-topk 8 --speculative-num-draft-tokens 64

# After (conservative, lower memory)
--speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4
```

### 第 4 步：限制并发请求数

```bash Command
# Fewer concurrent requests lowers in-flight load and can reduce OOM risk
--max-running-requests 4
```

### 快速 OOM 恢复配方

如果你遇到 OOM 且只想要一个能跑起来的方案，先从下面这个最小配置开始，再逐步加大：

```bash Command
python3 -m sglang.launch_server \
    --model <your-model> \
    --speculative-algorithm EAGLE \
    --speculative-draft-model-path <your-draft-model> \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 4 \
    --cuda-graph-max-bs-decode 2 \
    --mem-fraction-static 0.5 \
    --max-running-requests 4 \
    --log-level warning
```

然后逐步增大 `--speculative-num-draft-tokens`、`--speculative-eagle-topk` 和 `--cuda-graph-max-bs-decode`。最后再增大 `--mem-fraction-static`，仅在运行稳定之后。

## 参考资料

EAGLE 的流程如下：

- 在 EAGLE 中，草稿模型利用特征序列 $(f_1, ..., f_k)$ 和 token 序列 $(t_2, ..., t_&#123;k+1&#125;)$ 预测下一个特征向量，即原 LLM 的最后隐藏状态。
- 随后从 $p_&#123;k+2&#125;=\text&#123;LMHead&#125;(f_&#123;k+1&#125;)$ 中采样下一个 token。之后，这两条序列以树形方式扩展——每步扩展出多个可能的续写分支，分支因子由 `speculative_eagle_topk` 参数控制——以保证上下文衔接更连贯，并再次作为输入。
- 在 SGLang 的 EAGLE-2 实现中，草稿树按配置的步数扩展，然后重新排序，选出排名靠前的 `speculative_num_draft_tokens` 个最终节点作为草稿 token。
- EAGLE-3 移除了特征预测目标，纳入低层和中层特征，并以 on-policy 方式进行训练。

这种方法在特征层面而非 token 层面操作，输入更规整，再加上传入下一时间步的 token 来降低采样随机性，从而提升草稿准确率。更多细节参见 [EAGLE-2](https://arxiv.org/abs/2406.16858) 和 [EAGLE-3](https://arxiv.org/abs/2503.01840) 论文。

关于如何训练你自己的 EAGLE 模型，参见 [EAGLE 仓库](https://github.com/SafeAILab/EAGLE/tree/main?tab=readme-ov-file#train)。针对 EAGLE-3 训练，可以关注 [SpecForge](https://github.com/sgl-project/SpecForge)——SGLang 团队为 EAGLE-3 投机解码模型设计的训练框架，可无缝移植到 SGLang 推理服务。详情参见 [SpecForge 文档](https://docs.sglang.ai/SpecForge/) 和[博客文章](https://lmsys.org/blog/2025-07-25-spec-forge)。
