SGLang 支持种类丰富的 Attention 后端，它们各有优劣。
你可以按需测试后自行选择。

<Warning>
选择合适的 Attention 后端对最大化性能至关重要。不同后端各有擅长的场景，请根据你的模型、硬件和使用场景来选。并非所有后端都支持所有平台和模型架构。

如果你不指定 `--attention-backend`，SGLang 会根据你的硬件和模型架构尽力自动选择性能最佳的后端。
</Warning>

<Note>
💡 AI Infra 学习笔记：Attention 后端是推理引擎中最核心的性能组件之一——注意力计算占解码阶段的大部分时间，不同后端（FlashInfer、FA3/FA4、Triton 等）在页大小、量化 KV 缓存、滑动窗口、投机解码等特性上支持各不相同，选错后端可能带来数倍性能差异。这也是推理引擎性能优化面试的高频考点。
</Note>

## 支持矩阵

支持矩阵分为两部分：MHA（标准注意力）和 MLA（多头潜在注意力，multi-head latent attention）。关于 MHA 与 MLA 关键区别的说明，请参阅 [SGLang 的 DeepSeek MLA 文档](/cookbook/autoregressive/DeepSeek/DeepSeek-V3#4-2-4-mla-optimizations) 和原始的 [DeepSeek MLA 论文](https://arxiv.org/pdf/2405.04434)。

</Tip>

<Tip>
页大小控制把多少个 token 分到同一个 KV 缓存块中。要让前缀缓存生效，token 数量必须至少填满一个完整的页。例如，如果你的提示词只有 32 个 token，而 `page_size = 64`，它无法填满一页，也就无法在前缀缓存中匹配（页不能被填充）。当有 65 个 token、`page_size = 64` 时，只有第一页的 64 个 token 会被缓存并匹配，剩下 1 个 token 会被丢弃。想要最大化前缀复用（按 token 粒度匹配），请使用 `page_size = 1`。注意，更大的页大小通常能提升注意力 kernel 的性能，所以当前缀缓存复用不是关键时，优先用 `page_size > 1`。
</Tip>

<Note>
💡 AI Infra 学习笔记：页大小（page size）与前缀缓存是一对需要权衡的配置。页越大，注意力 kernel 的访存越规整、性能越好；但前缀缓存按整页匹配，页越大能命中的前缀粒度越粗（比如 `page_size = 64` 时，小于 64 token 的共享前缀完全无法复用）。批量对话、共享系统提示词等场景看重缓存命中，通常更倾向小页甚至 `page_size = 1`。
</Note>


许多不原生操作页的后端可以在包装层把页表展开为逐 token 索引，从而模拟 `page_size > 1`。"页大小 > 1（原生）"列表示真正的 kernel 内分页。有些后端要求固定的原生页大小，无法按其他方式缩小或模拟：TRTLLM MHA（16/32/64）、TRTLLM MLA（32/64）、CuteDSL MLA（32/64）、FlashMLA（64）、Cutlass MLA（128）、Ascend（128）、HPC-Ops（64）。

MLA 页大小约束：
- FlashInfer MLA：page_size = 1。
- FlashMLA：page_size = 64。
- Cutlass MLA：page_size = 128。
- TRTLLM MLA：page_size ∈ &#123;32, 64&#125;。
- CuteDSL MLA：page_size ∈ &#123;32, 64&#125;（仅解码；未设置时预填充回退到 `trtllm_mla`）。
- TokenSpeed MLA：page_size ∈ &#123;32, 64&#125;（仅 Blackwell SM100/SM12x；需要 `--kv-cache-dtype fp8_e4m3`）。

### GDN Attention 后端

GDN（Gated Delta Network，门控增量网络）是一种复杂度为 O(n) 的线性注意力机制，用于混合模型——这类模型在标准全注意力层之间交替穿插 GDN 线性注意力层。GDN **并不**通过 `--attention-backend` 选择；当模型架构需要时（例如 Qwen 3.5、Qwen 3 Next、Jet Nemotron、Jet VLM），它会自动激活。

GDN 线性注意力层有自己独立的 kernel 后端，通过 `--linear-attn-backend` 选择（默认：`triton`）。你也可以用 `--linear-attn-decode-backend` 和 `--linear-attn-prefill-backend` 按阶段覆盖 kernel 选择。

在 SM100/SM103 与 CUDA 13+ 环境下，当满足以下条件时，SGLang 会自动为 GDN 预填充选择 FlashInfer：未设置按阶段覆盖、基础线性注意力后端为 Triton、循环状态为 BF16、键/值头维度为 128、动态分块与 page-major KV 布局被禁用，且 `--chunked-prefill-size` 在 1 到 8192 之间。Radix 缓存可以禁用，或使用 `no_buffer`、`extra_buffer`、`extra_buffer_lazy`；extra-buffer 路径会使用状态检查点。

### 混合注意力（预填充与解码使用不同后端）（实验性）

<Warning>
混合注意力是实验性功能。
</Warning>

你可以为预填充和解码自由搭配 Attention 后端。当某个后端擅长预填充、另一个擅长解码时，这种做法很实用。实现细节请参见 `python/sglang/srt/layers/attention/hybrid_attn_backend.py`。

```bash Command
# Example: Prefill with FA4, Decode with TRTLLM MLA (Blackwell)
python3 -m sglang.launch_server \
  --model-path nvidia/DeepSeek-R1-FP4 \
  --tp 8 \
  --attention-backend trtllm_mla \
  --moe-runner-backend flashinfer_trtllm \
  --quantization modelopt_fp4 \
  --prefill-attention-backend fa4
```

#### 混合注意力下的投机解码

混合注意力同样可用于投机解码。草稿解码与目标验证所用的后端取决于 `--speculative-attention-mode`：

- `--speculative-attention-mode decode`（推荐）：草稿/验证使用解码后端。
- `--speculative-attention-mode prefill`（默认）：草稿/验证使用预填充后端。

将混合注意力与投机解码组合时的约束：

- 如果任一 Attention 后端是 `trtllm_mha`，投机解码只支持 `--speculative-eagle-topk 1`。
- 对于 `--page-size > 1` 且 `--speculative-eagle-topk > 1` 的分页 MHA 后端，仅支持 `flashinfer`。
- CUDA 图：解码后端始终会被捕获；预填充后端仅在 `--speculative-attention-mode prefill` 时才会被捕获。


<Tip>
如果你只设置了 `--prefill-attention-backend` 或 `--decode-attention-backend` 中的一项，未指定的阶段会继承 `--attention-backend`。
如果两者都指定且不同，SGLang 会自动启用混合包装器，按阶段分发到所选后端。
</Tip>

<Note>
💡 AI Infra 学习笔记：自动选择逻辑体现了硬件代际的演进规律——Hopper（H100/H200）默认用 FA3、Blackwell（B200）默认用 TRTLLM、老架构默认 FlashInfer/Triton。理解这套逻辑能帮你判断「该换后端还是该换机器」：同一型号 GPU 上性能瓶颈往往在后端特性（如页大小、KV 量化、投机解码支持），跨代 GPU 则要优先考虑为新一代硬件专门优化的 kernel。
</Note>

## Attention 后端选择指南（CUDA）

如果未指定 `--attention-backend` 参数，SGLang 会根据硬件（CUDA）和模型架构自动选择最佳后端。

### 自动选择逻辑

**1. MHA 模型（如 Llama、Qwen）**
- **Hopper（如 H100、H200）**：使用 CUDA 12.3+ 且模型配置受支持时，默认 `fa3`。
- **Blackwell（如 B200）**：默认 `trtllm_mha`，除非使用 `topk > 1` 的投机解码。
- **其他架构（Ampere、Ada 等）**：可用时默认 `flashinfer`，否则回退到 `triton`。

**2. MLA 模型（如 DeepSeek V3）**
- **Hopper**：默认 `fa3`（需要 CUDA 12.3+）。
- **Blackwell**：默认 `flashinfer`；DeepSeek V3 模型会专门自动选择 `trtllm_mla`。
- **其他架构**：默认 `triton`。

## 新增 Attention 后端的步骤
要新增一个 Attention 后端，你可以参考现有后端
（`python/sglang/srt/layers/attention/triton_backend.py`、`python/sglang/srt/layers/attention/flashattention_backend.py`）
并按照以下步骤进行。

<Note>
线性注意力 kernel 后端（GDN、KDA）采用不同的模式。它们在 `python/sglang/srt/layers/attention/linear/kernels/` 中实现 `LinearAttnKernelBase`，并由 `GDNKernelDispatcher` / `KDAKernelDispatcher` 分发，而不是通过 `@register_attention_backend` 注册。
</Note>

1. 先在无 CUDA 图的情况下运行，支持两个前向函数
    - forward_extend
        - 用于预填充、带 KV 缓存的预填充，以及目标验证
        - 每层调用一次
    - forward_decode
        - 用于常规解码和草稿解码
        - 每层调用一次
    - init_forward_metadata
        - 初始化类与所有层共享的公共元数据
        - 调用 plan 函数以支持 split_kv 等优化
        - 每次前向调用一次
2. 再在 CUDA 图模式下运行。它分为两个阶段（捕获与回放），你需要实现三个函数
    - init_cuda_graph_state
        - 在生命周期内只调用一次
        - 创建所有公共共享缓冲区
    - init_forward_metadata_capture_cuda_graph
        - 在捕获 CUDA 图之前调用
        - 与 init_forward_metadata 类似，但把元数据写入预定义的缓冲区
    - init_forward_metadata_replay_cuda_graph
        - 在回放 CUDA 图之前调用
        - 该函数位于关键路径上，必须足够快
