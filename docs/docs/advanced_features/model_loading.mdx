`--model-path` 选择要服务的检查点；`--load-format` 和下面的权重加载参数控制这些权重如何读入内存。要从云对象存储（S3/GCS/Azure）流式加载权重，见 [从对象存储加载模型](./object_storage)。

## 加载是如何工作的

SGLang 根据 `--load-format` 选择加载器，否则会从检查点或模型路径自动检测。默认的 `auto` 加载器读取 `safetensors`，失败时回退到 PyTorch `.bin`。

```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3.6-35B-A3B \
  --load-format auto
```

有些格式会自动检测并覆盖 `auto`：

- 检测到 Mistral 原生检查点时用 `mistral` 加载。
- 模型路径以 `.gguf` 结尾时用 `gguf` 加载。
- 对象存储 URI（`s3://`、`gs://`、`az://`）用 `runai_streamer` 加载。
- 远程 URI 用 `remote` 加载。

<Note>
💡 AI Infra 学习笔记：模型权重有多种存储格式，加载格式决定了引擎"怎么读"和"读到哪"：`safetensors` 是 Hugging Face 生态的主流格式（内存安全、可零拷贝 mmap），PyTorch `.bin` 是老格式（依赖 pickle、有安全风险），`dummy` 用随机值占位（供性能剖析，不读真实权重），`sharded_state` 让每个张量并行 rank 只读自己的分片（省掉"全部读进来再切分"的浪费）。选对加载格式直接影响启动速度和峰值内存，是部署环节的实用知识。
</Note>

## 模型加载器额外配置

`--model-loader-extra-config` 接受一个 JSON 字符串，会传给 `--load-format` 选中的加载器。

```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3.6-35B-A3B \
  --model-loader-extra-config '{"enable_multithread_load": true, "num_threads": 16}'
```

<Note>
💡 AI Infra 学习笔记：加载阶段的性能手段本质是"把磁盘/网络 I/O 与 CPU/GPU 利用重叠起来"：mmap 让文件按需映射、避免整份拷贝；多线程加载并行读分片；预取（prefetch）在真正加载前就把文件拉进操作系统 page cache——在 NFS/Lustre 这类共享文件系统上，多个 rank 各自预取一部分，能让总网络流量从"每个 rank 都读一整份"降到"整份只读一次"。做推理引擎面试时，"启动/加载优化"与"运行时优化"是两条并行的知识线，前者经常被忽略。
</Note>
