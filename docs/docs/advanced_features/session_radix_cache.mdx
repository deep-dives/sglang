---

会话感知 Radix 缓存（session-aware radix caching）能在内存压力下提升长生命周期、多轮对话类负载的缓存命中率。它把可复用的 KV 注册到某个会话名下，在驱逐时优先回收未被引用的 KV，再回收仍被活跃会话引用的 KV。

会话引用是软保护（soft protection），不是内存钉住（memory pin）。当回收未引用的 KV 仍不足以腾出空间时，被引用的 KV 同样可能被驱逐。

<Note>
💡 AI Infra 学习笔记：Radix 缓存的核心思路是把提示词中的公共前缀以树结构（Radix Tree）复用——多轮对话、共享系统提示词时命中率会显著提升。会话感知的变体进一步保证"活跃会话"引用的 KV 优先保留，避免长会话被不相关的短请求挤掉。这是多租户、agent 型长对话场景的关键优化。
</Note>

## 启用缓存

该特性只由 `UnifiedRadixCache` 实现。

```bash Command
SGLANG_ENABLE_UNIFIED_RADIX_TREE=1 python3 -m sglang.launch_server \
  --model-path MODEL_PATH \
  --enable-session-radix-cache
```

## 传递并关闭会话

你的应用必须在同一会话的每个请求中传递相同的顶层 `session_id`。该 ID 只用于标记缓存引用，不会拼接或重建对话上下文，所以每个请求仍须携带完整的提示词。

```bash Command
curl http://localhost:30000/generate \
  -H "Content-Type: application/json" \
  -d '{
    "text": "FULL_PROMPT_FOR_THIS_TURN",
    "sampling_params": {"max_new_tokens": 128},
    "session_id": "agent-42"
  }'
```

当一个请求结束时，SGLang 会自动把它可复用的缓存叶子节点注册到 `session_id` 名下。这种仅引用（reference-only）的工作流不需要调用 `/open_session`。

当应用会话结束时，调用 `/close_session`，包括出错和取消的路径：

```bash Command
curl -X POST http://localhost:30000/close_session \
  -H "Content-Type: application/json" \
  -d '{"session_id": "agent-42"}'
```

关闭只会移除会话的引用，不会立即释放其 KV。这些 KV 仍然可复用，并回到正常的驱逐顺序中。

## 驱逐行为

缓存会为每个 UnifiedRadixCache 组件分别跟踪引用。设备与主机（host）的驱逐采用相同的会话优先级。

| 组件 | 被引用的数据 | 驱逐顺序 |
| --- | --- | --- |
| Full attention | 从注册的叶子节点到根节点的可复用前缀路径 | 先驱逐未引用节点，再驱逐会话引用较少的节点，最后按配置的策略（如 LRU） |
| 滑动窗口注意力（SWA） | 覆盖滑动窗口及页对齐余量的可复用尾部 | 两轮 LRU：先驱逐未引用节点，空间仍不够时再驱逐被引用节点 |
| Mamba | 注册叶子节点上的可复用状态 | 两轮 LRU：先驱逐未引用节点，空间仍不够时再驱逐被引用节点 |

<Note>
💡 AI Infra 学习笔记：这里的"软保护"值得留意——即使被会话引用，KV 在内存不足时仍可能被驱逐。这是吞吐优先引擎的常见取舍：宁可牺牲个别会话的缓存命中，也要保证整体内存不失控。对可靠性要求极高的长会话业务，需要结合其他手段（如 HiCache 分层缓存）把重要 KV 放到更安全的层次。
</Note>

UnifiedRadixCache 仍会应用组件级联规则。驱逐一个内部 Full 节点时，其 SWA 与 Mamba 数据也会一并驱逐；驱逐 SWA 时 Mamba 数据一并驱逐；驱逐 Mamba 只影响 Mamba。驱逐一个叶子节点会移除该节点上的全部组件数据。
