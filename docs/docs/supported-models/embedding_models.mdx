---
title: 嵌入模型
description: 稠密与稀疏嵌入模型，支持 FlashInfer 加速与 SGLang 的批处理基础设施。
---
SGLang 通过将高效的服务化机制与灵活的程序接口相结合，为嵌入模型提供了完善的支持。这种集成简化了嵌入任务的处理，让检索与语义搜索更快、更准确。SGLang 的架构还能在嵌入模型部署中实现更好的资源利用率和更低的延迟。

<Warning>
原生编码器（encoder）嵌入架构与 `google/embeddinggemma-300m` 会被自动检测。解码器（decoder）风格的嵌入模型需要 `--is-embedding`；如果模型有要求，还需加上 `--trust-remote-code`。
</Warning>

<Note>
💡 AI Infra 学习笔记：嵌入模型与生成式 LLM 的推理差异很大。生成式模型是解码器结构，靠 KV 缓存 + 自回归逐步产出 token，瓶颈通常在于内存带宽与解码步数；而嵌入模型通常一次前向把整段输入编码成固定维度的向量（纯预填充、无自回归解码），更看重吞吐与批量处理能力。这也是 SGLang 用 `--is-embedding` 区分二者的原因——该参数会把模型切换到嵌入 runner，配合更激进的批处理与 FlashInfer 等加速 kernel，把"一次前向出向量"的流程压到最低延迟。理解这两类 workload 的差异，是推理引擎做调度与内存规划的前提。
</Note>

## 快速开始

### 启动服务端

```bash
sglang serve \
  --model-path Qwen/Qwen3-Embedding-4B \
  --is-embedding
```

### EmbeddingGemma

EmbeddingGemma 使用双向注意力，且会被自动检测，因此它最合适的默认命令很简单：

```bash
sglang serve --model-path google/embeddinggemma-300m
```

在 CUDA 上，SGLang 会自动为其完整的编码器预填充使用可拆分的 CUDA 图（BCG），并禁用不兼容的 radix 缓存与分块预填充行为。请勿添加已废弃的分段式 CUDA 图参数。

### 客户端请求

```python
import requests

url = "http://127.0.0.1:30000"

payload = {
    "model": "Qwen/Qwen3-Embedding-4B",
    "input": "What is the capital of France?",
    "encoding_format": "float"  # or "base64" for compact FP32 responses
}

response = requests.post(url + "/v1/embeddings", json=payload).json()
print("Embedding:", response["data"][0]["embedding"])
```


## 多模态嵌入示例

对于 GME 等同时支持文本和图像的多模态模型：

```bash
sglang serve \
  --model-path Alibaba-NLP/gme-Qwen2-VL-2B-Instruct \
  --is-embedding \
  --chat-template gme-qwen2-vl
```

```python Example
import requests

url = "http://127.0.0.1:30000"

text_input = "Represent this image in embedding space."
image_path = "https://huggingface.co/datasets/liuhaotian/llava-bench-in-the-wild/resolve/main/images/023.jpg"

payload = {
    "model": "gme-qwen2-vl",
    "input": [
        {
            "text": text_input
        },
        {
            "image": image_path
        }
    ],
}

response = requests.post(url + "/v1/embeddings", json=payload).json()

print("Embeddings:", [x.get("embedding") for x in response.get("data", [])])
```

## Matryoshka 嵌入示例

[Matryoshka Embeddings](https://sbert.net/examples/sentence_transformer/training/matryoshka/README.html#matryoshka-embeddings) 或 [Matryoshka Representation Learning (MRL)](https://arxiv.org/abs/2205.13147) 是一种用于训练嵌入模型的技术，它允许你在性能与成本之间进行权衡。

<Note>
💡 AI Infra 学习笔记：Matryoshka（套娃）嵌入是一种"一鱼多吃"的训练技巧：让模型输出向量按维度排序，靠前的子向量（如前 128 维）就已包含足够语义信息，因此同一模型可随请求参数截断到不同维度。对推理服务来说，维度越短，向量存储、相似度计算与网络传输开销越低，代价是检索精度下降——这是向量检索系统中典型的"精度 ↔ 成本"权衡点。SGLang 用 `matryoshka_dimensions` 声明可用维度，并校验请求中的 `dimensions` 是否合法。
</Note>

### 1. 启动支持 Matryoshka 的模型

如果模型配置已经包含 `matryoshka_dimensions` 或 `is_matryoshka`，则无需任何覆盖。否则，你可以像下面这样使用 `--json-model-override-args`：

```bash Command
sglang serve \
    --model-path Qwen/Qwen3-Embedding-0.6B \
    --is-embedding \
    --json-model-override-args '{"matryoshka_dimensions": [128, 256, 512, 1024, 1536]}'
```

1. 设置 `"is_matryoshka": true` 允许截断到任意维度。否则，服务端会校验请求中指定的维度是否为 `matryoshka_dimensions` 之一。
2. 在请求中省略 `dimensions` 会返回完整向量。

### 2. 使用不同的输出维度发起请求

```python
import requests

url = "http://127.0.0.1:30000"

# Request a truncated (Matryoshka) embedding by specifying a supported dimension.
payload = {
    "model": "Qwen/Qwen3-Embedding-0.6B",
    "input": "Explain diffusion models simply.",
    "dimensions": 512  # change to 128 / 1024 / omit for full size
}

response = requests.post(url + "/v1/embeddings", json=payload).json()
print("Embedding:", response["data"][0]["embedding"])
```
