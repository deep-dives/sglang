本文档说明如何在 SGLang 中添加对新的语言模型和多模态大语言模型（MLLM）的支持，并介绍如何测试新模型以及注册外部实现。

## 如何支持新的语言模型

要在 SGLang 中支持一个新模型，你只需在 [SGLang 模型目录](https://github.com/sgl-project/sglang/tree/main/python/sglang/srt/models) 下添加一个文件。你可以参考现有的模型实现，为你的模型创建新文件。对大多数模型来说，你都能找到一个相近的模型作为起点（例如从 Llama 开始）。另外请参考如何[将模型从 vLLM 移植到 SGLang](#port-a-model-from-vllm-to-sglang)。

<Note>
💡 AI Infra 学习笔记：推理引擎对"模型支持"的抽象通常很薄——引擎的调度、显存、kernel 都与具体模型无关，模型层只需要实现标准的前向接口。SGLang 把这一点做到了极致：加一个新模型只需在模型目录下放一个文件，实现前向并挂到注册表即可。理解这个分层（引擎 ↔ 模型层）是读推理引擎源码的起点；面试被问"如何给引擎加新模型"，本质就是在考察你对这条抽象边界的理解。
</Note>

## 如何支持新的多模态大语言模型

要在 SGLang 中支持一个新的多模态大语言模型（MLLM），除了标准的 LLM 支持外，还有几个关键组件：

1. **把新模型注册为多模态**：扩展 [model_config.py](https://github.com/sgl-project/sglang/blob/0ab3f437aba729b348a683ab32b35b214456efc7/python/sglang/srt/configs/model_config.py#L561) 中的 `is_multimodal_model`，让它在你的模型上返回 `True`。

2. **注册新的对话模板**：仅当你的默认对话模板无法接受图像输入时才需要：在 [conversation.py](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/parser/conversation.py) 中注册新的对话模板及对应的匹配函数。

3. **多模态数据处理**：定义一个新的 `Processor` 类，继承自 `BaseMultimodalProcessor`，并把该 processor 注册为模型专用的 processor。详见 [multimodal_processor.py](https://github.com/sgl-project/sglang/tree/main/python/sglang/srt/multimodal/processors)。

4. **处理多模态 token**：为你的新模型实现 `pad_input_ids` 函数。在该函数中，提示词中的多模态 token 应被展开（如有必要），并填充多模态数据哈希值，以便 SGLang 能通过 `RadixAttention` 识别不同的多模态数据。

5. **处理图像特征提取**：为你的新模型实现 `get_image_feature` 函数，从原始图像数据中提取图像特征，并转换为语言模型使用的嵌入。

6. **适配视觉注意力**：把 ViT 的多头 `Attention` 适配为 SGLang 的 `VisionAttention`。

你可以参考 [Qwen2VL](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/models/qwen2_vl.py) 或其他 MLLM 实现。这些模型展示了如何正确处理多模态与文本输入。

## 测试与调试

请把你所有的测试与基准测试结果都记录在 PR 描述中。

### 交互式调试

进行交互式调试时，对比 Hugging Face/Transformers 与 SGLang 的输出。以下两条命令应给出相同的文本输出与非常相似的预填充 logits：

- 获取参考输出：
  ```bash Command
  python3 scripts/playground/reference_hf.py --model-path [new model] --model-type {text,vlm}
  ```
- 获取 SGLang 输出：
  ```bash Command
  python3 -m sglang.bench_one_batch --correct --model [new model]
  ```

### 把模型加入测试套件

为确保新模型得到良好维护，请把它加入测试套件，即 [test_generation_models.py](https://github.com/sgl-project/sglang/blob/main/test/registered/models/test_generation_models.py) 文件中的 `ALL_OTHER_MODELS` 列表，在本地机器上测试新模型，并在 PR 中报告代表性基准（GSM8K、MMLU、MMMU、MMMU-Pro 等）的结果。\
对于 VLM，还需要在 `test_vision_openai_server_&#123;x&#125;.py`（例如 [test_vision_openai_server_a.py](https://github.com/sgl-project/sglang/blob/main/test/registered/vlm/test_vision_openai_server_a.py)）中加入一个测试。

下面是在本地机器上测试新模型的示例命令：

```bash Run Test
ONLY_RUN=Qwen/Qwen2-1.5B python3 -m unittest test_generation_models.TestGenerationModels.test_others
```

### 基准测试

- **（必做）MMMU**：按照 MMMU 基准测试 [README.md](https://github.com/sgl-project/sglang/blob/main/benchmark/mmmu/README.md) 获取 SGLang 与 HF Transformer 的精度对比。SGLang 运行的精度分数不应明显低于 HF Transformer 运行。同样，请按照 https://docs.sglang.io/developer_guide/benchmark_and_profiling.html 获取性能对比：TTFT 与吞吐量必须达到或超过基线（例如 HF Transformer）。
- **（可选）其他评测**：如果你运行了其他评测，请在 PR 描述中注明结果。

## 将模型从 vLLM 移植到 SGLang {#port-a-model-from-vllm-to-sglang}

[vLLM 模型目录](https://github.com/vllm-project/vllm/tree/main/vllm/model_executor/models) 是非常有价值的资源，因为 vLLM 覆盖了大量模型。SGLang 复用了 vLLM 的接口和部分层，因此从 vLLM 移植模型到 SGLang 相对容易。

要从 vLLM 移植模型到 SGLang：

- 对比以下两个文件作为参考：
  - [SGLang Llama 实现](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/models/llama.py)
  - [vLLM Llama 实现](https://github.com/vllm-project/vllm/blob/main/vllm/model_executor/models/llama.py)
- 主要差异包括：
  - **把 vLLM 的 `Attention` 替换为 `RadixAttention`**（务必把 `layer_id` 传给 `RadixAttention`）。
  - **把 vLLM 的 `LogitsProcessor` 替换为 SGLang 的 `LogitsProcessor`。**
  - **把 ViT 的多头 `Attention` 替换为 SGLang 的 `VisionAttention`。**
  - **把其他 vLLM 层**（如 `RMSNorm`、`SiluAndMul`）替换为 SGLang 的对应层。
  - **移除 `Sample`。**
  - **修改 `forward()` 函数**并新增 `forward_batch()` 方法。
  - **在文件末尾添加 `EntryClass`。**
  - **确保新实现只使用 SGLang 组件**，不依赖任何 vLLM 组件。

<Note>
💡 AI Infra 学习笔记：移植清单的核心是"把 `Attention` 换成 `RadixAttention`"。RadixAttention 是 SGLang 性能的核心：它把前缀缓存（Radix cache）直接接进注意力层，让多个请求共享相同前缀时能复用已有的 KV 缓存，大幅减少重复预填充的开销。这也是 SGLang 要求每个新模型必须通过 RadixAttention 接入、并显式传入 `layer_id` 的原因。理解"缓存如何进入模型层"，是把握 SGLang 相比朴素实现吞吐优势的关键。
</Note>

注意：请把新模型添加到 supported models 文档中的支持模型列表里。

## 注册外部模型实现

除了上述方法，你还可以在启动服务端前用 `ModelRegistry` 注册你的新模型。这样无需修改源码即可集成你的模型。

例如：

```python Register Model
from sglang.srt.models.registry import ModelRegistry
from sglang.srt.entrypoints.http_server import launch_server

# For a single model, add it to the registry:
ModelRegistry.models[model_name] = model_class

# For multiple models, you can imitate the import_model_classes() function:
from functools import lru_cache

@lru_cache()
def import_new_model_classes():
    model_arch_name_to_cls = {}
    # Populate model_arch_name_to_cls with your new model classes.
    ...
    return model_arch_name_to_cls

ModelRegistry.models.update(import_new_model_classes())

# Launch the server with your server arguments:
launch_server(server_args)
```

## 示例：实现并服务一个 Llama 包装模型

下面是一份入门级的分步教程，讲解如何在 SGLang 中端到端实现一个新模型，并通过 [Offline Engine](../basic_usage/offline_engine_api) 运行它。

### 实现我们的模型

为了简单起见，这个新模型将是 [Llama 3.1-8B-Instruct](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct) 的简单包装器，我们的目标只是在每次 `forward` 调用中，对每个 logit 取平方根，从而对输出 logits 施加偏置。

我们先在名为 `llama_wrapper.py` 的文件中定义模型。
第一步是从 SRT 导入所需库，SRT 是 SGLang 的内部后端。

```python Example
# In the file `llama_wrapper.py`

import torch
from transformers import LlamaConfig
from typing import Optional
from sglang.srt.layers.logits_processor import LogitsProcessorOutput
from sglang.srt.layers.quantization.base_config import QuantizationConfig
from sglang.srt.model_executor.forward_batch_info import ForwardBatch, PPProxyTensors

from sglang.srt.models.llama import LlamaForCausalLM
```

接下来，我们为模型声明一个新的 `class`，并让它继承 `LlamaForCausalLM`，这样我们的模型就能访问 `LlamaForCausalLM` 预定义的模块和层，例如 `LlamaAttention` 与 `LlamaMLP`。
请注意，几乎所有的模型实现都在 `__init__` 方法中接收 `config` 与 `quant_config` 两个参数；`config` 和 `quant_config` 通过 [`model_loader/loader.py`](https://github.com/sgl-project/sglang/blob/bf72b80122fd888bf619d17b96fa3e323ab809fc/python/sglang/srt/model_loader/loader.py#L219) 传入。
由于我们继承了 `LlamaForCausalLM`，可以直接把参数传给它的构造函数，由它来设置成员变量。

```python Class Definition
class LlamaWrapper(LlamaForCausalLM):
    def __init__(
        self,
        config: LlamaConfig,
        quant_config: Optional[QuantizationConfig] = None,
        prefix: str = "",
    ) -> None:
        super().__init__(config=config, quant_config=quant_config, prefix=prefix)
```

现在，我们定义 `forward` 方法，它将在推理时被调用。
请注意，任何模型的 `forward` 签名本质上都是相同的；你可以查看 [`models` 目录](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/models/) 中定义的其他模型作为参考。
想了解 `forward` 具体在 SGLang 运行时的内部哪里被调用，请看 [`ModelRunner` 类](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/model_executor/model_runner.py) 中的 [`forward_decode`](https://github.com/sgl-project/sglang/blob/bf72b80122fd888bf619d17b96fa3e323ab809fc/python/sglang/srt/model_executor/model_runner.py#L1705) 与 [`forward_extend`](https://github.com/sgl-project/sglang/blob/bf72b80122fd888bf619d17b96fa3e323ab809fc/python/sglang/srt/model_executor/model_runner.py#L1724)。

```python Forward Method Signature
    @torch.no_grad()
    def forward(
        self,
        input_ids: torch.Tensor,
        positions: torch.Tensor,
        forward_batch: ForwardBatch,
        pp_proxy_tensors: Optional[PPProxyTensors] = None,
        input_embeds: Optional[torch.Tensor] = None,
        get_embedding: bool = False,
    ) -> LogitsProcessorOutput:
```

现在我们调用 `self.model`（`LlamaForCausalLM` 在 `__init__` 中定义的成员变量）的 `__call__` 方法，它最终会调用 `LlamaForCausalLM` 的 `forward` 方法。
之后，我们把 `hidden_states` 送入我们模型的 `LogitsProcessor`（同样定义在 `LlamaForCausalLM` 中）。

```python Call Model and LogitsProcessor
        hidden_states = self.model(
            input_ids,
            positions,
            forward_batch,
            input_embeds,
            pp_proxy_tensors=pp_proxy_tensors,
        )

        res: LogitsProcessorOutput = self.logits_processor(
            input_ids,
            hidden_states,
            self.lm_head,
            forward_batch,
        )
```

拿到下一个 token 的 logits 后，我们终于可以执行偏置步骤了。

```python Logit Biasing
        orig_logits = res.next_token_logits
        res.next_token_logits = torch.where(
            orig_logits > 0,
            orig_logits.sqrt(),
            orig_logits
        )

        return res
```

现在，我们的 `LlamaWrapper` 模型已创建完成，可以服务了！

### 通过 SGLang 的离线引擎服务我们的模型

本教程的下一步是离线托管我们的新模型，这样它就能在本地、无需 HTTP 服务端的情况下被服务。

首先创建一个名为 `run.py` 的新文件。
现在，我们必须确保 SGLang 的 `ModelRegistry` 能找到我们的模型。
为此，我们先从 Huggingface 下载模型的配置与权重。

```python Example
# In the file `run.py`

import asyncio
from functools import lru_cache
from huggingface_hub import snapshot_download
from llama_wrapper import LlamaWrapper # Make sure to import our new model!
import sglang as sgl
from sglang.srt.models.registry import ModelRegistry

# Make sure to request access to this model on Huggingface, then export your
# `HF_TOKEN` to download the model snapshot
llama_dir = snapshot_download(
    repo_id="meta-llama/Llama-3.1-8B-Instruct",
    local_dir="./llama_ckpt",
)
```

现在模型已在本地，我们希望通过修改 `./llama_ckpt/config.json` 中的 `architectures` 字段为 `LlamaWrapper`，把模型指向 `LlamaWrapper`。
这样，当我们把模型检查点路径传给 SGLang 时，它就会知道我们想用 "LlamaWrapper" 而非 "LlamaForCausalLM" 作为模型。

```python Example
{
  "architectures": [
   #  "LlamaForCausalLM"
    "LlamaWrapper"
  ],
  ...
}
```

然而，如果我们不把 `LlamaWrapper` 类与 "LlamaWrapper" 注册关键字关联起来，SGLang 就无法找到我们的模型。
因此，要注册 `LlamaWrapper`，我们按照上面"注册外部模型实现"一节的步骤操作。

```python Register LlamaWrapper
@lru_cache()
def import_new_model_classes():
    model_arch_name_to_cls = {"LlamaWrapper": LlamaWrapper}
    return model_arch_name_to_cls

ModelRegistry.models.update(import_new_model_classes())
```

最后，创建 `Engine` 时，我们只需传入本地模型目录的路径。
然后，我们的 `LlamaWrapper` 就可以被服务了；本教程将使用 SGLang `Engine` 的非流式异步生成端点。

```python Example
def main():
    llm = sgl.Engine(model_path="./llama_ckpt")
    sampling_params = {"temperature": 0.2, "top_k": 5}
    prompts = [
        "Write a short, neutral self-introduction for a fictional character. Hello, my name is",
        "Provide a concise factual statement about France’s capital city. The capital of France is",
        "Explain possible future trends in artificial intelligence. The future of AI is",
    ]

    asyncio.run(run_llm(llm, sampling_params, prompts))

    llm.shutdown()

async def run_llm(
    llm,
    sampling_params,
    prompts,
) -> None:
    outputs = await llm.async_generate(prompts, sampling_params)

    for prompt, output in zip(prompts, outputs):
        print(f"\nPrompt: {prompt}")
        print(f"Generated text: {output['text']}")

if __name__ == "__main__":
    main()
```

现在，当我们运行 `python run.py` 时，就能得到新创建模型的输出了！

## 通过标准 CLI 服务外部模型

前面几节展示了如何通过 `ModelRegistry` 以编程方式注册模型，并通过离线引擎服务它。与 vLLM 模型插件类似，还有一种替代方案，可以让你继续使用标准的 `python -m sglang.launch_server` CLI 而无需修改任何 SGLang 源码：你可以用 `SGLANG_EXTERNAL_MODEL_PACKAGE` 环境变量注册模型。

### `EntryClass` 变量

当 SGLang 扫描模型包时，它会在 Python 文件的模块级寻找 `EntryClass` 变量。[模型注册表](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/models/registry.py) 会导入你的文件，检查 `EntryClass`，并注册赋给它的类。如果你使用的是基于 HuggingFace 的模型，该类的名称需要与模型 `config.json` 中的 `"architectures"` 字段一致。

例如，如果你实现的是一个 Llama 包装器，请在模型文件末尾添加这一行：

```python Example
# This is what "Add EntryClass at the end" means
EntryClass = LlamaWrapper
```

### 示例：纯文本模型

使用上一节中的同一个 Llama 包装器，下面介绍如何打包并通过 CLI 服务它。

1. 创建你的项目

```
sglang_custom_project/
|----setup.py
|----custom_llm/
     |----__init__.py
     |----llama_wrapper.py
```

编写 `setup.py`：

```python Example
# sglang_custom_project/setup.py

from setuptools import setup, find_packages
setup(
    name="sglang-custom-plugins",
    version="0.1",
    packages=find_packages(),
)
```

2. 编写你的模型代码

在 `llama_wrapper.py` 中编写模型并包含 `EntryClass`：

```python Example
# sglang_custom_project/custom_llm/llama_wrapper.py

import torch
from typing import Optional
from sglang.srt.layers.logits_processor import LogitsProcessorOutput
from sglang.srt.layers.quantization.base_config import QuantizationConfig
from sglang.srt.model_executor.forward_batch_info import ForwardBatch, PPProxyTensors
from sglang.srt.models.llama import LlamaForCausalLM

class LlamaWrapper(LlamaForCausalLM):
    def __init__(self, config, quant_config: Optional[QuantizationConfig] = None,
                 prefix: str = "") -> None:
        super().__init__(config=config, quant_config=quant_config, prefix=prefix)
    @torch.no_grad()
    def forward(self, input_ids, positions, forward_batch,
                pp_proxy_tensors=None, input_embeds=None, get_embedding=False):
        hidden_states = self.model(
            input_ids, positions, forward_batch, input_embeds,
            pp_proxy_tensors=pp_proxy_tensors,
        )
        res: LogitsProcessorOutput = self.logits_processor(
            input_ids, hidden_states, self.lm_head, forward_batch,
        )

        orig = res.next_token_logits
        res.next_token_logits = torch.where(orig > 0, orig.sqrt(), orig)
        return res

# Don't forget to add EntryClass
EntryClass = LlamaWrapper
```

3. 安装你的包

在 `sglang_custom_project` 目录内运行以下命令，把你的代码安装到当前 Python 环境：

```bash Command
pip install -e .
```

4. 更新你的 `config.json`

更新 HuggingFace 模型检查点目录下的 `config.json`，让 `architectures` 字段与你的类名一致：

```json Config
{
  "architectures": ["LlamaWrapper"],
  ...
}
```

5. 启动服务端

在运行 CLI 前设置环境变量：

```bash Command
export SGLANG_EXTERNAL_MODEL_PACKAGE=custom_llm
python -m sglang.launch_server \
    --model-path /path/to/Llama-3.1-8B-Instruct \
    --port 8000
```

`SGLANG_EXTERNAL_MODEL_PACKAGE` 应为包含模型相关代码的父文件夹名。在本例中应为 `custom_llm`。

### 示例：多模态模型

如果你处理的是多模态模型，仅设置 `SGLANG_EXTERNAL_MODEL_PACKAGE` 是不够的。SGLang 还需要把你的架构识别为多模态，以启用图像/视频处理流水线，并且需要一个自定义 processor。

你可以通过再设置两个环境变量来处理：

- `SGLANG_EXTERNAL_MM_MODEL_ARCH`：把你的架构名称加入 SGLang 内部的多模态模型列表。
- `SGLANG_EXTERNAL_MM_PROCESSOR_PACKAGE`：告诉 SGLang 到哪里找你的自定义 processor 类。

例如，让我们构建一个基于 Qwen2-VL-Instruct、对 logits 取平方根的自定义模型。

创建项目：

```
sglang_custom_project_vl/
|----setup.py
|----custom_vlm/
     |----__init__.py
     |----qwenvl_wrapper.py
```

编写 `setup.py`：

```python Example
# sglang_custom_project_vl/setup.py

from setuptools import setup, find_packages
setup(
    name="sglang-custom-plugins-vl",
    version="0.1",
    packages=find_packages(),
)
```

在 `qwenvl_wrapper.py` 中编写模型：

```python Example
# sglang_custom_project_vl/custom_vlm/qwenvl_wrapper.py
import torch
from sglang.srt.models.qwen2_vl import Qwen2VLForConditionalGeneration
from sglang.srt.multimodal.processors.qwen_vl import QwenVLImageProcessor

class CustomQwen2VL(Qwen2VLForConditionalGeneration):
    def forward(self, input_ids, positions, forward_batch,
                input_embeds=None, get_embedding=False):
        res = super().forward(
            input_ids, positions, forward_batch,
            input_embeds=input_embeds, get_embedding=get_embedding
        )
        if not get_embedding:
            orig = res.next_token_logits
            res.next_token_logits = torch.where(orig > 0, orig.sqrt(), orig)
        return res

class CustomQwen2VLProcessor(QwenVLImageProcessor):
    models = [CustomQwen2VL]

    def __init__(self, hf_config, server_args, _processor, *args, **kwargs):
        super().__init__(hf_config, server_args, _processor, *args, **kwargs)

EntryClass = CustomQwen2VL
```

**注意：** 只要把 processor 与具体模型类关联起来，就不需要为自定义 processor 单独设置 `EntryClass`。
