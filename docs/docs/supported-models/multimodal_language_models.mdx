这些模型接受多模态输入（如图像和文本）并生成文本输出。它们通过多模态编码器增强语言模型的能力。

## 示例启动命令

```bash Launch Server
python3 -m sglang.launch_server \
  --model-path meta-llama/Llama-3.2-11B-Vision-Instruct \  # example HF/local path
  --host 0.0.0.0 \
  --port 30000 \
```

> 如何发送多模态请求，请参阅 [OpenAI APIs 部分](../basic_usage/openai_api_vision)。

## 支持的模型

下表汇总了支持的模型。

如果你不确定某个特定架构是否已实现，可以通过 GitHub 搜索。例如，要搜索 `Qwen2_5_VLForConditionalGeneration`，请在 GitHub 搜索栏中使用以下表达式：

```text GitHub Search
repo:sgl-project/sglang path:/^python\/sglang\/srt\/models\// Qwen2_5_VLForConditionalGeneration
```

## 视频输入支持

SGLang 支持视觉语言模型（VLM）的视频输入，可完成视频问答、视频描述和整体场景理解等时序推理任务。视频片段会被解码、采样关键帧，并将生成的张量与文本提示词一起组成批次，使多模态推理能够融合视觉与语言上下文。

<Note>
💡 AI Infra 学习笔记：视频输入是显存的"放大镜"——1 秒视频按若干 FPS 采样成多帧，每帧再切成大量 patch 编码成 token，token 数轻松比纯文本多几个数量级，预填充计算量与 KV 缓存占用都会暴涨。SGLang 在视频支持上做了两件事来控制成本：一是按模型的训练设置做帧采样（如 2 FPS、最多 128 帧），二是像 EVS 这样在推理前从视频嵌入中剪掉冗余 token（默认剪掉 70%）。这也是为什么多模态场景里"怎么把视觉 token 数量降下来"常常比"模型本身"更影响性能。
</Note>

## 使用说明

### 性能优化

对于多模态模型，你可以使用 `--keep-mm-feature-on-device` 参数，以增加 GPU 内存占用为代价优化延迟：

- **默认行为**：多模态特征张量在处理后被移到 CPU 以节省 GPU 内存
- **使用 `--keep-mm-feature-on-device`**：特征张量保留在 GPU 上，减少设备到主机的拷贝开销并改善延迟，但会占用更多 GPU 内存

当你 GPU 内存充足且希望将多模态推理延迟降到最低时，可以使用此参数。

### 多模态输入限制

- **使用 `--mm-process-config '&#123;"image":&#123;"max_pixels":1048576&#125;,"video":&#123;"fps":3,"max_pixels":602112,"max_frames":60&#125;&#125;'`**：设置 `image`、`video` 和 `audio` 的输入限制。

这可以减少 GPU 内存占用、提高推理速度并帮助避免 OOM，但可能影响模型性能，因此请根据具体使用场景设置合适的值。配置项会作为 `images_kwargs`、`videos_kwargs` 和 `audio_kwargs` 传给 HuggingFace processor，因此每种模态的设置相互独立、不会冲突。关于模型 processor 的可用参数，请参考 HuggingFace 文档。

### 多模态模型服务中的双向注意力
**服务 Gemma-3 多模态模型的注意事项**：

正如 [Welcome Gemma 3: Google's all new multimodal, multilingual, long context open LLM
](https://huggingface.co/blog/gemma3#multimodality) 中所提到的，Gemma-3 在预填充阶段对图像 token 之间使用双向注意力。目前，SGLang 仅在使用 Triton Attention 后端时支持双向注意力。但请注意，SGLang 当前的双向注意力实现与 CUDA 图和分块预填充均不兼容。

<Note>
💡 AI Infra 学习笔记：这里体现了一个典型的工程取舍：Gemma-3 的图像 token 之间需要双向注意力（让图像内部彼此"看到"，而非严格的下三角掩码），但通用的 FlashAttention/分页注意力实现为了性能默认只支持因果掩码。SGLang 选择只在 Triton 后端支持双向注意力，代价是不能同时开启 CUDA 图与分块预填充——这两者恰恰是吞吐优化的关键。理解"某模型的特殊计算模式会锁死哪些优化开关"，是评估推理引擎对某模型支持成熟度的重要视角。
</Note>

要启用双向注意力，你可以使用 `TritonAttnBackend`，同时禁用 CUDA 图和分块预填充。示例启动命令：
```bash Bidirectional Attention
python -m sglang.launch_server \
  --model-path google/gemma-3-4b-it \
  --host 0.0.0.0 --port 30000 \
  --enable-multimodal \
  --dtype bfloat16 --triton-attention-reduce-in-fp32 \
  --attention-backend triton \ # Use Triton attention backend
  --disable-cuda-graph \ # Disable Cuda Graph
  --chunked-prefill-size -1 # Disable Chunked Prefill
```

如果对服务性能有更高要求，且能接受一定程度的精度损失，你可以选择使用其他注意力后端，也可以启用 CUDA 图和分块预填充等功能以获得更好的性能，但请注意此时模型将回退为使用因果注意力而非双向注意力。
