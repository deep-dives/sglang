## 关于 AI 辅助（"Vibe Coding"）PR

欢迎 Vibe Coding 产出的 PR——我们看的是代码质量，而不是它怎么来的。所有 PR 的标准一致：

- **不要过度注释。** 如果名字已经把意思说清楚了，就不要写 docstring。
- **不要过度捕获异常。** 不要为实际几乎不会发生的错误加防护。
- **提交前先测试。** AI 生成的代码可能隐藏微妙错误——务必端到端验证正确性。

## 提交信息规范

我们采用结构化的提交信息格式，以保持历史记录整洁。

**格式：**
```text
[diffusion] <scope>: <subject>
```

**示例：**
- `[diffusion] cli: add --perf-dump-path argument`
- `[diffusion] scheduler: fix deadlock in batch processing`
- `[diffusion] model: support Stable Diffusion 3.5`

**规则：**
- **前缀**：一律以 `[diffusion]` 开头。
- **作用域**（可选）：`cli`、`scheduler`、`model`、`pipeline`、`docs` 等。
- **主题**：用祈使句，简短清晰（例如 "add feature"，而不是 "added feature"）。

## 性能报告

对于会影响 **延迟**、**吞吐量** 或 **内存占用** 的 PR，你**应该**提供一份性能对比报告。

### 如何生成报告

1.  **基线**：运行基准测试（针对单个生成任务）
    ```bash
    $ sglang generate --model-path <model> --prompt "A benchmark prompt" --perf-dump-path baseline.json
    ```

2.  **新实现**：运行同样的基准测试，不改动任何 server_args 或 sampling_params
    ```bash
    $ sglang generate --model-path <model> --prompt "A benchmark prompt" --perf-dump-path new.json
    ```

3.  **对比**：运行对比脚本，它会向控制台输出一张 Markdown 表格
    ```bash
    $ python python/sglang/multimodal_gen/benchmarks/compare_perf.py baseline.json new.json [new2.json ...]
    ### Performance Comparison Report
    ...
    ```
4. **粘贴**：把表格粘贴到 PR 描述里

## 基于 CI 的变更保护

可以考虑往 `pr-test` 或 `nightly-test` 测试套件里加测试来保护你的改动，尤其是当 PR：

- 支持了新模型
    - 在 `testcase_configs.py` 中为这个新模型添加测试用例
- 支持或修复了重要功能
- 显著提升了性能

请运行对应的测试用例，然后按控制台提示（如有）更新或新增 `perf_baselines.json` 中的基线。

示例参见 [test](https://github.com/sgl-project/sglang/tree/main/python/sglang/multimodal_gen/test)
