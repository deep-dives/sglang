本指南介绍如何在 SGLang 中对多模态生成流水线做性能剖析。

## PyTorch Profiler

PyTorch Profiler 提供详细的 kernel 执行时间、调用栈和 GPU 利用率指标。

### 去噪阶段剖析

用采样时间步对去噪阶段做剖析（默认：1 步预热后剖析 5 步）：

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --prompt "A Logo With Bold Large Text: SGL Diffusion" \
  --seed 0 \
  --profile
```

**参数：**
- `--profile`：启用对去噪阶段的剖析
- `--num-profiled-timesteps N`：预热后要剖析的时间步数量（默认：5）
  - 更小的值会减小 trace 文件体积
  - 示例：`--num-profiled-timesteps 10` 表示预热 1 步后剖析 10 步

### 全流水线剖析

剖析所有流水线阶段（文本编码、去噪、VAE 解码等）：

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --prompt "A Logo With Bold Large Text: SGL Diffusion" \
  --seed 0 \
  --profile \
  --profile-all-stages
```

**参数：**
- `--profile-all-stages`：与 `--profile` 一起使用，剖析所有流水线阶段而非仅去噪阶段

### 输出位置

默认情况下，trace 文件保存在 ./logs/ 目录。

确切的输出文件路径会显示在控制台输出中，例如：

```bash
[mm-dd hh:mm:ss] Saved profiler traces to: /sgl-workspace/sglang/logs/mocked_fake_id_for_offline_generate-5_steps-global-rank0.trace.json.gz
```

### 查看 Trace

在以下地址加载并可视化 trace 文件：
- https://ui.perfetto.dev/（推荐）
- chrome://tracing（仅 Chrome）

对于较大的 trace 文件，可以减小 `--num-profiled-timesteps`，或避免使用 `--profile-all-stages`。


### `--perf-dump-path`（阶段/步骤耗时转储）

除了 profiler trace，你还可以导出一份轻量 JSON 报告，其中包含：
- 整个流水线的阶段级耗时分解
- 去噪阶段的步骤级耗时分解（每个扩散步骤）

这在快速定位「哪个阶段主导了端到端延迟」以及「去噪步骤的耗时是否均匀（如果否，哪一步出现了异常尖峰）」时很有用。

导出的 JSON 包含一个 `denoise_steps_ms` 字段，其格式为对象数组，每个对象带 `step` 键（步骤索引）和 `duration_ms` 键。

示例：

```bash
sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --prompt "<PROMPT>" \
  --perf-dump-path perf.json
```

## Nsight Systems

Nsight Systems 提供底层的 CUDA 剖析能力，包括 kernel 细节、寄存器使用情况和内存访问模式。

### 安装

安装说明参见 [SGLang 性能剖析指南](../developer_guide/benchmark_and_profiling#profile-with-nsight)。

### 基础剖析

剖析整个流水线的执行：

```bash
nsys profile \
  --trace-fork-before-exec=true \
  --cuda-graph-trace=node \
  --force-overwrite=true \
  -o QwenImage \
  sglang generate \
    --model-path Qwen/Qwen-Image \
    --prompt "A Logo With Bold Large Text: SGL Diffusion" \
    --seed 0
```

### 定向阶段剖析

用 `--delay` 和 `--duration` 捕获特定阶段并减小文件体积：

```bash
nsys profile \
  --trace-fork-before-exec=true \
  --cuda-graph-trace=node \
  --force-overwrite=true \
  --delay 10 \
  --duration 30 \
  -o QwenImage_denoising \
  sglang generate \
    --model-path Qwen/Qwen-Image \
    --prompt "A Logo With Bold Large Text: SGL Diffusion" \
    --seed 0
```

**参数：**
- `--delay N`：开始捕获前等待 N 秒（跳过初始化开销）
- `--duration N`：捕获 N 秒（聚焦特定阶段）
- `--force-overwrite`：覆盖已有的输出文件

## 注意事项

- **减小 trace 体积**：使用更小的 `--num-profiled-timesteps`，或对 Nsight Systems 使用 `--delay`/`--duration`
- **按阶段分析**：只用 `--profile` 剖析去噪阶段，加 `--profile-all-stages` 剖析完整流水线
- **多次运行**：用不同的提示词和分辨率做剖析，以识别跨工作负载的瓶颈

## FAQ

- 如果用 Nsight Systems 剖析 `sglang generate` 时发现生成的 profiler 文件没有捕获到任何 CUDA kernel，可以通过增加模型的推理步数来延长执行时间，从而解决这个问题。
