把本页作为 SGLang Diffusion 性能优化的起点。它把性能优化手段分成两大类决策：

- **保持输出 / 无损型：** 系统级设置，在改变驻留方式、并行、kernel 或调度的同时，应当保持模型行为不变。
- **质量权衡 / 有损或近似型：** 可能改变去噪路径、数值表示或生成输出的技术。

文档用"保持输出"而不是承诺逐位精确的"无损"，是因为不同的 kernel、GPU 类型或精度路径仍可能带来细微数值差异。判断边界在于：这个优化是否刻意用质量或输出等价性换取速度。

## 从这里开始

1. 从 [部署与性能模式](./deployment_cookbook) 中选择一种服务化或生成模式。`--performance-mode auto` 是默认值；当模型能装进 GPU 内存且延迟最要紧时用 `speed`，当 GPU 内存成为瓶颈时用 `memory`，当每个性能参数都要显式指定时用 `manual`。
2. 从 [Attention 后端](./attention_backends) 中选择合适的注意力后端。
3. 只有当模型与视频形状确实受益于序列切分时才使用 [序列并行](./ring_sp_performance)。
4. 服务化过程中，对并发的兼容请求使用 [推理批处理](./dynamic_batching)。
5. 在同时改动多个优化手段之前，先使用 [性能剖析](./profiling)。

<Note>
💡 AI Infra 学习笔记：性能优化手段可以粗分为"不改输出的系统优化"与"以输出换速度的近似优化"两类。生产调优的稳妥路径是：先建立基线 → 用无损手段（并行、kernel、批处理）压榨性能 → 只有在基线固定、且你有一套质量验收标准之后，才引入 Cache-DiT/TeaCache、渐进式分辨率、量化这类有损手段。这能避免"性能上去了，但没人知道输出变了多少"的尴尬。
</Note>

## 实操顺序

1. 用目标模型、分辨率、帧数、步数与 GPU 类型建立基线。
2. 选择 `--performance-mode` 以及显式的驻留或并行参数。
3. 针对部署形态调优 Attention 后端与批处理。
4. 瓶颈不清晰时先做性能剖析。
5. 只有在将输出质量与你的验收目标对比之后，再添加缓存、渐进式分辨率或量化。

## 诊断

[性能剖析](./profiling) 本身不是优化技术。它属于性能工作流，是因为它能在你改动多个优化手段之前，告诉你哪个阶段、哪个 kernel 或哪一步去噪值得优化。
