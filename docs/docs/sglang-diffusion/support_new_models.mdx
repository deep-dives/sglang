title: "支持新的扩散模型"
description: "一份把扩散模型家族接入 SGLang-Diffusion 的简明实现指南。"
---

把本指南当作一个分诊流程：找到能支持某个模型的最小改动。尽管运行时被拆成了不同文件夹，大多数新模型的工作只应触及一小批文件。

## 按这个顺序阅读代码

文件按运行时职责划分。对一个新模型，先读请求路径：

1. `registry.py` 选择模型家族、采样参数和流水线配置。
2. `configs/pipeline_configs/{model}.py` 定义模型专属的去噪和解码行为。
3. `runtime/pipelines/{model}.py` 把模块接入各阶段。
4. `runtime/pipelines_core/stages/` 运行共享的阶段逻辑。
5. 只有架构无法复用时，`runtime/models/` 才包含原生模型组件。

这就是依赖方向。避免做一个让读者不得不在文件夹之间按不同顺序跳来跳去的模型 PR。

`runtime/models/` 拥有建模代码：检查点定义的神经模块、架构封装、以及某个模型家族特有的权重加载或前向路径细节。可复用的服务化基础设施应放在 SGLang-Diffusion 运行时文件夹中，如 `runtime/cache/`、`runtime/distributed/`、`runtime/utils/` 或共享的流水线阶段。这包括缓存管理器、图运行器、进程组传输、请求工具和通用 action-policy 辅助。模型包可以调用这些辅助。除非代码真的是架构专属的，否则把所有权留在共享运行时文件夹里。

## 从最小改动开始

在添加文件之前，先判断哪种路径适合这个模型。

| 情况 | 该做什么 |
| --- | --- |
| 新检查点属于已有原生家族 | 添加 Hugging Face 路径，必要时加一个小的 `SamplingParams` 或 `PipelineConfig` 变体。复用现有流水线和模块。 |
| 模型有新的原生 DiT/UNet 架构 | 添加原生 SGLang 流水线和缺失的模型组件。除非实测行为需要模型专属逻辑，否则把去噪和解码留在共享阶段上。 |
| 模型属于长尾、或你只需要先兼容 | 先兼容支持优先用 Diffusers 后端。如果后续性能或部署需求证明有必要，再加原生支持。 |

不要只是为了镜像 Diffusers 仓库的目录结构就新增文件夹。只有当现有流水线、阶段、模块、配置或采样器无法清晰表达该行为时，才添加新文件。

## 最小文件映射

源码树按运行时职责划分。这种划分对优化很有用。让新模型 PR 只聚焦于模型行为所需的文件。

| 区域 | 何时添加或修改 | 典型文件 |
| --- | --- | --- |
| 注册表 | 总是，除非是在扩展已注册的家族 | `python/sglang/multimodal_gen/registry.py` |
| 运行时参数 | 请求 schema 与现有模型不同 | `configs/sample/{model}.py` |
| 流水线配置 | 去噪、解码、精度、位置编码或 CFG 钩子不同 | `configs/pipeline_configs/{model}.py` |
| 流水线接线 | 模型需要新的阶段布局或模块列表 | `runtime/pipelines/{model}.py` |
| DiT/UNet 模块 | 去噪网络是全新的 | `runtime/models/dits/{model}.py` |
| dVLA 或 policy 模块 | 检查点定义了新的 action-policy 架构 | `runtime/models/{family}/modeling_*.py` 或任务专属的模型子文件夹 |
| 共享运行时基础设施 | 缓存、CUDA 图、分布式传输、请求工具或 action-policy 辅助可被未来模型复用 | `runtime/cache/`、`runtime/distributed/`、`runtime/utils/`、`runtime/pipelines_core/stages/` |
| 模型组件配置 | 模型组件有静态架构配置 | `configs/models/dits/{model}.py`、`configs/models/vaes/{model}.py` |
| 模型专属阶段 | 某个阶段的运行时语义无法用原生阶段或它的窄子类表达 | `runtime/pipelines_core/stages/model_specific_stages/{model}.py` |
| 编码器、VAE、调度器 | 现有实现都不可复用 | `runtime/models/encoders/`、`runtime/models/vaes/`、`runtime/models/schedulers/` |

对一个新原生架构，常见的最小集是：

1. `registry.py`
2. `configs/sample/{model}.py`
3. `configs/pipeline_configs/{model}.py`
4. `runtime/pipelines/{model}.py`
5. `runtime/models/dits/{model}.py`

每个额外的文件都应该对应到现有代码无法清晰表达的行为。

对 dVLA 或其它非图像扩散策略，保持相同的所有权规则。策略网络、VLM/action 专家模块、检查点映射和模型专属前向代码属于 `runtime/models/`。前缀缓存、请求局部上下文、去噪图运行器、OpenPI 兼容传输、前缀/action 进程组工具，只要它们对第一个模型之外也有用，就应是共享的 SGLang-Diffusion 运行时基础设施。

<Note>
💡 AI Infra 学习笔记：为什么把扩散流水线拆成"编码→潜空间准备→去噪→解码"这些标准阶段？因为性能优化都是按阶段生效的——CPU 卸载可以只针对大编码器/VAE 组件、CUDA 图捕获可以只针对循环去噪的 DiT、分离部署按编码器/去噪器/解码器拆分、profiling 按阶段计时。如果一个新模型把所有逻辑塞进一个自定义阶段，就等于绕开了这些共享钩子，后续每项优化都要为它单独实现一遍。这也是"先复用原生阶段、再窄子类、最后才自定义"这条优先级排序的底层原因。
</Note>

## 先读参考实现

把模型的 Diffusers 流水线、官方实现或 `model_index.json` 当作权威来源。记下：

- 必须加载哪些模块：分词器、文本编码器、图像编码器、transformer、调度器、VAE、processor，以及任何额外适配器。
- 提示词和图像编码流程。
- 潜空间形状、打包、缩放、偏移、dtype 和设备规则。
- timestep 与 sigma 调度。
- 去噪网络期望的精确 `forward()` kwargs。
- VAE 解码规则和输出后处理。

如果新模型接近 Flux、Qwen-Image、GLM-Image、Wan、HunyuanVideo 或 LTX，先从扩展那个实现开始，而不是从空文件起步。

## 选择流水线形态

SGLang-Diffusion 用 `ComposedPipelineBase` 把阶段接线在一起。大多数原生流水线应选择保留运行时语义的侵入性最小的阶段形态。

| 形态 | 何时使用 | 布局 |
| --- | --- | --- |
| 原生阶段 | 文本/图像编码、潜空间准备、timestep 准备、去噪、解码与现有辅助一致 | `add_standard_t2i_stages()`、`add_standard_ti2i_stages()` 或类似辅助 |
| 原生阶段子类 | 某个阶段有模型专属细节，但阶段边界和 batch 契约仍与现有原生阶段一致 | `{Model}TextEncodingStage(TextEncodingStage) -> LatentPreparationStage -> TimestepPreparationStage -> DenoisingStage -> DecodingStage` |
| 自定义单一用途阶段 | 某一步的状态持有者或 batch 字段生命周期不同，无法干净地继承原生阶段 | 原生阶段中插入或替换一个 `{Model}{Purpose}Stage` |
| 聚合自定义阶段 | 参考流水线中几个准备步骤密不可分，拆分会产生脆弱的重复状态 | `{Model}BeforeDenoisingStage -> DenoisingStage -> DecodingStage` |

优先按这个顺序：

1. **直接使用原生阶段。** 这能让模型留在共享代码路径上，获得卸载、组件就绪、性能剖析、分离部署、批处理以及未来的阶段级优化。
2. **子类化最窄的原生阶段。** 如果只有提示词处理不同，继承 `TextEncodingStage`。如果只有潜空间设置、timestep 设置、去噪或解码不同，继承对应的那个原生阶段。尽可能保留现有的输入/输出字段。
3. **只有当没有原生阶段契约匹配时，才添加自定义单一用途阶段。** 保持阶段持有者职责单一：一个阶段只做一件连贯的变换，比如自定义条件组装步骤或模型专属的 policy/action 桥接。
4. **只在万不得已时使用聚合的 `BeforeDenoisingStage`。** 这是最不推荐的形态，因为它把多个运行时职责藏在一个阶段里，增加代码量和审查成本，并且绕过了卸载、性能剖析、分离部署、批处理以及未来阶段级优化的共享钩子。

## 实现各个部分

### 1. 采样参数

只为用户运行时能设置的值创建请求参数。

```python
# python/sglang/multimodal_gen/configs/sample/my_model.py
from dataclasses import dataclass

from sglang.multimodal_gen.configs.sample.sampling_params import ImageSamplingParams


@dataclass
class MyModelSamplingParams(ImageSamplingParams):
    guidance_scale: float = 4.0
    num_inference_steps: int = 28
```

### 2. 流水线配置

`PipelineConfig` 是共享的去噪和解码阶段获取模型专属回调的地方。

```python
# python/sglang/multimodal_gen/configs/pipeline_configs/my_model.py
from dataclasses import dataclass, field


@dataclass
class MyModelPipelineConfig(ImagePipelineConfig):
    task_type: ModelTaskType = ModelTaskType.T2I
    should_use_guidance: bool = True
    dit_config: DiTConfig = field(default_factory=MyModelDiTConfig)
    vae_config: VAEConfig = field(default_factory=MyModelVAEConfig)

    def prepare_pos_cond_kwargs(self, batch, latent_model_input, t, **kwargs):
        return {
            "hidden_states": latent_model_input,
            "encoder_hidden_states": batch.prompt_embeds[0],
            "timestep": t,
        }

    def prepare_neg_cond_kwargs(self, batch, latent_model_input, t, **kwargs):
        return {
            "hidden_states": latent_model_input,
            "encoder_hidden_states": batch.negative_prompt_embeds[0],
            "timestep": t,
        }
```

让这些 kwargs 与去噪模块的 `forward()` 签名完全一致。

### 3. 流水线接线

当模型符合标准辅助时，使用它。

```python
# python/sglang/multimodal_gen/runtime/pipelines/my_model.py
class MyModelPipeline(LoRAPipeline, ComposedPipelineBase):
    pipeline_name = "MyModelPipeline"

    _required_config_modules = [
        "text_encoder",
        "tokenizer",
        "transformer",
        "scheduler",
        "vae",
    ]

    def create_pipeline_stages(self, server_args: ServerArgs):
        self.add_standard_t2i_stages()


EntryClass = [MyModelPipeline]
```

当标准辅助不够用时，先检查是否只有一个原生阶段需要模型专属行为。如果是，就子类化那个阶段，其余保持标准。例如，自定义分词或提示词窗口逻辑通常应直接继承 `TextEncodingStage`。

```python
class MyModelPipeline(LoRAPipeline, ComposedPipelineBase):
    pipeline_name = "MyModelPipeline"

    _required_config_modules = [
        "text_encoder",
        "tokenizer",
        "transformer",
        "scheduler",
        "vae",
    ]

    def create_pipeline_stages(self, server_args: ServerArgs):
        self.add_stage(InputValidationStage())
        self.add_stage_factory(
            RoleType.ENCODER,
            lambda: MyModelTextEncodingStage(
                text_encoder=self.get_module("text_encoder"),
                tokenizer=self.get_module("tokenizer"),
            ),
            "my_model_text_encoding_stage",
        )
        self.add_standard_latent_preparation_stage()
        self.add_standard_timestep_preparation_stage()
        self.add_standard_denoising_stage()
        self.add_standard_decoding_stage()


EntryClass = [MyModelPipeline]
```

只有当参考流水线中有一个步骤无法用钩子或原生阶段子类干净表达时，才使用自定义单一用途阶段。保持自定义阶段职责单一，并在它前后复用原生阶段。

```python
class MyModelPipeline(LoRAPipeline, ComposedPipelineBase):
    pipeline_name = "MyModelPipeline"

    _required_config_modules = [
        "text_encoder",
        "tokenizer",
        "transformer",
        "scheduler",
        "vae",
    ]

    def create_pipeline_stages(self, server_args: ServerArgs):
        self.add_stage(InputValidationStage())
        self.add_standard_text_encoding_stage()
        self.add_stage_factory(
            RoleType.ENCODER,
            lambda: MyModelConditioningStage(
                scheduler=self.get_module("scheduler"),
                vae=self.get_module("vae"),
            ),
            "my_model_conditioning_stage",
        )
        self.add_standard_latent_preparation_stage()
        self.add_standard_timestep_preparation_stage()
        self.add_standard_denoising_stage()
        self.add_standard_decoding_stage()


EntryClass = [MyModelPipeline]
```

只有当参考流水线把几个准备步骤耦合得如此紧密、拆分会导致脆弱的重复状态或额外同步时，才使用聚合的 `BeforeDenoisingStage`。不要一开始就用这种形态。

```python
class MyModelPipeline(LoRAPipeline, ComposedPipelineBase):
    pipeline_name = "MyModelPipeline"

    _required_config_modules = [
        "text_encoder",
        "tokenizer",
        "transformer",
        "scheduler",
        "vae",
    ]

    def create_pipeline_stages(self, server_args: ServerArgs):
        self.add_stage(InputValidationStage())
        self.add_stage(
            MyModelBeforeDenoisingStage(
                text_encoder=self.get_module("text_encoder"),
                tokenizer=self.get_module("tokenizer"),
                scheduler=self.get_module("scheduler"),
                vae=self.get_module("vae"),
            )
        )
        self.add_standard_denoising_stage()
        self.add_standard_decoding_stage()


EntryClass = [MyModelPipeline]
```

### 4. 万不得已才用的去噪前阶段

`BeforeDenoisingStage` 不是原生阶段的万能替代。当模型有自定义潜空间打包、条件组装、timestep 准备或请求局部状态、而这些装不进 `LatentPreparationStage` 或 `TimestepPreparationStage` 时才使用它，并且要先用前面检查过：能否做成原生阶段子类或自定义单一用途阶段。如果差异只在提示词处理，请子类化 `TextEncodingStage`。

一个合格的 `BeforeDenoisingStage` 应该填充 `DenoisingStage` 消费的 batch 字段。

```python
class MyModelBeforeDenoisingStage(PipelineStage):
    @torch.no_grad()
    def forward(self, batch: Req, server_args: ServerArgs) -> Req:
        prompt_embeds, negative_prompt_embeds = self._encode_prompt(batch)
        latents = self._prepare_latents(batch)
        timesteps, sigmas = self._prepare_timesteps(batch)

        batch.prompt_embeds = [prompt_embeds]
        batch.negative_prompt_embeds = [negative_prompt_embeds]
        batch.latents = latents
        batch.timesteps = timesteps
        batch.num_inference_steps = len(timesteps)
        batch.sigmas = sigmas.tolist()
        batch.raw_latent_shape = latents.shape
        return batch
```

`DenoisingStage` 需要的字段：

| 字段 | 说明 |
| --- | --- |
| `batch.latents` | 初始潜张量，包括模型所需的任何打包。 |
| `batch.timesteps` | 与参考流水线完全一致顺序的 timestep 张量。 |
| `batch.sigmas` | 当调度器需要 sigma 值时，用 Python 列表。 |
| `batch.prompt_embeds` | 正条件嵌入，用列表包裹。 |
| `batch.negative_prompt_embeds` | 使用 CFG 时，用列表包裹的负条件嵌入。 |
| `batch.num_inference_steps` | 去噪迭代次数。 |
| `batch.raw_latent_shape` | 打包前的原始潜空间形状，解码需要时使用。 |

### 5. 去噪模块

只有当架构是全新的时，才在 `runtime/models/dits/` 下添加文件。尽可能复用现有的编码器、VAE、调度器、归一化层和融合 kernel。

多 GPU 服务化：先在单 GPU 路径正确后，再加 TP/SP 支持。有用的参考：

- `runtime/models/dits/wanvideo.py`：TP 加 SP。
- `runtime/models/dits/qwen_image.py`：USP 注意力。

### 6. 注册表

采样参数和流水线配置就绪后，注册这个家族。

```python
register_configs(
    model_family="my_model",
    sampling_param_cls=MyModelSamplingParams,
    pipeline_config_cls=MyModelPipelineConfig,
    hf_model_paths=["org/my-model"],
)
```

流水线文件通过它的 `EntryClass` 被发现；不要加第二个流水线注册表，除非现有注册表确实要求。

## 验证移植

使用一个确定性的提示词和种子，与参考实现对比。

1. 运行单 GPU 冒烟测试，检查输出是否包含连贯的内容。
2. 对比潜空间缩放与偏移、timestep 顺序、sigma 值以及 conditioning kwargs 是否与 Diffusers 或官方实现一致。
3. 把 VAE 解码和后处理与去噪分开验证。
4. 如果模型支持 LoRA、CFG 并行、TP、SP 或分离部署，逐个显式测试这些特性。
5. 当用户需要新的启动命令时，添加或更新文档、示例或兼容性矩阵。

常见失败点：

- 潜空间缩放或偏移错误。
- timestep 顺序颠倒或 dtype 不匹配。
- 启用 CFG 时缺少负条件嵌入。
- conditioning kwarg 名称与 DiT `forward()` 不匹配。
- 旋转嵌入的形状或风格不匹配。
- 解码打包后的潜空间时没有恢复 `raw_latent_shape`。

## PR 检查清单

- [ ] 尽可能复用了现有家族、阶段、模块、调度器或 VAE。
- [ ] 保持新模型的改动面小，并为任何额外文件给出理由。
- [ ] 需要原生支持时，添加了 `SamplingParams`、`PipelineConfig`、流水线接线、DiT 模块和注册表条目。
- [ ] 确认适用时 `pipeline_name` 与 Diffusers `model_index.json` 的 `_class_name` 一致。
- [ ] 确认 `_required_config_modules` 与模型仓库一致。
- [ ] 对照参考输出验证了图像或视频质量。
- [ ] 如果 PR 声称支持 TP、SP、CFG 并行或分布式服务化，测试了多 GPU 路径。
