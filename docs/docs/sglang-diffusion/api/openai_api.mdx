SGLang 扩散 HTTP 服务端实现了兼容 OpenAI 的 API，用于图像和视频生成，以及 LoRA 适配器管理。

## 前置条件

- 如果你想用 OpenAI Python SDK，需要 Python 3.11 及以上。

## 服务

用 `sglang serve` 命令启动服务端。

### 启动服务端

```bash
SERVER_ARGS=(
  --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers
  --text-encoder-cpu-offload
  --pin-cpu-memory
  --num-gpus 4
  --ulysses-degree=2
  --ring-degree=2
  --port 30010
)

sglang serve "${SERVER_ARGS[@]}"
```

- **--model-path**：模型路径或模型 ID。
- **--port**：HTTP 监听端口（默认：`30000`）。

**获取模型信息**

**端点：** `GET /models`

返回本服务端所服务模型的信息，包括模型路径、任务类型、流水线配置和精度设置。

**Curl 示例：**

```bash curl
curl -sS -X GET "http://localhost:30010/models"
```

**响应示例：**

```json
{
  "model_path": "Wan-AI/Wan2.1-T2V-1.3B-Diffusers",
  "task_type": "T2V",
  "pipeline_name": "wan_pipeline",
  "pipeline_class": "WanPipeline",
  "num_gpus": 4,
  "dit_precision": "bf16",
  "vae_precision": "fp16"
}
```

## 端点

### 图像生成

服务端在 `/v1/images` 命名空间下实现了兼容 OpenAI 的 Images API。

**创建一张图像**

**端点：** `POST /v1/images/generations`

#### 请求质量

`quality` 在模型公布了采样级别时选择模型自有的采样级别：`lossless` 走参考路径，`high` 走经过验证的加速路径。省略它（或传 OpenAI 默认的 `auto`）则保持运行时默认值。它与只控制输出文件压缩的 `output_quality` 不同。同一个扩展参数也适用于图像编辑和视频请求。

**Python 示例（b64_json 响应）：**

```python Python
import base64
from openai import OpenAI

client = OpenAI(api_key="sk-proj-1234567890", base_url="http://localhost:30010/v1")

img = client.images.generate(
    prompt="A calico cat playing a piano on stage",
    size="1024x1024",
    n=1,
    response_format="b64_json",
)

image_bytes = base64.b64decode(img.data[0].b64_json)
with open("output.png", "wb") as f:
    f.write(image_bytes)
```

**Curl 示例：**

```bash curl
curl -sS -X POST "http://localhost:30010/v1/images/generations" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -d '{
        "prompt": "A calico cat playing a piano on stage",
        "size": "1024x1024",
        "n": 1,
        "response_format": "b64_json"
      }'
```

> **注意**
> 如果使用 `response_format=url` 且没有配置云存储，API 会返回相对 URL，例如 `/v1/images/<IMAGE_ID>/content`。

**编辑一张图像**

**端点：** `POST /v1/images/edits`

该端点接受带输入图像和文本提示词的多部分表单上传。服务端可以返回 base64 编码的图像，或返回可下载图像的 URL。

**Curl 示例（b64_json 响应）：**

```bash Command
curl -sS -X POST "http://localhost:30010/v1/images/edits" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -F "image=@local_input_image.png" \
  -F "url=image_url.jpg" \
  -F "prompt=A calico cat playing a piano on stage" \
  -F "size=1024x1024" \
  -F "response_format=b64_json"
```

**Curl 示例（URL 响应）：**

```bash Command
curl -sS -X POST "http://localhost:30010/v1/images/edits" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -F "image=@local_input_image.png" \
  -F "url=image_url.jpg" \
  -F "prompt=A calico cat playing a piano on stage" \
  -F "size=1024x1024" \
  -F "response_format=url"
```

**下载图像内容**

当 `POST /v1/images/generations` 或 `POST /v1/images/edits` 使用 `response_format=url` 时，
API 会返回相对 URL，例如 `/v1/images/<IMAGE_ID>/content`。

**端点：** `GET /v1/images/&#123;image_id&#125;/content`

**Curl 示例：**

```bash
curl -sS -L "http://localhost:30010/v1/images/<IMAGE_ID>/content" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -o output.png
```

### 视频生成

服务端在 `/v1/videos` 命名空间下实现了 OpenAI Videos API 的一个子集。

**创建一个视频（文生视频）**

**端点：** `POST /v1/videos`

**Python 示例：**

```python Python
from openai import OpenAI

client = OpenAI(api_key="sk-proj-1234567890", base_url="http://localhost:30010/v1")

video = client.videos.create(
    prompt="A calico cat playing a piano on stage",
    size="1280x720"
)
print(f"Video ID: {video.id}, Status: {video.status}")
```

**Curl 示例：**

```bash curl
curl -sS -X POST "http://localhost:30010/v1/videos" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -d '{
        "prompt": "A calico cat playing a piano on stage",
        "size": "1280x720"
      }'
```

**创建一个视频（图生视频）**

对 I2V 或 TI2V 模型（例如 Wan2.1 I2V、LTX-2.3 两阶段），通过多部分表单上传或参考 URL 传入输入图像。

**Curl 示例（多部分表单上传）：**

```bash Command
curl -sS -X POST "http://localhost:30010/v1/videos" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -F "prompt=A cat playing a piano" \
  -F "input_reference=@input_image.png" \
  -F "size=1280x720"
```

**Curl 示例（参考 URL）：**

```bash Command
curl -sS -X POST "http://localhost:30010/v1/videos" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -d '{
        "prompt": "A cat playing a piano",
        "reference_url": "https://example.com/input_image.png",
        "size": "1280x720"
      }'
```

**列出视频**

**端点：** `GET /v1/videos`

**Python 示例：**

```python Python
videos = client.videos.list()
for item in videos.data:
    print(item.id, item.status)
```

**Curl 示例：**

```bash curl
curl -sS -X GET "http://localhost:30010/v1/videos" \
  -H "Authorization: Bearer sk-proj-1234567890"
```

**下载视频内容**

**端点：** `GET /v1/videos/&#123;video_id&#125;/content`

**Python 示例：**

```python Python
import time

# Poll for completion
while True:
    page = client.videos.list()
    item = next((v for v in page.data if v.id == video_id), None)
    if item and item.status == "completed":
        break
    time.sleep(5)

# Download content
resp = client.videos.download_content(video_id=video_id)
with open("output.mp4", "wb") as f:
    f.write(resp.read())
```

**Curl 示例：**

```bash curl
curl -sS -L "http://localhost:30010/v1/videos/<VIDEO_ID>/content" \
  -H "Authorization: Bearer sk-proj-1234567890" \
  -o output.mp4
```

### LoRA 管理

服务端支持 LoRA 适配器的动态加载、合并和取消合并。

**重要说明：**
- 互斥：每个目标同一时刻只能有一个 LoRA 配置处于激活状态
- 切换：要切换 LoRA，先用 `unmerge_lora_weights` 停用当前 LoRA，再 `set` 新的
- 缓存：服务端会在内存中缓存已加载的 LoRA 权重。切回之前加载过的 LoRA（相同路径）成本很低

**设置 LoRA 适配器**

加载一个或多个 LoRA 适配器并应用到模型。默认情况下，常规权重会被静态合并，而 FSDP 分片的权重使用动态 LoRA，以避免 full-gather 内存峰值。

**端点：** `POST /v1/set_lora`

**参数：**
- `lora_nickname`（字符串或字符串列表，必填）：LoRA 适配器的唯一标识。可以是单个字符串，也可以是多个 LoRA 的字符串列表
- `lora_path`（字符串、字符串列表或 None，可选）：`.safetensors` 文件或 Hugging Face 仓库 ID 的路径。首次加载必填；重新激活已缓存的 nickname 时可省略。如果是列表，长度必须与 `lora_nickname` 一致
- `target`（字符串或字符串列表，可选）：要应用 LoRA 的 transformer。如果是列表，长度必须与 `lora_nickname` 一致。合法值：
  - `"all"`（默认）：应用到所有 transformer
  - `"transformer"`：只应用到主 transformer（Wan2.2 的高噪声部分）
  - `"transformer_2"`：只应用到 transformer_2（Wan2.2 的低噪声部分）
  - `"critic"`：只应用到 critic 模型
- `strength`（浮点数或浮点数列表，可选）：合并时的 LoRA 强度，默认 1.0。如果是列表，长度必须与 `lora_nickname` 一致。小于 1.0 削弱效果，大于 1.0 增强效果
- `merge_mode`（字符串，可选）：`"auto"`（默认服务端策略）、`"merge"`（强制静态合并）或 `"dynamic"`（在前向时应用 LoRA）

**单个 LoRA 示例：**

```bash Command
curl -X POST http://localhost:30010/v1/set_lora \
  -H "Content-Type: application/json" \
  -d '{
        "lora_nickname": "lora_name",
        "lora_path": "/path/to/lora.safetensors",
        "target": "all",
        "strength": 0.8
      }'
```

**多个 LoRA 示例：**

```bash Command
curl -X POST http://localhost:30010/v1/set_lora \
  -H "Content-Type: application/json" \
  -d '{
        "lora_nickname": ["lora_1", "lora_2"],
        "lora_path": ["/path/to/lora1.safetensors", "/path/to/lora2.safetensors"],
        "target": ["transformer", "transformer_2"],
        "strength": [0.8, 1.0]
      }'
```

**多个 LoRA 应用同一目标：**

```bash Command
curl -X POST http://localhost:30010/v1/set_lora \
  -H "Content-Type: application/json" \
  -d '{
        "lora_nickname": ["style_lora", "character_lora"],
        "lora_path": ["/path/to/style.safetensors", "/path/to/character.safetensors"],
        "target": "all",
        "strength": [0.7, 0.9]
      }'
```

> [!NOTE]
> 使用多个 LoRA 时：
> - 所有列表参数（`lora_nickname`、`lora_path`、`target`、`strength`）的长度必须一致
> - 如果 `target` 或 `strength` 是单个值，它会应用到所有 LoRA
> - 应用到同一目标的多个 LoRA 会按顺序应用


**合并 LoRA 权重**

手动把当前设置的 LoRA 权重合并进基础模型。

> [!NOTE]
> 对 FSDP 分片的权重，手动合并可能需要 full-gather，可能 OOM。低峰值路径请用 `merge_mode="auto"` 或 `"dynamic"` 的 `set_lora`。

**端点：** `POST /v1/merge_lora_weights`

**参数：**
- `target`（字符串，可选）：要合并的 transformer。`"all"`（默认）、`"transformer"`、`"transformer_2"`、`"critic"` 之一
- `strength`（浮点数，可选）：合并时的 LoRA 强度，默认 1.0。小于 1.0 削弱效果，大于 1.0 增强效果

**Curl 示例：**

```bash
curl -X POST http://localhost:30010/v1/merge_lora_weights \
  -H "Content-Type: application/json" \
  -d '{"strength": 0.8}'
```


**取消合并 LoRA 权重**

把当前激活的 LoRA 权重从基础模型中取消合并，恢复其原始状态。设置不同的 LoRA 之前**必须**调用它。

**端点：** `POST /v1/unmerge_lora_weights`

**Curl 示例：**

```bash
curl -X POST http://localhost:30010/v1/unmerge_lora_weights \
  -H "Content-Type: application/json"
```

**列出 LoRA 适配器**

返回已加载的 LoRA 适配器以及每个模块当前的应用状态。

**端点：** `GET /v1/list_loras`

**Curl 示例：**

```bash
curl -sS -X GET "http://localhost:30010/v1/list_loras"
```

**响应示例：**

```json
{
  "loaded_adapters": [
    { "nickname": "lora_a", "path": "/weights/lora_a.safetensors" },
    { "nickname": "lora_b", "path": "/weights/lora_b.safetensors" }
  ],
  "active": {
    "transformer": [
      {
        "nickname": "lora2",
        "path": "tarn59/pixel_art_style_lora_z_image_turbo",
        "merged": true,
        "mode": "merged",
        "strength": 1.0
      }
    ]
  }
}
```

说明：
- 如果当前流水线未启用 LoRA，服务端会返回错误。
- `num_lora_layers_with_weights` 只统计激活适配器实际应用了 LoRA 权重的层数。

### 调整输出质量

服务端支持通过 `output-quality` 和 `output-compression` 参数调整图像和视频生成的输出质量与压缩级别。

#### 参数

- **`output-quality`**（字符串，可选）：自动设置压缩级别的预设质量档。**默认是 `"default"`**。合法值：
  - `"maximum"`：最高质量（100）
  - `"high"`：高质量（90）
  - `"medium"`：中等质量（55）
  - `"low"`：较低质量（35）
  - `"default"`：按媒体类型自动调整（视频 50，图像 75）

- **`output-compression`**（整数，可选）：直接覆盖压缩级别（0-100）。**默认是 `None`**。提供时（非 `None`）优先于 `output-quality`。
  - `0`：最低质量，最小文件体积
  - `100`：最高质量，最大文件体积

#### 说明

- **优先级**：同时提供 `output-quality` 和 `output-compression` 时，`output-compression` 优先
- **格式支持**：质量设置适用于 JPEG 和视频格式。PNG 使用无损压缩，会忽略这些设置
- **文件体积与质量**：更低的压缩值（或 "low" 质量预设）会产生更小的文件，但可能出现可见的伪影
