用 `sglang generate` 做一次性生成，或用 `sglang serve` 启动常驻 HTTP 服务端。

### 非 diffusers 模型的 Overlay 仓库

如果 `--model-path` 指向一个受支持的非 diffusers 源仓库，SGLang 可以通过自托管的 overlay 仓库解析它。

SGLang 首先检查内置的 overlay 注册表。具体的内置映射可以随时间添加，而无需改变 CLI 表面。

覆盖示例：

```bash Command
export SGLANG_DIFFUSION_MODEL_OVERLAY_REGISTRY='{
  "Wan-AI/Wan2.2-S2V-14B": {
    "overlay_repo_id": "your-org/Wan2.2-S2V-14B-overlay",
    "overlay_revision": "main"
  }
}'

sglang generate \
  --model-path Wan-AI/Wan2.2-S2V-14B \
  --config configs/wan_s2v.yaml
```

overlay 仓库应该是一个完整的 diffusers 风格/组件化仓库。

如果某个仓库包含 `_overlay/overlay_manifest.json`，你也可以把 overlay 仓库本身作为 `--model-path` 传入。

注意事项：
1. `SGLANG_DIFFUSION_MODEL_OVERLAY_REGISTRY` 只是用于开发和调试的可选覆盖。它接受 JSON 对象或 JSON 文件路径，可以为当前进程扩展或替换内置条目。
2. 首次加载时，SGLang 会：
   - 从 overlay 仓库下载 overlay 元数据
   - 从原始源仓库下载所需文件
   - 在 `~/.cache/sgl_diffusion/materialized_models/` 下物化出一个本地标准组件仓库
3. 之后的加载会复用物化后的本地仓库。运行时把物化仓库当作普通的组件化模型目录加载。

## 快速上手

### 生成

```bash Command
sglang generate \
  --model-path Qwen/Qwen-Image \
  --prompt "A beautiful sunset over the mountains" \
  --save-output
```

### 服务

```bash Command
sglang serve \
  --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
  --num-gpus 4 \
  --ulysses-degree 2 \
  --ring-degree 2 \
  --port 30010
```

请求和响应示例见 [OpenAI 兼容 API](./openai_api)。

<Tip>
用 `sglang generate --help` 和 `sglang serve --help` 查看完整参数列表。CLI 帮助输出是穷尽参数列表的权威来源。
</Tip>

## 常用选项

### 模型与运行时

- `--model-path {MODEL}`：模型路径或 Hugging Face 模型 ID
- `--model-variant {NAME}`：当单个模型仓库包含多个权重分区时，要加载的语义化检查点变体。加载前，流水线会把这个稳定名称映射到仓库布局；例如 MiniMax-H3 接受 `fl2va` 和 `ref2va`。这是服务端/加载时的选择，不同于请求里的 `task`。
- `--model-subfolder {PATH}`：对模型仓库内某个组件子文件夹的高级直接覆盖。当流水线暴露语义化路由时，优先用 `--model-variant`。如果两者都提供，它们必须解析到同一个权重分区。
- `--lora-path {PATH}` 和 `--lora-nickname {NAME}`：加载一个 LoRA 适配器
- `--lora-merge-mode {auto|merge|dynamic}`：选择 LoRA 的应用方式。`auto` 静态合并常规权重，并对 FSDP 分片的权重使用动态 LoRA，以避免 full-gather 峰值。
- `--num-gpus {N}`：要使用的 GPU 数量
- `--performance-mode {manual|auto|speed|memory}` / `--mode`：延迟/吞吐与内存默认值的预设。`auto` 是默认值，保留安全的卸载默认值，只在已验证的 DiT 卸载替代路径上使用 FSDP；`speed` 还会启用 `--enable-torch-compile`，除非模型专属部署配置选择退出或你显式禁用它。用 `manual` 把性能相关的服务端参数保持在显式用户控制下。在所有模式下，显式的卸载、FSDP 和并行参数都优先。
- `--tp-size {N}`：张量并行大小。取决于流水线，它可以分片 DiT、一个或多个编码器，或两者都分片。
- `--sp-degree {N}`：序列并行大小
- `--dp-size {N}`（别名 `--data-parallel-size`）：数据并行副本数。每个副本都是引擎在 `num_gpus / N` 块 GPU 上的完整拷贝，自带入口；生成请求在各副本间轮询分配，实时会话固定在持有其状态的副本上，控制操作（权重、LoRA、内存占用、关闭）会应用到每个副本。可与其它并行轴组合（`num_gpus = dp × cfg × tp × sp`）；仅限单体服务。
- `--ulysses-degree {N}` 和 `--ring-degree {N}`：USP 并行控制项
- `--kv-gather-degree {N}`：一种序列并行度数：在注意力内部按行拆分，并用一次 K/V all-gather 交换（查询保持局部），而不是 Ulysses 的 all-to-all。仅限非因果注意力；暂不能与 `--ulysses-degree`/`--ring-degree` 组合。没有显式设置 SP 度数时，`sp_degree=2` 默认使用 `kv_gather_degree=2`（其实测胜出的区间），更高度数默认使用 Ulysses；在该自动分配下，调用 gather 路径的注意力无法回退到 Ulysses 交换，而显式指定度数失败时会直接报错而不是降级。
- `--enable-cfg-parallel {true|false}`：启用或显式禁用 CFG 并行
- `--encoder-parallel {auto|fold|dp|replicate}`：文本/图像编码器如何使用 DiT 副本在编码期间闲置的 GPU。`auto`（`generate` 和 `serve` 的默认值）对足够宽的编码器做 TP 折叠以摊薄逐层 all-reduce 成本，在服务器批处理能生效时选择 DP，否则复制；`fold` 只要维度允许就强制分片；`dp` 把批量编码拆分到各 rank，需要 `--batching-max-size > 1` 才能生效；`replicate` 在每个 rank 上冗余编码。`fold` 和 `replicate` 与单 GPU 编码逐位一致。见[编码器并行](/docs/sglang-diffusion/encoder_parallel)。
- `--warmup-mode {off|request|server}`：控制 `sglang serve` 的启动预热；`off` 跳过预热，`request` 预热请求路径，`server` 在开始服务流量前运行一次完整的合成服务端预热
- `--enable-torch-compile {true|false}`：编译原生扩散热路径。未配置预热模式时，这也会启用服务端预热，让第一批真实请求不必承担编译延迟。
- `--offload-during-compile {true|false}`：编译预热激活时，临时逐层卸载 DiT 权重并把常驻的非 DiT 组件移出设备，让 `max-autotune` 在内存更紧的 GPU 上装得下；真实流量到达前恢复配置好的服务驻留方式。在已有逐层卸载、Cache-DiT 或 FSDP 情况下会跳过。
- `--enable-breakable-cuda-graph {true|false}`：把受支持的 DiT 前向过程捕获为可打断的 CUDA 图段，以降低启动开销。要求为每个服务的分辨率提供 `--warmup-resolutions`，因为每个分辨率都会单独捕获。
- `--bcg-text-buckets {N...}`：可打断 CUDA 图捕获/重放复用的提示词长度填充桶。
- `--attention-backend {BACKEND}`：原生 SGLang 和 diffusers 流水线的注意力后端
- `--component-attention-backends {MAP}`：按组件覆盖注意力后端，例如 `text_encoder=torch_sdpa,transformer=fa`
- `--attention-backend-config {CONFIG}`：注意力后端配置
- `--srt-encoder-url {HTTPADDRESS}`：带 AR 模型的 SGLang srt 服务端地址，用于 GLM-Image 这类模型。见[带 AR 阶段的模型](../models_with_ar)。
- `--srt-encoder-timeout {SECONDS}`：向 SGLang 编码器服务端发起 HTTP 请求的超时时间（秒）
- `--srt-encoder-connection-timeout {SECONDS}`：SGLang 编码器服务端的 TCP 连接超时时间（秒）
- `--pe-server-url {HTTPADDRESS}`：托管 PE 模型的 SGLang 服务端 URL（例如用于 ERNIE-Image）。见[带提示词增强的模型](../models_with_pe)。

### 采样与输出

- `--prompt {PROMPT}` 和 `--negative-prompt {PROMPT}`
- `--image-path {PATH} [{PATH} ...]`：图生视频或图生图生成的输入图像
- `--num-inference-steps {STEPS}` 和 `--seed {SEED}`
- `--num-outputs-per-prompt {N}` / `--num-outputs {N}`：为每个提示词生成多个输出。标量种子会按 `seed + output_index` 展开。
- `--quality {lossless,high}`：请求级质量。`lossless`（默认）保持精确的参考路径，与参考实现逐位一致；`high` 选择模型自有的经过验证的加速路径，其质量仍有保证但不再逐位一致。支持情况和经过验证的部署约束因模型而异。
- `--height {HEIGHT}`、`--width {WIDTH}`、`--num-frames {N}`、`--fps {FPS}`
- `--output-path {PATH}`、`--output-file-name {NAME}`、`--save-output`、`--return-frames`

帧插值和超分辨率见[后处理](./post_processing)。

### 量化 transformer

对量化 transformer 检查点，优先使用：

- `--model-path`：基础流水线
- `--transformer-path`：量化 `transformers` transformer 组件文件夹
- `--transformer-weights-path`：量化的 safetensors 文件、目录或仓库
- `--quantization`：在线量化（加载时对未量化模型应用量化，激活动态量化）
- `--quantization-ignored-layers`：保持未量化的层名模式（例如 `attention.to_`）

受支持的量化家族和示例见[量化](../quantization)。

### 请求日志

- `--log-requests`：记录所有请求的用户可见字段（默认：`False`）。详细程度由 `--log-requests-level` 决定。
- `--log-requests-level &#123;0|1|2|3&#125;`：请求日志的详细级别（默认：`2`）。0：记录元数据（请求 id）。1：记录元数据和采样配置（seed、steps、guidance、resolution、frames、fps、……）。2：记录元数据、采样配置和提示词（截断到 2 KiB）。3：记录元数据、采样配置和完整提示词。
- `--log-requests-format &#123;text|json&#125;`：请求日志的格式（默认：`text`）。`text` 是人类可读的；`json` 输出结构化的 JSON 行。
- `--log-requests-target &#123;TARGET...&#125;`：请求日志的目标位置。用 `stdout` 输出到控制台，和/或用目录路径输出到文件。可以指定多个目标，例如 `--log-requests-target stdout /my/log/dir`。

## 配置文件


## 生成

`sglang generate` 运行单个生成任务，任务结束后退出。

```bash Command
sglang generate \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --text-encoder-cpu-offload \
  --pin-cpu-memory \
  --num-gpus 4 \
  --ulysses-degree 2 \
  --ring-degree 2 \
  --prompt "A curious raccoon" \
  --save-output \
  --output-path outputs \
  --output-file-name "a-curious-raccoon.mp4"
```

<Note>
仅 HTTP 服务端使用的参数会被 `sglang generate` 忽略。
</Note>

对受支持的原生流水线，设置 `SGLANG_CACHE_DIT_ENABLED=true` 以启用 Cache-DiT。对 diffusers 后端，使用 `--backend diffusers --cache-dit-config ...`。见 [Cache-DiT](../cache_dit)。

对受支持的图像流水线，可以用 `--enable-breakable-cuda-graph` 启用可打断 CUDA 图，但你必须在 `--warmup-resolutions` 中声明每个服务的分辨率，让预热捕获到匹配的图签名。

### 逐层卸载

当大组件无法舒适地放进 GPU 内存时，使用逐层卸载。默认情况下，`--dit-layerwise-offload` 只适用于旧版 DiT 组件。用 `--layerwise-offload-components` 显式选择流水线组件名（`--layerwise-offload-modules` 被接受为别名）：

```bash Command
sglang generate \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --dit-layerwise-offload \
  --layerwise-offload-components transformer text_encoder \
  --dit-offload-prefetch-size 0 \
  --prompt "A quiet city street after rain"
```

这些值必须匹配所选流水线 `pipeline.modules` 中的键，例如 `transformer`、`text_encoder`、`image_encoder`、`vae`、`condition_image_encoder`、`spatial_upsampler` 或 `vocoder`。用 `all` 选择所有可逐层卸载的组件。优先选择能解决内存问题的最小组件集，因为逐层卸载可能增加延迟。

## 服务

`sglang serve` 启动 HTTP 服务端，并让模型保持加载以处理重复请求。

```bash Command
sglang serve \
  --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
  --text-encoder-cpu-offload \
  --pin-cpu-memory \
  --num-gpus 4 \
  --ulysses-degree 2 \
  --ring-degree 2 \
  --port 30010
```

### 云存储

SGLang Diffusion 可以在生成后把图像和视频上传到兼容 S3 的对象存储。

```bash Command
export SGLANG_CLOUD_STORAGE_TYPE=s3
export SGLANG_S3_BUCKET_NAME=my-bucket
export SGLANG_S3_ACCESS_KEY_ID=your-access-key
export SGLANG_S3_SECRET_ACCESS_KEY=your-secret-key
export SGLANG_S3_ENDPOINT_URL=https://minio.example.com
```

完整的存储选项见[环境变量](../environment_variables)。

## 组件路径覆盖

用 `--<component>-path` 覆盖单个流水线组件，如 `vae`、`transformer` 或 `text_encoder`。

```bash Command
sglang serve \
  --model-path black-forest-labs/FLUX.2-dev \
  --vae-path fal/FLUX.2-Tiny-AutoEncoder
```

组件键必须匹配模型 `model_index.json` 中的键，路径必须是 Hugging Face 仓库 ID 或完整的组件目录。

## 组件注意力后端覆盖

当某个流水线组件需要与全局 `--attention-backend` 不同的原生注意力后端时，使用 `--component-attention-backends`。

```bash Command
sglang generate \
  --model-path Lightricks/LTX-2.3 \
  --attention-backend fa \
  --component-attention-backends text_encoder=torch_sdpa
```

组件键必须匹配流水线模块键，例如 `text_encoder`、`text_encoder_2`、`transformer`、`transformer_2` 或 `connectors`。只有在构建该组件期间，组件覆盖才优先于全局 `--attention-backend`。

你也可以传点号分隔的 CLI 条目：

```bash Command
sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --component-attention-backends.text_encoder torch_sdpa \
  --component-attention-backends.transformer fa
```

### 示例

```bash
sglang generate \
  --model-path AIDC-AI/Ovis-Image-7B \
  --backend diffusers \
  --trust-remote-code \
  --attention-backend flash \
  --prompt "A serene Japanese garden with cherry blossoms" \
  --height 1024 \
  --width 1024 \
  --num-inference-steps 30 \
  --save-output \
  --output-path outputs \
  --output-file-name ovis_garden.png
```

对 CLI 未暴露的流水线专属参数，在配置文件中传入 `diffusers_kwargs`。
