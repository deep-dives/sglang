本页记录受支持的 SGLang Diffusion 模型家族及其优化兼容性，也覆盖那些还没有专门 cookbook 配方的长尾模型。

需要模型专属的使用配方时，从 [Diffusion Cookbook](/cookbook/diffusion/intro) 开始。Cookbook 页面带示例覆盖了主要模型；本页保留精简的支持与兼容性清单。

## 受支持的模型清单

把 `Hugging Face Model ID` 传给 `sglang generate` 或 `sglang serve` 的 `--model-path`。Python API 用户可以把同一个 ID 传给 SGLang Diffusion 的模型加载辅助函数。

缺少某个检查点别名并不代表该模型家族不受支持。运行时注册表也可能接受与同一家族匹配的基于检测器的别名或本地模型目录。

当多个家族共享同一条运行时路径或优化支持时，行会分组。需要逐优化的兼容性时，使用下面的详细矩阵。

## 优化兼容性

详细的视频矩阵使用以下符号：

- ✅ = 完全兼容
- ❌ = 不兼容
- ⭕ = 不适用于该模型

<Note>
💡 AI Infra 学习笔记：视频扩散的注意力是性能大头——视频潜空间序列很长，标准注意力开销是 O(n²)，而视频相邻帧高度冗余。TeaCache、Sage Attention、VSA、SLA、Laser Attention、BSA 这些优化本质上在做两件事：一是减少冗余计算（缓存相似的去噪步、对注意力矩阵做稀疏化），二是把计算压到更便宜的形式（线性注意力）。但稀疏/缓存类优化对内容敏感，选错参数会明显掉画质，所以下面这个矩阵才会逐模型标注 ✅/❌/⭕——优化不是"开箱即用"，而是"验证过的模型才敢开"。
</Note>

### 视频生成模型

为保持矩阵可读，优化列使用缩写：

- `Tea` = TeaCache
- `Tile` = 滑动分块注意力（Sliding Tile Attention）
- `Sage` = Sage 注意力
- `VSA` = 视频稀疏注意力（Video Sparse Attention）
- `SLA` = 稀疏线性注意力（Sparse Linear Attention）
- `SageSLA` = Sage 稀疏线性注意力（Sage Sparse Linear Attention）
- `SVG2` = 稀疏视频生成 2（Sparse Video Gen 2）
- `LA` = Laser 注意力（Laser Attention）
- `BSA` = 块稀疏注意力（Block Sparse Attention）
- `RF` = Rain Fusion 注意力（Rain Fusion Attention）

## 受支持的组件

SGLang Diffusion 支持用 `--<component>-path` 覆盖单个流水线组件。值可以是 Hugging Face 仓库 ID，也可以是本地组件目录。

同样的覆盖也可以通过配置文件里的 `component_paths.<component>` 提供。

### 通用语法

CLI：

```bash Command
sglang generate \
  --model-path black-forest-labs/FLUX.2-dev \
  --vae-path black-forest-labs/FLUX.2-small-decoder \
  --transformer-path /models/flux2/transformer
```

配置文件：

```yaml Config
model_path: black-forest-labs/FLUX.2-dev
component_paths:
  vae: black-forest-labs/FLUX.2-small-decoder
  transformer: /models/flux2/transformer
```

### VAE

- `--vae-path` 是常见的图像生成覆盖项。
- `--video-vae-path` 和 `--audio-vae-path` 只对带独立视频或音频 VAE 的流水线相关。

### Transformer / DiT

- `--transformer-path` 是主去噪 transformer 的标准覆盖项。
- 对量化 transformer，优先用 `--transformer-path` 或 `--transformer-weights-path`；见 `quantization.md`。
- `--video-dit-path` 和 `--audio-dit-path` 只用于按模态拆分去噪器的流水线。

### 文本编码器与预处理器

- `--text-encoder-path` 和 `--text-encoder-2-path` 覆盖主、次文本编码器。
- 当替换编码器需要匹配的预处理资源时，`--tokenizer-path`、`--processor-path` 和 `--image-processor-path` 很有用。

### 辅助组件

- `--scheduler-path` 只对暴露调度器组件的流水线相关。
- `--spatial-upsampler-path` 主要用于 `LTX2TwoStagePipeline` 这样的两阶段流水线。
- `--vocoder-path`、`--connectors-path`、`--dual-tower-bridge-path`、`--image-encoder-path` 和 `--vision-language-encoder-path` 只对暴露这些组件的流水线有效。

### 说明

1. 组件覆盖只在目标流水线确实使用该组件时才有效。
2. 覆盖键应与流水线 `model_index.json` 中的组件名或原生流水线注册的模块名一致。
