决策依据是所选 GPU 上的可用内存。

- 多 GPU 部署：选中的 GPU 中剩余内存最少的那块是瓶颈。一块满载的 80 GiB GPU 表现可能和一块小得多的 GPU 一样。
- 单 GPU 部署：FSDP 会把 DiT 权重分片到多块 GPU 上。它不能用来把单 GPU 部署维持在单卡上；这种情况请用 CPU 卸载。

## 性能模式

`--performance-mode` 在**不覆盖**显式卸载、FSDP 或并行参数的前提下应用安全预设。`auto` 是默认值。当你需要把性能相关的服务端参数保持在显式用户控制下时，用 `manual`。`--mode` 是它的短别名。

`auto` 在应用 FSDP 之前会检查所选 GPU 的内存。多 GPU 运行时，它取所选 GPU 中最小的可用内存，并且只有当这样做能替代 DiT 卸载时才会自动开启 FSDP。文本编码器、图像编码器及其他组件的驻留方式仍遵循卸载策略，除非模型把某个高内存驻留路径标记为安全。当模型默认使用 CFG 且用户没有设置并行策略时，`auto` 还可能启用 CFG 并行。`speed` 有意不检查内存；它适合更看重延迟/吞吐、能接受 OOM 风险的用户，并且除非显式设置了 `--enable-torch-compile false`，否则会自动开启 `torch.compile`。

这些模式会为向组件驻留管理器注册的原生流水线组件调节驻留方式。目前覆盖主要的 DiT、文本/图像编码器、VAE、声码器和上采样器组件；DiT 在受支持时可以使用逐层卸载，而文本编码器要么常驻执行、要么组件级 CPU 卸载。除非模型实现并验证了文本编码器的逐层卸载，否则不要假定它可用。

启用 `torch.compile` 时，`--offload-during-compile` 默认保持开启。在编译预热期间，它会临时卸载 DiT 并把常驻的非 DiT 组件逐出，让 `max-autotune` 在内存更紧的 GPU 上装得下，然后在真实流量到达前恢复配置好的服务驻留方式。

可打断 CUDA 图是受支持图像流水线的一个独立手动选项。如果你启用 `--enable-breakable-cuda-graph`，必须在 `--warmup-resolutions` 中声明每一个会服务的分辨率，让预热捕获到匹配的图签名。

> [!NOTE]
> 这个预设刻意比较粗糙。未来用 `0.0` 到 `1.0` 这样的连续值或许能更精确地表达速度-内存权衡，但那需要模型专属的内存模型和更清晰的用户预期。在那之前，请用预设外加显式参数来覆盖。

示例：

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --num-gpus 2 \
  --performance-mode auto
```

```bash
sglang generate \
  --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
  --performance-mode memory
```

显式参数优先于模式：

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --num-gpus 2 \
  --performance-mode auto \
  --use-fsdp-inference false
```

在这个例子里，`auto` 不会重新启用 FSDP。并行参数同理；例如 `--enable-cfg-parallel false` 会让 CFG 并行保持关闭。

## 理解这些杠杆

<Note>
💡 AI Infra 学习笔记：部署模式本质上是几个"内存-延迟"权衡的旋钮。CPU 卸载把大组件搬到主存，显存占用降下来，但每次访问都要跨 PCIe 走一趟，延迟上升；FSDP 把权重分片到多卡、前向时 all-gather，适合多卡但引入通信；序列并行（SP）解决的是单卡装不下长序列激活的问题，代价是通信开销。性能模式预设（auto/speed/memory）只是把这些旋钮组合成安全默认值——调优时能说清"我卡在显存还是算力、该拧哪个旋钮"，比记住预设名更重要。
</Note>

**不卸载** 让模型组件常驻 GPU。内存充足时它通常最快。

**组件级 CPU 卸载** 通过把大组件搬到 CPU 来降低 GPU 内存。它简单可靠，但通常是以延迟换内存。

**逐层 DiT 卸载** 对受支持的 Wan/MOVA 模型，通过在 CPU 与 GPU 之间搬运 DiT 层，进一步降低 DiT 内存。它可能是单 GPU 上最好的内存模式，但可能增加延迟、降低吞吐。

**FSDP** 把 DiT 权重分片到多块 GPU，并在前向过程中对权重做 all-gather。它可以降低多 GPU 部署上的 DiT CPU 卸载开销，尤其是经过验证的 Wan I2V 负载。

FSDP 的分片粒度很关键。SGLang Diffusion 倾向于分片直接的重复 transformer 块条目，比如 `transformer_blocks.0` 或 `blocks.0`。更粗的分片会降低 wrapper 数量，但可能抬高 all-gather 峰值内存；更细的分片能降低瞬时内存，但会引入更多通信和调度开销。如果模型没有定义显式分片规则，加载器会回退到重复块类名和常见的直接编号块路径。

**CFG 并行** 把正/负 CFG 分支拆分到多块 GPU 上。对步数正常的 Qwen/Wan 负载，这是目前观察到的最可靠的多 GPU 加速手段。

**SP/Ulysses/Ring** 拆分序列计算。它可能对视频负载有帮助，但经过验证的 Qwen/Wan 运行显示，在延迟方面 CFG 并行优于 SP。

**TP** 出于兼容性和某些模型结构而受支持，但目前的实测结果并不让它成为 Qwen/Wan 的默认延迟路径。

## 当前基准测试要点

观察到的常规规模趋势：

- Z-Image：在测试配置中，单 GPU 不卸载比 FSDP/SP 更快；除非内存或并行需要，否则保持 FSDP 关闭。
- Qwen-Image：除非已经在目标硬件上对某个特定的 FSDP/SP/Ring 配置做过基准测试，否则保持默认的非 FSDP 路径。
- Wan：在验证过的多 GPU 负载上，FSDP 可以替代 DiT 卸载，而文本/图像编码器可能仍需要组件卸载。在把某个路径的 FSDP 设为自动之前，先做模型专属的精度检查。
- 组件卸载主要降低内存；在测试的不卸载 vs 卸载对比中，它并没有改善延迟。

在锁定生产默认值之前，务必用你实际的分辨率、帧数、步数和 GPU 型号做基准测试。
