SGLang 集成了 [Cache-DiT](https://github.com/vipshop/cache-dit)——一个面向扩散 Transformer（DiT）的缓存加速引擎，在质量损失很小的情况下最高可带来 **1.69x 推理加速**。

## 概览

**Cache-DiT** 使用智能缓存策略，在去噪循环中跳过冗余计算：

- **DBCache（双块缓存）**：基于残差差异动态决定何时缓存 transformer 块
- **TaylorSeer**：使用泰勒展开做校准，优化缓存决策
- **SCM（步骤级计算掩码）**：步骤级缓存控制，进一步提升速度

<Note>
💡 AI Infra 学习笔记：Cache-DiT 属于"块级"缓存——它在去噪过程中观察每个 transformer 块的残差差异：如果某块相邻两次的输出变化很小，就判定"这块这次不用重算"，直接用上一次的结果。DBCache 负责动态判定要不要缓存某块，TaylorSeer 用泰勒展开更精确地预测变化趋势，SCM 则从"步"的粒度再筛一遍。粒度越细，节省越多，但误判（该算的没算）对画质的影响也越难排查。
</Note>

## 基本用法

通过导出环境变量并使用 `sglang generate` 或 `sglang serve` 来启用 Cache-DiT：

```bash
SGLANG_CACHE_DIT_ENABLED=true \
sglang generate --model-path Qwen/Qwen-Image \
    --prompt "A beautiful sunset over the mountains"
```

## Diffusers 后端

Cache-DiT 支持从自定义 YAML 文件加载加速配置。对于 diffusers 管线（`diffusers` 后端），通过 `--cache-dit-config` 传入 YAML/JSON 路径。该流程需要 cache-dit >= 1.2.0（`cache_dit.load_configs`）。

### 单 GPU 推理

定义一个包含以下内容的 `cache.yaml` 文件：

- DBCache + TaylorSeer

```yaml
cache_config:
  max_warmup_steps: 8
  warmup_interval: 2
  max_cached_steps: -1
  max_continuous_cached_steps: 2
  Fn_compute_blocks: 1
  Bn_compute_blocks: 0
  residual_diff_threshold: 0.12
  enable_taylorseer: true
  taylorseer_order: 1
```

然后用以下命令应用该配置：

```bash
sglang generate \
  --backend diffusers \
  --model-path Qwen/Qwen-Image \
  --cache-dit-config cache.yaml \
  --prompt "A beautiful sunset over the mountains"
```

- DBCache + TaylorSeer + SCM（步骤级计算掩码）

```yaml Config
cache_config:
  max_warmup_steps: 8
  warmup_interval: 2
  max_cached_steps: -1
  max_continuous_cached_steps: 2
  Fn_compute_blocks: 1
  Bn_compute_blocks: 0
  residual_diff_threshold: 0.12
  enable_taylorseer: true
  taylorseer_order: 1
  # Must set the num_inference_steps for SCM. The SCM will automatically
  # generate the steps computation mask based on the num_inference_steps.
  # Reference: https://cache-dit.readthedocs.io/en/latest/user_guide/CACHE_API/#scm-steps-computation-masking
  num_inference_steps: 28
  steps_computation_mask: fast
```

- DBCache + TaylorSeer + SCM（步骤级计算掩码）+ Cache CFG

```yaml Config
cache_config:
  max_warmup_steps: 8
  warmup_interval: 2
  max_cached_steps: -1
  max_continuous_cached_steps: 2
  Fn_compute_blocks: 1
  Bn_compute_blocks: 0
  residual_diff_threshold: 0.12
  enable_taylorseer: true
  taylorseer_order: 1
  num_inference_steps: 28
  steps_computation_mask: fast
  enable_sperate_cfg: true # e.g, Qwen-Image, Wan, Chroma, Ovis-Image, etc.
```

### 分布式推理

- 1D 并行

定义一个只包含并行配置的 `parallel.yaml` 文件，内容如下：

```yaml Config
parallelism_config:
  ulysses_size: auto
  attention_backend: native
```

然后从 yaml 应用分布式推理加速配置。`ulysses_size: auto` 表示 cache-dit 会自动把 `world_size` 检测为 ulysses_size；否则你需要手动设为具体的整数，例如 4。

然后用以下命令应用分布式配置：（注意：请加上 `--num-gpus N` 指定分布式推理的 GPU 数量）

```bash
sglang generate \
  --backend diffusers \
  --num-gpus 4 \
  --model-path Qwen/Qwen-Image \
  --cache-dit-config parallel.yaml \
  --prompt "A futuristic cityscape at sunset"
```

- 2D 并行

你也可以定义一个包含 2D 并行配置的 `parallel_2d.yaml` 文件，内容如下：

```yaml Config
parallelism_config:
  ulysses_size: auto
  tp_size: 2
  attention_backend: native
```
然后从 yaml 应用 2D 并行配置。这里的 `tp_size: 2` 表示使用规模为 2 的张量并行。`ulysses_size: auto` 表示 cache-dit 会自动把 `world_size // tp_size` 检测为 ulysses_size。

- 3D 并行

你也可以定义一个包含 3D 并行配置的 `parallel_3d.yaml` 文件，内容如下：

```yaml Config
parallelism_config:
  ulysses_size: 2
  ring_size: 2
  tp_size: 2
  attention_backend: native
```
然后从 yaml 应用 3D 并行配置。这里的 `ulysses_size: 2`、`ring_size: 2`、`tp_size: 2` 分别表示规模为 2 的 ulysses 并行、环形并行与张量并行。

- Ulysses Anything Attention

要启用 Ulysses Anything Attention，你可以定义一个包含以下内容的并行配置 `parallel_uaa.yaml` 文件：

```yaml Config
parallelism_config:
  ulysses_size: auto
  attention_backend: native
  ulysses_anything: true
```

- Ulysses FP8 通信

对于不支持 NVLink 的设备，你可以启用 Ulysses FP8 通信来进一步降低通信开销。你可以定义一个包含以下内容的并行配置 `parallel_fp8.yaml` 文件：

```yaml Config
parallelism_config:
  ulysses_size: auto
  attention_backend: native
  ulysses_float8: true
```

- 异步 Ulysses CP

你也可以启用异步 ulysses CP 来让通信与计算重叠。定义一个包含以下内容的并行配置 `parallel_async.yaml` 文件：

```yaml Config
parallelism_config:
  ulysses_size: auto
  attention_backend: native
  ulysses_async: true # Now, only support for FLUX.1, Qwen-Image, Ovis-Image and Z-Image.
```
然后从 yaml 应用该配置。这里的 `ulysses_async: true` 表示启用异步 ulysses CP。

- TE-P 与 VAE-P

你也可以在 yaml 配置中指定额外的并行模块。例如，定义一个包含以下内容的并行配置 `parallel_extra.yaml` 文件：

```yaml Config
parallelism_config:
  ulysses_size: auto
  attention_backend: native
  extra_parallel_modules: ["text_encoder", "vae"]
```

<Note>
💡 AI Infra 学习笔记：Cache-DiT 的并行配置复用了一套熟悉的并行词汇——Ulysses（按序列维度切分注意力）、ring（环形通信做序列并行）、TP（张量并行切分 GEMM）。视频生成里 latent 序列很长，序列并行是必选项；而 `ulysses_float8` 这类开关是为了在没有 NVLink 的环境（PCIe 互联）里压低通信带宽。理解"切什么维度、走什么通信、什么硬件受限"是评估这类配置的通用思路。
</Note>

### 混合缓存与并行

定义一个同时包含缓存与并行加速配置的 `hybrid.yaml` 文件，内容如下：

```yaml Config
cache_config:
  max_warmup_steps: 8
  warmup_interval: 2
  max_cached_steps: -1
  max_continuous_cached_steps: 2
  Fn_compute_blocks: 1
  Bn_compute_blocks: 0
  residual_diff_threshold: 0.12
  enable_taylorseer: true
  taylorseer_order: 1
parallelism_config:
  ulysses_size: auto
  attention_backend: native
  extra_parallel_modules: ["text_encoder", "vae"]
```

然后从 yaml 应用混合缓存与并行加速配置。

```bash
sglang generate \
  --backend diffusers \
  --num-gpus 4 \
  --model-path Qwen/Qwen-Image \
  --cache-dit-config hybrid.yaml \
  --prompt "A beautiful sunset over the mountains"
```

### Attention 后端

有些情况下，用户只想指定 Attention 后端而不加任何其他优化配置。此时你可以定义一个只包含以下内容的 `attention.yaml` 文件：

```yaml Config
attention_backend: "flash" # '_flash_3' for Hopper
```

### 量化

你也可以在 yaml 文件中指定量化配置，需要 `torchao>=0.16.0`。例如，定义一个包含以下内容的 `quantize.yaml` 文件：

```yaml Config
quantize_config: # quantization configuration for transformer modules
  # float8 (DQ), float8_weight_only, float8_blockwise, int8 (DQ), int8_weight_only, etc.
  quant_type: "float8"
  # layers to exclude from quantization (transformer). layers that contains any of the
  # keywords in the exclude_layers list will be excluded from quantization. This is useful
  # for some sensitive layers that are not robust to quantization, e.g., embedding layers.
  exclude_layers:
    - "embedder"
    - "embed"
  verbose: false # whether to print verbose logs during quantization
```
然后从 yaml 应用量化配置。使用量化时，也请启用 torch.compile 以获得更好的性能。例如：

```bash Command
sglang generate \
  --backend diffusers \
  --model-path Qwen/Qwen-Image \
  --warmup-mode request \
  --cache-dit-config quantize.yaml \
  --enable-torch-compile \
  --dit-cpu-offload false \
  --text-encoder-cpu-offload false \
  --prompt "A beautiful sunset over the mountains"
```

### 组合配置：缓存 + 并行 + 量化

你也可以把上述所有配置组合到单个 `combined.yaml` 文件中，内容如下：

```yaml Config
cache_config:
  max_warmup_steps: 8
  warmup_interval: 2
  max_cached_steps: -1
  max_continuous_cached_steps: 2
  Fn_compute_blocks: 1
  Bn_compute_blocks: 0
  residual_diff_threshold: 0.12
  enable_taylorseer: true
  taylorseer_order: 1
parallelism_config:
  ulysses_size: auto
  attention_backend: native
  extra_parallel_modules: ["text_encoder", "vae"]
quantize_config:
  quant_type: "float8"
  exclude_layers:
    - "embedder"
    - "embed"
  verbose: false
```
然后从 yaml 应用组合的缓存、并行与量化配置。使用量化时，也请启用 torch.compile 以获得更好的性能。

### 组合配置示例

DBCache 与 TaylorSeer 是互补的策略，可以同时工作，你可以同时配置两组参数：

```bash
SGLANG_CACHE_DIT_ENABLED=true \
SGLANG_CACHE_DIT_FN=2 \
SGLANG_CACHE_DIT_BN=1 \
SGLANG_CACHE_DIT_WARMUP=4 \
SGLANG_CACHE_DIT_RDT=0.4 \
SGLANG_CACHE_DIT_MC=4 \
SGLANG_CACHE_DIT_TAYLORSEER=true \
SGLANG_CACHE_DIT_TS_ORDER=2 \
sglang generate --model-path black-forest-labs/FLUX.1-dev \
    --prompt "A curious raccoon in a forest"
```

## 性能提示

1. **从默认值开始**：默认参数对大多数模型都表现良好
2. **使用 TaylorSeer**：它通常同时改善速度与质量
3. **调优 R 阈值**：更小 = 质量更好，更大 = 更快
4. **用 SCM 额外提速**：`medium` 预设能在速度与质量之间取得良好平衡
5. **预热很重要**：更高的预热步数 = 更稳定的缓存决策

## 限制

- **SGLang 原生管线**：受支持的管线存在分布式 Cache-DiT 路径。混合 SP+TP 配置会增加通信与缓存协调开销，因此在将其作为生产默认配置之前，请在目标模型与硬件上验证。
- **SCM 最少步数**：SCM 需要 >= 8 个推理步骤才能生效
- **模型支持**：模型必须注册在 Cache-DiT 的 `BlockAdapterRegister` 中，或者拥有 SGLang 自定义块适配器。

## 故障排查

### 低步数时 SCM 被禁用

对于推理步骤少于 8 个的模型（例如 DMD 蒸馏模型），SCM 会自动禁用。DBCache 加速仍然有效。
