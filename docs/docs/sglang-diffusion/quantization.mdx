SGLang-Diffusion 支持量化的 transformer 检查点。多数情况下，把基础模型和量化 transformer 覆盖分开。

<Note>
💡 AI Infra 学习笔记：扩散模型量化和 LLM 量化有个关键区别：扩散的主干是 DiT，去噪过程中每一步的激活分布都在变，所以在线量化必须动态量化激活（W8A8/W4A4），而不能像 LLM 那样用静态定标；同时生成任务对量化误差很敏感，通常要把调制层（modulation）、时间步嵌入、首尾 transformer 块等关键路径留在 BF16。格式选择（FP8/NVFP4/INT4）还要和 kernel 后端（TensorRT-LLM/CUTLASS FP4 GEMM）配合，才能既省显存又吃到低精度计算的红利——这也正是"量化不只是换精度，而是精度-质量-后端三者权衡"的体现。
</Note>

## 快速参考

使用这些路径：

- `--model-path`：基础模型或原始模型
- `--transformer-path`：已量化、自带 `config.json` 的 transformers 风格 transformer 组件目录
- `--transformer-weights-path`：以单个 safetensors 文件、分片 safetensors 目录、本地路径或 Hugging Face 仓库 ID 提供的量化 transformer 权重
- `--quantization`：在加载时对未量化模型应用在线量化（激活动态量化）
- `--quantization-ignored-layers`：保持未量化的层名模式（例如 `attention.to_`）

预量化检查点的推荐示例：

```bash
sglang generate \
  --model-path black-forest-labs/FLUX.2-dev \
  --transformer-weights-path black-forest-labs/FLUX.2-dev-NVFP4 \
  --prompt "a curious pikachu"
```

对量化的 transformers 风格 transformer 组件文件夹：

```bash
sglang generate \
  --model-path /path/to/base-model \
  --transformer-path /path/to/quantized-transformer \
  --prompt "A Logo With Bold Large Text: SGL Diffusion"
```

注意：某些模型专属集成也接受把量化仓库或本地目录直接作为 `--model-path`，但那是兼容路径。如果仓库里包含多个候选检查点，请显式传入 `--transformer-weights-path`。

## 在线量化

在线量化在加载时对未量化模型应用量化。当没有预量化检查点可用时很有用。

### FP8 在线量化

对任意未量化模型应用 FP8 量化：

```bash
sglang generate \
  --model-path Tongyi-MAI/Z-Image-Turbo \
  --quantization fp8 \
  --prompt "a beautiful sunset" \
  --save-output
```

MiniMax-H3 支持这条路径，同时保留其必需的 FP32 patch、timestep 和输出投影。其分布式服务配方见
[MiniMax-H3 cookbook](/cookbook/diffusion/MiniMax/MiniMax-H3#7-runtime-feature-recipes)。

### MXFP4 在线量化

MXFP4 通过在线量化提供激进的 4 位压缩。**注意：需要 ROCm 和 MI350+（gfx95x）GPU。**

```bash
sglang generate \
  --model-path Tongyi-MAI/Z-Image-Turbo \
  --quantization mxfp4 \
  --prompt "a beautiful sunset" \
  --save-output
```
**注意：** 需要带 MXFP4 kernel 支持的 `aiter` 包

### 跳过某些层

默认情况下，在线量化会量化 transformer 中的每个线性层。不过可以用 `--quantization-ignored-layers` 让特定层保持原始精度：

```bash
sglang generate \
  --model-path Tongyi-MAI/Z-Image-Turbo \
  --quantization fp8 \
  --quantization-ignored-layers attention.to_ \
  --prompt "a beautiful sunset" \
  --save-output

sglang generate \
  --model-path Tongyi-MAI/Z-Image-Turbo \
  --quantization mxfp4 \
  --quantization-ignored-layers attention.to_ \
  --prompt "a beautiful sunset" \
  --save-output
```

每个模式都会与完整层前缀匹配（例如 `layers.0.attention.to_q`）。如果某个层的前缀包含任意给定模式，该层就会被跳过并保持未量化。

## ModelOpt FP8

### 用法示例

转换后的 ModelOpt FP8 transformer 仓库应以 transformer 组件覆盖的方式加载。如果仓库或本地目录已包含 `config.json`，使用 `--transformer-path`。像 NVIDIA Wan2.2 FP8 检查点这样的完整 Diffusers 仓库可以直接用 `--model-path` 传入。

```bash
sglang generate \
  --model-path black-forest-labs/FLUX.2-dev \
  --transformer-path lmsys/flux2-dev-modelopt-fp8-sglang-transformer \
  --prompt "A Logo With Bold Large Text: SGL Diffusion" \
  --save-output
```

```bash
sglang generate \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --transformer-path lmsys/wan22-t2v-a14b-modelopt-fp8-sglang-transformer \
  --prompt "a fox walking through neon rain" \
  --save-output
```

```bash
sglang generate \
  --model-path hunyuanvideo-community/HunyuanVideo \
  --transformer-path lmsys/hunyuanvideo-modelopt-fp8-sglang-transformer \
  --height 544 --width 960 --num-frames 17 \
  --prompt "A cinematic shot of a red sports car driving through rain at night" \
  --save-output
```

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --transformer-path lmsys/qwen-image-modelopt-fp8-sglang-transformer \
  --prompt "A tiny astronaut reading a book under a glass greenhouse" \
  --save-output
```

```bash
sglang generate \
  --model-path Qwen/Qwen-Image-Edit-2511 \
  --transformer-path lmsys/qwen-image-edit-modelopt-fp8-sglang-transformer \
  --image-path /path/to/input.png \
  --prompt "Turn the scene into a warm watercolor illustration" \
  --save-output
```

### 说明

- `--transformer-path` 是转换后、已带 `config.json` 的 ModelOpt FP8 transformer 组件仓库或目录的规范参数。
- 如果覆盖仓库或本地目录自带 `config.json`，SGLang 会从该覆盖中读取量化配置，而不是依赖基础模型配置。
- 当你刻意指向原始权重文件、或一个应先按权重做元数据探测的目录时，`--transformer-weights-path` 仍然可用。
- ModelOpt FP8 检查点支持 `dit_layerwise_offload`。
- ModelOpt FP8 检查点的 `dit_cpu_offload` 仍保持禁用。
- 逐层卸载路径现在会保留运行时 FP8 GEMM 路径期望的非连续 FP8 权重步长。
- 在磁盘上，量化配置保持 `quant_method=modelopt` 且 `quant_algo=FP8`；本文档中的 `modelopt-fp8` 标签是支持家族名称，不是序列化配置键。
- 要从 ModelOpt diffusers 导出手动构建转换后的检查点，使用 `python -m sglang.multimodal_gen.tools.build_modelopt_fp8_transformer`。

## ModelOpt NVFP4

### 用法示例

对已包含 `config.json` 的混合 ModelOpt NVFP4 transformer 覆盖，保持基础模型和量化 transformer 分离，并使用 `--transformer-path`：

```bash
sglang generate \
  --model-path black-forest-labs/FLUX.1-dev \
  --transformer-path lmsys/flux1-dev-modelopt-nvfp4-sglang-transformer \
  --prompt "A Logo With Bold Large Text: SGL Diffusion" \
  --save-output
```

对官方 FLUX.2 发布版这样的原始 NVFP4 导出，使用 `--transformer-weights-path`：

```bash
sglang generate \
  --model-path black-forest-labs/FLUX.2-dev \
  --transformer-weights-path black-forest-labs/FLUX.2-dev-NVFP4 \
  --prompt "A Logo With Bold Large Text: SGL Diffusion" \
  --save-output
```

SGLang 也支持把 NVFP4 仓库或本地目录直接作为 `--model-path` 传入：

```bash
sglang generate \
  --model-path black-forest-labs/FLUX.2-dev-NVFP4 \
  --prompt "A Logo With Bold Large Text: SGL Diffusion" \
  --save-output
```

对只有主 `transformer` 被量化的双 transformer Wan2.2 导出：

```bash
sglang generate \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --transformer-path lmsys/wan22-t2v-a14b-modelopt-nvfp4-sglang-transformer \
  --prompt "a fox walking through neon rain" \
  --save-output
```

对完整的 Qwen Image NVFP4 导出，直接加载已发布仓库：

```bash
sglang generate \
  --model-path lmsys/qwen-image-2512-modelopt-nvfp4-sglang \
  --prompt "A tiny astronaut reading a book under a glass greenhouse" \
  --save-output
```

在 B200 上做高分辨率 Qwen-Image 家族生成时，FlashInfer CUTLASS FP4 GEMM 后端可能比默认的 TensorRT-LLM 后端更快：

```bash
SGLANG_DIFFUSION_FLASHINFER_FP4_GEMM_BACKEND=cutlass \
sglang generate \
  --model-path lmsys/qwen-image-2512-modelopt-nvfp4-sglang \
  --width 2048 --height 2048 \
  --prompt "A tiny astronaut reading a book under a glass greenhouse" \
  --save-output
```

### 说明

- 对已包含 `config.json` 的混合 ModelOpt NVFP4 transformer 仓库或本地目录，使用 `--transformer-path`。
- 对原始 NVFP4 导出、单个 safetensors 文件、或应优先按权重处理的仓库布局，使用 `--transformer-weights-path`。
- 对 `Wan2.2-T2V-A14B-Diffusers` 这样的双 transformer 流水线，主 `--transformer-path` 覆盖只作用于 `transformer`。只有当你有意要非默认的 `transformer_2` 时，才使用 `--transformer-2-path` 这样的按组件覆盖。
- 在 Blackwell 上，扩散 ModelOpt NVFP4 路径默认使用 FlashInfer TensorRT-LLM FP4 GEMM（`flashinfer_trtllm`）。
- 已发布的 Qwen Image NVFP4 导出把 `img_mod`/`txt_mod` 调制投影和首/尾 transformer 块保持在 BF16。
- Qwen-Image NVFP4 在 1024x1024 下并不总能改善延迟。在 B200 上，经过验证的 ModelOpt 导出在 2048x2048 配合 `SGLANG_DIFFUSION_FLASHINFER_FP4_GEMM_BACKEND=cutlass` 时比 BF16 快，而 1024x1024 仍是 BF16 更快。
- 直接 `--model-path` 加载是完整 Qwen Image ModelOpt NVFP4 仓库的规范路径，也是 FLUX.2 NVFP4 风格仓库或本地目录的兼容路径。
- 如果显式提供了 `--transformer-weights-path`，它优先于兼容的 `--model-path` 流程。
- 对本地目录，SGLang 先查找 `*-mixed.safetensors`，再回退到从目录加载。
- 要把扩散 ModelOpt FP4 路径强制到不同的 FlashInfer 后端，设置 `SGLANG_DIFFUSION_FLASHINFER_FP4_GEMM_BACKEND`。支持的值包括 `flashinfer_cudnn`、`flashinfer_cutlass` 和 `flashinfer_trtllm`。
- 在磁盘上，量化配置保持 `quant_method=modelopt` 且 `quant_algo=NVFP4`；这里的 `modelopt-nvfp4` 标签同样是文档家族名称，而不是序列化配置键。

### 用法示例

推荐的自动检测流程：

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --transformer-weights-path /path/to/svdq-int4_r32-qwen-image.safetensors \
  --prompt "a beautiful sunset" \
  --save-output
```

当文件名没有编码量化设置时手动覆盖：

```bash
sglang generate \
  --model-path Qwen/Qwen-Image \
  --transformer-weights-path /path/to/custom_nunchaku_checkpoint.safetensors \
  --enable-svdquant \
  --quantization-precision int4 \
  --quantization-rank 128 \
  --prompt "a beautiful sunset" \
  --save-output
```

### 说明

- `--transformer-weights-path` 是 Nunchaku 检查点的规范参数。`quantized_model_path` 等旧配置名会被当作兼容别名。
- 只有当检查点 basename 匹配 `svdq-(int4|fp4)_r{rank}` 时才会自动检测。
- CLI 值是 `int4` 和 `nvfp4`。在文件名中，NVFP4 变体写作 `fp4`。
- Lightning 检查点通常期望匹配的 `--num-inference-steps`，例如 `4` 或 `8`。
- 当前运行时验证只允许 Nunchaku 在 NVIDIA CUDA Ampere（SM8x）或 SM12x GPU 上运行。Hopper（SM90）目前会被拒绝。

## [ModelSlim](https://gitcode.com/Ascend/msmodelslim) {#modelslim}
MindStudio-ModelSlim（msModelSlim）是 MindStudio 推出的模型离线量化压缩工具，针对昇腾硬件优化。

- **安装**

    ```bash
    # Clone repo and install msmodelslim:
    git clone https://gitcode.com/Ascend/msmodelslim.git
    cd msmodelslim
    bash install.sh
    ```

- **Multimodal_sd 量化**

    下载大模型的原始浮点权重。以 Wan2.2-T2V-A14B 为例，你可以到 [Wan2.2-T2V-A14B](https://modelscope.cn/models/Wan-AI/Wan2.2-T2V-A14B) 获取原始模型权重。然后安装其它依赖（与模型相关，参考 modelscope 模型卡）。
    > 注意：你可以在 [modelscope/Eco-Tech](https://modelscope.cn/models/Eco-Tech) 找到预量化且经过验证的模型。

  使用一键量化运行量化（推荐）：

  ```bash
  msmodelslim quant \
    --model_path /path/to/wan2_2_float_weights \
    --save_path /path/to/wan2_2_quantized_weights \
    --device npu \
    --model_type Wan2_2 \
    --quant_type w8a8 \
    --trust_remote_code True
  ```

  更详细的模型量化示例及其支持情况，见 ModelSLim 仓库的 [examples](https://gitcode.com/Ascend/msmodelslim/blob/master/example/multimodal_sd/README.md) 部分。

  > 注意：SGLang 不支持量化嵌入，用 msmodelslim 量化时请禁用该选项。

- **自动检测与不同格式**

    对 msmodelslim 检查点，只需指定 ```--model-path``` 即可，量化检测会根据解析 `quant_model_description.json` 配置自动逐层完成。

    对 `Wan2.2`，只支持 `Diffusers` 权重存储格式，而 modelslim 会把量化模型保存为原始的 `Wan2.2` 格式。
    转换请用一步式的 `wan_repack.py` 脚本：

    ```bash
    python wan_repack.py \
      --model-type Wan2.2-TI2V-5B \
      --original-model-path {path_to_original_diffusers_model} \
      --quant-path {path_to_quantized_model} \
      --output-path {path_to_converted_model}
    ```

    支持的 `--model-type` 值：`Wan2.2-TI2V-5B`（单 transformer）、`Wan2.2-T2V-A14B` 和 `Wan2.2-I2V-A14B`（级联双 transformer）。
    该脚本自动处理：复制基础模型、把量化权重转换为 Diffusers 格式、以及恢复 `config.json`。

- **用法示例**

    使用自动检测流程：

    ```bash
    sglang generate \
      --model-path Eco-Tech/Wan2.2-T2V-A14B-Diffusers-w8a8 \
      --prompt "a beautiful sunset" \
      --save-output
    ```

- **可用量化方法**：
    - [x]  ```W4A4_DYNAMIC``` 带激活在线量化的线性层
    - [x]  ```W8A8``` 带激活离线量化的线性层
    - [x]  ```W8A8_DYNAMIC``` 带激活在线量化的线性层
    - [x]  ```W8A8_MXFP8``` 带离线量化的线性层（msmodelslim 预量化权重）
    - [x]  ```mxfp8``` 带激活在线量化的线性层（`--quantization mxfp8`）
    - [x]  ```W4A4_MXFP4``` / ```W4A4_MXFP4_DUALSCALE``` 带离线量化的线性层（msmodelslim 预量化权重）
    - [x]  ```mxfp4_npu``` 带激活在线量化的线性层（`--quantization mxfp4_npu`）

## MXFP8 在线量化

在线 MXFP8 量化：加载原始 FP16/BF16 模型并加上 `--quantization mxfp8`。
权重在加载时通过 `npu_dynamic_mx_quant` 量化，激活在推理期间用 `npu_quant_matmul`（block_size=32）逐 token 量化。

```bash
sglang generate \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --quantization mxfp8 \
  --prompt "a fox walking through neon rain" \
  --save-output
```

> **硬件要求：** 昇腾 A5 系列或更新版本。`npu_dynamic_mx_quant` 在 A2/A3 上不可用。

## MXFP8 离线量化（msmodelslim）

msmodelslim 导出的预量化 MXFP8 权重会通过 `quant_model_description.json`（`W8A8_MXFP8` 方案）自动检测。用 `wan_repack.py` 把量化权重转换为 Diffusers 格式，然后用 `--model-path` 加载转换后的模型：

```bash
sglang generate \
  --model-path Eco-Tech/Wan2.2-T2V-A14B-Diffusers-mxfp8 \
  --prompt "a beautiful sunset" \
  --save-output
```

## MXFP4 在线量化

在昇腾 NPU 上做在线 MXFP4 量化：加载原始 FP16/BF16 模型并加上
`--quantization mxfp4_npu`。在昇腾上使用 `mxfp4_npu` 键，因为 `mxfp4`
保留给 ROCm/aiter 后端。

权重在加载时通过 `npu_dynamic_dual_level_mx_quant` 量化，激活在推理期间、`npu_dual_level_quant_matmul` 之前逐 token 量化。MXFP4 使用双层块缩放，L1 块大小为 32，L0 块大小为 512。

```bash
sglang generate \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --quantization mxfp4_npu \
  --prompt "a fox walking through neon rain" \
  --save-output
```

> **硬件要求：** 昇腾 A5 系列或更新版本。`npu_dynamic_dual_level_mx_quant`
> 和 `npu_dual_level_quant_matmul` 在 A2/A3 上不可用。
>
> **注意：** 在线 MXFP4 权重量化是实验性的。离线 msmodelslim
> 流程使用预量化权重，可能产生不同的数值结果。

## MXFP4 离线量化（msmodelslim）

msmodelslim 导出的预量化 MXFP4 权重会通过
`quant_model_description.json`（`W4A4_MXFP4` / `W4A4_MXFP4_DUALSCALE` 方案）自动检测。
用 `wan_repack.py` 把量化权重转换为 Diffusers 格式，然后用 `--model-path` 加载转换后的模型：

```bash
sglang generate \
  --model-path {path_to_converted_mxfp4_model} \
  --prompt "a beautiful sunset" \
  --save-output
```

离线 MXFP4 检查点把权重存放在 FP8 容器中，并包含双层
缩放（`weight_scale`、`weight_dual_scale`）。如果使用平滑量化导出，
`mul_scale` 会被加载并在激活量化前应用，使激活与校准后的权重对齐。
