    description: "把 SGLang Diffusion 流水线拆分为独立的编码器、去噪器和解码器服务，实现分离部署。"
---

把单体式文生视频/图流水线拆分为独立的 **Encoder（编码器）**、**Denoiser（去噪器）** 和 **Decoder（解码器）** 角色，各自运行在各自的 GPU 上。一个中央 **DiffusionServer** 负责把请求在流水线中路由。

<Note>
💡 AI Infra 学习笔记：分离部署（disaggregation）的思路源于 LLM 推理里的 PD 分离——prefill 阶段计算密集、decode 阶段受内存带宽约束，两者混跑会互相拖累，拆开后可独立扩缩容。扩散推理同样适用：DiT 去噪循环（Denoiser）是计算量最大的瓶颈（几十步迭代），而文本/图像编码（Encoder）和 VAE 解码（Decoder）相对轻量且各自有独立的扩展需求。把三者拆成独立服务，就能按各自负载独立加 GPU、做缓存或换硬件，代价是多了进程间张量传输与调度协调的开销。面试中常问的"为什么服务化推理要拆分阶段"正可以从这个角度回答。
</Note>

## 快速上手

分离部署由单个参数控制：`--disagg-role`。每个组件独立启动，和 LLM 的 PD 分离方式一样。

> 每个阶段通过 `PipelineStage` 上的 `role_affinity` 属性声明自己的角色（默认 `ENCODER`）。当 `--disagg-role` 不是 `monolithic` 时，流水线只实例化亲和性匹配的阶段，所以上表是每个进程实际运行内容的唯一权威来源。

### 单机示例（已验证）

以下命令已在 8×H200 机器上使用 `Wan-AI/Wan2.1-T2V-1.3B-Diffusers` 端到端测试通过。每个角色通过 `--base-gpu-id` 运行在单独的 GPU 上；`server` 头节点不需要 GPU。

```bash
# Terminal 1: Encoder (GPU 0)
sglang serve --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
    --disagg-role encoder \
    --disagg-server-addr tcp://127.0.0.1:19655 \
    --scheduler-port 19000 \
    --num-gpus 1 --base-gpu-id 0

# Terminal 2: Denoiser (GPU 1)
sglang serve --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
    --disagg-role denoiser \
    --disagg-server-addr tcp://127.0.0.1:19655 \
    --scheduler-port 19001 \
    --num-gpus 1 --base-gpu-id 1

# Terminal 3: Decoder (GPU 2)
sglang serve --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
    --disagg-role decoder \
    --disagg-server-addr tcp://127.0.0.1:19655 \
    --scheduler-port 19002 \
    --num-gpus 1 --base-gpu-id 2

# Terminal 4: DiffusionServer head (no GPU, receives HTTP requests)
sglang serve --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
    --disagg-role server \
    --encoder-urls  "tcp://127.0.0.1:19000" \
    --denoiser-urls "tcp://127.0.0.1:19001" \
    --decoder-urls  "tcp://127.0.0.1:19002" \
    --host 0.0.0.0 --port 22000 \
    --scheduler-port 19655

# Send request (video generation)
curl http://127.0.0.1:22000/v1/videos \
    -H "Content-Type: application/json" \
    -d '{"model": "Wan-AI/Wan2.1-T2V-1.3B-Diffusers", "prompt": "A curious raccoon exploring a garden, cinematic", "size": "832x480"}'
```

> **测试结果（8×H200）：**
> Encoder 2.3 s（TextEncoding）→ Denoiser 312.8 s（50 步，逐层卸载）→ Decoder 7.1 s（VAE 解码）。
> 81 帧 1024×1024 视频总计约 322 s。

> **提示：** `--base-gpu-id` 控制该角色使用哪块物理 GPU。
> Encoder 和 Decoder 可以共用一块 GPU（例如都设 `--base-gpu-id 0`）以节省资源，
> 但要确保合并后的 GPU 内存足够。

### 多机示例

CLI 模式完全一样——只需把 `127.0.0.1` 换成实际 IP，并加上用于直接传输的 RDMA 参数：

```bash
# Machine A (10.0.0.1): Encoder
sglang serve --model-path Wan-AI/Wan2.1-T2V-14B-Diffusers \
    --disagg-role encoder \
    --disagg-server-addr tcp://10.0.0.4:19655 \
    --scheduler-port 19000 \
    --num-gpus 1 \
    --disagg-p2p-hostname 10.0.0.1 --disagg-ib-device mlx5_0

# Machine B (10.0.0.2): Denoiser (4 GPUs with SP)
sglang serve --model-path Wan-AI/Wan2.1-T2V-14B-Diffusers \
    --disagg-role denoiser \
    --disagg-server-addr tcp://10.0.0.4:19655 \
    --scheduler-port 19001 \
    --num-gpus 4 --denoiser-sp 4 --denoiser-ulysses 2 --denoiser-ring 2 \
    --disagg-p2p-hostname 10.0.0.2 --disagg-ib-device mlx5_0

# Machine C (10.0.0.3): Decoder
sglang serve --model-path Wan-AI/Wan2.1-T2V-14B-Diffusers \
    --disagg-role decoder \
    --disagg-server-addr tcp://10.0.0.4:19655 \
    --scheduler-port 19002 \
    --num-gpus 1 \
    --disagg-p2p-hostname 10.0.0.3 --disagg-ib-device mlx5_0

# Machine D (10.0.0.4): DiffusionServer head
sglang serve --model-path Wan-AI/Wan2.1-T2V-14B-Diffusers \
    --disagg-role server \
    --encoder-urls  "tcp://10.0.0.1:19000" \
    --denoiser-urls "tcp://10.0.0.2:19001" \
    --decoder-urls  "tcp://10.0.0.3:19002" \
    --host 0.0.0.0 --port 30000 \
    --scheduler-port 19655 \
    --disagg-dispatch-policy max_free_slots
```

> ZMQ 能优雅地处理启动顺序——实例和头节点可以任意顺序启动。

## 每个角色的多实例

在 `--*-urls` 中用分号注册多个实例：

```bash
# 2 encoders + 2 denoisers (4-GPU SP each) + 1 decoder
sglang serve --model-path ... --disagg-role server \
    --encoder-urls  "tcp://10.0.0.1:35000;tcp://10.0.0.2:35000" \
    --denoiser-urls "tcp://10.0.0.3:35000;tcp://10.0.0.4:35000" \
    --decoder-urls  "tcp://10.0.0.5:35000"
```

## 传输机制

角色之间的张量数据（encoder→denoiser、denoiser→decoder）通过 P2P 传输引擎传递。DiffusionServer 只路由轻量控制消息（alloc/push/ready）；真正的张量数据直接在实例之间流动。

扩散模型的分离部署需要 **mooncake-transfer-engine**。它提供 RDMA 支持 GPU 到 GPU 的直接数据传输。

```bash
pip install mooncake-transfer-engine
```

### 传输流程

1. **发送方**（encoder/denoiser）暂存张量：异步拷贝到传输缓冲区（GPU 或 CPU 锁页，取决于 GPUDirect 支持情况），与元数据 JSON 序列化重叠进行。
2. **发送方**向 DiffusionServer 发送 `transfer_staged` 控制消息（只含元数据，不含张量数据）。
3. **DiffusionServer** 向接收方发送 `transfer_alloc` → 接收方分配缓冲区槽位 → 回复 `transfer_allocated`。
4. **DiffusionServer** 向接收方发送带发送方地址信息的 `transfer_push`。
5. **接收方**通过传输引擎（Mooncake RDMA 或 mock）拉取数据，发送 `transfer_ready`。
6. **接收方**在专用传输流上异步加载张量，与上一个请求的计算重叠进行。

解码器结果（最终输出）以原始 ZMQ 帧的形式经 DiffusionServer 回流到 HTTP 客户端。

## Python API

要用编程方式做单机部署，可以使用 `launch_pool_disagg_server()`：

```python
from sglang.multimodal_gen.runtime.server_args import ServerArgs
from sglang.multimodal_gen.runtime.launch_server import launch_pool_disagg_server

server_args = ServerArgs.from_kwargs(
    model_path="Wan-AI/Wan2.1-T2V-14B-Diffusers",
    denoiser_sp=4, denoiser_ulysses=2, denoiser_ring=2,
    disagg_ib_device="mlx5_0",
)

launch_pool_disagg_server(
    server_args,
    encoder_gpus=[[0]],
    denoiser_gpus=[[1, 2, 3, 4], [5, 6, 7, 8]],
    decoder_gpus=[[0]],
)
```

## 架构

```
Client ─── HTTP (port 30000) ──► FastAPI Server
                                      │
                                      ▼
                              DiffusionServer (ROUTER, scheduler_port)
                              ┌───────┼───────┐
                   PUSH work  │       │       │  PUSH work
                              ▼       │       ▼
                    Encoder[0..N]     │    Decoder[0..K]
                              │       │       ▲
                   P2P tensor │       │       │ P2P tensor
                   transfer   ▼       │       │ transfer
                          Denoiser[0..M] ─────┘
                                      │
                    PULL results ◄────┘  (decoder → DS → client)
```

### 请求状态机

```
PENDING → ENCODER_WAITING → ENCODER_RUNNING → ENCODER_DONE
                                                    │
                        DENOISING_WAITING → DENOISING_RUNNING → DENOISING_DONE
                                                                       │
                                    DECODER_WAITING → DECODER_RUNNING → DONE
```

任何状态都可以转换到 `FAILED` 或 `TIMED_OUT`。
