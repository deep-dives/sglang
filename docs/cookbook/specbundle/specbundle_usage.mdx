## 关于 SpecBundle

投机解码（speculative decoding），尤其是 EAGLE3，既有很强的理论保证，也在 token 接受率和端到端推理速度上带来稳定的实证提升。然而，尽管有这些进展，投机解码——特别是 EAGLE3——在开源生态中的采用仍然有限，主要原因有三个。

1. 缺乏生产可用的训练基础设施：现有的投机解码工具链大多是研究原型，系统级优化有限，对多样化的架构和大规模模型支持不足。
2. 高质量草稿模型稀缺：有效的投机解码依赖强力的草稿模型，而公开可用的 EAGLE3 兼容检查点极少，主要来自原作者。
3. 现有草稿模型的训练规模不足：大多数可用的草稿模型都是在小型或经过挑选的数据集上训练的，无法泛化到现代 LLM 训练所用的大规模多样语料，导致 token 接受率低、实际加速效果大打折扣。

<Note>
💡 AI Infra 学习笔记：投机解码的核心思路是让一个更小的「草稿模型」快速猜测多个 token，再由目标模型一次性并行验证；猜中的 token 越多，实际加速越明显。EAGLE3 是其中的代表方案，它复用目标模型的隐藏状态做自回归草稿，接受率更高。草稿模型质量直接决定收益，这正是 SpecBundle 致力于补齐高质量草稿权重的背景。
</Note>

**SpecBundle** 正是针对这些局限的直接回应。它由开源社区与 **蚂蚁集团**（Ant Group）、**美团**（Meituan）、**Nex-AGI**、**EigenAI** 等产业伙伴共同推动，是**首个开放计划**，旨在普及投机解码——为主流开源 LLM 提供高性能、生产级的 EAGLE3 草稿模型权重。这一计划也通过多种规模与架构来验证 [**SpecForge**](https://github.com/sgl-project/SpecForge) 框架的健壮性。

## 使用方法

### 用 SpecBundle 模型启动 SGLang 服务端

可以用下面的命令用 SpecBundle 模型启动 SGLang 服务端。遇到内存问题时，请加上 `--tp`、`--ep` 和 `--mem-fraction-static` 参数。

```bash Command
python3 -m sglang.launch_server \
    --model <target-model-path> \
    --speculative-algorithm EAGLE3 \
    --speculative-draft-model-path <draft-model-path> \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 4
```

例如：

```bash Command
SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1 python3 -m sglang.launch_server \
    --model Qwen/Qwen3-30B-A3B-Instruct-2507 \
    --speculative-algorithm EAGLE3 \
    --speculative-draft-model-path lmsys/SGLang-EAGLE3-Qwen3-30B-A3B-Instruct-2507-SpecForge-Nex \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 4 \
    --tp 4
```

### 用 SpecBundle 对比投机解码草稿模型的性能

我们提供了一个基准测试套件，用来评估 SpecBundle 草稿模型的性能，见[这里](https://github.com/sgl-project/SpecForge/tree/main/benchmarks)。

#### 示例：

1. 启动一个 SGLang 服务端

```bash Command
SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1 python3 -m sglang.launch_server \
    --model Qwen/Qwen3-30B-A3B-Instruct-2507 \
    --speculative-algorithm EAGLE3 \
    --speculative-draft-model-path lmsys/SGLang-EAGLE3-Qwen3-30B-A3B-Instruct-2507-SpecForge-Nex \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 4 \
    --tp 4
```

2. 用基准测试套件评估 SpecBundle 草稿模型的性能

`bench_eagle3.py` 可以同时启动一个 SGLang 服务端进程和一个基准测试进程。这样你就不用手动启动 SGLang 服务端了——脚本会在不同的投机解码配置下自动处理 SGLang 的启动。一些重要参数如下：

- `--model-path`：目标模型的路径。
- `--speculative-draft-model-path`：草稿模型的路径。
- `--port`：启动 SGLang 服务端的端口。
- `--trust-remote-code`：信任远程代码。
- `--mem-fraction-static`：静态内存占用的比例。
- `--tp-size`：张量并行大小。
- `--attention-backend`：Attention 后端。
- `--config-list`：要测试的投机解码配置列表，格式为 `<batch-size>,<num-steps>,<topk>,<num-draft-tokens>`。
- `--benchmark-list`：要测试的基准测试列表，格式为 `<benchmark-name>:<num-prompts>:<subset>`。

```bash Command
cd SpecForge/benchmarks
python bench_eagle3.py \
    --model-path Qwen/Qwen3-30B-A3B-Instruct-2507 \
    --port 30000 \
    --config-list 1,3,1,4 \
    --benchmark-list mtbench:5 gsm8k:100 \
    --skip-launch-server
```
