## 1. 模型介绍

[Llama-3.3-70B-Instruct](https://huggingface.co/meta-llama/Llama-3.3-70B-Instruct) 是 Meta 最新的 700 亿参数指令微调语言模型，在性能和效率上都优于 Llama 3.1。它拥有 128K token 的上下文窗口，在推理、编码和多语言任务上能力更强，在给出 SOTA 级结果的同时，也保持了生产部署的易用性。

<Note>
💡 AI Infra 学习笔记：70B 模型能单卡部署，核心是显存账。BF16 权重约 140GB，刚好塞进 MI300X 的 192GB——剩下的显存才用来放 KV 缓存和中间激活，所以 `--mem-fraction-static` 和上下文长度就成了能否跑得下的关键。换成 FP8 量化后权重减半（约 70GB），给 KV 缓存留出的空间更大，这也是 FP8 变体（如 `-FP8-KV`）在服务场景里受欢迎的原因。
</Note>

**核心特性：**

- **更强的性能**：指令遵循、推理和任务完成度相对 Llama 3.1 都有提升
- **工具调用**：原生支持函数调用和工具使用场景
- **多语言支持**：针对 8 种语言优化（英语、德语、法语、意大利语、葡萄牙语、印地语、西班牙语和泰语）
- **超长上下文**：128K token 的上下文窗口，可处理长文档和复杂任务
- **部署高效**：70B 参数可在一张 AMD MI300X 上完成部署

### 3.2 配置要点

**AMD GPU 部署：**

- 所有 AMD GPU（MI300X、MI325X、MI355X）在 BF16 和 FP8 版本下都支持 TP=1

### 4.2 进阶用法

#### 4.2.1 工具调用

Llama 3.3 70B Instruct 原生支持工具调用。部署时启用工具解析器：

```shell Command
python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.3-70B-Instruct \
  --tool-call-parser llama3 \
  --tp 1 \
  --host 0.0.0.0 \
  --port 30000
```

**Python 示例：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request
response = client.chat.completions.create(
    model="meta-llama/Llama-3.3-70B-Instruct",
    messages=[
        {"role": "user", "content": "What's the weather in Tokyo?"}
    ],
    tools=tools,
    temperature=0.7
)

# Check for tool calls
message = response.choices[0].message
if message.tool_calls:
    tool_call = message.tool_calls[0]
    print(f"Function: {tool_call.function.name}")
    print(f"Arguments: {tool_call.function.arguments}")
```

**处理工具调用结果：**

```python Example
# After executing the function, send the result back
def get_weather(location, unit="celsius"):
    # Your weather API call here
    return f"The weather in {location} is 22°{unit[0].upper()} and sunny."

# Build conversation with tool result
messages = [
    {"role": "user", "content": "What's the weather in Tokyo?"},
    {
        "role": "assistant",
        "content": None,
        "tool_calls": [{
            "id": "call_123",
            "type": "function",
            "function": {
                "name": "get_weather",
                "arguments": '{"location": "Tokyo", "unit": "celsius"}'
            }
        }]
    },
    {
        "role": "tool",
        "tool_call_id": "call_123",
        "content": get_weather("Tokyo", "celsius")
    }
]

final_response = client.chat.completions.create(
    model="meta-llama/Llama-3.3-70B-Instruct",
    messages=messages,
    temperature=0.7
)

print(final_response.choices[0].message.content)
# Output: "The current weather in Tokyo is 22°C and sunny. A perfect day!"
```

#### 4.2.2 长上下文处理

利用 128K 上下文窗口处理长文档：

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY"
)

# Example with long document
long_document = "..." * 10000  # Your long document here

response = client.chat.completions.create(
    model="meta-llama/Llama-3.3-70B-Instruct",
    messages=[
        {"role": "user", "content": f"Summarize this document:\n\n{long_document}"}
    ],
    temperature=0.7,
    max_tokens=1000
)

print(response.choices[0].message.content)
```

<Note>
💡 AI Infra 学习笔记：长上下文（128K）场景下，KV 缓存随输入长度线性增长，单个请求就可能吃掉数 GB 显存。推理引擎的应对包括分块预填充（chunked prefill）平滑显存峰值、前缀缓存（prefix caching）复用公共前缀，以及 KV 量化。这也是评估长上下文模型能否在生产环境落地时最需要关注的内存维度。
</Note>

## 5. 基准测试

用 SGLang 基准测试套件测试模型在不同负载模式下的表现：

### 5.1 基础基准测试命令

```bash Command
python -m sglang.bench_serving \
  --backend sglang \
  --dataset-name random \
  --num-prompts 1000 \
  --random-input 1024 \
  --random-output 1024 \
  --max-concurrency 16
```

### 5.2 调整基准测试参数

**输入/输出长度**：调整 `--random-input` 和 `--random-output`，测试不同的负载模式：

- 短对话：`--random-input 1024 --random-output 1024`
- 长输出：`--random-input 1024 --random-output 8192`
- 长输入：`--random-input 8192 --random-output 1024`

**并发级别**：调整 `--max-concurrency`，测试不同的负载场景：

- 低并发（偏重延迟）：`--max-concurrency 1 --num-prompts 100`
- 中等并发（均衡）：`--max-concurrency 16 --num-prompts 1000`
- 高并发（偏重吞吐）：`--max-concurrency 100 --num-prompts 2000`
