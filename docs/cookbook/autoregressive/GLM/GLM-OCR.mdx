## 1. 模型介绍

[GLM-OCR](https://huggingface.co/zai-org/GLM-OCR) 是一个面向复杂文档理解的多模态 OCR 模型，基于 GLM-V 编码器—解码器架构构建。它引入了多 token 预测（MTP）损失和稳定的全任务强化学习，以提升训练效率、识别准确率和泛化能力。

该模型集成了在大规模图文数据上预训练的 CogViT 视觉编码器、带高效 token 下采样的轻量跨模态连接器，以及 GLM-0.5B 语言解码器。再结合基于 PP-DocLayout-V3 的「版面分析 + 并行识别」两阶段流水线，GLM-OCR 能在多样的文档版式上提供稳健、高质量的 OCR 性能。

**硬件支持：** NVIDIA B200/H100/H200

<Note>
💡 AI Infra 学习笔记：OCR/文档理解是典型的多模态推理负载——图像先经视觉编码器（CogViT）变成视觉 token，再经轻量跨模态连接器下采样后送入语言解码器。只有 0.9B 参数让这种模型特别「轻」：推理延迟和算力成本都很低，天然适合高并发和边缘部署，也让「文档解析 + LLM 后处理」的流水线成为可能。
</Note>

**主要特性：**

- **SOTA 性能**：在 OmniDocBench V1.5 上取得 94.62 分、排名第一，并在公式识别、表格识别、信息抽取等主要文档理解基准测试上均取得 SOTA 结果。
- **面向真实场景优化**：专门针对实际业务场景优化，在复杂表格、代码文档、印章等棘手版式上仍能保持稳定准确的性能。
- **高效推理**：仅有 0.9B 参数，GLM-OCR 支持通过 vLLM 和 SGLang 部署，显著降低推理延迟和算力成本——非常适合高并发和边缘部署。
- **易于使用**：完全开源，附带完整的 SDK 和推理工具链，支持一行调用、无缝接入现有系统。

更多细节请参考[官方 GLM-OCR 模型卡片](https://huggingface.co/zai-org/GLM-OCR)。

### 3.2 配置技巧

- **CUDA IPC 传输**：设置 `SGLANG_USE_CUDA_IPC_TRANSPORT=1` 环境变量，用 CUDA IPC 传输多模态特征，可显著改善 TTFT。
- **MTP（多 token 预测）**：启用 MTP 使用 EAGLE 投机解码加速推理。该特性一次预测多个 token，从而降低延迟。
- **显存管理**：对显存受限的环境，你可能需要调整 `--mem-fraction-static` 和/或 `--max-running-requests`。

<Note>
💡 AI Infra 学习笔记：这里的两条优化与 GLM-4.5V 一脉相承——多模态特征在「视觉编码器 → 语言模型」之间的搬运是 TTFT 的重要构成，CUDA IPC 共享内存传输能省掉跨进程拷贝；MTP 则用一次预测多个 token 的投机解码降低端到端延迟。小模型 + 轻量优化，正是 OCR 这类高并发服务的典型组合。
</Note>

### 4.2 高级用法

#### 4.2.1 OCR 图像处理

GLM-OCR 支持多种文档类型的 OCR 任务。下面是一个基础示例：

```python Example
import time
from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",
    base_url="http://localhost:30000/v1",
    timeout=3600
)

messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {
                    "url": "https://ofasys-multimodal-wlcb-3-toshanghai.oss-accelerate.aliyuncs.com/wpf272043/keepme/image/receipt.png"
                }
            },
            {
                "type": "text",
                "text": "Please extract all text from this image."
            }
        ]
    }
]

start = time.time()
response = client.chat.completions.create(
    model="zai-org/GLM-OCR",
    messages=messages,
    max_tokens=2048
)
print(f"Response costs: {time.time() - start:.2f}s")
print(f"Generated text: {response.choices[0].message.content}")
```

**输出示例：**

```text Output
Response costs: 2.29s
Generated text: CINNAMON SUGAR
1 x 17,000 17,000

SUB TOTAL 17,000

GRAND TOTAL 17,000

CASH IDR 20,000

CHANGE DUE 3,000

```

#### 4.2.2 复杂文档处理

GLM-OCR 擅长处理复杂文档，包括：

- **表格**：准确抽取表格数据并保留结构
- **公式**：数学公式识别
- **代码文档**：从截图中提取源代码
- **印章**：识别文档中的印章
- **多版式文档**：文本、图像和表格混合的内容

```python Example
import time
from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",
    base_url="http://localhost:30000/v1",
    timeout=3600
)

# Example: Processing a document with tables
messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {
                    "url": "YOUR_DOCUMENT_IMAGE_URL"
                }
            },
            {
                "type": "text",
                "text": "Please extract the table content from this document and format it as markdown."
            }
        ]
    }
]

response = client.chat.completions.create(
    model="zai-org/GLM-OCR",
    messages=messages,
    max_tokens=4096
)
print(response.choices[0].message.content)
```
