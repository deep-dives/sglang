## 1. 模型介绍

[GLM-4.6](https://huggingface.co/zai-org/GLM-4.6) 是智谱 AI 开发的强大语言模型，具备先进的推理、函数调用和多模态理解能力。

作为 GLM 系列的最新迭代，GLM-4.6 在真实世界编码、长上下文处理、推理、搜索、写作和 Agent 应用等多个领域实现了全面增强。具体如下：

- **更长的上下文窗口**：上下文窗口从 128K 扩展到 200K token，让模型能处理更复杂的 Agent 任务。
- **出色的编码能力**：模型在代码基准测试上取得更高分数，在 Claude Code、Cline、Roo Code 和 Kilo Code 等应用中表现更佳，包括生成视觉上更精致的前端页面。
- **先进推理**：GLM-4.6 的推理性能有明显提升，并支持在推理过程中使用工具，整体能力更强。
- **更强的 Agent**：GLM-4.6 在工具使用和基于搜索的 Agent 上表现更强，也能更有效地集成进 Agent 框架。
- **写作更精炼**：在风格和可读性上更贴合人类偏好，角色扮演场景下表现更自然。

更多细节请参考[官方 GLM-4.6 文档](https://docs.z.ai/guides/llm/glm-4.6)。

<Note>
💡 AI Infra 学习笔记：GLM 系列以 Agent 工作负载著称，这类负载对推理引擎有特殊要求——单轮对话里往往既有很长的上下文（此处高达 200K token），又夹杂多轮工具调用。长上下文意味着 prefill 计算量和大尺寸 KV 缓存，工具调用则会产生大量「短输入短输出」的突发请求。这两点直接决定了调度策略、KV 缓存复用（前缀缓存）和显存规划的设计方向。
</Note>

#### 4.2.1 推理解析器（Reasoning Parser）

GLM-4.6 默认支持思考模式。部署时启用推理解析器，即可把思考过程与正文内容分开：

```shell Command
python -m sglang.launch_server \
  --model zai-org/GLM-4.6 \
  --reasoning-parser glm45 \
  --tp 8 \
  --host 0.0.0.0 \
  --port 8000
```

**带思考过程的流式输出：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Enable streaming to see the thinking process in real-time
response = client.chat.completions.create(
    model="zai-org/GLM-4.6",
    messages=[
        {"role": "user", "content": "Solve this problem step by step: What is 15% of 240?"}
    ],
    temperature=0.7,
    max_tokens=2048,
    stream=True
)

# Process the stream
has_thinking = False
has_answer = False
thinking_started = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print answer content
        if delta.content:
            # Close thinking section and add content header
            if has_thinking and not has_answer:
                print("\n=============== Content =================", flush=True)
                has_answer = True
            print(delta.content, end="", flush=True)

print()
```

**输出示例：**

```text Output
=============== Thinking =================
To solve this problem, I need to calculate 15% of 240.
Step 1: Convert 15% to decimal: 15% = 0.15
Step 2: Multiply 240 by 0.15
Step 3: 240 × 0.15 = 36
=============== Content =================

The answer is 36. To find 15% of 240, we multiply 240 by 0.15, which equals 36.
```

**注意：** 推理解析器会捕获模型逐步的思考过程，让你看到模型是如何得出结论的。

#### 4.2.2 工具调用

<Note>
**不同模型使用的解析器名称：** GLM-4.5 和 GLM-4.6 使用 `--tool-call-parser glm45`。GLM-4.7 和 GLM-4.7-Flash 使用 `--tool-call-parser glm47`。所有 GLM 模型无论哪一代都使用 `--reasoning-parser glm45`。
</Note>

GLM-4.6 支持工具调用。启用工具调用解析器：

```shell Command
python -m sglang.launch_server \
  --model zai-org/GLM-4.6 \
  --reasoning-parser glm45 \
  --tool-call-parser glm45 \
  --tp 8 \
  --host 0.0.0.0 \
  --port 8000
```

**Python 示例（带思考过程）：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request with streaming to see thinking process
response = client.chat.completions.create(
    model="zai-org/GLM-4.6",
    messages=[
        {"role": "user", "content": "What's the weather in Beijing?"}
    ],
    tools=tools,
    temperature=0.7,
    stream=True
)

# Process streaming response
thinking_started = False
has_thinking = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print tool calls
        if hasattr(delta, 'tool_calls') and delta.tool_calls:
            # Close thinking section if needed
            if has_thinking and thinking_started:
                print("\n=============== Content =================", flush=True)
                thinking_started = False

            for tool_call in delta.tool_calls:
                if tool_call.function:
                    print(f"🔧 Tool Call: {tool_call.function.name}")
                    print(f"   Arguments: {tool_call.function.arguments}")

        # Print content
        if delta.content:
            print(delta.content, end="", flush=True)

print()
```

**输出示例：**

```text Output
=============== Thinking =================
The user is asking about the weather in Beijing. I need to use the get_weather function to retrieve this information.
I should call the function with location="Beijing".
=============== Content =================

🔧 Tool Call: get_weather
   Arguments: {"location": "Beijing", "unit": "celsius"}
```

**注意：**

- 推理解析器会展示模型是如何决定使用某个工具的
- 工具调用会用函数名和参数清晰地标注出来
- 之后你可以执行该函数，把结果发回给模型以继续对话

**处理工具调用结果：**

```python Example
# After getting the tool call, execute the function
def get_weather(location, unit="celsius"):
    # Your actual weather API call here
    return f"The weather in {location} is 22°{unit[0].upper()} and sunny."

# Send tool result back to the model
messages = [
    {"role": "user", "content": "What's the weather in Beijing?"},
    {
        "role": "assistant",
        "content": None,
        "tool_calls": [{
            "id": "call_123",
            "type": "function",
            "function": {
                "name": "get_weather",
                "arguments": '{"location": "Beijing", "unit": "celsius"}'
            }
        }]
    },
    {
        "role": "tool",
        "tool_call_id": "call_123",
        "content": get_weather("Beijing", "celsius")
    }
]

final_response = client.chat.completions.create(
    model="zai-org/GLM-4.6",
    messages=messages,
    temperature=0.7
)

print(final_response.choices[0].message.content)
# Output: "The weather in Beijing is currently 22°C and sunny."
```

#### 4.2.3 思考预算（Thinking Budget） {#4-2-3-thinking-budget}

用 `CustomLogitProcessor` 限制思考 token 的数量。启动时加上 `--enable-custom-logit-processor`：

```python Example
import openai
from sglang.srt.sampling.custom_logit_processor import Glm4MoeThinkingBudgetLogitProcessor

client = openai.Client(base_url="http://127.0.0.1:30000/v1", api_key="*")
response = client.chat.completions.create(
    model="zai-org/GLM-4.6",
    messages=[{"role": "user", "content": "Is Paris the Capital of France?"}],
    max_tokens=1024,
    extra_body={
        "custom_logit_processor": Glm4MoeThinkingBudgetLogitProcessor().to_str(),
        "custom_params": {"thinking_budget": 512},
    },
)
print(response)
```

#### 5.1.2 并发级别

在三个并发级别下分别测试每个场景，以刻画吞吐量与延迟之间的权衡曲线（帕累托前沿）：

- **低并发**：`--max-concurrency 1`（面向低延迟优化）
- **中并发**：`--max-concurrency 16`（均衡）
- **高并发**：`--max-concurrency 100`（面向高吞吐量优化）

#### 5.1.3 提示词数量

对每个并发级别，配置 `num_prompts` 以模拟真实的用户负载：

- **快速测试**：`num_prompts = concurrency × 1`（最小化测试）
- **推荐**：`num_prompts = concurrency × 5`（标准基准测试）
- **稳定测量**：`num_prompts = concurrency × 10`（生产级）

#### 5.1.5 结果解读

**关键指标：**

- **请求吞吐量（req/s）**：每秒处理的请求数
- **输出 token 吞吐量（tok/s）**：每秒生成的 token 总数
- **平均 TTFT（ms）**：首 token 时间——衡量响应速度
- **平均 TPOT（ms）**：每输出一个 token 的时间——衡量生成速度
- **平均 ITL（ms）**：token 间延迟——衡量流式输出的连贯性

<Note>
💡 AI Infra 学习笔记：TTFT（首 token 时间）、TPOT（每输出 token 时间）和 ITL（token 间延迟）是服务性能的三大核心指标。TTFT 主要受 prefill 阶段影响，反映用户的「第一印象」；TPOT 反映 decode 阶段的单 token 生成速度；ITL 则衡量流式输出的稳定性。三者存在此消彼长的关系——并发越高，通常吞吐量越大，但 TTFT/TPOT 也会随之变差，因此要用「吞吐 vs 延迟」的帕累托前沿来整体评估。
</Note>

**为什么这些配置很重要：**

- **1K/1K（对话）**：代表最常见的对话式 AI 负载，也是大多数部署中优先级最高的场景。
- **1K/8K（推理）**：测试长文本生成能力，对复杂推理、代码生成和详细解释至关重要。
- **8K/1K（摘要）**：评估大上下文输入下的性能，对 RAG 系统、文档问答和摘要任务必不可少。
- **可变并发**：刻画帕累托前沿——不同负载水平下吞吐量与延迟的最优权衡。低并发展示最佳延迟，高并发展示最大吞吐量。

**结果解读方法：**

- 把你的结果与对应硬件的基线数值对比
- 相同延迟下吞吐量更高 = 性能更好
- TTFT 更低 = 用户响应体验更流畅
- TPOT 更低 = 生成速度更快
