## 1. 模型介绍

[GLM-4.7-Flash](https://huggingface.co/zai-org/GLM-4.7-Flash) 是智谱 AI 开发的 GLM-4.7 系列中的轻量高速模型，具备推理、函数调用等先进能力，且特别适合高效的本地部署。

作为 GLM-4.7 家族中的紧凑变体，GLM-4.7-Flash 是一个 **30B-A3B 混合专家（MoE）** 模型，在性能与效率之间取得平衡：

- **轻量架构**：总参数 30B，但每次推理只激活 3B 参数，推理高效
- **增强的推理**：继承了 GLM-4.7 的推理能力，性能经过优化
- **出色的编码**：具备强大的代码生成与理解能力
- **先进的工具使用**：工具调用和 Agent 能力稳健，可应对复杂工作流
- **面向本地部署优化**：专为单卡部署场景设计

更多细节请参考[官方 GLM-4.7 文档](https://docs.z.ai/guides/llm/glm-4.7)。

<Note>
💡 AI Infra 学习笔记：30B-A3B 中的「30B 总参数 / 3B 激活参数」是 MoE（混合专家）模型的典型标记。MoE 把 FFN 层拆成多个专家，每个 token 只激活其中一小部分——这大幅降低了 decode 阶段的计算量，但全部专家权重仍要常驻显存。所以 MoE 是「计算省、显存大」，非常依赖 KV 缓存压缩、专家权重量化等手段，也是推理引擎里专家并行（EP）与负载均衡设计的核心场景。
</Note>

**主要特性：**

- **高效的 MoE 架构**：30B-A3B 稀疏激活，实现性能与效率的最优平衡
- **多种量化方式**：提供 BF16 和 FP8 版本，用于在性能与显存占用之间取舍
- **硬件优化**：专门针对 NVIDIA H100/H200/B200 GPU 调优
- **高性能**：对吞吐量和延迟两类场景都做了优化

**可用模型：**

- **BF16（全精度）**：[zai-org/GLM-4.7-Flash](https://huggingface.co/zai-org/GLM-4.7-Flash)

**许可证：**

许可详情请参考[官方 GLM-4.7-Flash 模型卡片](https://huggingface.co/zai-org/GLM-4.7-Flash)。

#### 4.2.1 推理解析器（Reasoning Parser）

GLM-4.7-Flash 默认支持思考模式。部署时启用推理解析器，即可把思考过程与正文内容分开：

```shell Command
python -m sglang.launch_server \
  --model zai-org/GLM-4.7-Flash \
  --reasoning-parser glm45 \
  --attention-backend triton \
  --tp 1 \
  --host 0.0.0.0 \
  --port 8000
```

**带思考过程的流式输出：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Enable streaming to see the thinking process in real-time
response = client.chat.completions.create(
    model="zai-org/GLM-4.7-Flash",
    messages=[
        {"role": "user", "content": "Solve this problem step by step: What is 15% of 240?"}
    ],
    temperature=0.7,
    max_tokens=2048,
    stream=True
)

# Process the stream
has_thinking = False
has_answer = False
thinking_started = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print answer content
        if delta.content:
            # Close thinking section and add content header
            if has_thinking and not has_answer:
                print("\n=============== Content =================", flush=True)
                has_answer = True
            print(delta.content, end="", flush=True)

print()
```

**输出示例：**

```text Output
=============== Thinking =================
To solve this problem, I need to calculate 15% of 240.
Step 1: Convert 15% to decimal: 15% = 0.15
Step 2: Multiply 240 by 0.15
Step 3: 240 × 0.15 = 36
=============== Content =================

The answer is 36. To find 15% of 240, we multiply 240 by 0.15, which equals 36.
```

**注意：** 推理解析器会捕获模型逐步的思考过程，让你看到模型是如何得出结论的。

#### 4.2.2 工具调用

<Note>
**不同模型使用的解析器名称：** GLM-4.5 和 GLM-4.6 使用 `--tool-call-parser glm45`。GLM-4.7 和 GLM-4.7-Flash 使用 `--tool-call-parser glm47`。所有 GLM 模型无论哪一代都使用 `--reasoning-parser glm45`。
</Note>

GLM-4.7-Flash 支持工具调用。启用工具调用解析器：

```shell Command
python -m sglang.launch_server \
  --model zai-org/GLM-4.7-Flash \
  --reasoning-parser glm45 \
  --tool-call-parser glm47 \
  --attention-backend triton \
  --tp 1 \
  --host 0.0.0.0 \
  --port 8000
```

**Python 示例（带思考过程）：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request with streaming to see thinking process
response = client.chat.completions.create(
    model="zai-org/GLM-4.7-Flash",
    messages=[
        {"role": "user", "content": "What's the weather in Beijing?"}
    ],
    tools=tools,
    temperature=0.7,
    stream=True
)

# Process streaming response
thinking_started = False
has_thinking = False
tool_calls_accumulator = {}

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Accumulate tool calls (tool call deltas may stream in multiple chunks)
        if hasattr(delta, 'tool_calls') and delta.tool_calls:
            for tool_call in delta.tool_calls:
                index = tool_call.index
                if index not in tool_calls_accumulator:
                    tool_calls_accumulator[index] = {
                        'name': None,
                        'arguments': ''
                    }

                if tool_call.function:
                    if tool_call.function.name:
                        tool_calls_accumulator[index]['name'] = tool_call.function.name
                    if tool_call.function.arguments:
                        tool_calls_accumulator[index]['arguments'] += tool_call.function.arguments

        # Print content
        if delta.content:
            print(delta.content, end="", flush=True)

# Print accumulated tool calls
if tool_calls_accumulator:
    print("\n=============== Tool Calls =================", flush=True)
    for index, tool_call in sorted(tool_calls_accumulator.items()):
        print(f"Tool Call: {tool_call['name']}")
        print(f"   Arguments: {tool_call['arguments']}")

print()
```

**输出示例：**

```text Output
=============== Thinking =================
The user is asking for the weather in Beijing. I have the get_weather function available which can provide weather information for a location. The required parameter is "location" and the
 user has provided "Beijing". There's an optional parameter "unit" for temperature unit, but the user hasn't specified which unit they prefer, and since it's optional, I should not ask about it or make up a value for it. I'll call the function with just the location parameter.I'll check the current weather in Beijing for you.
=============== Tool Calls =================
Tool Call: get_weather
   Arguments: {"location": "Beijing"}

```

**注意：**

- 推理解析器会展示模型是如何决定使用某个工具的
- 工具调用会用函数名和参数清晰地标注出来
- 之后你可以执行该函数，把结果发回给模型以继续对话

**处理工具调用结果：**

```python Example
# After getting the tool call, execute the function
def get_weather(location, unit="celsius"):
    # Your actual weather API call here
    return f"The weather in {location} is 22°{unit[0].upper()} and sunny."

# Send tool result back to the model
messages = [
    {"role": "user", "content": "What's the weather in Beijing?"},
    {
        "role": "assistant",
        "content": None,
        "tool_calls": [{
            "id": "call_123",
            "type": "function",
            "function": {
                "name": "get_weather",
                "arguments": '{"location": "Beijing", "unit": "celsius"}'
            }
        }]
    },
    {
        "role": "tool",
        "tool_call_id": "call_123",
        "content": get_weather("Beijing", "celsius")
    }
]

final_response = client.chat.completions.create(
    model="zai-org/GLM-4.7-Flash",
    messages=messages,
    temperature=0.7
)

print(final_response.choices[0].message.content)
# Output: "The weather in Beijing is currently 22°C and sunny."
```

#### 5.1.2 并发级别

在三个并发级别下分别测试每个场景，以刻画吞吐量与延迟之间的权衡曲线（帕累托前沿）：

- **低并发**：`--max-concurrency 1`（面向低延迟优化）
- **中并发**：`--max-concurrency 16`（均衡）
- **高并发**：`--max-concurrency 100`（面向高吞吐量优化）

#### 5.1.3 提示词数量

对每个并发级别，配置 `num_prompts` 以模拟真实的用户负载：

- **快速测试**：`num_prompts = concurrency × 1`（最小化测试）
- **推荐**：`num_prompts = concurrency × 5`（标准基准测试）
- **稳定测量**：`num_prompts = concurrency × 10`（生产级）

#### 5.1.5 结果解读

**关键指标：**

- **请求吞吐量（req/s）**：每秒处理的请求数
- **输出 token 吞吐量（tok/s）**：每秒生成的 token 总数
- **平均 TTFT（ms）**：首 token 时间——衡量响应速度
- **平均 TPOT（ms）**：每输出一个 token 的时间——衡量生成速度
- **平均 ITL（ms）**：token 间延迟——衡量流式输出的连贯性

**为什么这些配置很重要：**

- **1K/1K（对话）**：代表最常见的对话式 AI 负载，也是大多数部署中优先级最高的场景。
- **1K/8K（推理）**：测试长文本生成能力，对复杂推理、代码生成和详细解释至关重要。
- **8K/1K（摘要）**：评估大上下文输入下的性能，对 RAG 系统、文档问答和摘要任务必不可少。
- **可变并发**：刻画帕累托前沿——不同负载水平下吞吐量与延迟的最优权衡。低并发展示最佳延迟，高并发展示最大吞吐量。

**结果解读方法：**

- 把你的结果与对应硬件的基线数值对比
- 相同延迟下吞吐量更高 = 性能更好
- TTFT 更低 = 用户响应体验更流畅
- TPOT 更低 = 生成速度更快
