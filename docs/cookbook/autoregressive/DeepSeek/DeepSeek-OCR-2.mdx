## 1. 模型介绍

[DeepSeek-OCR-2](https://github.com/deepseek-ai/DeepSeek-OCR-2) 是 DeepSeek 的下一代 OCR（光学字符识别）模型，在 DeepSeek-OCR 的基础上提升了精度与文档理解能力。该模型针对从各种文档类型与格式中高精度提取文字做了优化。

**核心特性：**

- **语义感知视觉编码（DeepEncoder V2）**：DeepSeek-OCR-2 引入 DeepEncoder V2，用更接近人类、以语义驱动的方式建模文档阅读顺序，而非依赖固定的栅格扫描。这显著改善了复杂版式（如多栏文档）中的逻辑阅读顺序。
- **更强的版式与结构理解**：DeepSeek-OCR-2 在表格、表单、密集多栏页面等结构化文档上表现更好。相比原版，它减少了阅读顺序错误，整体文档解析更稳健。
- **保持 token 效率的同时提升精度**：初代 DeepSeek-OCR 强调激进的视觉 token 压缩。OCR-2 在保持高 token 效率的同时，在基准测试上取得了更高成绩，尤其在文档级理解任务上。
- **更复杂的文档任务泛化能力更好**：DeepSeek-OCR-2 在多语言文档、结构化数据抽取、视觉复杂内容上表现更一致，更适合纯文本 OCR 之外的现实文档智能场景。

<Note>
💡 AI Infra 学习笔记：视觉编码器直接决定一张图要"花多少 token"。栅格扫描按固定网格切分图像，token 数与图像大小强相关；DeepEncoder V2 这类语义驱动编码则按内容语义分配 token，还能顺带建模阅读顺序。对推理引擎来说，视觉 token 越少，预填充与 KV 缓存开销越小——这也是"token 效率"在多模态模型里如此重要的原因。
</Note>

**可用模型：**

**注意**：DeepSeek-OCR-2 约 3B 参数，单块现代 GPU 即可轻松容纳。低延迟服务无需模型并行。若追求高吞吐，可考虑用 SGLang Model Gateway 做数据并行——详见 [DP、DPA 与 SGLang DP Router](../../../docs/advanced_features/sgl_model_gateway)。

### 3.2 配置技巧

- **单 GPU 部署**：DeepSeek-OCR-2（约 3B 参数）单块现代 GPU 即可容纳——低延迟服务无需张量并行。
- **高吞吐**：高吞吐场景下用 SGLang Model Gateway 做数据并行。参见 [DP、DPA 与 SGLang DP Router](../../../docs/advanced_features/sgl_model_gateway)。
- **NCCL 超时**：若模型加载缓慢，增大 `--dist-timeout 3600`。
- **Xeon CPU 服务配置**：请参考 [SGLang CPU 服务端文档](../../../docs/hardware-platforms/cpu_server#launch-of-the-serving-engine) 中启动服务引擎一节的 `Notes` 部分，了解如何配置参数，尤其是 NUMA 绑定设置。

<Note>
💡 AI Infra 学习笔记：小模型（3B）与大 MoE 模型（671B）的并行策略完全不同——前者单卡放得下，加张量并行反而引入通信开销、收益有限；后者必须靠 TP/EP 切分。提高吞吐的另一条路是数据并行（DP）：多份模型副本各处理一批请求，再靠 Router/Gateway 分配流量。选并行策略的关键是先算清楚「显存装不装得下、通信是否成为瓶颈」。
</Note>

## 4. 模型调用

### 4.1 基本用法

**兼容 OpenAI 的请求示例**

```python Example
import requests

url = "http://localhost:30000/v1/chat/completions"

data = {
    "model": "deepseek-ai/DeepSeek-OCR-2",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "<image>\n<|grounding|>Convert the document to markdown."},
                {"type": "image_url", "image_url": {"url": "https://example.com/your_image.jpg"}},
            ],
        }
    ],
    "max_tokens": 512,
}

response = requests.post(url, json=data)
print(response.text)
```

**参考资料**
- [SGLang 基本用法指南](../../../docs/basic_usage/send_request)

### 4.2 推荐提示词

以下是[官方模型卡](https://huggingface.co/deepseek-ai/DeepSeek-OCR-2#main-prompts)推荐的提示词。

```text Example
<image>
<|grounding|>Convert the document to markdown.
```

**自由式 OCR**——只提取文字、不带版式：

```text Example
<image>
Free OCR.
```

**测试环境：**

- 硬件：NVIDIA H200 GPU（1 卡）
- 模型：DeepSeek-OCR-2
- 张量并行度：1
- SGLang 版本：0.0.0.dev1+g93fca0bbc

我们用 SGLang 内置的基准测试工具，在 [ShareGPT_Vicuna_unfiltered](https://huggingface.co/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered) 数据集上做性能评估。该数据集包含真实对话数据，能更好地反映实际使用场景的性能。为模拟真实使用模式，我们把每个请求配置为 1024 个输入 token 与 1024 个输出 token，代表带详细回答的典型中等长度对话。更多评估方法请见[用 SGLang 评估新模型](../../../docs/developer_guide/evaluating_new_models)。
