## 1. 模型介绍

[DeepSeek V3.1](https://huggingface.co/deepseek-ai/DeepSeek-V3.1) 是 DeepSeek 开发的高级混合专家（MoE）大语言模型，相比 DeepSeek V3 在能力与易用性上有显著升级。作为 DeepSeek V3 家族的精炼迭代，DeepSeek V3.1 引入了混合推理范式：既支持快速的非思考响应，也支持显式的多步推理；同时大幅改进了工具调用与 agent 行为。得益于持续训练、对齐优化与推理期改进，该模型在推理、数学、编程、长上下文理解以及真实 agent 工作流上都表现出色。DeepSeek V3.1 定位为稳健的通用基础模型，适合对话式 AI、结构化工具调用、搜索增强生成与复杂多步任务，同时通过稀疏 MoE 架构保持高效率。

**[DeepSeek-V3.1-Terminus](https://huggingface.co/deepseek-ai/DeepSeek-V3.1-Terminus)** 是面向通用对话与长上下文处理的实验版本。它具备混合思考能力，可在深思熟虑的"思考"模式与更快的"非思考"模式之间切换。推荐用于通用对话、长上下文处理与实验性场景。

<Note>
💡 AI Infra 学习笔记：混合推理（hybrid reasoning）让同一个模型既支持快速直答（Non-Think 模式），也支持显式的多步思考（Think 模式）。两种模式的负载特征差异巨大——思考模式生成 token 多、KV 缓存增长快，适合配合 PD 分离；直答模式更看重低 TTFT。推理引擎在调度与资源分配上需要按模式区分对待。
</Note>

> 官方 DeepSeek-V3.1 检查点已是 FP8 格式——服务时**不要**再加 `--quantization fp8`。

**DeepGEMM 预编译（NVIDIA Hopper / Blackwell）：** 在首次启动服务前预编译 GEMM kernel，避免 JIT 开销（约 10 分钟）：
```bash
python3 -m sglang.compile_deep_gemm --model deepseek-ai/DeepSeek-V3.1 --tp 8 --trust-remote-code
```
DeepGEMM 在 Hopper/Blackwell 上默认启用，可用 `SGLANG_ENABLE_JIT_DEEPGEMM=0` 禁用。

**数据并行注意力（`--enable-dp-attention`）：** 推荐用于大批量高吞吐场景。可减少 TP rank 之间 KV 缓存的重复。在单节点 8 卡上用 `--enable-dp-attention --tp 8 --dp 8`。不推荐用于低延迟、小批量负载。

**NCCL 超时：** 若模型加载缓慢并触发 NCCL 超时，增大它：`--dist-timeout 3600`。

**Xeon CPU 服务配置：** 请参考 [SGLang CPU 服务端文档](../../../docs/hardware-platforms/cpu_server#launch-of-the-serving-engine) 中启动服务引擎一节的 `Notes` 部分，了解如何配置参数，尤其是 TP（张量并行）与 NUMA 绑定设置。

#### 4.2.1 推理解析器

DeepSeek-V3.1 支持推理模式。部署时启用推理解析器，可把思考与内容部分分开：

```shell Command
python -m sglang.launch_server \
  --model deepseek-ai/DeepSeek-V3.1-Terminus \
  --reasoning-parser deepseek-v3 \
  --tp 8 \
  --host 0.0.0.0 \
  --port 8000
```

**带思考过程的流式输出：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Enable streaming to see the thinking process in real-time
response = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3.1-Terminus",
    messages=[
        {"role": "user", "content": "Solve this problem step by step: What is 15% of 240?"}
    ],
    temperature=0.7,
    max_tokens=2048,
    extra_body = {"chat_template_kwargs": {"thinking": True}},
    stream=True
)

# Process the stream
has_thinking = False
has_answer = False
thinking_started = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print answer content
        if delta.content:
            # Close thinking section and add content header
            if has_thinking and not has_answer:
                print("\n=============== Content =================", flush=True)
                has_answer = True
            print(delta.content, end="", flush=True)

print()
```

**输出示例：**

```text Output

To find a percentage of a number, I can multiply the number by the percentage expressed as a decimal. So, I need to convert 15% to a decimal. To do that, I divide 15 by 100, which gives me 0.15.
```

#### 4.2.2 工具调用

DeepSeek-V3.1 与 DeepSeek-V3.1-Terminus 都支持工具调用能力。启用工具调用解析器：

**部署命令：**

```shell Command
python -m sglang.launch_server \
  --model deepseek-ai/DeepSeek-V3.1-Terminus \
  --tool-call-parser deepseekv31 \
  --reasoning-parser deepseek-v3 \
  --chat-template ./examples/chat_template/tool_chat_template_deepseekv31.jinja \
  --tp 8 \
  --host 0.0.0.0 \
  --port 8000
```

对于 DeepSeek-V3.1，同样使用 `--tool-call-parser deepseekv31`。

**Python 示例（带思考过程）：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request with streaming to see thinking process
response = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3.1-Terminus",
    messages=[
        {"role": "user", "content": "What's the weather in Beijing?"}
    ],
    tools=tools,
    extra_body = {"chat_template_kwargs": {"thinking": True}},
    temperature=0.7,
    stream=True
)

# Process streaming response
thinking_started = False
has_thinking = False
tool_calls_accumulator = {}

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Accumulate tool calls
        if hasattr(delta, 'tool_calls') and delta.tool_calls:
            # Close thinking section if needed
            if has_thinking and thinking_started:
                print("\n=============== Content =================\n", flush=True)
                thinking_started = False

            for tool_call in delta.tool_calls:
                index = tool_call.index
                if index not in tool_calls_accumulator:
                    tool_calls_accumulator[index] = {
                        'name': None,
                        'arguments': ''
                    }

                if tool_call.function:
                    if tool_call.function.name:
                        tool_calls_accumulator[index]['name'] = tool_call.function.name
                    if tool_call.function.arguments:
                        tool_calls_accumulator[index]['arguments'] += tool_call.function.arguments

        # Print content
        if delta.content:
            print(delta.content, end="", flush=True)

# Print accumulated tool calls
for index, tool_call in sorted(tool_calls_accumulator.items()):
    print(f"🔧 Tool Call: {tool_call['name']}")
    print(f"   Arguments: {tool_call['arguments']}")

print()
```

**输出示例：**

```text Output
=============== Thinking =================
Hmm, the user is asking for the weather in Beijing. This is a straightforward request that matches exactly what the weather tool can provide.

I need to call the get_weather function with Beijing as the location parameter. The user didn't specify a temperature unit, so I'll default to Celsius since that's commonly used in most parts of the world.

The tool call format needs to be precise - just the city name and unit selection. Once I get the weather data back, I'll present it clearly to the user.I'll check the weather in Beijing for you.
=============== Content =================

🔧 Tool Call: get_weather
   Arguments: {"location": "Beijing", "unit": "celsius"}
```

**注意：**

- 推理解析器会展示模型如何决定使用工具
- 工具调用会用函数名与参数清晰地标出
- 之后你可以执行该函数并把结果返回给模型以继续对话

**处理工具调用结果：**

请把下面的代码块附加到前面的 Python 脚本中。

```python Example
# After getting the tool call, execute the function
def get_weather(location, unit="celsius"):
    # Your actual weather API call here
    return f"The weather in {location} is 22°{unit[0].upper()} and sunny."

# Send tool result back to the model
messages = [
    {"role": "user", "content": "What's the weather in Beijing?"},
    {
        "role": "assistant",
        "content": None,
        "tool_calls": [{
            "id": "call_123",
            "type": "function",
            "function": {
                "name": "get_weather",
                "arguments": '{"location": "Beijing", "unit": "celsius"}'
            }
        }]
    },
    {
        "role": "tool",
        "tool_call_id": "call_123",
        "content": get_weather("Beijing", "celsius")
    }
]

final_response = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3.1-Terminus",
    messages=messages,
    temperature=0.7
)

print(final_response.choices[0].message.content)
# Output: "Currently, it is **22°C and sunny** in Beijing."
```

#### 5.1.2 并发级别

- **低并发**：`--max-concurrency 1`（面向延迟优化）
- **中并发**：`--max-concurrency 16`（均衡）

#### 5.1.3 提示词数量

对每个并发级别，配置 `num_prompts` 以模拟真实的用户负载：

- **快速测试**：`num_prompts = concurrency × 1`（最小测试）
- **推荐**：`num_prompts = concurrency × 5`（标准基准）
- **稳定测量**：`num_prompts = concurrency × 10`（生产级）

#### 5.1.5 理解结果

**关键指标：**

- **请求吞吐量（req/s）**：每秒处理的请求数
- **输出 token 吞吐量（tok/s）**：每秒生成的 token 总数
- **平均 TTFT（ms）**：首 token 时间——衡量响应速度
- **平均 TPOT（ms）**：单输出 token 时间——衡量生成速度
- **平均 ITL（ms）**：token 间延迟——衡量流式输出的稳定性

**这些配置为什么重要：**

- **1K/1K（聊天）**：代表最常见的对话式 AI 负载。对大多数部署来说这是最高优先级的场景。
- **1K/8K（推理）**：测试长文生成能力，对复杂推理、代码生成与详细解释至关重要。
- **8K/1K（摘要）**：评估大上下文输入下的性能，对 RAG 系统、文档问答与摘要任务必不可少。
- **可变并发**：捕捉帕累托前沿——不同负载水平下吞吐量与延迟之间的最优权衡。低并发展示最佳情况延迟，高并发展示最大吞吐量。

**解读结果：**

- 把你的结果与硬件基线数据对比
- 相同延迟下吞吐更高 = 性能更好
- 更低的 TTFT = 更快的用户响应体验
- 更低的 TPOT = 更快的生成速度
