## 1. 模型介绍

[DeepSeek V3](https://huggingface.co/deepseek-ai/DeepSeek-V3) 是 DeepSeek 开发的大规模混合专家（MoE）语言模型，以高训练与推理效率提供强大的通用推理、编程与工具增强能力。作为 DeepSeek 模型家族的最新一代，DeepSeek V3 引入了一系列系统性的架构与训练创新，在推理、数学、编程与长上下文理解等方面显著提升性能，同时保持有竞争力的计算成本。

主要亮点包括：

- **高效的 MoE 架构**：DeepSeek V3 采用细粒度混合专家设计，拥有大量专家与稀疏激活，在保持可管理的推理与训练成本的同时提供更高的模型容量。
- **先进的推理与编程能力**：得益于改进的数据筛选与训练策略，该模型在数学推理、逻辑推断与真实编程基准上表现强劲。
- **长上下文能力**：DeepSeek V3 支持扩展的上下文长度，能更有效地处理长文档、复杂的多步推理以及 agent 式工作流。
- **工具使用与函数调用**：模型经过训练支持结构化输出与工具调用，可在推理阶段无缝集成外部工具与 agent 框架。

> 官方 DeepSeek-V3 检查点已是 FP8 格式——服务时**不要**再加 `--quantization fp8`。

**DeepGEMM 预编译（NVIDIA Hopper / Blackwell）：** 在首次启动服务前预编译 GEMM kernel，避免 JIT 开销（约 10 分钟）：
```bash
python3 -m sglang.compile_deep_gemm --model deepseek-ai/DeepSeek-V3 --tp 8 --trust-remote-code
```
DeepGEMM 在 Hopper/Blackwell 上默认启用，可用 `SGLANG_ENABLE_JIT_DEEPGEMM=0` 禁用。

**数据并行注意力（`--enable-dp-attention`）：** 推荐用于大批量高吞吐场景。可减少 TP rank 之间 KV 缓存的重复。在单节点 8 卡上用 `--enable-dp-attention --tp 8 --dp 8`。不推荐用于低延迟、小批量负载。

**NCCL 超时：** 若模型加载缓慢并触发 NCCL 超时，增大它：`--dist-timeout 3600`。

**Xeon CPU 服务配置：** 请参考 [SGLang CPU 服务端文档](../../../docs/hardware-platforms/cpu_server#launch-of-the-serving-engine) 中启动服务引擎一节的 `Notes` 部分，了解如何配置参数，尤其是 TP（张量并行）与 NUMA 绑定设置。

#### 4.2.1 推理解析器

DeepSeek-V3 支持推理模式。部署时启用推理解析器，可把思考与内容部分分开：

```shell Command
python -m sglang.launch_server \
  --model deepseek-ai/DeepSeek-V3 \
  --reasoning-parser deepseek-v3 \
  --tp 8
```

**带思考过程的流式输出：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY"
)

# Enable streaming to see the thinking process in real-time
response = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3",
    messages=[
        {"role": "user", "content": "Solve this problem step by step: What is 15% of 240?"}
    ],
    temperature=0.7,
    max_tokens=2048,
    extra_body = {"chat_template_kwargs": {"thinking": True}},
    stream=True
)

# Process the stream
has_thinking = False
has_answer = False
thinking_started = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print answer content
        if delta.content:
            # Close thinking section and add content header
            if has_thinking and not has_answer:
                print("\n=============== Content =================", flush=True)
                has_answer = True
            print(delta.content, end="", flush=True)

print()
```

**输出示例：**

```text Output
=============== Thinking =================
To determine 15% of a number, follow these steps:

**Step 1: Understand the Problem**
You need to find 15% of a given number. Let's assume the number is 240 for this example.

**Step 2: Convert the Percentage to a Decimal**
To work with percentages in calculations, convert the percentage to its decimal form. To do this, divide the percentage by 100.

\[ 15\% = \frac{15}{100} = 0.15 \]

**Step 3: Multiply the Decimal by the Number**
Now, multiply the decimal form of the percentage by the number you want to find the percentage of.

\[ 0.15 \times 240 \]

**Step 4: Perform the Multiplication**
Calculate the product:

\[ 0.15 \times 240 = 36 \]

**Step 5: Conclusion**
Therefore, 15% of 240 is:

\boxed{36}

The answer is 36. To find 15% of 240, we multiply 240 by 0.15, which equals 36.
```

**注意：** 推理解析器会捕获模型的逐步思考过程，让你看到模型是如何得出结论的。

<Note>
用较低的 `temperature`（例如 `0`）可以让工具调用结果更一致。上面的 `--chat-template` 参数为工具使用提供了改进的统一提示词。
</Note>

**Python 示例（带思考过程）：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request with streaming to see thinking process
response = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3",
    messages=[
        {"role": "user", "content": "What's the weather in Beijing?"}
    ],
    tools=tools,
    extra_body = {"chat_template_kwargs": {"thinking": True}},
    temperature=0.7,
    stream=True
)

# Process streaming response
thinking_started = False
has_thinking = False
tool_calls_accumulator = {}

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Accumulate tool calls
        if hasattr(delta, 'tool_calls') and delta.tool_calls:
            # Close thinking section if needed
            if has_thinking and thinking_started:
                print("\n=============== Content =================\n", flush=True)
                thinking_started = False

            for tool_call in delta.tool_calls:
                index = tool_call.index
                if index not in tool_calls_accumulator:
                    tool_calls_accumulator[index] = {
                        'name': None,
                        'arguments': ''
                    }

                if tool_call.function:
                    if tool_call.function.name:
                        tool_calls_accumulator[index]['name'] = tool_call.function.name
                    if tool_call.function.arguments:
                        tool_calls_accumulator[index]['arguments'] += tool_call.function.arguments

        # Print content
        if delta.content:
            print(delta.content, end="", flush=True)

# Print accumulated tool calls
for index, tool_call in sorted(tool_calls_accumulator.items()):
    print(f"🔧 Tool Call: {tool_call['name']}")
    print(f"   Arguments: {tool_call['arguments']}")

print()
```

**输出示例：**

```text Output
🔧 Tool Call: get_weather
   Arguments: {"location": "Beijing", "unit": "celsius"}
```

**注意：**

- 推理解析器会展示模型如何决定使用工具
- 工具调用会用函数名与参数清晰地标出
- 之后你可以执行该函数并把结果返回给模型以继续对话

**处理工具调用结果：**

请把下面的代码块附加到前面的 Python 脚本中。

```python Example
# After getting the tool call, execute the function
def get_weather(location, unit="celsius"):
    # Your actual weather API call here
    return f"The weather in {location} is 22°{unit[0].upper()} and sunny."

# Send tool result back to the model

    {"role": "user", "content": "What's the weather in Beijing?"},

        "role": "assistant",
        "content": None,

            "id": "call_123",

        "tool_call_id": "call_123",

    }

    model="deepseek-ai/DeepSeek-V3",

# Output: "The weather in Beijing is currently 22°C and sunny."
```

#### 4.2.3 多 token 预测（EAGLE 投机解码） {#4-2-3-multi-token-prediction-eagle-speculative-decoding}

SGLang 基于 [EAGLE 投机解码](../../../docs/advanced_features/speculative_decoding#eagle-decoding) 实现了 DeepSeek V3 的多 token 预测（MTP）。借助这一优化，在 H200 TP8 上，批大小 1 时解码速度最高提升 **1.8×**，批大小 32 时最高提升 **1.5×**。

<Note>
💡 AI Infra 学习笔记：投机解码的思路是"小步快跑"——先用轻量的草稿机制猜出几个 token，再用大模型一次性并行验证，猜对了就白赚解码速度。DeepSeek 的 MTP 用模型自带的多 token 预测头当草稿（EAGLE），无需额外引入草稿模型。基准输出里的 `Accept length` 代表平均每次接受多少个草稿 token，是衡量投机收益的关键指标。
</Note>

**启用方式：**

```shell Command
python3 -m sglang.launch_server \
  --model-path deepseek-ai/DeepSeek-V3-0324 \
  --speculative-algorithm EAGLE \
  --trust-remote-code \
  --tp 8
```

默认配置是 `--speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`。用 [bench_speculative.py](https://github.com/sgl-project/sglang/blob/main/scripts/playground/bench_speculative.py) 为你的负载找到最佳取值。最小可用配置是 `--speculative-num-steps 1 --speculative-eagle-topk 1 --speculative-num-draft-tokens 2`。

<Note>
对于大批量（>48），需要把 `--max-running-requests` 从默认的 48 增大以用于 MTP。同时设置 `--cuda-graph-bs` 覆盖你的目标批大小（投机解码默认捕获的批大小为 48）。
</Note>

<Tip>
spec-v2 重叠调度器默认启用。它通过重叠草稿与验证阶段来提升性能。传 `--disable-overlap-schedule` 可禁用。
</Tip>

#### 4.2.4 MLA 优化 {#4-2-4-mla-optimizations}

DeepSeek V3 使用[多头潜在注意力（MLA）](https://arxiv.org/pdf/2405.04434)，这是一种提升推理效率的注意力机制。SGLang 实现了多项优化：

- **权重吸收（Weight Absorption）**：重排矩阵乘法以提升解码阶段效率。
- **MLA Attention 后端**：FA3、FlashInfer、FlashMLA、CutlassMLA、TRTLLM MLA（Blackwell）与 Triton。FA3 是默认后端。
- **FP8 量化**：W8A8 FP8 与 KV 缓存 FP8，FP8 权重吸收 MLA 提供 BMM 算子。
- **CUDA 图与 Torch.compile**：MLA 与 MoE 都支持 CUDA 图与 Torch.compile，可降低解码延迟。
- **分块前缀缓存（Chunked Prefix Cache）**：提升长序列分块预填充的吞吐（仅 FlashAttention3 后端）。

<Note>
💡 AI Infra 学习笔记：MLA 是 DeepSeek 系模型最核心的 KV 缓存优化。传统注意力每个 token 要存完整的多头 K/V，而 MLA 只存一个低秩潜在向量，计算时再用权重矩阵投影回多头——KV 缓存显存大幅下降，这正是 671B 级模型能塞进有限显存、支撑长上下文的关键。「权重吸收」则进一步把投影合并进矩阵乘法，减少解码阶段的计算量。这是推理引擎优化面试的高频考点。
</Note>

总体而言，这些优化相比基线可带来最高 **7×** 的输出吞吐提升。
