## 1. 模型介绍

[Qwen3-VL 系列](https://github.com/QwenLM/Qwen3-VL) 是 Qwen 系列目前最强的视觉语言模型，具备多模态理解、推理和智能体应用等先进能力。

这一代模型在各个方面都有全面升级：

- **卓越的文本理解与生成**：Qwen3-VL-235B-A22B-Instruct 在 lmarena.ai 上被评为[文本类排名第一的开源模型](https://x.com/arena/status/1973151703563460942)
- **更深入的视觉感知与推理**：图像和视频理解能力增强。
- **更长的上下文**：支持最长 262K token，可处理长文档和长视频。
- **更强的空间与视频动态理解**：对空间关系和时序动态的理解更好。
- **更强的智能体交互能力**：工具使用和基于搜索的智能体表现更好。
- **灵活的部署选项**：提供 Dense 和 MoE 两种架构，可从边缘设备扩展到云端，并有 Instruct 和增强推理的 Thinking 版本。

更多细节请参考 [Qwen3-VL 官方 GitHub 仓库](https://github.com/QwenLM/Qwen3-VL)。

### 3.1 基础配置

Qwen3-VL 系列提供多种尺寸和架构的模型，针对 NVIDIA、AMD GPU 以及 Intel Xeon CPU 等不同硬件平台做了优化。推荐的启动配置因硬件和模型尺寸而异。

<Note>
💡 AI Infra 学习笔记：多模态请求的输入 token 主要由视觉 token 构成：图片/视频先经过视觉编码器切块编码成若干「视觉 token」，再与文本 token 拼成一个序列走预填充。`--mm-attention-backend` 选的是视觉 token 与文本 token 之间的注意力计算 kernel（fa3/fa4/triton_attn 等），不同后端对不同硬件和页大小的支持不同；`--keep-mm-feature-on-device` 则避免图像特征在 CPU/GPU 间反复拷贝。长视频会把视觉 token 数放大到几万甚至几十万，直接决定显存与 TTFT，这是多模态部署与纯文本部署最大的差异点。
</Note>

### 3.2 配置建议

* **多模态注意力后端**：通常 `--mm-attention-backend` 在 H100/H200/A100 上默认为 `fa3`（性能更好），在 B200 上默认为 `triton_attn`（出于兼容性考虑）。
* **TTFT 优化**：设置 `SGLANG_USE_CUDA_IPC_TRANSPORT=1`，用 CUDA IPC 传输多模态特征，可显著改善 TTFT。这会额外消耗显存，可能需要调整 `--mem-fraction-static` 和/或 `--max-running-requests`（额外显存与「图像大小 × 当前运行请求中的图像数量」成正比）。
* **显存管理**：设置更小的 `--context-length` 以节省显存。默认是 262K，多数场景下 `128000` 就够了。
* **专家并行**：SGLang 通过 `--ep` 支持专家并行（EP），可以把 MoE 模型中的专家部署到不同的 GPU 上以获得更高吞吐。需要注意的是，对于量化模型，`--ep` 必须满足约束：`(moe_intermediate_size / moe_tp_size) % weight_block_size_n == 0, where moe_tp_size is equal to tp_size divided by ep_size.` 另外，低并发场景下 EP 可能因为额外的通信开销而表现更差。更多细节见 [专家并行部署](../../../docs/advanced_features/expert_parallelism)。
* **kernel 调优**：要在你的特定硬件上调整 MoE Triton kernel，参考 [fused_moe_triton](https://github.com/sgl-project/sglang/tree/main/benchmark/kernels/fused_moe_triton)。

**硬件相关说明：**
- **H100（FP8）**：使用 `Qwen/Qwen3-VL-235B-A22B-Instruct-FP8` 检查点以获得最佳显存效率。
- **A100 / H100（BF16）**：使用标准多模态参数来平衡吞吐与 GPU 显存占用。
- **H200 / B200**：开箱即用，支持完整上下文长度以及图像 + 视频并发处理。

**其它多模态服务端参数：**
- `--keep-mm-feature-on-device`：处理完成后把多模态特征张量保留在 GPU 上，避免设备到主机的显存拷贝，可提升高频推理的性能。

**完整多模态优化的示例：**
```bash Command

SGLANG_VLM_CACHE_SIZE_MB=0 \
python -m sglang.launch_server \

```

#### 4.2.2 推理解析器

Qwen3-VL-Thinking 支持推理模式。部署时启用推理解析器，可以把思考过程和回答内容分开：

```shell Command
python -m sglang.launch_server \
  --model Qwen/Qwen3-VL-235B-A22B-Thinking \
  --reasoning-parser qwen3 \
  --tp 8 \
  --host 0.0.0.0 \
  --port 30000
```

**带思考过程的流式输出：**

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY"
)

# Enable streaming to see the thinking process in real-time
response = client.chat.completions.create(
    model="Qwen/Qwen3-VL-235B-A22B-Thinking",
    messages=[
        {"role": "user", "content": "Solve this problem step by step: What is 15% of 240?"}
    ],
    temperature=0.7,
    max_tokens=2048,
    stream=True
)

# Process the stream
has_thinking = False
has_answer = False
thinking_started = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print answer content
        if delta.content:
            # Close thinking section and add content header
            if has_thinking and not has_answer:
                print("\n=============== Content =================", flush=True)
                has_answer = True
            print(delta.content, end="", flush=True)

print()
```

**示例输出：**

```text Output

To solve this problem, I need to calculate 15% of 240.
Step 1: Convert 15% to decimal: 15% = 0.15
Step 2: Multiply 240 by 0.15
Step 3: 240 × 0.15 = 36
=============== Content =================

The answer is 36. To find 15% of 240, we multiply 240 by 0.15, which equals 36.
```

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request with streaming to see thinking process
response = client.chat.completions.create(
    model="Qwen/Qwen3-VL-235B-A22B-Thinking",
    messages=[
        {"role": "user", "content": "What's the weather in Beijing?"}
    ],
    tools=tools,
    temperature=0.7,
    stream=True
)

# Process streaming response
thinking_started = False
has_thinking = False
tool_calls_accumulator = {}

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Accumulate tool calls
        if hasattr(delta, 'tool_calls') and delta.tool_calls:
            # Close thinking section if needed
            if has_thinking and thinking_started:
                print("\n=============== Content =================\n", flush=True)
                thinking_started = False

            for tool_call in delta.tool_calls:
                index = tool_call.index
                if index not in tool_calls_accumulator:
                    tool_calls_accumulator[index] = {
                        'name': None,
                        'arguments': ''
                    }

                if tool_call.function:
                    if tool_call.function.name:
                        tool_calls_accumulator[index]['name'] = tool_call.function.name
                    if tool_call.function.arguments:
                        tool_calls_accumulator[index]['arguments'] += tool_call.function.arguments

        # Print content
        if delta.content:
            print(delta.content, end="", flush=True)

# Print accumulated tool calls
for index, tool_call in sorted(tool_calls_accumulator.items()):
    print(f"🔧 Tool Call: {tool_call['name']}")
    print(f"   Arguments: {tool_call['arguments']}")

print()
```

**示例输出：**

```text Output
=============== Thinking =================
The user is asking about the weather in Beijing. I need to use the get_weather function to retrieve this information.
I should call the function with location="Beijing".
=============== Content =================

🔧 Tool Call: get_weather
   Arguments: {"location": "Beijing", "unit": "celsius"}
```

**注意：**

- 推理解析器展示了模型如何决定使用某个工具
- 工具调用会清楚标出函数名和参数
- 之后你可以执行该函数并把结果传回，继续对话

<Note>
💡 AI Infra 学习笔记：多模态场景下 TTFT 的瓶颈往往不在注意力计算，而在「图像特征张量的搬运」：视觉编码器在 GPU 上算出的特征要传给做注意力/采样的模块，默认可能经过 CPU（设备到主机再回设备），延迟很高。CUDA IPC（进程间共享显存）让特征直接在 GPU 间传递，显著降低首 token 延迟，代价是额外显存（与图像大小、并发请求数成正比）——这也是 `--mem-fraction-static` 要调低的原因。
</Note>


- 模型部署命令：

```shell Command

  --tp 8 \
  --host 0.0.0.0 \
  --port 30000
```
