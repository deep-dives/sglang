## 1. 模型介绍

**[Qwen2.5-VL](https://huggingface.co/collections/Qwen/qwen25-vl)** 是 Qwen 团队推出的视觉语言模型系列，在理解、推理和多模态处理上相比前代有显著提升。

**主要特性：**

- **视觉理解**：擅长识别花、鸟、鱼、昆虫等常见物体，也能很好地分析图像中的文字、图表、图标、图形和版式。
- **更强的智能体能力**：可作为视觉智能体进行推理并动态调用工具，支持操作电脑和手机。
- **理解长视频并捕捉事件**：支持理解超过 1 小时的视频，并新增了通过定位相关视频片段来捕捉事件的能力。
- **多种格式的视觉定位**：通过生成边界框或点来精确定位图像中的物体，并能对坐标和属性输出稳定的 JSON 结果。
- **结构化输出**：支持对图像内容做结构化输出，便于金融、电商等场景处理发票、表单、表格等扫描件数据。
- **视频理解的动态分辨率与动态帧率训练**：通过动态 FPS 采样把动态分辨率扩展到时间维度，让模型能理解不同采样率下的视频。相应地，我们用 ID 和绝对时间对齐更新了时间维度的 mRoPE，使模型能学习时间顺序与速度，最终具备精准定位具体时刻的能力。
- **多种尺寸**：提供 3B、7B、32B 和 72B 等变体，满足不同部署需求。
- **ROCm 支持**：通过 SGLang 兼容 AMD MI300X、MI325X 和 MI355X GPU（已验证）。

更多细节请参考 [Qwen2.5-VL 官方 GitHub 仓库](https://github.com/QwenLM/Qwen3-VL)。

### 4.2 高级用法

#### 4.2.1 多模态输入

Qwen2.5-VL 支持图像输入。下面是一个单图输入的基础示例：

<Note>
💡 AI Infra 学习笔记：多模态输入的内部流程：图片会先经过视觉编码器（ViT）切成图块并转成「视觉 token」，再与文本 token 一起拼进同一个序列参与预填充与解码。Qwen2.5-VL 采用动态分辨率与动态 FPS 采样，图片 token 数随分辨率和帧率浮动——大图、长视频会显著拉高输入 token 数，从而放大预填充阶段的显存与算力开销，这也是需要为 `--mem-fraction-static` 预留空间的原因。
</Note>


```python Example
import time
from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",
    base_url="http://localhost:30000/v1",
    timeout=3600
)

messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {
                    "url": "https://ofasys-multimodal-wlcb-3-toshanghai.oss-accelerate.aliyuncs.com/wpf272043/keepme/image/receipt.png"
                }
            },
            {
                "type": "text",
                "text": "Read all the text in the image."
            }
        ]
    }
]

start = time.time()
response = client.chat.completions.create(
    model="Qwen/Qwen2.5-VL-7B-Instruct",
    messages=messages,
    max_tokens=2048
)
print(f"Response costs: {time.time() - start:.2f}s")
print(f"Generated text: {response.choices[0].message.content}")
```

**多图输入示例：**

Qwen2.5-VL 可以在一次请求中处理多张图片，用于对比或分析：

```python Example
import time
from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",
    base_url="http://localhost:30000/v1",
    timeout=3600
)

messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {
                    "url": "https://www.civitatis.com/f/china/hong-kong/guia/taxi.jpg"
                }
            },
            {
                "type": "image_url",
                "image_url": {
                    "url": "https://cdn.cheapoguides.com/wp-content/uploads/sites/7/2025/05/GettyImages-509614603-1280x600.jpg"
                }
            },
            {
                "type": "text",
                "text": "Compare these two images and describe the differences in 100 words or less."
            }
        ]
    }
]

start = time.time()
response = client.chat.completions.create(
    model="Qwen/Qwen2.5-VL-7B-Instruct",
    messages=messages,
    max_tokens=2048
)
print(f"Response costs: {time.time() - start:.2f}s")
print(f"Generated text: {response.choices[0].message.content}")
```

**示例输出：**

```text Output
Response costs: 13.79s
Generated text: The first image shows a single red taxi driving on a street with a few other taxis in the background. The second image shows a large number of taxis parked in a lot, with some appearing to be in various states of repair. The first image has a single taxi with a visible license plate, while the second image has multiple taxis with different license plates. The first image has a clear view of the street and surrounding area, while the second image is taken from an elevated perspective, showing a wider view of the parking lot and the surrounding area.
```

**注意：**

- 你也可以使用 `file://` 协议提供本地文件路径。
- 处理更大的图片可能需要更多显存，请相应调整 `--mem-fraction-static`。

## 5. 基准测试

### 5.1 速度基准测试

**测试环境：**

- 硬件：AMD MI300X GPU（8 块）
- 模型：Qwen2.5-VL-72B-Instruct
- 张量并行：8
- SGLang 版本：0.5.6

我们使用 SGLang 内置的基准测试工具，用随机图像进行性能评估。为模拟真实使用场景，你可以为每个请求指定不同的输入、输出长度。例如每个请求可以包含 128 个输入 token、两张 720p 图片和 1024 个输出 token。

<Note>
💡 AI Infra 学习笔记：从下面的基准结果可以看到，两张 720p 图片产生的视觉 token（约 2.4 万）远超 128 个文本 token——多模态请求的输入 token 绝大部分来自图像。TTFT（首 token 延迟）受预填充速度主导，TPOT（除去首 token 后每输出一个 token 的耗时）反映解码速度，这两项是评估推理引擎多模态性能的核心指标。
</Note>
