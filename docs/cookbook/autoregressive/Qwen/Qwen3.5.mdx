## 1. 模型介绍

[Qwen3.5-397B-A17B](https://huggingface.co/Qwen/Qwen3.5-397B-A17B) 是阿里巴巴推出的 Qwen 系列最新旗舰模型，在统一视觉语言基础、高效混合架构和可扩展强化学习上实现了重大跨越。

Qwen3.5 采用 Gated Delta Network 与稀疏混合专家（MoE）架构组合（总参数 397B，激活 17B），在极低延迟下实现高吞吐推理。它支持多模态输入（文本、图像、视频），原生支持最长 262,144 token 的上下文，并可通过扩展支持超过 1M token。

<Note>
💡 AI Infra 学习笔记：Qwen3.5 的「混合注意力」是当前长上下文模型的主流方向：线性注意力（Gated DeltaNet）把复杂度降到 O(n)，让长序列处理成本大幅下降，但纯线性注意力难以精确回忆信息；因此每隔几层插入一次标准全注意力来补足「联想记忆」。对推理引擎来说，这种架构意味着注意力层不再是统一的 kernel 调用——需要分别调度线性注意力与全注意力路径，还要为 mamba 状态单独管理显存（这就是下面 `--mamba-radix-cache-strategy` 与 `--max-mamba-cache-size` 这些参数的由来）。
</Note>


**架构细节：**
- **混合注意力**：Gated Delta Network（线性注意力，复杂度 O(n)）与每隔 4 层插入一次的全注意力相结合——线性层以极低代价处理长上下文，周期性全注意力则保证较强的联想记忆能力。
- **MoE 路由**：512 个路由专家中激活 top-10，另设一个专门的共享专家负责通用特征，在 397B 总参数中保持 17B 激活。
- **原生多模态**：采用带 Conv3d 时间编码的 DeepStack Vision Transformer，无需独立的视觉编码器即可理解图像和视频。

**主要特性：**

- **统一视觉语言基础**：对多模态 token 进行早期融合训练，达到与 Qwen3 跨代持平的水平，并优于 Qwen3-VL 系列模型
- **高效混合架构**：Gated Delta Network + 稀疏 MoE（总参数 397B / 激活 17B），支撑高吞吐推理
- **混合推理**：默认开启思考模式，逐步推理，也可关闭以直接作答
- **工具调用**：内置工具调用支持，使用 `qwen3_coder` 解析器
- **多 token 预测（MTP）**：支持投机解码，降低延迟
- **201 种语言支持**：多语言覆盖扩展至 201 种语言和方言

## 2. 安装 SGLang

Qwen3.5 需要使用 main 分支的 SGLang。你可以从源码安装，也可以使用 Docker 镜像：

```bash Command
# Install from source
uv pip install 'git+https://github.com/sgl-project/sglang.git#subdirectory=python'

# Or use Docker (NVIDIA GPUs)
docker pull lmsysorg/sglang:latest

# Or use Docker (AMD MI300X/MI325X)
docker pull lmsysorg/sglang-rocm:v0.5.15.post1-rocm720-mi30x-20260715

# Or use Docker (AMD MI355X)
docker pull lmsysorg/sglang-rocm:v0.5.15.post1-rocm720-mi35x-20260715
```

完整的 Docker 配置和其它安装方式请参考 [SGLang 官方安装指南](../../../docs/get-started/install)。

如需在 CPU 上安装 SGLang，请参考 [CPU 版安装指南](../../../docs/hardware-platforms/cpu_server#installation)。

### 3.2 配置建议

- 投机解码（MTP）可以显著降低交互式场景的延迟。
- **H100 FP8**：添加 `--enable-symm-mem` 以启用 NCCL 对称内存，加快集合通信，在多 GPU 场景下获得更好的性能。
- **AMD GPU（MI300X / MI325X / MI355X）**：使用 `SGLANG_USE_AITER=1` 和 `SGLANG_USE_AITER_UNIFIED_ATTN=1`，并配合 `--attention-backend aiter`（需要 `--page-size 16`，还可以开启 `--enable-aiter-allreduce-fusion`）。另外设置 `AITER_FLYDSL_FORCE=1` 强制使用 AITER FlyDSL MoE kernel，并设置 `SGLANG_MAMBA_SSM_DTYPE=bfloat16` 以 bfloat16 存储 Mamba SSM 状态（默认是 float32）。对于 **MI355X 上的 MXFP4 检查点**，设置 `ROCM_QUICK_REDUCE_QUANTIZATION=INT8` 让多 GPU 集合通信走 INT8 量化的 ROCm quick all-reduce，并去掉 `--enable-aiter-allreduce-fusion`（两者互斥；本配方优先使用 quick all-reduce）。
- **Watchdog 超时**：对于这种大模型，把 `--watchdog-timeout` 提高到 `1200` 或更高，因为权重加载可能耗时很长。
- **Mamba Radix 缓存**：Qwen3.5 的混合 Gated Delta Network 架构通过 `--mamba-radix-cache-strategy` 支持两种 mamba 调度策略：
  - **V1（`no_buffer`）**：默认。无重叠调度器，显存占用更低。AMD MI GPU 必需。
  - **V2（`extra_buffer`）**：使用 `--mamba-radix-cache-strategy extra_buffer --page-size 64` 启用重叠调度与分支点缓存。需要 FLA kernel 后端（仅 NVIDIA GPU）。以更高的 mamba 状态显存换取更高吞吐。在非 KV 缓存受限场景下严格更优；在 KV 缓存受限场景下，需要在重叠调度带来的收益与并发度下降之间权衡。`--page-size` 必须满足 `FLA_CHUNK_SIZE % page_size == 0` 或 `page_size % FLA_CHUNK_SIZE == 0`（目前 `FLA_CHUNK_SIZE` 为 64）。
- 建议用 `--mem-fraction-static` 参数获得最优的显存利用率，请根据你的硬件和工作负载调整。
- 上下文长度默认为 262,144 token。如果遇到 OOM 错误，可以考虑调小，但建议至少保留 128K 以保持思考能力。
- 为了加快这种大模型的权重加载，在启动命令中加入 `--model-loader-extra-config='{"enable_multithread_load": "true","num_threads": 64}'`。
- **CUDA IPC 传输**：添加环境变量 `SGLANG_USE_CUDA_IPC_TRANSPORT=1`，用 CUDA IPC 传输多模态特征，可显著改善 TTFT（首 token 延迟）。注意：这会按图像大小消耗额外显存，你可能需要调低 `--mem-fraction-static` 或 `--max-running-requests`。
- **多模态注意力后端**：在 H100/H200 上用 `--mm-attention-backend fa3` 获得更好的视觉性能，在 B200/B300 上用 `--mm-attention-backend fa4`。
- **B200（FP8）**：添加 `--enable-flashinfer-allreduce-fusion` 以在 Blackwell 上获得优化吞吐。
- 处理大图或视频时，你可能需要调低 `--mem-fraction-static`，为图像特征张量留出空间。
- 硬件要求：
    - **BF16**：约 397B 参数，权重需要约 800GB GPU 显存。
        - **H100（80GB）** 需要 tp=16（2 个节点），因为 tp=8 时每个 rank 需要约 100GB。
        - **H200（141GB）** 用 tp=8 即可。
        - **B200（183GB）** 用 tp=8 即可。
        - **B300（275GB）** 用 tp=4 即可。
        - **MI300X（192GB）** 用 tp=8 即可。
        - **MI325X（256GB）** 用 tp=4 即可。
        - **MI355X（288GB）** 用 tp=4 即可。
    - **FP8**：FP8 量化模型权重约需 400GB，显存减半。
        - **H100（80GB）** 用 tp=8 即可。
        - **H200（141GB）** 用 tp=4 即可。
        - **B200（183GB）** 用 tp=4 即可。
        - **B300（275GB）** 用 tp=2 即可。
        - **MI300X（192GB）** 用 tp=4 即可。
        - **MI325X（256GB）** 用 tp=2 即可。
        - **MI355X（288GB）** 用 tp=2 即可。
    - **FP4**：FP4 量化模型权重约需 250GB，显存降到接近 1/4。NVFP4（[nvidia/Qwen3.5-397B-A17B-NVFP4](https://huggingface.co/nvidia/Qwen3.5-397B-A17B-NVFP4)）需要 B200/B300（Blackwell 架构）；AMD 为 MI355X 提供 MXFP4 检查点（[amd/Qwen3.5-397B-A17B-MXFP4](https://huggingface.co/amd/Qwen3.5-397B-A17B-MXFP4)）。
        - **B200（183GB）** 用 tp=4 即可。（NVFP4）
        - **B300（275GB）** 用 tp=2 即可。（NVFP4）
        - **MI355X（288GB）** 用 tp=2 即可（低并发时用 tp=4）。（MXFP4）

💡 AI Infra 学习笔记：KV 缓存是解码阶段最大的显存开销，把 KV 缓存量化到 FP8 可以省约一半空间，从而支持更长的上下文或更高的并发。但 KV 缓存量化与权重量化不同：它需要根据真实数据分布预先校准每通道/每头的缩放因子，否则直接使用缩放系数 1.0 会在推理密集任务上明显掉点。生产环境通常要么用自带校准因子的量化检查点，要么先在代表性数据上跑一遍校准流程。
</Note>


- **Xeon CPU 服务配置**：请参考 [SGLang CPU 服务端文档](../../../docs/hardware-platforms/cpu_server#launch-of-the-serving-engine) 中启动推理引擎一节的 `Notes` 部分，以更好地理解如何配置相关参数，尤其是 TP（张量并行）和 NUMA 绑定设置。
