## 1. 模型介绍

[Qwen3-Next](https://huggingface.co/collections/Qwen/qwen3-next) 是阿里巴巴 Qwen 团队开发的一种先进大语言模型架构，旨在提升处理超长上下文和大规模参数时的效率与性能。它具备先进的推理、函数调用和多语言理解能力。

<Note>
💡 AI Infra 学习笔记：Qwen3-Next 把两条省算力的思路合在了一起：一是「混合注意力」，用线性注意力（Gated DeltaNet，复杂度 O(n)）处理大部分长序列，只在部分层用全注意力；二是「高稀疏 MoE」，80B 总参数每 token 只激活 3B，FLOPs 大幅下降。两者叠加，让超大模型在保持容量（记忆能力、知识面）的同时，把单 token 的推理成本压到接近小模型，这正是它能处理 262K 长上下文并实现高吞吐的根本原因。
</Note>


Qwen3-Next 引入了几项开创性创新：

- **混合注意力机制**：用 **Gated DeltaNet**（线性注意力）与 **全注意力** 的组合取代标准注意力，能够高效处理长达 262,144 token 的上下文。这种混合方案非常适合分析整本书、整份合同这类超长文档。

- **高度稀疏的混合专家（MoE）**：采用 800 亿参数架构，推理时仅激活 30 亿参数。这种设计最多可降低 90% 的计算成本，同时保持高性能，在不牺牲模型容量的前提下大幅减少每 token 的 FLOPs。

- **多 token 预测（MTP）**：每个推理步骤可一次生成多个 token，显著降低延迟，改善实时应用的用户体验。这一创新同时提升了预训练表现和推理速度。

- **多语言支持**：原生支持 119 种语言，方便跨语言任务，适合全球应用。

- **企业级部署**：采用 Apache 2.0 许可证发布，提供本地、虚拟私有云（VPC）和私有云等灵活的部署选项，满足企业的安全与合规要求。

- **高级推理与稳定性**：推理性能明显提升，并支持推理过程中的工具使用。包含稳定性优化，如 **零中心化** 与 **权重衰减 layernorm**，让预训练和后训练更加稳健。

更多细节请参考 [Qwen3-Next 官方博客](https://qwen.ai/blog?id=4074cca80393150c248e508aa62983f9cb7d27cd&from=research.latest-advancements-list)。

### 3.2 配置建议

- `--max-mamba-cache-size`：调整 `--max-mamba-cache-size` 可以增大 mamba 缓存空间和最大运行请求数。代价是 KV 缓存空间相应减少。你可以根据负载调整。

- `--mamba-ssm-dtype`：`bfloat16` 或 `float32`。用 `bfloat16` 可节省 mamba 缓存大小，用 `float32` 结果更精确。默认为 `float32`。

- `--mamba-full-memory-ratio`：调整 `--mamba-full-memory-ratio` 设置 mamba 状态显存占完整 KV 缓存显存的比例。默认为 `0.9`。

- **Mamba Radix 缓存**：Qwen3-Next 的混合 Gated Delta Network 架构通过 `--mamba-radix-cache-strategy` 支持两种 mamba 调度策略：
  - **V1（`no_buffer`）**：默认。无重叠调度器，显存占用更低。
  - **V2（`extra_buffer`）**：使用 `--mamba-radix-cache-strategy extra_buffer --page-size 64` 启用重叠调度与分支点缓存。需要 FLA kernel 后端。以更高的 mamba 状态显存换取更高吞吐。在非 KV 缓存受限场景下严格更优；在 KV 缓存受限场景下，需要在重叠调度带来的收益与并发度下降之间权衡。`--page-size` 必须满足 `FLA_CHUNK_SIZE % page_size == 0` 或 `page_size % FLA_CHUNK_SIZE == 0`（目前 `FLA_CHUNK_SIZE` 为 64）。

- **Xeon CPU 服务配置**：请参考 [SGLang CPU 服务端文档](../../../docs/hardware-platforms/cpu_server#launch-of-the-serving-engine) 中启动推理引擎一节的 `Notes` 部分，以更好地理解如何配置相关参数，尤其是 TP（张量并行）和 NUMA 绑定设置。

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Enable streaming to see the thinking process in real-time
response = client.chat.completions.create(
    model="Qwen/Qwen3-Next-80B-A3B-Thinking",
    messages=[
        {"role": "user", "content": "Solve this problem step by step: What is 15% of 240?"}
    ],
    temperature=0.7,
    max_tokens=2048,
    stream=True
)

# Process the stream
has_thinking = False
has_answer = False
thinking_started = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print answer content
        if delta.content:
            # Close thinking section and add content header
            if has_thinking and not has_answer:
                print("\n=============== Content =================", flush=True)
                has_answer = True
            print(delta.content, end="", flush=True)

print()
```

```python Example
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY"
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city name"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Make request with streaming to see thinking process
response = client.chat.completions.create(
    model="Qwen/Qwen3-Next-80B-A3B-Instruct",
    messages=[
        {"role": "user", "content": "What's the weather in Beijing?"}
    ],
    tools=tools,
    temperature=0.7,
    stream=True
)

# Process streaming response
thinking_started = False
has_thinking = False

for chunk in response:
    if chunk.choices and len(chunk.choices) > 0:
        delta = chunk.choices[0].delta

        # Print thinking process
        if hasattr(delta, 'reasoning_content') and delta.reasoning_content:
            if not thinking_started:
                print("=============== Thinking =================", flush=True)
                thinking_started = True
            has_thinking = True
            print(delta.reasoning_content, end="", flush=True)

        # Print tool calls
        if hasattr(delta, 'tool_calls') and delta.tool_calls:
            # Close thinking section if needed
            if has_thinking and thinking_started:
                print("\n=============== Content =================", flush=True)
                thinking_started = False

            for tool_call in delta.tool_calls:
                if tool_call.function:
                    print(f"🔧 Tool Call: {tool_call.function.name}")
                    print(f"   Arguments: {tool_call.function.arguments}")

        # Print content
        if delta.content:
            print(delta.content, end="", flush=True)

print()
```

#### 4.2.4 多 token 预测（NEXTN 投机解码）

Qwen3-Next 内置了多 token 预测（MTP）层，并通过 `NEXTN` 算法支持 [EAGLE 风格的投机解码](../../../docs/advanced_features/speculative_decoding#eagle-decoding)。MTP 权重已打包在主检查点中，因此无需单独的草稿模型。

<Note>
💡 AI Infra 学习笔记：常规投机解码需要额外加载一个草稿模型（占用显存），而 Qwen3-Next 把 MTP 预测层直接内嵌进主检查点，省去了草稿模型的显存和加载成本。`--speculative-num-steps`、`--speculative-eagle-topk`、`--speculative-num-draft-tokens` 这几个参数共同决定草稿长度与验证节奏，加速比取决于草稿的接受率——想在生产环境调优时，建议用仓库里的 bench_speculative.py 按真实负载扫一遍参数组合。
</Note>


```shell Command
python3 -m sglang.launch_server \
  --model Qwen/Qwen3-Next-80B-A3B-Instruct \
  --speculative-algorithm NEXTN \
  --speculative-num-steps 3 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4 \
  --tp 4
```

根据你的工作负载，用 [bench_speculative.py](https://github.com/sgl-project/sglang/blob/main/scripts/playground/bench_speculative.py) 调整 `--speculative-num-steps`、`--speculative-eagle-topk` 和 `--speculative-num-draft-tokens`。实现细节见 [PR #10233](https://github.com/sgl-project/sglang/pull/10233)。
