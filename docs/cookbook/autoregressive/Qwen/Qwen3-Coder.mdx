## 1. 模型介绍

[Qwen3-Coder](https://huggingface.co/collections/Qwen/qwen3-coder) 是 Qwen 团队推出的最新代码大语言模型系列。基于 Qwen3 构建，Qwen3-Coder 在代码生成、理解和推理任务上表现出色。

**主要特性：**

- **顶尖的编码性能**：在 HumanEval、MBPP、LiveCodeBench 等主要编码基准测试上取得一流成绩。
- **工具调用支持**：原生支持函数调用和工具使用，可无缝集成外部 API 和服务。
- **更长的上下文**：支持最长 256K token，可处理大型代码库和长文档。
- **多语言代码支持**：精通 Python、JavaScript、TypeScript、Java、C++、Go、Rust 等多种编程语言。
- **MoE 架构**：高效的混合专家设计，性能/成本比最优。
- **ROCm 支持**：通过 SGLang 兼容 AMD MI300X、MI325X 和 MI355X GPU（已验证）。
- **NVIDIA GPU 支持**：通过 SGLang 兼容 NVIDIA GB200 和 B200 GPU（已验证）。

更多细节请参考 [Qwen3-Coder 官方 GitHub 仓库](https://github.com/QwenLM/Qwen3-Coder)。

## 3. 模型部署

本节提供已在 AMD MI300X、MI325X、MI355X、NVIDIA B200、GB200 和 Intel Xeon CPU 硬件平台上验证过的部署配置。

<Note>
💡 AI Infra 学习笔记：Qwen3-Coder-480B-A35B 是超大规模 MoE 编码模型，FP8 量化后仍需 `--ep 2` 是因为要满足专家权重的维度对齐约束：`(moe_intermediate_size / moe_tp_size) % weight_block_size_n == 0`。专家并行（EP）把不同专家分到不同 GPU，配合张量并行（TP）能显著提升 MoE 的吞吐——但低并发下通信开销可能抵消收益，因此 EP/TP 组合通常要按实际负载来选。
</Note>

### 3.2 配置建议

**AMD（MI300X/MI325X/MI355X）：**
* **显存管理**：我们已在 MI300X/MI325X/MI355X 上验证 `--context-length 8192` 可成功部署。更大的上下文长度可能也支持，但需要更多显存。
* **专家并行**：对于 FP8 量化的 480B-A35B，需要 `--ep 2` 才能满足维度对齐要求。
* **页大小**：MoE 模型建议使用 `--page-size 32` 以优化显存使用。
* **环境变量**：如果遇到与 aiter 相关的问题，可以尝试设置 `SGLANG_USE_AITER=0`。

**NVIDIA（B200/GB200）：**
* **GB200 并行**：GB200 上使用 `--tp 4 --ep 4`。B200 使用上面生成的默认 NVIDIA 设置。
* **NVFP4 量化**：需要 `--quantization modelopt_fp4`，并使用不同的模型路径（`nvidia/Qwen3-Coder-...`）。
* **DP 注意力**：NVFP4 配置支持 `--enable-dp-attention` 以提高吞吐。

**Intel Xeon CPU：**
* 请参考 [SGLang CPU 服务端文档](../../../docs/hardware-platforms/cpu_server#launch-of-the-serving-engine) 中启动推理引擎一节的 `Notes` 部分，以更好地理解如何配置相关参数，尤其是 TP（张量并行）和 NUMA 绑定设置。

**通用：**
* **工具使用**：要在启动命令中启用工具调用，添加 `--tool-call-parser qwen3_coder`。

```python
from typing import List, Optional, TypeVar

T = TypeVar('T')

def binary_search(arr: List[T], target: T) -> Optional[int]:
    """
    Perform binary search on a sorted list to find the index of a target element.

    This function implements the binary search algorithm, which efficiently finds
    a target value in a sorted array by repeatedly dividing the search interval
    in half.

    Args:
        arr (List[T]): A sorted list of elements to search through.
        target (T): The element to search for in the list.

    Returns:
        Optional[int]: The index of the target element if found, None otherwise.

    Time Complexity:
        O(log n) where n is the number of elements in the array.

    Space Complexity:
        O(1) - iterative implementation uses constant extra space.

    Examples:
        >>> binary_search([1, 2, 3, 4, 5], 3)
        2
        >>> binary_search([1, 2, 3, 4, 5], 6)
        None
        >>> binary_search(['a', 'b', 'c', 'd'], 'b')
        1
        >>> binary_search([], 1)
        None
    """
    if not arr:
        return None

    left: int = 0
    right: int = len(arr) - 1

    while left <= right:
        mid: int = (left + right) // 2

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return None

# Alternative recursive implementation
def binary_search_recursive(arr: List[T], target: T, left: int = 0, right: Optional[int] = None) -> Optional[int]:
    """
    Perform binary search recursively on a sorted list to find the index of a target element.

    Args:
        arr (List[T]): A sorted list of elements to search through.
        target (T): The element to search for in the list.
        left (int): Left boundary of the search range (inclusive).
        right (Optional[int]): Right boundary of the search range (inclusive).

    Returns:
        Optional[int]: The index of the target element if found, None otherwise.

    Time Complexity:
        O(log n) where n is the number of elements in the array.

    Space Complexity:
        O(log n) due to recursive call stack.

    Examples:
        >>> binary_search_recursive([1, 2, 3, 4, 5], 3)
        2
        >>> binary_search_recursive([1, 2, 3, 4, 5], 6)
        None
    """
    if not arr:
        return None

    if right is None:
        right = len(arr) - 1

    if left > right:
        return None

    mid: int = (left + right) // 2

    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search_recursive(arr, target, mid + 1, right)
    else:
        return binary_search_recursive(arr, target, left, mid - 1)
```

1. **Main function** (`binary_search`): An iterative implementation that's more memory-efficient
2. **Alternative function** (`binary_search_recursive`): A recursive implementation for educational purposes
3. **Type hints**: Using generics (`TypeVar`) to work with any comparable type
4. **Comprehensive docstring**: Including description, parameters, return value, complexity analysis, and examples
5. **Edge case handling**: Empty lists, elements not found, etc.
6. **Clear variable names**: Self-documenting code
7. **Examples**: Doctest-style examples in the docstring

The function works with any sorted list of comparable elements (integers, strings, etc.) and returns the index of the target element if found, or `None` if not found.

#### 4.2.2 工具调用示例

Qwen3-Coder 支持工具调用。部署时启用工具调用解析器。下面的示例使用 30B-A3B 模型：

```shell Command
SGLANG_USE_AITER=0 python -m sglang.launch_server \
  --model Qwen/Qwen3-Coder-30B-A3B-Instruct \
  --tp 1 \
  --context-length 8192 \
  --page-size 32 \
  --tool-call-parser qwen3_coder
```

**Python 示例：**

```python Example
from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",
    base_url="http://localhost:30000/v1",
    timeout=3600
)

# Define available tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "execute_code",
            "description": "Execute Python code and return the result",
            "parameters": {
                "type": "object",
                "properties": {
                    "code": {
                        "type": "string",
                        "description": "The Python code to execute"
                    }
                },
                "required": ["code"]
            }
        }
    }
]

response = client.chat.completions.create(
    model="Qwen/Qwen3-Coder-30B-A3B-Instruct",
    messages=[
        {"role": "user", "content": "Calculate the factorial of 10 using Python"}
    ],
    tools=tools,
    temperature=0.7
)

# Check if the model wants to call a tool
if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    print(f"Tool: {tool_call.function.name}")
    print(f"Arguments: {tool_call.function.arguments}")
else:
    # Model may return tool call in content format
    print(response.choices[0].message.content)
```

**示例输出：**

```text Output

Arguments: {"code": "def factorial(n):\n    if n == 0 or n == 1:\n        return 1\n    else:\n        return n * factorial(n-1)\n\nresult = factorial(10)\nresult"}
```

## 5. 基准测试

### 5.1 速度基准测试

**测试环境：**

- 硬件：AMD MI300X GPU（8 块）
- 模型：Qwen/Qwen3-Coder-480B-A35B-Instruct-FP8
- 张量并行：8
- 专家并行：2
- SGLang 版本：0.5.7

我们使用 SGLang 内置的基准测试工具，用随机数据集进行性能评估。

<Note>
💡 AI Infra 学习笔记：对比下面 AMD 与 NVIDIA 的基准结果可以发现，低并发（1 请求）时每请求延迟更高、吞吐很低，而高并发（320 请求）时总吞吐大幅攀升、但单个请求的端到端延迟明显变长——这正是连续批处理下「吞吐优先 vs 延迟优先」的经典取舍，也解释了为什么延迟敏感场景要限制 `--max-concurrency` 或用投机解码。
</Note>
