`sglang.bench_serving` 是一个命令行工具，用于对大型语言模型（LLM）和视觉语言模型（VLM）的在线服务化吞吐量与延迟做基准测试。它支持多种后端（`SGLang`、`vLLM` 等），并能灵活配置请求速率、数据集类型和性能剖析。

## 1. 快速开始

### 基本用法（随机数据）

用随机生成的提示词对本地 SGLang 服务端运行基准测试。

```bash Command
python -m sglang.bench_serving --backend sglang --port 30000 --dataset-name random --num-prompts 100
```

### 真实数据（ShareGPT）

使用 ShareGPT 数据集以指定的请求速率运行基准测试。

```shell Command
python -m sglang.bench_serving \
  --backend sglang \
  --dataset-name sharegpt \
  --dataset-path ./ShareGPT_V3_unfiltered_cleaned_split.json \
  --num-prompts 1000 \
  --request-rate 10
```

### 2.3 输入/输出长度控制

用于控制请求形态（上下文长度与生成长度）的参数。

#### 随机/图像数据集：

- `--random-input-len`：每个请求的输入 token 数。
- `--random-output-len`：每个请求的输出 token 数。
- `--random-range-ratio`：采样输入/输出长度时使用的范围比例。

#### ShareGPT 数据集：

- `--sharegpt-output-len`：覆盖数据集中为每个请求定义的输出长度。
- `--sharegpt-context-len`：最大上下文长度，超过该长度的请求会被丢弃。

#### 通用请求修饰项：

- `--extra-request-body`：向请求负载追加一个 JSON 对象（例如 \{"key": "value"\}）。适合用来传递采样参数。
- `--prompt-suffix`：追加到所有用户提示词末尾的字符串后缀。
- `--disable-ignore-eos`：设置后，模型遇到 EOS token 即停止生成（基准测试通常会忽略 EOS，以强制达到最大生成长度）。
- `--apply-chat-template`：对输入应用模型的对话模板。

### 2.6 高级选项

#### 2.6.1 图像 / 多模态

仅当 --dataset-name 设置为 image 时适用。

- `--image-count`：每个请求的图像数量。
- `--image-resolution`：分辨率（例如 1080p、4k 或自定义的 1080x1920）。
- `--image-format`：jpeg 或 png。
- `--image-content`：random（噪声）或 blank。

#### 2.6.2 LoRA 基准测试

用于模拟多 LoRA 服务化场景。

- `--lora-name`：LoRA 适配器名称列表（例如 `--lora-name` adapter1 adapter2）。
- `--lora-request-distribution`：请求如何分配给各适配器：
  - `uniform`：等概率分配。
  - `distinct`：每个请求使用新适配器。
  - `skewed`：服从 Zipf 分布（模拟热/冷适配器）。
- `--lora-zipf-alpha`：Zipf 分布的 alpha 参数（使用 `skewed` 时）。

#### 2.6.3 性能剖析

用于深入性能分析的选项。

- `--profile`：启用 Torch Profiler（需要服务端设置 `SGLANG_TORCH_PROFILER_DIR` 环境变量）。
- `--plot-throughput`：生成吞吐量/并发图（需要 `termplotlib` 和 `gnuplot`）。
- `--profile-activities`：要剖析的活动（CPU、GPU、CUDA_PROFILER）。
- `--profile-num-steps`：要剖析的步数。
- `--profile-by-stage` / `--profile-stages`：剖析特定的处理阶段。

#### 2.6.4 PD 分离部署

用于对 Prefill-Decode（PD）分离架构做基准测试。

- `--pd-separated`：启用 PD 分离部署基准测试。
- `--profile-prefill-url`：用于剖析的 prefill worker 的 URL。
- `--profile-decode-url`：用于剖析的 decode worker 的 URL。

<span style={{color:"red"}}>注意</span>：在 PD 模式下，`prefill` 和 `decode` 必须分别剖析。

### 2.7 专用数据集

#### 2.7.1 生成的共享前缀（GSP）：

用于测试系统提示词缓存/前缀共享性能。

- `--gsp-num-groups`：唯一系统提示词的数量。
- `--gsp-prompts-per-group`：共享同一系统提示词的用户问题数量。
- `--gsp-system-prompt-len`：共享前缀的长度。
- `--gsp-fast-prepare`：跳过部分统计计算以加快启动。

#### 2.7.2 Mooncake

用于轨迹回放（trace replay）。

- `--mooncake-slowdown-factor`：放慢轨迹回放的速度（例如 2.0 = 慢 2 倍）。
- `--mooncake-num-rounds`：对话轮数（支持多轮）。
- `--use-trace-timestamps`：根据轨迹文件中的时间戳调度请求。

## 3. 指标

运行基准测试后，工具通常会报告以下指标：

<Note>
💡 AI Infra 学习笔记：TTFT、TPOT、ITL 是衡量在线推理服务体验的三大核心指标。TTFT 对应首 token 延迟（主要受预填充阶段影响），TPOT/ITL 反映生成阶段的吞吐与流畅度。做性能优化或对比不同引擎时，这三项指标比单纯的端到端耗时更能定位瓶颈。
</Note>

- `E2E`（端到端延迟）：从发送请求到收到最后一个 token 的总耗时。
- `TTFT`（首 token 时间）：从发送请求到看到第一个字出现之间的时间。它反映的是 Prefill（预填充）耗时，即处理图像和文本提示词的时间。
- `TPOT`（每个输出 token 的时间）：生成单个 token 的平均耗时（不含第一个 token），按每个请求分别计算。
- `ITL`（token 间延迟）：两个相邻流式数据包之间的时间间隔。TPOT 是平均值，而 ITL 衡量的是流的"抖动"或平滑度。
